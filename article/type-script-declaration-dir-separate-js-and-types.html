TypeScript declarationDir: Separate JS and Types

Managing build artifacts in TypeScript often requires distinguishing between executable runtime code and static type declarations. This article explains how the declarationDir compiler option functions, how it interacts with outDir and declaration, and how to configure tsconfig.json to direct emitted JavaScript files and TypeScript declaration files into entirely separate folders.

The Default Emit Behavior

When TypeScript compiles a project with declarations enabled, it generates both JavaScript files (.js) and type declaration files (.d.ts). By default, if you specify an outDir, the TypeScript compiler (tsc) places both types of emitted files together into the same directory structure.

For example, a file at src/index.ts will emit both dist/index.js and dist/index.d.ts into the specified dist folder. While functional, mixing runtime code and declaration files can clutter build directories and complicate packaging strategies.

How declarationDir Works

The declarationDir compiler option explicitly reroutes the output path for .d.ts and .d.ts.map files without affecting where the .js and .js.map files are written.

When declarationDir is set:

  • JavaScript files (and their source maps) continue emitting to the directory specified by outDir.
  • Declaration files (and their source maps) emit to the path specified by declarationDir.

Both destinations preserve the original directory hierarchy of the source code relative to rootDir.

Configuration Requirements

To separate emitted files, you must enable three key settings inside your tsconfig.json:

  1. "declaration": true — Instructs the compiler to emit .d.ts files.
  2. "outDir": "<path>" — Sets the destination for compiled JavaScript files.
  3. "declarationDir": "<path>" — Overrides the destination exclusively for emitted .d.ts files.

Example tsconfig.json Setup

{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "rootDir": "./src",
    "outDir": "./dist/js",
    "declaration": true,
    "declarationDir": "./dist/types",
    "strict": true
  },
  "include": ["src/**/*"]
}

Resulting Directory Structure

Given a source structure like this:

my-project/
├── src/
│   ├── components/
│   │   └── button.ts
│   └── index.ts
└── tsconfig.json

Running tsc with the configuration above generates cleanly separated output paths:

my-project/
└── dist/
    ├── js/
    │   ├── components/
    │   │   └── button.js
    │   └── index.js
    └── types/
        ├── components/
        │   └── button.d.ts
        └── index.d.ts

Configuring package.json

When using separate output directories for a published library, update your package.json entry points to match the designated locations:

{
  "name": "my-library",
  "version": "1.0.0",
  "main": "./dist/js/index.js",
  "types": "./dist/types/index.d.ts",
  "exports": {
    ".": {
      "types": "./dist/types/index.d.ts",
      "import": "./dist/js/index.js"
    }
  }
}

By decoupling the declaration target from the general compilation target, declarationDir gives you full control over your project's distribution layout, making package maintenance and post-processing steps simpler and cleaner.
