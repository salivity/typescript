Freshness in TypeScript Object Literal Types

Freshness, also known as strict object literal checking or excess property checking, is a TypeScript mechanism designed to catch typos and unintended properties in object literals. While TypeScript typically uses a structural type system that allows objects to contain extra properties, it treats newly created object literals with a unique "fresh" state that strictly forbids unexpected keys. This article explains what freshness is, why it exists, how it differs from standard structural typing, and how an object literal loses its freshness.

The Purpose of Freshness

In TypeScript's standard structural type system, an object is compatible with an interface as long as it satisfies all required properties of that interface, regardless of whether it contains extra properties. This is called "width subtyping."

However, when developers write object literals directly, extra properties are almost always mistakes, such as misspelled keys or deprecated options. To prevent these bugs without breaking general structural subtyping, TypeScript introduces freshness. When an object literal is assigned directly to a typed variable or passed as a typed function argument, TypeScript flags any property that does not explicitly exist on the target type.

How Freshness Works in Practice

Consider an interface defining a user profile:

interface User {
  name: string;
  age: number;
}

If you pass an object literal directly with an extra or misspelled property, TypeScript marks the literal as "fresh" and applies excess property checking:

// Error: Object literal may only specify known properties, and 'agge' does not exist in type 'User'.
const user: User = {
  name: "Alice",
  agge: 30 
};

Even though the object literal has the valid name property, TypeScript rejects it because the "fresh" status strictly disallows the unexpected agge key.

Fresh vs. Non-Fresh Objects

An object literal only retains its freshness until it is assigned to a variable without an explicit type annotation or used in a way that widens its type. Once an object is stored in an intermediate variable, it loses its freshness, and TypeScript falls back to standard structural typing.

// Intermediate object (not fresh when assigned to User)
const rawInput = {
  name: "Alice",
  age: 30,
  extraData: "Allowed"
};

// Valid: rawInput is no longer fresh, so standard structural typing applies
const validUser: User = rawInput;

In this scenario, rawInput satisfies the contract of User by containing name and age. Because it is not a fresh literal at the point of assignment to validUser, the excess property check is skipped.

How an Object Loses Freshness

An object literal loses its freshness in two common scenarios:

  1. Assignment to an Intermediate Variable: Storing the literal in an un-annotated variable widens its type to the inferred shape, stripping the freshness flag.
  2. Type Assertions: Using the as keyword overrides freshness checking completely:
const user: User = {
  name: "Alice",
  age: 30,
  extraData: "Bypassed"
} as User; // No error: freshness is explicitly circumvented

Summary

Freshness is a targeted safeguard in TypeScript. It bridges the gap between the flexibility of structural typing and the safety developers expect when writing inline code. By treating newly defined object literals as fresh, TypeScript prevents silent bugs caused by typos and invalid parameters at the exact moment those objects are created.
