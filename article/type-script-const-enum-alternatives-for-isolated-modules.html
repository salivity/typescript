TypeScript Const Enum Alternatives for isolatedModules

When TypeScript's isolatedModules flag is enabled, compilers like Babel, SWC, and esbuild transpile each file independently without full type graph awareness, rendering const enum exports invalid because they cannot be safely inlined across file boundaries. To maintain compile-time safety and runtime performance without breaking isolated transpilation pipelines, developers must rely on effective alternatives. This article covers the top replacements for const enum, including as const object maps, literal union types, and standard enums, outlining how each approach satisfies the constraints of modern build tools.

The Problem with const enum Under isolatedModules

A standard const enum is erased during compilation, and its values are inlined directly at the call site. However, when transpilers operate on a single-file basis via isolatedModules, they cannot read external type definitions to inline values from imported const enum declarations. This results in a runtime error or a compilation failure.

Below are the most effective alternatives.

1. Object Literals with as const (Recommended)

The most popular and idiomatic modern TypeScript pattern is combining an immutable object literal with a mapped type.

export const Direction = {
  Up: 'UP',
  Down: 'DOWN',
  Left: 'LEFT',
  Right: 'RIGHT',
} as const;

export type Direction = typeof Direction[keyof typeof Direction];

Why It Works

  • Compatibility: Generates standard JavaScript objects that single-file transpilers like esbuild and Babel can parse without issue.
  • Unified Namespace: You can use Direction as both a runtime object (Direction.Up) and a TypeScript type (let d: Direction).
  • Tree-shaking: Dead-code elimination tools easily optimize plain object structures.

2. String Literal Union Types

If you only need type safety without the need to iterate over values at runtime, pure string literal unions are the simplest alternative.

export type Direction = 'UP' | 'DOWN' | 'LEFT' | 'RIGHT';

function move(direction: Direction) {
  // ...
}

Why It Works

  • Zero Runtime Cost: Entirely erased during compilation, leaving no JavaScript output.
  • Refactoring: Fully supported by IDE autocomplete and rename refactoring.
  • Simplicity: Eliminates the ceremony of accessing object properties.

3. Regular (Non-Const) Enums

Removing the const modifier turns the declaration into a standard TypeScript enum.

export enum Direction {
  Up = 'UP',
  Down = 'DOWN',
  Left = 'LEFT',
  Right = 'RIGHT',
}

Why It Works

  • Syntax Familiarity: Preserves classic TypeScript enum syntax and nominal type checking.
  • Safe Transpilation: Regular enums compile into an Immediately Invoked Function Expression (IIFE) object at runtime, allowing single-file transpilers to preserve the imported reference.

Note: Regular enums add a minor amount of boilerplate code to your final build output compared to pure objects or unions.

4. Transpiler Plugins

If migrating existing codebases away from const enum is too costly, you can keep them by integrating dedicated build plugins into your toolchain:

  • Babel: babel-plugin-const-enum transforms const enum declarations into numeric/string literals or regular enums during the Babel build step.
  • esbuild/SWC: Specialized pre-processing plugins exist in various bundler ecosystems (like Vite or Webpack) that inline the types before the single-file transpilation stage executes.
