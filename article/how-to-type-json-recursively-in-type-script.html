How to Type JSON Recursively in TypeScript

Handling arbitrary JSON data safely in TypeScript requires defining a type that accounts for nested structures of arbitrary depth. This article demonstrates how to construct a robust, recursive type definition for JSON values using TypeScript's recursive type aliases, handle immutable variations, and properly enforce JSON serialization rules.

Defining the Core JSON Types

A valid JSON value can only be a string, number, boolean, null, an object whose values are JSON values, or an array of JSON values. Starting with TypeScript 3.7, type aliases can reference themselves recursively, making this definition straightforward:

export type JsonPrimitive = string | number | boolean | null;

export type JsonValue =
  | JsonPrimitive
  | JsonObject
  | JsonArray;

export type JsonObject = {
  [key: string]: JsonValue;
};

export type JsonArray = JsonValue[];

In this setup:

  • JsonPrimitive models the leaf nodes of any JSON tree. Note that undefined, symbol, and bigint are deliberately omitted because they are not valid in standard JSON.
  • JsonObject uses an index signature where every string key maps to a recursive JsonValue.
  • JsonArray is an array whose elements are recursive JsonValue instances.
  • JsonValue acts as the union of all possible states.

Making JSON Types Read-Only

When consuming JSON data from external APIs or configurations where mutation should be prevented, define a deep read-only variant using TypeScript's readonly modifiers:

export type ReadonlyJsonValue =
  | JsonPrimitive
  | ReadonlyJsonObject
  | ReadonlyJsonArray;

export type ReadonlyJsonObject = {
  readonly [key: string]: ReadonlyJsonValue;
};

export type ReadonlyJsonArray = readonly ReadonlyJsonValue[];

This prevents accidental in-place mutations such as data.items.push(...) or data.nested.field = 'new'.

Handling Optional Properties and Undefined

According to the JSON specification (RFC 8259), object keys cannot have a value of undefined. However, JavaScript objects frequently have missing keys. If an object type needs to allow omitted properties while remaining JSON-compatible, you can permit undefined strictly on keys without making it a root JsonValue:

export type LooseJsonObject = {
  [key: string]: JsonValue | undefined;
};

This ensures that while a property can be absent (undefined), any concrete nested value inside arrays or explicitly passed must still adhere to valid JSON primitive or structural rules.

Practical Usage: Safer JSON.parse

By default, JSON.parse returns any, which disables type checking and can lead to runtime errors. You can use the recursive JsonValue type to introduce type safety:

function safeJsonParse(jsonString: string): JsonValue {
  return JSON.parse(jsonString) as JsonValue;
}

const parsed = safeJsonParse('{"user": {"name": "Alice", "tags": ["admin"]}}');

// Type narrowing works predictably:
if (typeof parsed === "object" && parsed !== null && !Array.isArray(parsed)) {
  const user = parsed["user"];
  if (typeof user === "object" && user !== null && !Array.isArray(user)) {
    console.log(user["name"]);
  }
}

By defining JSON recursively, TypeScript enforces that nested properties cannot unexpectedly hold unsupported JavaScript values like functions, class instances, or symbols.
