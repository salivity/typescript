TypeScript Accessor Decorators: Get and Set Traps

Modern TypeScript (version 5.0 and later) adopts the ECMAScript Stage 3 decorators standard, introducing dedicated decorators for auto-accessors defined with the accessor keyword. By applying a decorator to an auto-accessor, developers can return an object containing custom get and set methods that wrap the underlying storage slot. These methods act as traps, intercepting property access and mutation directly at the prototype level to enable validation, logging, reactivity, and lazy evaluation without the boilerplate of manually declaring private backing fields.

The Auto-Accessor Keyword

Before decorators can intercept read and write operations, the property must be defined as an auto-accessor using the accessor keyword:

class User {
  accessor name: string;

  constructor(name: string) {
    this.name = name;
  }
}

Under the hood, TypeScript desugars this syntax into a private backing field combined with a standard getter and setter pair on the class prototype:

class User {
  #name: string;
  get name() { return this.#name; }
  set name(value: string) { this.#name = value; }
}

Decorator Signature and Return Types

An accessor decorator receives two arguments:

  1. target: An object containing the original get and set functions representing the default auto-accessor behavior: { get: () => T, set: (value: T) => void }.
  2. context: A ClassAccessorDecoratorContext object that provides metadata such as the property name, access utilities, and lifecycle methods like addInitializer.

To introduce get and set traps, the decorator returns a ClassAccessorDecoratorResult object. This object may define:

  • get: A replacement getter function.
  • set: A replacement setter function.
  • init: An optional function that transforms the initial value passed during construction.

Implementing Get and Set Traps

When an accessor decorator returns replacement functions, TypeScript routes all property access through the newly provided methods. The original accessors passed via target are invoked explicitly within the traps to interact with the underlying private slot.

type AccessorTarget<This, Value> = {
  get: (this: This) => Value;
  set: (this: This, value: Value) => void;
};

function logged<This, Value>(
  target: AccessorTarget<This, Value>,
  context: ClassAccessorDecoratorContext<This, Value>
) {
  const propertyKey = String(context.name);

  return {
    get(this: This): Value {
      const value = target.get.call(this);
      console.log(`[GET] ${propertyKey} read as: ${value}`);
      return value;
    },
    set(this: This, value: Value): void {
      console.log(`[SET] ${propertyKey} changing to: ${value}`);
      target.set.call(this, value);
    },
    init(this: This, initialValue: Value): Value {
      console.log(`[INIT] ${propertyKey} initialized to: ${initialValue}`);
      return initialValue;
    }
  };
}

class Product {
  @logged
  accessor price: number;

  constructor(price: number) {
    this.price = price;
  }
}

const item = new Product(100); // Logs [INIT] and [SET]
item.price = 150;              // Logs [SET] price changing to: 150
const current = item.price;    // Logs [GET] price read as: 150

How Traps Intercept Property Mutations

The set trap receives the incoming value before it is written to the backing store. This allows developers to enforce invariant conditions, validate types at runtime, normalize data, or trigger external observers.

function positiveOnly<This>(
  target: AccessorTarget<This, number>,
  context: ClassAccessorDecoratorContext<This, number>
) {
  return {
    set(this: This, value: number) {
      if (value < 0) {
        throw new RangeError(`${String(context.name)} must be a positive number.`);
      }
      target.set.call(this, value);
    }
  };
}

class Account {
  @positiveOnly
  accessor balance: number = 0;
}

If an assignment violates the validation logic, execution halts before target.set.call(this, value) is reached, preventing the internal state from corrupting.

How Traps Intercept Property Reads

The get trap intercepts the retrieval pipeline, enabling behaviors such as memoization, reactive dependency registration, or transformation of the retrieved value.

function trimmed<This>(
  target: AccessorTarget<This, string>,
  context: ClassAccessorDecoratorContext<This, string>
) {
  return {
    get(this: This): string {
      const raw = target.get.call(this);
      return raw ? raw.trim() : raw;
    }
  };
}

Whenever the property is referenced, the trap invokes target.get.call(this) to obtain the stored state, applies the transformation, and returns the modified result.

Advantages Over Legacy Decorators and Proxies

Compared to experimental TypeScript decorators, modern accessor decorators do not require direct manipulation of Object.defineProperty or manual traversal of prototype property descriptors. Compared to Proxy objects, accessor decorators introduce traps directly on the class prototype without creating wrapper objects, preserving instance identity (this), and avoiding the memory overhead associated with proxying entire object instances.
