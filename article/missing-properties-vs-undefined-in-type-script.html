Missing Properties vs Undefined in TypeScript

In JavaScript and TypeScript, an object property that is omitted entirely behaves differently at runtime from a property that exists but holds the value undefined. By default, TypeScript blurs this boundary by allowing optional properties to accept an explicit undefined value. However, through structural typing behavior and the exactOptionalPropertyTypes compiler flag, TypeScript provides clear mechanisms to distinguish between a key that is missing and a key explicitly set to undefined.

The Default Behavior

By default, when you define an optional property on an interface or type alias, TypeScript treats being absent and holding undefined as equivalent:

interface UserProfile {
  bio?: string;
}

// Both are valid by default:
const userA: UserProfile = {}; 
const userB: UserProfile = { bio: undefined };

Under default compiler settings, bio?: string is implicitly interpreted as bio?: string | undefined. TypeScript allows you to assign undefined directly to the key, even though at runtime the two objects have different internal structures.

The Runtime Discrepancy

While standard TypeScript type checking may treat these states interchangeably, JavaScript runtime methods do not. Operations that inspect object keys expose the difference:

const userA = {};
const userB = { bio: undefined };

// Using the 'in' operator
console.log("bio" in userA); // false
console.log("bio" in userB); // true

// Using Object.keys()
console.log(Object.keys(userA)); // []
console.log(Object.keys(userB)); // ["bio"]

// Serialization via JSON.stringify()
console.log(JSON.stringify(userA)); // "{}"
console.log(JSON.stringify(userB)); // "{}" (undefined properties are omitted by JSON.stringify)

If your application relies on 'bio' in user checks, Object.assign(), or spread syntax ({ ...defaultValues, ...user }), an explicit undefined will overwrite existing values, whereas a missing property will not.

Distinguishing States with exactOptionalPropertyTypes

To resolve this discrepancy, TypeScript 4.4 introduced the exactOptionalPropertyTypes compiler option in tsconfig.json:

{
  "compilerOptions": {
    "exactOptionalPropertyTypes": true
  }
}

When this flag is enabled, TypeScript strictly differentiates between a missing property and a property set to undefined.

1. Pure Optional Properties

With the flag enabled, an optional property marked with ? can only be present with the specified type, or omitted entirely:

interface UserProfile {
  bio?: string;
}

const userA: UserProfile = {}; // Valid: property is absent
const userB: UserProfile = { bio: "Hello" }; // Valid: property is present

// Error: Type 'undefined' is not assignable to type 'string'
const userC: UserProfile = { bio: undefined };

2. Explicitly Allowing undefined

If you intend to allow an object to explicitly define the key with an undefined value, you must explicitly declare undefined as part of a union:

interface UserProfile {
  bio?: string | undefined;
}

const userA: UserProfile = {}; // Valid: property is absent
const userB: UserProfile = { bio: "Hello" }; // Valid: property is present
const userC: UserProfile = { bio: undefined }; // Valid: property is present with undefined

3. Required Properties Set to undefined

If a property must exist on the object, but its value can be undefined, omit the ? modifier and use the undefined type directly:

interface UserProfile {
  bio: string | undefined;
}

const userA: UserProfile = { bio: undefined }; // Valid: key is present
const userB: UserProfile = {}; // Error: Property 'bio' is missing

Summary of Type Representations

When exactOptionalPropertyTypes is active, TypeScript allows you to define three distinct states:

  • prop?: T — Property may be absent, or present with type T. It cannot be explicitly set to undefined.
  • prop?: T | undefined — Property may be absent, present with type T, or present with value undefined.
  • prop: T | undefined — Property must be present, and its value can be either T or undefined.
