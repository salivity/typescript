How to Use the satisfies Operator in TypeScript

The satisfies operator in TypeScript, introduced in version 4.9, allows developers to validate that an expression conforms to a specific type without altering or widening the resulting type of that expression. This article explains how satisfies functions, the limitations of traditional type annotations and assertions it overcomes, and practical code examples demonstrating how it preserves precise type inference while maintaining strict compile-time safety.

The Problem with Type Annotations and Assertions

Before TypeScript 4.9, developers generally relied on two methods to ensure an object matched a specific contract: type annotations and type assertions. Both approaches introduced compromises.

Using a standard type annotation ensures safety, but it widens the inferred type to match the annotation:

type Colors = 'red' | 'green' | 'blue';
type RGB = [red: number, green: number, blue: number];

const palette: Record<Colors, string | RGB> = {
  red: [255, 0, 0],
  green: '#00ff00',
  blue: [0, 0, 255],
};

// Error: Property 'toUpperCase' does not exist on type 'string | RGB'.
// Property 'toUpperCase' does not exist on type 'RGB'.
palette.green.toUpperCase();

Because palette was annotated with Record<Colors, string | RGB>, TypeScript treats every property as string | RGB. The compiler forgets that palette.green is definitely a string.

Using a type assertion (as) bypasses this widening but sacrifices safety:

const badPalette = {
  red: [255, 0, 0],
  grene: '#00ff00', // Typo in property name
} as Record<Colors, string | RGB>; // Compiles, but introduces a runtime bug

Type assertions tell the compiler to trust the developer, silencing valid errors such as misspelled property names or missing fields.

How the satisfies Operator Works

The satisfies operator validates an expression against a type without changing the inferred type of that expression. The syntax is placed after the expression:

const value = expression satisfies Type;

When evaluated, TypeScript verifies that expression meets all structural requirements defined by Type. If the expression violates the type, a compilation error occurs. If it passes, TypeScript assigns value the narrow, inferred type of expression rather than the broader Type.

Resolving the previous palette scenario with satisfies:

type Colors = 'red' | 'green' | 'blue';
type RGB = [red: number, green: number, blue: number];

const palette = {
  red: [255, 0, 0],
  green: '#00ff00',
  blue: [0, 0, 255],
} satisfies Record<Colors, string | RGB>;

// Fully supported: TypeScript knows 'green' is a string
palette.green.toUpperCase();

// Fully supported: TypeScript knows 'red' is a tuple of numbers
palette.red.map((channel) => channel / 255);

Key Use Cases

1. Catching Typos While Preserving Exact Object Keys

When defining configuration maps or dictionaries, you often want to ensure all keys match a set pattern without losing track of the specific keys declared:

type RouteConfig = Record<string, { path: string; requiresAuth: boolean }>;

const routes = {
  home: { path: '/', requiresAuth: false },
  dashboard: { path: '/dashboard', requiresAuth: true },
} satisfies RouteConfig;

// TypeScript preserves the exact keys: "home" | "dashboard"
routes.home.requiresAuth; // Valid

// Error: Property 'profile' does not exist on type '{ home: ...; dashboard: ...; }'
routes.profile;

Had routes been annotated with : RouteConfig, routes.profile would return { path: string; requiresAuth: boolean } | undefined instead of producing a compile-time error.

2. Enforcing Literal Types and Const Contexts

When combined with as const, the satisfies operator validates that deeply immutable data structures adhere to a strict interface:

interface ConnectionConfig {
  host: string;
  port: number;
  protocol: 'http' | 'https';
}

const config = {
  host: 'localhost',
  port: 8080,
  protocol: 'https',
} as const satisfies ConnectionConfig;

// config.protocol is typed as the literal 'https', not 'string' or 'http' | 'https'

Summary of Differences

  • Annotation (const x: T = ...): Enforces that the value matches T, but widens the inferred type of x to T.
  • Assertion (const x = ... as T): Casts the value to T, suppressing compiler checks and risking runtime errors.
  • Validation (const x = ... satisfies T): Enforces that the value matches T, while retaining the most specific, narrow inferred type possible.
