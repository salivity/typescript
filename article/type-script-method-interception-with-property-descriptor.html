TypeScript Method Interception with PropertyDescriptor

TypeScript method decorators provide access to the target method's underlying PropertyDescriptor, enabling developers to inspect, modify, or completely replace the method implementation at runtime. By capturing the original function assigned to descriptor.value and reassigning it to a new wrapper function, developers can intercept execution flow to execute custom logic before and after the invocation, modify arguments, alter return values, or handle errors seamlessly without changing the original class code.

The Role of PropertyDescriptor

In JavaScript and TypeScript, every object property is defined internally by a property descriptor, which details its configuration attributes: value, writable, enumerable, and configurable. For class methods, the actual callable function is held inside the value property.

When TypeScript evaluates a method decorator, it passes three arguments:

  1. target: The prototype of the class (or the constructor function for static members).
  2. propertyKey: The name of the member being decorated.
  3. descriptor: A typed TypedPropertyDescriptor<T> object representing the target method.

Because the decorator receives this descriptor by reference, modifying descriptor.value directly dictates what the runtime executes when the method is called.

How Method Interception Works

Method interception using PropertyDescriptor follows a four-step pattern:

  1. Capture the Original Method: Store a reference to descriptor.value in a local variable to preserve the original implementation.
  2. Assign a Wrapper Function: Reassign descriptor.value to a new function. This new function receives the arguments passed to the method at call time.
  3. Invoke with Correct Context: Inside the wrapper, call the original method using originalMethod.apply(this, args). Using this ensures the original method retains access to the class instance and its state.
  4. Return the Descriptor: Return the mutated descriptor from the decorator function so the TypeScript runtime applies the modified configuration via Object.defineProperty.

Implementation Example

The following code illustrates an execution-logging interceptor:

function LogExecution(
  target: any,
  propertyKey: string,
  descriptor: PropertyDescriptor
): PropertyDescriptor {
  // 1. Capture original method reference
  const originalMethod = descriptor.value;

  // 2. Override descriptor.value with an intercepting function
  descriptor.value = function (...args: any[]) {
    console.log(`[Before] Invoking ${propertyKey} with arguments:`, args);

    // 3. Execute original method preserving the 'this' context
    const result = originalMethod.apply(this, args);

    console.log(`[After] ${propertyKey} returned:`, result);

    // 4. Return the result back to the caller
    return result;
  };

  return descriptor;
}

class OrderService {
  @LogExecution
  calculateTotal(price: number, quantity: number): number {
    return price * quantity;
  }
}

Advantages of PropertyDescriptor Interception

  • Aspect-Oriented Programming (AOP): Cross-cutting concerns such as logging, validation, caching, performance profiling, and authorization can be encapsulated into modular, reusable decorator functions.
  • Context Preservation: Standard invocation via apply(this, args) prevents breaking access to class member variables and private fields.
  • Asynchronous Compatibility: By marking the wrapper function as async and awaiting originalMethod.apply(this, args), the pattern naturally extends to asynchronous promises without altering method signatures.
