What Does emitDeclarationOnly Do in TypeScript?

The emitDeclarationOnly flag is a TypeScript compiler option that instructs the compiler to generate only TypeScript declaration files (.d.ts) and skip the generation of JavaScript files (.js). This article explains the mechanics of emitDeclarationOnly, its configuration requirements, and the primary scenarios where developers use it to optimize their build pipelines.

How emitDeclarationOnly Works

By default, when you run the TypeScript compiler (tsc), it performs type checking and outputs both compiled JavaScript code (.js files) and, if configured, corresponding type declaration files (.d.ts files).

When you enable emitDeclarationOnly:

  • The compiler generates .d.ts files and their source maps (.d.ts.map), if enabled.
  • The compiler completely suppresses the emission of .js, .jsx, and JavaScript source maps (.js.map).
  • Full type checking is still performed across the codebase before outputting the declarations.

Configuration

To use emitDeclarationOnly, the declaration flag must also be set to true in your tsconfig.json, or an error will occur during compilation.

Here is an example configuration:

{
  "compilerOptions": {
    "target": "ESNext",
    "module": "ESNext",
    "declaration": true,
    "emitDeclarationOnly": true,
    "outDir": "./dist/types"
  },
  "include": ["src/**/*"]
}

You can also pass it as a flag directly through the command line interface:

tsc --emitDeclarationOnly

Common Use Cases

1. Integration with Modern Bundlers and Transpilers

Modern tools such as Babel, SWC, esbuild, and Vite transpile TypeScript code into JavaScript significantly faster than tsc. However, these tools generally strip out types without validating them and cannot generate .d.ts files.

Developers pair these tools with tsc --emitDeclarationOnly:

  • The bundler/transpiler handles the transpilation of .ts to .js.
  • The TypeScript compiler handles type checking and generates .d.ts files.

This separation of concerns enables faster builds while preserving type safety and library definitions.

2. Monorepos and Library Publishing

When publishing libraries to npm, consumers require declaration files to enable autocompletion and static type checking in their editors. If a library's JavaScript files are bundled into a single file (like an ESM or UMD bundle via Rollup), generating individual .js files via tsc is unnecessary. Enabling emitDeclarationOnly ensures you produce only the .d.ts bundle or folder required for distribution.

3. Parallelized CI/CD Pipelines

In continuous integration environments, tasks can be split to run concurrently. One worker can bundle the application code, while another worker runs tsc --emitDeclarationOnly to verify types and prepare types for downstream packages, reducing overall pipeline runtimes.
