Using tsconfig.base.json in TypeScript Monorepos

Managing configurations across multiple packages in a TypeScript monorepo can quickly lead to duplication and inconsistencies. A tsconfig.base.json file serves as the centralized foundation for the entire workspace, establishing common compiler rules, path mappings, and build constraints that every sub-project inherits. By standardizing these rules in a single file, developers ensure consistent code quality, simplify maintenance, and streamline build tooling across libraries and applications.

The Core Role of tsconfig.base.json

In a monorepo, different projects often share fundamental requirements, such as strict type-checking rules, modern ECMAScript targets, and module resolution strategies. Placing these shared settings in a root-level tsconfig.base.json allows it to act as the single source of truth.

Instead of defining identical compilerOptions in every package, individual packages extend the base file using TypeScript’s built-in extends property:

{
  "extends": "../../tsconfig.base.json",
  "compilerOptions": {
    "outDir": "./dist"
  },
  "include": ["src"]
}

This inheritance model ensures that any global update—such as enabling a new strict check or bumping the target ECMAScript version—propagates automatically to every package in the monorepo.

Centralized Path Aliasing

Monorepos frequently consist of internal packages that depend on each other. A tsconfig.base.json file centralizes path mappings via the paths and baseUrl properties, enabling smooth cross-package imports during development:

{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@workspace/ui": ["packages/ui/src"],
      "@workspace/utils": ["packages/utils/src"]
    }
  }
}

Defining these paths at the root level provides editors and the TypeScript language server with immediate resolution across package boundaries, eliminating the need to re-declare aliases in every individual package config.

Flexibility Through Project Overrides

While tsconfig.base.json defines universal defaults, sub-projects within a monorepo often have distinct runtime environments. For example, a React frontend requires JSX support and browser DOM types, whereas a Node.js backend requires Node typings and CommonJS or ESM execution defaults.

The base configuration handles this divergence gracefully. Sub-projects inherit baseline rules—like "strict": true and "forceConsistentCasingInFileNames": true—while selectively overriding environment-specific flags:

  • Frontend applications can add "jsx": "react-jsx" and "lib": ["DOM", "ESNext"].
  • Backend services can adjust "module": "CommonJS" or "moduleResolution": "Node".
  • Published libraries can enable "declaration": true and "declarationMap": true.

Alignment with Project References

Modern TypeScript monorepos rely heavily on Project References to enable incremental builds and enforce clear architectural boundaries. A centralized configuration is essential for orchestrating this setup.

The tsconfig.base.json file can enforce constraints necessary for references, such as "composite": true, "declaration": true, and "incremental": true. A companion root tsconfig.json can then reference each workspace package using the references array, enabling tsc --build to optimize build orders and cache outputs across the entire monorepo without re-compiling unchanged packages.
