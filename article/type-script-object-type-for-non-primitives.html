TypeScript object Type for Non-Primitives

In TypeScript, ensuring that an argument or variable strictly represents a reference type rather than a primitive value is a common requirement. This guide demonstrates how to strictly enforce non-primitive types using TypeScript’s lowercase object keyword, details how it differs from types like Object and {}, and illustrates its application in functions, generic constraints, and runtime narrowing.

Understanding the object Keyword

TypeScript introduced the lowercase object type in version 2.2 specifically to represent any non-primitive type. A primitive in JavaScript is any value that is not an object and has no methods: string, number, bigint, boolean, symbol, null, or undefined.

When a variable or parameter is annotated with object, TypeScript permits any reference value—such as plain objects, arrays, functions, sets, and class instances—while strictly rejecting all primitive values.

function processReference(target: object): void {
  // Logic here
}

// Valid assignments (non-primitives)
processReference({});
processReference({ key: "value" });
processReference([1, 2, 3]);
processReference(() => "hello");
processReference(new Map());

// Compile-time errors (primitives)
processReference(42);         // Error: Argument of type 'number' is not assignable to parameter of type 'object'.
processReference("text");     // Error: Argument of type 'string' is not assignable to parameter of type 'object'.
processReference(true);       // Error: Argument of type 'boolean' is not assignable to parameter of type 'object'.
processReference(null);       // Error: Argument of type 'null' is not assignable to parameter of type 'object'.
processReference(undefined);  // Error: Argument of type 'undefined' is not assignable to parameter of type 'object'.

The Difference Between object, Object, and {}

A common pitfall in TypeScript is confusing object with Object and {}:

  • object (lowercase): Strictly non-primitive values.
  • Object (uppercase): Represents the functionality provided by the JavaScript runtime's global Object interface. It permits any value except null and undefined because primitives can be auto-boxed into object wrappers.
  • {} (empty type): Represents any non-nullish value. Similar to Object, strings, numbers, and booleans can be assigned to {}.

To enforce non-primitive guarantees at compile time, always use lowercase object.

Using object as a Generic Constraint

The object keyword is frequently used to constrain generic parameters, preventing consumers from passing primitive values to functions designed specifically for objects.

function freezeEntity<T extends object>(entity: T): Readonly<T> {
  return Object.freeze(entity);
}

// Allowed
const user = freezeEntity({ id: 1, name: "Alice" });
const list = freezeEntity([1, 2, 3]);

// Prevented
freezeEntity("invalid"); // Error: Type 'string' does not satisfy the constraint 'object'.
freezeEntity(100);       // Error: Type 'number' does not satisfy the constraint 'object'.

Working with Values Typed as object

The object type acts as a black box; by design, it does not expose arbitrary properties because TypeScript cannot infer its exact shape. Attempting to access arbitrary keys directly will trigger a compiler error:

function inspect(data: object) {
  // console.log(data.id); // Error: Property 'id' does not exist on type 'object'.
}

To safely interact with properties while retaining the non-primitive constraint:

  1. Use Type Narrowing with the in Operator:

    function inspect(data: object) {
  if ("id" in data) {
    console.log((data as { id: unknown }).id);
  }
}

  2. Combine with Record<PropertyKey, unknown> for Dictionary Access: If dynamic property access is required, combine or replace object with an index signature:

    function readDynamic(data: Record<string, unknown>) {
  console.log(data.id); // Allowed, typed as 'unknown'
}
