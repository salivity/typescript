TypeScript Factory Functions with Declaration Merging

Declaration merging in TypeScript allows developers to combine a callable function with a namespace sharing the same name. This article explains how declaration merging enables factory functions to host static utility methods with complete type safety, eliminating the need for manual type assertions or awkward Object.assign type overrides while providing seamless editor autocompletion.

The Problem: Attaching Methods to Functions

In JavaScript and TypeScript, functions are first-class objects capable of holding properties and methods. Factory functions often benefit from having companion utilities attached directly to them—such as validation helpers, default configurations, or alternative instantiation strategies.

Attempting to assign properties directly to a standard TypeScript function often triggers type errors:

function createUser(name: string) {
  return { id: "1", name };
}

// Error: Property 'isValid' does not exist on type '(name: string) => ...'
createUser.isValid = (name: string) => name.length > 0;

While developers frequently work around this using Object.assign or defining composite interfaces with call signatures, these approaches can be verbose and harm readability.

How Declaration Merging Solves It

TypeScript's declaration merging rules state that declarations of different kinds with the same identifier can merge into a single entity. Specifically, a function declaration can merge with a namespace declaration of the exact same name.

When you merge a function with a namespace:

  1. The function defines the callable implementation.
  2. The namespace defines the static properties and methods attached to that function.
  3. TypeScript combines their types, producing a callable object type with full IntelliSense support.

Practical Implementation

To implement a factory function with utility methods using declaration merging, define the function and namespace sequentially using identical identifiers:

export interface User {
  id: string;
  name: string;
  role: string;
}

// 1. The factory function
export function createUser(name: string): User {
  return {
    id: crypto.randomUUID(),
    name,
    role: createUser.defaultRole,
  };
}

// 2. The merged namespace containing utility methods and constants
export namespace createUser {
  export const defaultRole = "member";

  export function isValid(name: string): boolean {
    return name.trim().length >= 2;
  }

  export function createAdmin(name: string): User {
    return {
      id: crypto.randomUUID(),
      name,
      role: "admin",
    };
  }
}

Usage

Consumers can call the factory function directly or access its companion methods via property access on the same identifier:

// Using the factory function directly
const user = createUser("Alice");

// Using the merged utility methods
if (createUser.isValid("Bob")) {
  const admin = createUser.createAdmin("Bob");
}

console.log(createUser.defaultRole); // "member"

Runtime Behavior and Compilation

At the JavaScript level, TypeScript compiles the namespace into an immediately invoked function expression (IIFE) that attaches each exported member directly to the existing function object:

function createUser(name) {
  return {
    id: crypto.randomUUID(),
    name,
    role: createUser.defaultRole,
  };
}

(function (createUser) {
  createUser.defaultRole = "member";
  function isValid(name) {
    return name.trim().length >= 2;
  }
  createUser.isValid = isValid;
})(createUser || (createUser = {}));

Because TypeScript handles the property assignments under the hood, the runtime object and compile-time types stay perfectly in sync.

Key Advantages

  • Zero Type Assertions: There is no need to cast the function using as unknown as FactoryWithUtils.
  • Encapsulated Exports: Importing the factory function automatically brings along all attached utilities in a single import statement.
  • Type Co-location: You can export types and interfaces from within the namespace (e.g., createUser.Options), keeping related types grouped logically with their factory.
