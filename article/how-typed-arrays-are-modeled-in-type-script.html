How Typed Arrays Are Modeled in TypeScript

JavaScript typed arrays, such as Uint8Array and Float32Array, provide mechanisms for reading and writing raw binary data in memory buffers. In TypeScript, typed arrays are modeled using a comprehensive set of built-in interfaces defined in the standard library (lib.es5.d.ts and subsequent ECMAScript declarations). These definitions mirror the underlying JavaScript specification, treating typed arrays as specialized views over an ArrayBuffer while enforcing numeric access patterns, buffer association, and specific memory layout constraints.

The Core Architecture: Buffers and Views

TypeScript models binary data using two distinct concepts: raw memory storage and structured data views.

  1. ArrayBufferLike and ArrayBuffer: Represents the raw chunk of memory.
  2. ArrayBufferView: A base interface representing any view into an ArrayBuffer. It guarantees properties such as buffer, byteOffset, and byteLength.
interface ArrayBufferView {
    buffer: ArrayBufferLike;
    byteOffset: number;
    byteLength: number;
}

Every specific typed array—including Uint8Array, Int16Array, Float32Array, and BigInt64Array—implements ArrayBufferView.

Individual Typed Array Interfaces

Each typed array variant has its own pair of interfaces in TypeScript: an instance interface and a constructor interface.

Taking Uint8Array as an example:

interface Uint8Array {
    readonly BYTES_PER_ELEMENT: number;
    readonly buffer: ArrayBufferLike;
    readonly byteLength: number;
    readonly byteOffset: number;
    readonly length: number;
    [index: number]: number;

    // Array-like methods adapted for typed buffers
    set(array: ArrayLike<number>, offset?: number): void;
    subarray(begin?: number, end?: number): Uint8Array;
    slice(start?: number, end?: number): Uint8Array;
    // ... iteration and higher-order methods (map, filter, forEach)
}

interface Uint8ArrayConstructor {
    new (length: number): Uint8Array;
    new (array: ArrayLike<number> | ArrayBufferView): Uint8Array;
    new (buffer: ArrayBufferLike, byteOffset?: number, length?: number): Uint8Array;
    readonly BYTES_PER_ELEMENT: number;
    of(...items: number[]): Uint8Array;
    from(arrayLike: ArrayLike<number>): Uint8Array;
}

This separation allows TypeScript to strongly type both the static methods on the constructor (such as Uint8Array.from()) and the methods available on the instantiated instance.

Generics Over the Underlying Buffer

In modern versions of TypeScript, typed arrays are generic over their backing buffer type:

interface Uint8Array<TArrayBuffer extends ArrayBufferLike = ArrayBufferLike> {
    readonly buffer: TArrayBuffer;
    // ...
}

This generic parameter allows the type system to distinguish between a typed array backed by an exclusive ArrayBuffer versus one backed by a SharedArrayBuffer. When a typed array is created from a specific buffer, TypeScript tracks that buffer type:

const standardBuffer = new ArrayBuffer(16);
const sharedBuffer = new SharedArrayBuffer(16);

const standardView = new Uint8Array(standardBuffer); 
// Type: Uint8Array<ArrayBuffer>

const sharedView = new Uint8Array(sharedBuffer); 
// Type: Uint8Array<SharedArrayBuffer>

This prevents passing thread-shared memory structures into APIs that require exclusive ownership.

Key Differences from Standard Arrays

Although typed arrays look similar to standard JavaScript arrays, TypeScript models them with key functional differences:

  • Fixed Element Types: Unlike standard generic arrays (Array<T>), typed arrays only work with numeric primitives (number for integer/float arrays, or bigint for BigInt64Array and BigUint64Array).
  • No Length Mutation: Methods that alter array lengths—such as push(), pop(), shift(), and splice()—are omitted from typed array interfaces.
  • Return Types on Iteration: Higher-order functions like subarray() return the specific typed array type (e.g., Uint8Array), whereas methods like map() return a typed array if returning numbers, preserving the binary representation.

Type Compatibility and ArrayLike

All typed arrays implement ArrayLike<number> (or ArrayLike<bigint>), which means they can be passed to generic functions expecting read-only indexed collections. However, different typed array types are not directly assignable to one another because their byte footprints and memory semantics are distinct. For example, a function expecting a Float32Array will reject a Uint8Array at compile time, preventing alignment errors and data misinterpretation.
