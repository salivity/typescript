TypeScript Readonly Array Immutability Explained

This article explores how TypeScript enforces array immutability through the readonly modifier. You will learn the mechanics behind compile-time validation, including the removal of mutating methods, restrictions on element reassignment, and type assignability rules. The guide also highlights critical limitations, such as the distinction between shallow compile-time checks and true runtime immutability.

The Readonly Array Type System

TypeScript provides array immutability by altering the interface used to represent the array. In TypeScript, standard arrays implement the Array<T> interface, which includes mutating methods such as push(), pop(), splice(), and index reassignments.

When you apply the readonly modifier to an array, TypeScript instead maps the type to the ReadonlyArray<T> interface. You can declare these types using several syntaxes:

// Prefix modifier
const numbers: readonly number[] = [1, 2, 3];

// Generic type
const strings: ReadonlyArray<string> = ["a", "b", "c"];

// Type assertion (const assertion)
const values = [10, 20, 30] as const;

Regardless of the syntax used, TypeScript changes the underlying type definition to strip out any operations that alter the array in place.

How TypeScript Validates Immutability

TypeScript enforces immutability at compile time through two primary mechanisms: stripping mutating methods and restricting index signatures.

1. Removal of Mutating Methods

The ReadonlyArray<T> interface simply omits methods that modify the array in place. Methods that safely read or return new arrays—such as map(), filter(), slice(), and concat()—remain available.

If you attempt to invoke a mutating method, the TypeScript compiler flags it immediately:

const list: readonly number[] = [1, 2, 3];

// Error: Property 'push' does not exist on type 'readonly number[]'.
list.push(4);

// Error: Property 'splice' does not exist on type 'readonly number[]'.
list.splice(0, 1);

2. Read-Only Index Signatures

A standard array allows reassignment of individual elements via bracket notation. TypeScript allows this through an index signature that accepts assignments: [n: number]: T.

With a readonly array, TypeScript marks the index signature as readonly:

interface ReadonlyArray<T> {
  readonly [n: number]: T;
  // ...
}

Attempting to assign a new value to an index causes the compiler to reject the operation:

const list: readonly number[] = [1, 2, 3];

// Error: Index signature in type 'readonly number[]' only permits reading.
list[0] = 10;

Assignability Rules

TypeScript uses directional type assignability to prevent accidental mutations:

  • Mutable to Readonly: You can assign a standard array (T[]) to a readonly T[]. This is safe because the consumer promises not to mutate the data.
  • Readonly to Mutable: You cannot assign a readonly T[] to a standard T[]. This prevents passing a read-only array into a function that might alter it.
function mutateArray(arr: number[]) {
  arr.push(42);
}

const immutable: readonly number[] = [1, 2, 3];

// Error: Argument of type 'readonly number[]' is not assignable to parameter of type 'number[]'.
// The type 'readonly number[]' is 'readonly' and cannot be assigned to the mutable type 'number[]'.
mutateArray(immutable);

To pass a readonly array to a function expecting a mutable array, you must explicitly create a copy (e.g., using [...immutable]) or cast the type.

Key Limitations

While the readonly modifier provides strong compile-time safety, it has two notable limitations:

  1. Shallow Immutability: The readonly modifier only applies to the array itself, not to the elements within it. If the array contains objects, those objects can still be mutated:

    const users: readonly { name: string }[] = [{ name: "Alice" }];
users[0].name = "Bob"; // Valid: the object property is not readonly

    To make objects immutable, you must use nested Readonly<T> types or apply as const across the entire structure.

  2. No Runtime Enforcement: TypeScript's type checks are erased during compilation. In the emitted JavaScript, a readonly array is just a standard JavaScript array. If external JavaScript code interacts with your compiled code, or if you cast away the type with as number[], the array can still be mutated at runtime unless protected by Object.freeze().
