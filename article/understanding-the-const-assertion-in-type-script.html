Understanding the Const Assertion in TypeScript

This article provides an overview of the const assertion (as const) in TypeScript, explaining its fundamental purpose, how it prevents type widening, and how it enforces immutability at compile time. By examining its core behavior with objects, arrays, and primitive values, you will understand how to use this feature to produce stricter, more predictable types across your codebase.

In TypeScript, declaring a variable with the JavaScript const keyword prevents the variable reference from being reassigned, but it does not make nested values immutable, nor does it stop the TypeScript compiler from widening types. When you declare an object or an array, TypeScript naturally widens literal types to their broader primitives—such as converting "admin" to string or [1, 2] to number[]. The primary purpose of the const assertion (as const) is to signal to the compiler that an entire expression should be treated as a deeply immutable, read-only literal type.

Preventing Literal Widening

By default, TypeScript assumes that the properties of an object or elements of an array might change later. For instance:

// Type is { role: string }
const user = {
  role: "admin",
};

When you append as const, TypeScript retains the exact literal value rather than broadening it:

// Type is { readonly role: "admin" }
const user = {
  role: "admin",
} as const;

This is essential when passing values to functions that accept strict union types (e.g., "admin" | "editor"), as a generic string type would trigger a compiler error.

Enforcing Read-Only Structures

Applying as const recursively assigns the readonly modifier to all properties in an object literal, effectively preventing accidental property mutation at compile time:

const config = {
  endpoint: "https://api.example.com",
  retries: 3,
} as const;

// Error: Cannot assign to 'endpoint' because it is a read-only property.
config.endpoint = "https://new-api.example.com";

Converting Arrays to Fixed Tuples

When applied to an array, the const assertion transforms a standard mutable array into a readonly tuple with a fixed length and specific literal elements in precise positions:

// Type is readonly ["GET", "POST"]
const allowedMethods = ["GET", "POST"] as const;

// Error: Property 'push' does not exist on type 'readonly ["GET", "POST"]'.
allowedMethods.push("DELETE");

Deriving Types from Values

A major advantage of using const assertions is enabling the "single source of truth" pattern. Instead of declaring an explicit TypeScript type or enum and a matching runtime array, you can define the runtime array using as const and extract the union type directly:

const roles = ["admin", "editor", "viewer"] as const;

// Equivalent to: type Role = "admin" | "editor" | "viewer"
type Role = (typeof roles)[number];

The const assertion eliminates the need for redundant type annotations while ensuring that complex data structures remain fully typed, narrow, and immutable throughout your application.
