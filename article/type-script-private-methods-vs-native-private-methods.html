TypeScript Private Methods vs Native Private Methods

TypeScript provides two mechanisms for declaring private class members: the compile-time private keyword and the ECMAScript native # prefix syntax. While both prevent accidental access from outside a class, they diverge significantly in how the TypeScript compiler handles them, resulting in fundamentally different emitted JavaScript, runtime behaviors, and security guarantees.

TypeScript's private Keyword (Compile-Time Privacy)

The private modifier is a TypeScript-exclusive feature introduced early in the language's lifecycle. It operates purely as a type-system constraint.

Emitted Output

When you compile a class using the private keyword, the TypeScript compiler strips the modifier entirely during the emit process:

// TypeScript source
class DataHandler {
  private logInternal(msg: string): void {
    console.log(msg);
  }
}

Targeting modern JavaScript yields standard prototype methods:

// Compiled JavaScript
class DataHandler {
  logInternal(msg) {
    console.log(msg);
  }
}

Runtime Behavior

Because the modifier is removed at compile time, there is zero runtime encapsulation. The compiled method is attached directly to the class prototype, making it accessible through dynamic access, bracket notation (instance['logInternal']()), or type casting ((instance as any).logInternal()).

Native Private Methods (#) (Runtime Privacy)

The #identifier syntax is part of the ECMAScript standard (introduced in ES2022). TypeScript supports this standard directly, offering "hard" runtime privacy.

// TypeScript source
class DataHandler {
  #logInternal(msg: string): void {
    console.log(msg);
  }
}

Emitted Output by Target

How TypeScript compiles native private methods depends on the target specified in your tsconfig.json.

1. Targeting ES2022 or Later

When targeting modern runtimes that support private class elements, TypeScript preserves the syntax natively:

// Compiled JavaScript (ES2022+)
class DataHandler {
  #logInternal(msg) {
    console.log(msg);
  }
}

The JavaScript engine itself handles privacy enforcement directly.

2. Targeting Older Standards (ES2015 to ES2021)

When targeting versions that lack native support, TypeScript transforms native private methods using WeakSet instances to emulate hard privacy:

// Compiled JavaScript (Downleveled)
var _DataHandler_instances, _DataHandler_logInternal;
class DataHandler {
  constructor() {
    _DataHandler_instances.add(this);
  }
}
_DataHandler_instances = new WeakSet();
_DataHandler_logInternal = function _DataHandler_logInternal(msg) {
  console.log(msg);
};

When #logInternal is invoked, TypeScript inserts an internal helper function that checks whether this is present in the WeakSet. If not, it throws a TypeError.

Runtime Behavior

Native private members provide hard encapsulation. The method is completely inaccessible from outside the class lexical scope. Reflection APIs such as Object.keys(), Object.getOwnPropertyNames(), and bracket notation cannot reveal or invoke the method.

Comparison Summary

Feature TypeScript private Native #private
Enforcement Compile-time only Runtime and compile-time
JS Representation Normal prototype method Native # or WeakSet closure
Runtime Access Possible via bracket notation Throws a TypeError or SyntaxError
Overriding in Subclasses Causes a compile-time collision error Completely invisible to subclasses; no name collisions
Downleveling Overhead None (standard methods) Generates WeakSet tracking per instance
