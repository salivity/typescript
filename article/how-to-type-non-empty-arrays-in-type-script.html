How to Type Non-Empty Arrays in TypeScript

In TypeScript, standard array types like T[] or Array<T> represent lists of any length, including zero elements. When writing functions that depend on at least one item being present—such as finding the head of a list, calculating averages, or running reductions without initial values—accepting an empty array can lead to unexpected runtime bugs. This guide demonstrates how to construct and use custom non-empty array types using TypeScript tuples and spread elements to enforce compile-time safety.

Defining the Non-Empty Array Type

The most idiomatic way to type a non-empty array is by defining a tuple that requires a first element of type T, followed by zero or more elements of type T using the rest syntax:

export type NonEmptyArray<T> = [T, ...T[]];

This definition tells TypeScript that the array must contain at least one item at index 0.

Using the Type in Functions

You can apply NonEmptyArray<T> directly as a parameter type for your functions:

function getHead<T>(arr: NonEmptyArray<T>): T {
  return arr[0];
}

function calculateAverage(numbers: NonEmptyArray<number>): number {
  const total = numbers.reduce((sum, val) => sum + val, 0);
  return total / numbers.length;
}

When you pass an array literal to these functions, TypeScript evaluates whether the requirement is satisfied:

// Valid calls
getHead([1, 2, 3]);          // Returns 1
calculateAverage([10, 20]);   // Returns 15
getHead(["only-one"]);        // Returns "only-one"

// Compiler error
getHead([]); 
// Error: Argument of type '[]' is not assignable to parameter of type 'NonEmptyArray<never>'.

Handling Readonly Arrays

If your function should also accept immutable or as const arrays, you can declare a readonly version:

export type ReadonlyNonEmptyArray<T> = readonly [T, ...T[]];

function printFirst<T>(items: ReadonlyNonEmptyArray<T>): void {
  console.log(items[0]);
}

const tags = ['typescript', 'javascript'] as const;
printFirst(tags); // Works correctly

Validating Dynamic Data with Type Guards

When working with data from external sources like APIs or user inputs, the data often arrives as a standard T[]. To safely pass these arrays into functions requiring a NonEmptyArray<T>, use a custom type guard:

function isNonEmpty<T>(arr: T[]): arr is NonEmptyArray<T> {
  return arr.length > 0;
}

// Example usage
const dynamicList: string[] = fetchItems();

if (isNonEmpty(dynamicList)) {
  // dynamicList is narrowed to NonEmptyArray<string>
  getHead(dynamicList);
} else {
  console.warn("Array is empty!");
}

Using this pattern eliminates unnecessary undefined checks on the first element, providing full type safety across your codebase.
