TypeScript Exhaustive Type Checking Using Never

Exhaustive type checking in TypeScript is a compile-time technique used to ensure that all possible variants of a union type are handled across branching logic. By leveraging TypeScript's never type, developers can make the compiler raise an error whenever a new case is added to a union but forgotten in a switch or if/else block. This article explains how the never type functions as a safety net, how to implement an exhaustive check pattern, and why it prevents runtime bugs.

Understanding the never Type

In TypeScript, the never type represents the absence of any value. It is the bottom type in the TypeScript type hierarchy, meaning that nothing can be assigned to never except never itself.

When TypeScript narrows down types through control flow analysis—such as checking the type or kind property of a discriminated union—it eliminates possibilities one by one. Once every possible type in a union has been handled, the type of the variable in the remaining branch is narrowed down to never.

The Mechanism of Exhaustive Checking

Exhaustive type checking works by attempting to assign the remaining narrowed value to a never type inside an unhandled fallback block, typically the default branch of a switch statement.

If all branches are accounted for, the variable has indeed narrowed to never, and the assignment succeeds. If any variant is omitted, the variable retains that unhandled type. Because a real type cannot be assigned to never, the TypeScript compiler flags a compilation error.

Code Example

Consider a discriminated union representing shapes:

type Circle = { kind: "circle"; radius: number };
type Square = { kind: "square"; sideLength: number };

type Shape = Circle | Square;

To calculate the area, you handle each variant using a switch statement:

function getArea(shape: Shape): number {
  switch (shape.kind) {
    case "circle":
      return Math.PI * shape.radius ** 2;
    case "square":
      return shape.sideLength ** 2;
    default:
      // Exhaustive check
      const _exhaustiveCheck: never = shape;
      return _exhaustiveCheck;
  }
}

In this scenario, shape can only be Circle or Square. Both are handled by specific case statements. Inside default, TypeScript narrows shape to never. The assignment const _exhaustiveCheck: never = shape; passes compilation cleanly.

What Happens When a Union Expands?

If you extend the Shape union by adding a new type:

type Triangle = { kind: "triangle"; base: number; height: number };

type Shape = Circle | Square | Triangle;

If you do not update getArea, TypeScript evaluates the default branch and finds that shape is now of type Triangle instead of never. The compiler immediately raises an error:

Type 'Triangle' is not assignable to type 'never'.

This error forces you to add a case "triangle" branch before the code can compile, guaranteeing that your application logic stays synchronized with your domain models.

Using an assertNever Helper Function

Instead of declaring an inline variable in every default case, you can define a reusable helper function:

function assertNever(value: never): never {
  throw new Error(`Unhandled discriminated union member: ${JSON.stringify(value)}`);
}

You can then call this function in the default case:

function getArea(shape: Shape): number {
  switch (shape.kind) {
    case "circle":
      return Math.PI * shape.radius ** 2;
    case "square":
      return shape.sideLength ** 2;
    default:
      return assertNever(shape);
  }
}

This pattern provides two layers of safety:

  1. Compile-time safety: TypeScript reports an error if assertNever receives anything other than never.
  2. Runtime safety: If runtime data bypasses static type checks (e.g., unvalidated external API responses), the function throws an explicit exception instead of failing silently.
