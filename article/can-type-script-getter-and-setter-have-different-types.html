Can TypeScript Getter and Setter Have Different Types?

In TypeScript 4.3 and later, getters and setters can have different types for the same property. This feature, known as separate write types on properties, allows you to accept flexible input types when writing a value while returning a strict, refined type when reading it. This article explains how differing accessor types work, the fundamental rule governing their relationship, and how to implement them in classes and interfaces.

How Different Accessor Types Work

Prior to version 4.3, TypeScript enforced that a setter's parameter must match the exact return type of its corresponding getter. Modern TypeScript removes this restriction to accommodate common JavaScript patterns where a setter converts incoming data before storing it.

Here is a practical example:

class Measurement {
  private _meters: number = 0;

  get meters(): number {
    return this._meters;
  }

  set meters(value: string | number) {
    if (typeof value === "string") {
      this._meters = parseFloat(value);
    } else {
      this._meters = value;
    }
  }
}

const item = new Measurement();

// Valid writes: accepts string or number
item.meters = 10;
item.meters = "25.5";

// Valid read: returns number
const distance: number = item.meters;

In this example, consumers can assign either a string or a number, but when accessing the property, TypeScript guarantees the result is always a number.

The Assignment Rule

While getter and setter types can differ, they cannot be completely unrelated. TypeScript enforces one critical rule: the getter's return type must be assignable to the setter's parameter type.

This rule ensures that self-assignment operations like obj.prop = obj.prop are always type-safe:

// VALID: 'number' is assignable to 'string | number'
get value(): number { ... }
set value(input: string | number) { ... }

// INVALID: 'string | number' is NOT assignable to 'number'
get value(): string | number { ... }
set value(input: number) { ... }
// Error: Type 'string | number' is not assignable to type 'number'.

The setter type must represent a superset of the getter type.

Usage in Interfaces and Types

Separate read and write types are not limited to class declarations; they can also be defined in interfaces and type aliases using explicit get and set syntax:

interface HTMLStyleSheet {
  get opacity(): number;
  set opacity(val: number | string);
}

Any class or object implementing this interface must provide a getter that outputs a number and a setter that accepts both number and string.
