TypeScript Getter Setter Type Mismatches in Strict Mode

This article explores how TypeScript manages divergent types between getters and setters, particularly under strict compiler settings. Historically, TypeScript required identical types for both accessors, but modern versions allow asymmetric types to support common JavaScript patterns. Below, you will learn the core rules governing accessor type compatibility, why strict mode enforces them, and how to properly handle mismatch scenarios in your codebase.

The Fundamental Rule: Getter Must Be Assignable to Setter

In TypeScript 4.3 and later, getters and setters are permitted to have different types, but with a critical condition: the return type of the getter must be assignable to the parameter type of the setter.

This rule applies universally across TypeScript and is rigorously enforced under strict mode (specifically with strictNullChecks enabled).

The rule exists to ensure that self-assignment remains type-safe:

instance.property = instance.property;

If the getter returned a type that the setter could not accept, this common and standard operation would break type safety at runtime.

Valid Scenario: Setter Accepts a Wider Type

A common design pattern involves writing a value using multiple formats (e.g., a string or a number) while reading the value always yields a normalized, specific format. This is completely valid in strict mode because the getter's return type satisfies the setter's parameter type.

class Dimension {
  private _value: number = 0;

  // Getter returns a specific type
  get value(): number {
    return this._value;
  }

  // Setter accepts a wider type
  set value(val: number | string) {
    if (typeof val === "string") {
      this._value = parseFloat(val);
    } else {
      this._value = val;
    }
  }
}

const box = new Dimension();
box.value = "42px"; // OK: string is allowed for writing
box.value = 10;     // OK: number is allowed for writing
const current: number = box.value; // OK: reading always produces a number

Here, the getter type (number) is assignable to the setter parameter type (number | string), so TypeScript allows it without error.

Invalid Scenario: Getter Returns a Wider or Incompatible Type

If the getter returns a type that is wider than, or incompatible with, the setter's expected type, TypeScript issues a compilation error in strict mode.

class Configuration {
  private _timeout: number | undefined;

  // Error: The return type of a 'get' accessor must be assignable to its 'set' accessor type.
  get timeout(): number | undefined {
    return this._timeout;
  }

  set timeout(value: number) {
    this._timeout = value;
  }
}

In this case, reading timeout might return undefined, but setting timeout only accepts number. Because number | undefined is not assignable to number, TypeScript rejects the implementation.

Strict Mode Nuances

When strict (or strictNullChecks) is disabled, TypeScript becomes lenient with null and undefined, which can mask accessor incompatibilities. However, with strict checks active:

  1. strictNullChecks: Ensures that optional or nullable properties in getters are strictly accounted for in setter parameters.
  2. Contextual Typing: If a setter does not specify an explicit parameter type, TypeScript infers its type directly from the getter's return type. If you want divergent types, you must explicitly annotate the setter's parameter.
  3. Interfaces and Type Aliases: Interfaces also support divergent accessors through property signatures that separate reading and writing using separate getter/setter syntax or intersecting types.

Resolving Type Mismatch Errors

To resolve getter/setter compatibility errors in strict mode:

  • Widen the setter parameter: Allow the setter to accept all types that the getter can return, along with any additional input formats.
  • Narrow the getter return value: Ensure the getter guarantees a return type that satisfies the constraints of the setter.
