TypeScript allowUnreachableCode Explained

This article explains the allowUnreachableCode compiler option in TypeScript, detailing what unreachable code is, the available configuration settings in tsconfig.json, and how to use this flag to maintain code quality and prevent dead code in your projects.

What is Unreachable Code?

Unreachable code refers to statements within a program that can never be executed at runtime. This typically happens when code is placed immediately after a terminating statement, such as a return, throw, break, or continue, or following an infinite loop.

function calculateDiscount(price: number): number {
  return price * 0.9;
  console.log("This will never run"); // Unreachable code
}

Dead code adds unnecessary bloat, confuses developers reading the codebase, and often signals an underlying logic error.

What Does allowUnreachableCode Do?

The allowUnreachableCode setting in TypeScript controls how the compiler detects and reports this dead code. You configure it inside the compilerOptions section of your tsconfig.json file.

The option accepts three possible states:

  • undefined (Default): TypeScript provides non-blocking diagnostic hints or warnings. In editors like Visual Studio Code, unreachable statements appear grayed out or dimmed, but the TypeScript compiler (tsc) does not generate a blocking build error.
  • false: TypeScript strictly forbids dead code. The compiler generates an error (e.g., TS7027: Unreachable code detected.) and halts or fails the build if unreachable statements are encountered.
  • true: TypeScript completely ignores unreachable code. The compiler suppresses all warnings and editor hints, allowing the code to compile without any notification.

Example Configuration

To enforce strict checks and prevent unreachable code from slipping into production, set the option to false in your tsconfig.json:

{
  "compilerOptions": {
    "allowUnreachableCode": false
  }
}

With this configuration, any dead code will trigger a compile-time failure:

function verifyUser(isAdmin: boolean) {
  if (isAdmin) {
    return "Access granted";
  } else {
    throw new Error("Access denied");
  }

  // Compiler Error: TS7027: Unreachable code detected.
  const status = "Pending"; 
}

Best Practices

For production applications and shared libraries, setting allowUnreachableCode to false is recommended. Enforcing this rule catches unintentional bugs early, keeps the codebase clean, and integrates well into Continuous Integration (CI) pipelines to block faulty commits. Leaving it at undefined is generally acceptable during early development and prototyping, while setting it to true is rarely recommended outside of legacy migration scenarios.
