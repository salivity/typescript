TypeScript Intersection Types: Explained with Use Cases

Intersection types in TypeScript allow developers to combine multiple types into a single, unified type containing all the features and properties of each constituent member. This article explains what intersection types are, demonstrates their syntax using the ampersand (&) operator, and highlights the most effective scenarios for their application, such as object composition, extending third-party types, and building flexible API layers.

What Are Intersection Types?

An intersection type combines two or more types into one using the ampersand (&) operator. An object of an intersection type must satisfy every individual type included in the intersection.

type Timestamps = {
  createdAt: Date;
  updatedAt: Date;
};

type User = {
  id: string;
  name: string;
};

// UserWithTimestamps requires id, name, createdAt, and updatedAt
type UserWithTimestamps = User & Timestamps;

const activeUser: UserWithTimestamps = {
  id: "u123",
  name: "Alex",
  createdAt: new Date(),
  updatedAt: new Date()
};

Unlike union types (|), which represent an "either-or" relationship (value satisfies at least one type), intersection types represent an "all-of" relationship.

When Should You Apply Intersection Types?

1. Extending Objects Without Classical Inheritance

Intersection types facilitate the "composition over inheritance" principle. Instead of building deep, brittle class hierarchies, you can compose smaller, independent data shapes into cohesive domain models.

type Identifiable = { id: string };
type Auditable = { lastModifiedBy: string; version: number };
type Document = { title: string; content: string };

type PersistedDocument = Document & Identifiable & Auditable;

2. Augmenting Third-Party or Legacy Types

When consuming types from an external library, modifying the original definition is often impossible or inadvisable. Intersection types enable you to append custom metadata or application-specific properties safely.

import { ExternalUserProfile } from "some-auth-library";

type AppUser = ExternalUserProfile & {
  internalRole: "admin" | "editor" | "viewer";
  preferences: Record<string, string>;
};

3. Combining React Component Props with Native Attributes

In UI development, custom components frequently need to accept their own props alongside standard HTML attributes.

type CustomButtonProps = {
  isLoading: boolean;
  variant: "primary" | "secondary";
};

// Combines custom props with native button HTML attributes
type ButtonProps = CustomButtonProps & React.ButtonHTMLAttributes<HTMLButtonElement>;

4. Implementing the Mixin Pattern

Mixins dynamically add behaviors or state to classes and factory functions. Intersection types accurately type the output of a function that merges multiple objects.

function extend<T extends object, U extends object>(first: T, second: U): T & U {
  return { ...first, ...second };
}

const entity = extend({ id: 1 }, { name: "Service" });
// entity is inferred as { id: number } & { name: string }

Potential Pitfall: Conflicting Property Types

When intersecting types that share property keys with conflicting, non-overlapping primitive types, TypeScript evaluates the colliding property to never.

type A = { id: string };
type B = { id: number };

// id becomes string & number, which resolves to never
type Impossible = A & B;

// Error: Type 'string' is not assignable to type 'never'
const item: Impossible = { id: "123" };

Intersection types should be used whenever you need structural composition, mixins, or additive type layers without the overhead of class inheritance.
