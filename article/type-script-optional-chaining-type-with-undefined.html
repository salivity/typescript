TypeScript Optional Chaining Type with Undefined

This article explains how TypeScript determines the type of an optional chaining expression when the target resolves to undefined or null. You will learn how the TypeScript compiler handles the resulting union types at compile time and what value is returned at runtime when an expression short-circuits.

The Resulting Type: T | undefined

When an optional chaining expression (?.) encounters a target that is null or undefined, the expression short-circuits and evaluates to undefined. At compile time, TypeScript reflects this behavior by adding undefined to the return type of the accessed property, resulting in a union type: T | undefined (where T is the type of the accessed member).

Even if the target object is explicitly typed as null, the optional chaining operator will always produce undefined—never null—when short-circuiting occurs. Consequently, TypeScript does not include null in the resulting type unless the property itself can be null.

Example Walkthrough

Consider the following interface and function:

interface User {
  profile?: {
    age: number;
  };
}

function getAge(user: User | undefined) {
  const age = user?.profile?.age;
  // Type of age: number | undefined
  return age;
}

In this example:

  1. If user is undefined, execution stops immediately, and the expression evaluates to undefined.
  2. If user.profile is undefined, execution stops, and the expression evaluates to undefined.
  3. If both exist, the value is a number.

Because the expression can exit early at any step, TypeScript assigns age the static type of number | undefined.

Behavior with null Targets

The operator treats null identically to undefined in terms of short-circuiting logic, but the output type behavior has a specific rule:

type Target = { name: string } | null;

function getName(target: Target) {
  const name = target?.name;
  // Type of name: string | undefined
  return name;
}

Although target can be null, target?.name has the type string | undefined. TypeScript excludes null from the final union because the ECMAScript specification guarantees that an optional chain short-circuits to the value undefined.

Method Calls and Element Access

This typing behavior applies uniformly across all forms of optional chaining, including optional element access (?.[]) and optional function calls (?.()):

  • Element access: arr?.[0] resolves to T | undefined.
  • Method calls: obj?.method() resolves to ReturnType | undefined.

If the target does not exist, the call is skipped entirely, and TypeScript types the entire expression as the expected return type unioned with undefined.
