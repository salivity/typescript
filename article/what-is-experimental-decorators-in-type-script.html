What Is experimentalDecorators in TypeScript?

This article explores the purpose of the experimentalDecorators compiler option in modern TypeScript configurations, detailing its historical context and current relevance. Readers will learn the difference between legacy Stage 2 decorators and the official ECMAScript Stage 3 decorators introduced natively in TypeScript 5.0, as well as the specific scenarios where enabling this flag remains necessary today.

In TypeScript, the experimentalDecorators flag controls which decorator specification the compiler uses when processing annotated classes, methods, accessors, and properties. When set to true in a project's tsconfig.json, TypeScript compiles decorators according to the legacy TC39 Stage 2 proposal. When omitted or set to false, modern versions of TypeScript (version 5.0 and later) default to the standardized TC39 Stage 3 decorators specification.

Decorators allow developers to modify or annotate classes and their members declaratively. During the early days of TypeScript, the language team implemented support for the Stage 2 draft of the decorator proposal under the experimentalDecorators flag. This legacy implementation became the foundation for major frameworks and libraries, most notably Angular, NestJS, TypeORM, and class-validator.

With the release of TypeScript 5.0, the language added native support for decorators that reached Stage 3 in the TC39 standardization process. These standard decorators work out of the box without requiring the experimentalDecorators setting.

Despite the availability of native standard decorators, the experimentalDecorators flag remains essential in modern TypeScript configurations for two primary reasons:

  1. Framework Compatibility: Established ecosystems like NestJS, TypeORM, and older Angular codebases depend entirely on the mechanics of the legacy Stage 2 implementation. Modernizing these libraries to the Stage 3 standard is an ongoing process across the ecosystem. Setting the flag to true ensures that existing projects continue to compile and function without breaking changes.

  2. Parameter Decorators and Metadata Reflection: The legacy implementation works in tandem with another compiler option, emitDecoratorMetadata, and the reflect-metadata package to enable runtime dependency injection and type reflection. Additionally, legacy decorators support parameter decorators (decorating individual function or constructor arguments). The current Stage 3 standard does not include parameter decorators or runtime type metadata emission. Projects relying on these specific patterns must continue using experimentalDecorators.

If you are developing a new project that does not rely on legacy reflection libraries or frameworks tied to Stage 2 decorators, you should omit experimentalDecorators or set it to false to stay aligned with current ECMAScript standards. If you are using frameworks like NestJS or libraries like TypeORM, setting "experimentalDecorators": true remains a mandatory requirement in your tsconfig.json.
