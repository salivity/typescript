How TypeScript Generates .d.ts Declaration Files

TypeScript generates .d.ts declaration files by parsing source code into an Abstract Syntax Tree (AST), stripping all executable JavaScript logic, inferring and resolving required types, and emitting pure type descriptions. This article explains the exact compiler mechanisms, configuration flags, and transformation steps the TypeScript compiler (tsc) uses to produce these ambient type definition files for libraries and applications.

The Compiler Options: Enabling Declarations

The generation of .d.ts files is controlled through TypeScript's compiler options, typically configured in a project's tsconfig.json file or passed via command-line arguments to tsc.

The primary setting is the declaration flag:

{
  "compilerOptions": {
    "declaration": true
  }
}

When set to true, the compiler emits a .d.ts file alongside every compiled .js file.

Additional relevant flags include:

  • declarationMap: Generates .d.ts.map source map files, allowing editors to navigate directly to the original .ts source file instead of the generated definition.
  • emitDeclarationOnly: Instructs the compiler to output only .d.ts files, skipping the emission of JavaScript runtime code. This is common in build pipelines that use tools like Babel, esbuild, or SWC to handle JavaScript transpilation while delegating type verification and declarations to tsc.
  • declarationDir: Specifies a dedicated output directory for all generated .d.ts files.

The Internal Compilation Process

When you run tsc, the compiler follows a structured multi-phase pipeline to produce .d.ts files:

1. Parsing and AST Construction

The TypeScript parser reads .ts files and converts the source code into an Abstract Syntax Tree (AST). The AST represents every construct in the file—functions, classes, variables, statements, and type annotations—as discrete nodes.

2. Semantic Analysis and Type Resolution

The binder and type checker inspect the AST to ensure the code contains no type errors. During this phase, TypeScript evaluates implicit types:

  • If a function lacks an explicit return type, the compiler computes the inferred type based on the function's return statements.
  • If a variable lacks an explicit type, the compiler determines its type based on its initial value.

In the declaration file, these inferred types become explicit.

3. AST Transformation via the Declaration Emitter

Once type checking succeeds, the AST is passed to the declaration emitter. The declaration emitter traverses the AST and transforms it:

  • Code Stripping: All runtime execution code—such as function bodies, variable initializers, and control flow structures (loops, conditionals)—is discarded.
  • Surface Preservation: Public API surfaces, including exported classes, interfaces, function signatures, enums, and module declarations, are preserved.
  • Modifier Conversion: Implementation details are replaced with declare keywords (e.g., declare function, declare class). Class definitions retain constructor signatures, method signatures, and property types, but their internal implementations are removed. Private class members (using TypeScript's private keyword) remain in the declaration to enforce type compatibility, whereas ECMAScript private fields (using the # syntax) are hidden.

4. Dependency Resolution and Import Optimization

The emitter analyzes dependencies needed by the exposed types:

  • If an exported function returns a type defined in another module, TypeScript inserts the necessary import statements into the .d.ts file.
  • Unused imports and internal-only types that do not escape into the public API are omitted, keeping the declaration footprint minimal.

5. Serialization and File Emission

The transformed declaration AST is serialized into plain text and written to the filesystem with the .d.ts extension. The output matches the directory structure of the source files unless overridden by the declarationDir setting.

Faster Generation with Isolated Declarations

In modern TypeScript (version 5.5 and later), the isolatedDeclarations option enforces a strict rule: all public APIs must have explicitly declared types rather than relying on inference.

When isolatedDeclarations is enabled:

  • TypeScript does not need to run full type checking across the entire project graph to infer types for exports.
  • Declarations can be generated file-by-file in isolation.
  • Third-party, high-speed build tools (such as SWC or Oxlint) can generate .d.ts files directly without needing TypeScript's complex type-checking engine.
