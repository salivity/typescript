Build a Type-Safe Query String Parser in TypeScript

Building a type-safe query string parser in TypeScript requires transforming a compile-time string literal into a strongly typed object representation while synchronizing it with a runtime extraction mechanism. This article covers the core type-level patterns needed—specifically template literal types, conditional type inference using the infer keyword, and recursive type definitions—alongside a paired runtime function that enforces these static guarantees.

The Core Mechanism

The mechanism relies on two synchronized layers:

  1. Type-Level Parsing: Recursively decomposes a string literal type (e.g., "?page=2&sort=asc") into key-value pairs, accumulates them into an object type, and handles edge cases like arrays or flags.
  2. Runtime Execution: Iterates over the string using standard APIs like URLSearchParams while asserting the return type matches the type computed by the static parser.

1. Type-Level Deconstruction

TypeScript's template literal types allow string pattern matching using the infer keyword. The parsing process is divided into three recursive steps: stripping delimiters, splitting key-value pairs, and merging results.

Stripping the Leading Query Marker

Query strings optionally start with a ?. A helper type checks for this character and strips it before processing the rest of the string:

type StripPrefix<T extends string> = T extends `?${infer Rest}` ? Rest : T;

Parsing Key-Value Pairs

Individual key-value pairs are separated by the = character. If no = is present, the key can be interpreted as a boolean flag:

type ParsePair<T extends string> = T extends `${infer Key}=${infer Value}`
  ? { [K in Key]: Value }
  : T extends `${infer Key}`
  ? Key extends "" 
    ? Record<string, never> 
    : { [K in Key]: true }
  : Record<string, never>;

Merging Objects and Handling Duplicates

When multiple pairs share the same key (e.g., tag=ts&tag=js), the types must merge into an array rather than overwrite each other:

type MergeValues<Existing, New> = Existing extends any[]
  ? [...Existing, New]
  : [Existing, New];

type Merge<A, B> = {
  [K in keyof A | keyof B]: K extends keyof A
    ? K extends keyof B
      ? MergeValues<A[K], B[K]>
      : A[K]
    : K extends keyof B
    ? B[K]
    : never;
};

Recursive Query Decomposition

Pairs are separated by the & delimiter. Using conditional recursion, the type isolates the first segment, parses it, and recursively calls itself on the remaining string:

type ParsePairs<T extends string> = T extends `${infer Head}&${infer Tail}`
  ? Merge<ParsePair<Head>, ParsePairs<Tail>>
  : ParsePair<T>;

export type ParseQueryString<T extends string> = ParsePairs<StripPrefix<T>>;

2. Runtime Implementation

The runtime parser executes standard JavaScript parsing logic and returns the inferred static type. URLSearchParams handles URL decoding and iteration natively.

export function parseQuery<T extends string>(query: T): ParseQueryString<T> {
  const cleanQuery = query.startsWith("?") ? query.slice(1) : query;
  const searchParams = new URLSearchParams(cleanQuery);
  const result: Record<string, unknown> = {};

  for (const [key, value] of searchParams.entries()) {
    if (Object.prototype.hasOwnProperty.call(result, key)) {
      const existing = result[key];
      if (Array.isArray(existing)) {
        existing.push(value);
      } else {
        result[key] = [existing, value];
      }
    } else {
      result[key] = value === "" ? true : value;
    }
  }

  return result as ParseQueryString<T>;
}

3. Practical Usage and Type Inference

When invoking parseQuery with a string literal, TypeScript infers exact keys and literal values without requiring manual type annotations:

const parsed = parseQuery("?search=typescript&filter=true&tag=web&tag=node");

// TypeScript statically infers the type of `parsed` as:
// {
//   search: "typescript";
//   filter: "true";
//   tag: ["web", "node"];
// }

const search: "typescript" = parsed.search;
const tags: ["web", "node"] = parsed.tag;

If dynamic variables are passed instead of literals (e.g., a generic string type), the parser gracefully falls back to Record<string, unknown> or a generalized index signature, preserving type safety across dynamic and static contexts.
