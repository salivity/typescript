Using TypeScript as a Linter with noEmit

The TypeScript compiler conventionally handles two responsibilities: type checking and transpiling TypeScript source code into plain JavaScript. By enabling the noEmit flag, you instruct the compiler to skip generating output files and exclusively perform static analysis. This article explains the technical mechanism behind noEmit, how it repurposes the TypeScript compiler into a dedicated type linter, and how to implement it within modern development workflows.

The Dual Architecture of the TypeScript Compiler

Under standard operation, invoking the TypeScript compiler (tsc) initiates a multi-stage process:

  1. Parsing and Binding: Code is converted into an Abstract Syntax Tree (AST), and symbols are resolved across your files.
  2. Type Checking: The type checker traverses the AST, enforces type safety, verifies contracts, and collects diagnostic errors.
  3. Emitter: If no blocking errors occur (or if configured to emit on error), the compiler transforms the AST into .js, .d.ts, and source map files written to disk.

When you pass the --noEmit flag via the CLI or define "noEmit": true in tsconfig.json, the execution terminates immediately after the type checking phase. The emitter pipeline is bypassed completely.

Why noEmit Functions as a Linter

A linter is a tool that analyzes source code to flag programming errors, bugs, and stylistic anomalies without executing or building the code.

When noEmit is active, tsc acts identically to a linter:

  • Error Reporting: It analyzes code against type declarations and language rules, outputting any mismatches, missing properties, or syntax issues directly to the terminal.
  • Exit Codes: It exits with a non-zero status code if errors are found, enabling automated pipelines to pass or fail builds based on type integrity.
  • Zero Artifacts: It produces no .js files or output directories, leaving the repository state unmodified.

While general-purpose linters like ESLint evaluate syntax patterns and stylistic rules within single-file scopes (unless configured with heavy type-aware parsers), tsc --noEmit offers full, project-wide semantic analysis across your entire dependency graph.

Implementation

You can run TypeScript purely as a linter either through your configuration file or directly via the command line.

In tsconfig.json

Add the flag to your compilerOptions:

{
  "compilerOptions": {
    "noEmit": true,
    "strict": true
  }
}

In package.json

Define a script to run the type checker across the project:

{
  "scripts": {
    "typecheck": "tsc --noEmit"
  }
}

Running npm run typecheck runs static type validation without generating build files.

Decoupling Type Checking from Bundling

Modern build systems—such as Vite, esbuild, Next.js, and SWC—compile TypeScript to JavaScript by stripping types using fast, parallelized native engines. However, these tools intentionally bypass static type verification to optimize build speed.

Pairing these tools with tsc --noEmit creates an optimal separation of concerns:

  • Transpilers/Bundlers: Focus exclusively on speed, bundling, and generating runtime code.
  • tsc --noEmit: Runs concurrently in CI/CD pipelines, pre-commit hooks, or background terminal processes strictly to catch type-level bugs.
