TypeScript Function Overload Resolution Order

Function overload resolution in TypeScript determines which specific type signature applies to a function call that has multiple definitions. TypeScript resolves overloads using a strict top-to-bottom order, selecting the first signature that is structurally compatible with the passed arguments. Because the compiler stops checking as soon as it finds a valid match, the order in which overloads are declared is critical to avoiding unintended type inferences and masked signatures.

Top-to-Bottom Evaluation

When a function with multiple overload signatures is invoked, the TypeScript compiler checks the declared signatures sequentially, beginning with the first one listed in the code. The resolution process follows these rules:

  1. Sequential Evaluation: The compiler tests the call arguments against each overload signature from top to bottom.
  2. First Match Wins: As soon as an overload signature matches the types and count of the provided arguments, the compiler selects that signature and stops evaluating further overloads.
  3. The Implementation Signature is Ignored: The final signature—the one containing the actual function body—is the implementation signature. It is invisible to external callers and is not considered during overload resolution.

The Specificity Rule: Narrow to Wide

Because the first matching overload is always selected, you must order signatures from most specific (narrowest) to least specific (widest). Placing a general signature above a specific signature will "shadow" the specific signature, preventing it from ever being invoked.

Incorrect Ordering (Wide Before Narrow)

In this example, the string parameter matches any string value, so the literal "admin" overload is never reached:

// Incorrect: Broad overload first
function getRole(role: string): string;
function getRole(role: "admin"): boolean;
function getRole(role: any): any {
  return role === "admin" ? true : role;
}

// Result: Return type is 'string', not 'boolean'
const result = getRole("admin");

Correct Ordering (Narrow Before Wide)

Moving the narrow literal type above the broader primitive type ensures that the compiler matches the specialized behavior first:

// Correct: Specific overload first
function getRole(role: "admin"): boolean;
function getRole(role: string): string;
function getRole(role: any): any {
  return role === "admin" ? true : role;
}

// Result: Return type is correctly resolved as 'boolean'
const result = getRole("admin");

Union and Subtype Overloads

The same principle applies when dealing with inheritance, unions, and optional parameters:

  • Subtypes vs. Supertypes: If a derived class or specialized interface is overloaded alongside its base class, the derived class must be placed first.
  • Optional Parameters: Overloads with fewer, more specific parameters should typically be ordered according to precision to prevent an overload with optional parameters from catching arguments meant for a different signature.

If the arguments provided do not match any of the overload signatures, TypeScript raises a compile-time error pointing to the closest overload candidate or stating that no overload matches the call.
