Enforce Even Length Tuples in TypeScript

This article explains how to restrict function parameters to tuples with an even number of elements using TypeScript's type system. By leveraging recursive conditional types, you can inspect the length of a tuple at compile time and cause a type error whenever an odd number of items is passed to a function.

Creating the Recursive Helper Type

TypeScript does not have a native mathematical operator to check for parity (modulo) on tuple lengths. However, you can achieve this by peeling off two elements at a time using recursive conditional types and rest tuples.

type IsEven<T extends readonly unknown[]> = T extends readonly []
  ? true
  : T extends readonly [unknown, unknown, ...infer Rest]
  ? IsEven<Rest>
  : false;

Here is how the evaluation works:

  1. If the tuple is empty ([]), its length is 0, which is even (true).
  2. If the tuple has at least two elements ([unknown, unknown, ...infer Rest]), TypeScript discards the pair and recurses on Rest.
  3. If an odd element remains and cannot form a pair, the second pattern fails to match, evaluating to false.

Enforcing the Constraint in a Function

Once you have the helper type, apply it to a generic function parameter. If the tuple has an odd number of elements, you can resolve the parameter type to a descriptive error type or never.

function processEvenPairs<T extends readonly unknown[]>(
  items: IsEven<T> extends true 
    ? T 
    : [errorMessage: "Tuple must contain an even number of elements"]
) {
  return items;
}

Practical Usage and Compiler Verification

When calling this function, passing an array literal without assertions might infer a generic number[] or string[] type instead of a fixed tuple. To enforce the check, TypeScript needs tuple inference, which is typically provided by passing the arguments directly or using as const.

Valid Function Calls

// Passed as an empty tuple (0 items is even)
processEvenPairs([]);

// Passed as a two-item tuple
processEvenPairs([1, "a"]);

// Passed as a four-item tuple
processEvenPairs([1, 2, 3, 4]);

// With `as const`
const validReadonly = ["key1", "val1", "key2", "val2"] as const;
processEvenPairs(validReadonly);

Invalid Function Calls

// Error: Type 'number' is not assignable to type '"Tuple must contain an even number of elements"'
processEvenPairs([1]);

// Error: Type 'number' is not assignable to type '"Tuple must contain an even number of elements"'
processEvenPairs([1, 2, 3]);

// Fails with read-only tuples of odd length
const invalidReadonly = ["x", "y", "z"] as const;
processEvenPairs(invalidReadonly);

Alternate Approach: Enforcing Pairs with Variadic Tuples

If your tuple consists of uniform data paired together, you can also define the parameter type by recursively constructing pairs directly instead of checking the validity afterwards:

type KeyValuePair<K = string, V = unknown> = [K, V];

type EvenPairs<T> = T extends [infer K, infer V, ...infer Rest]
  ? [K, V, ...EvenPairs<Rest>]
  : [];

function pairValues<T extends unknown[]>(values: EvenPairs<T>) {
  // Implementation logic here
  return values;
}

This alternative forces the elements to strictly alternate or resolve explicitly to valid pairs during argument evaluation.
