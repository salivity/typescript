Accessor vs Property Decorators in TypeScript

This article explains the core differences between accessor decorators and property decorators in TypeScript. While both allow developers to inspect, modify, or annotate class members, they target different elements of a class definition, accept different parameters, and have distinct capabilities regarding runtime behavior and property descriptors.

What is a Property Decorator?

A property decorator is applied directly to a class field declaration. In legacy (experimental) TypeScript, a property decorator function receives two arguments:

  1. target: Either the constructor function for a static member or the prototype of the class for an instance member.
  2. propertyKey: The name of the member being decorated (string | symbol).

Because a standard class field does not exist on the prototype until an instance is created, a property decorator does not receive a PropertyDescriptor. As a result, it cannot directly modify property descriptors or alter how a property is initialized unless it manually calls Object.defineProperty on the prototype or utilizes metadata reflection libraries.

function LogProperty(target: any, propertyKey: string) {
  console.log(`Property registered: ${propertyKey}`);
}

class User {
  @LogProperty
  name: string = "Alice";
}

What is an Accessor Decorator?

An accessor decorator is applied to an explicit getter or setter method within a class. Unlike property decorators, an accessor decorator receives three arguments in legacy TypeScript:

  1. target: The constructor function (static) or prototype (instance).
  2. propertyKey: The name of the getter or setter.
  3. descriptor: The PropertyDescriptor for the member.

Because it has direct access to the PropertyDescriptor, an accessor decorator can inspect, modify, or return a completely new property descriptor. This allows you to easily wrap getter/setter behavior, cache return values, or intercept read and write operations.

function ReadOnly(target: any, propertyKey: string, descriptor: PropertyDescriptor) {
  descriptor.writable = false;
  return descriptor;
}

class Account {
  private _balance: number = 100;

  @ReadOnly
  get balance() {
    return this._balance;
  }
}

Key Differences

Feature Property Decorator Accessor Decorator
Application Target Plain class fields Getters and setters (get / set)
Property Descriptor Not provided to the decorator Provided (PropertyDescriptor)
Return Value Effect Return value is ignored Returned descriptor overrides original descriptor
Primary Use Cases Metadata reflection, dependency injection, validation markers Caching, logging read/write operations, altering access permissions

ECMAScript Stage 3 Decorators (TypeScript 5.0+)

In modern TypeScript (5.0 and later) following the ECMAScript standard:

  • Field Decorators receive the field's initial value (usually undefined on definition) and a context object with kind: "field". They can return an initializer function that modifies the initial value.
  • Getter/Setter Decorators receive the original method function and a context object with kind: "getter" or kind: "setter". They can return a wrapped function to modify access behavior.
  • Auto-Accessor Decorators are introduced using the accessor keyword (e.g., accessor name: string). They receive an object with both get and set functions and can alter storage and access behavior simultaneously.

When to Use Which

Choose a property decorator when you need to annotate fields with metadata (such as for serialization or ORM mapping) without changing how the field's value is retrieved or updated.

Choose an accessor decorator when you need to intercept, modify, or govern the logic executed during read or write operations, such as enforcing read-only states, validating assignments, or lazy-loading data.
