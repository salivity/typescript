Typing Generators in TypeScript: Yield, Return, Next

TypeScript provides first-class support for typing generator functions through the built-in generic interface Generator<TYield, TReturn, TNext>. This interface allows you to strictly define the types of values emitted by the yield operator, the final value returned upon completion, and the values accepted into the generator via the .next() method. By leveraging these three type parameters, you can eliminate runtime type errors and enforce strict communication boundaries between the generator and the calling code.

The Generator<TYield, TReturn, TNext> Interface

A generator function's return type is defined by three generic arguments:

Generator<TYield, TReturn, TNext>
  • TYield: The type of values emitted by the generator using the yield keyword.
  • TReturn: The type of the value returned when the generator finishes execution (via a return statement).
  • TNext: The type of values that can be passed into the generator via iterator.next(value). This is the type that expressions evaluating yield will resolve to.

Defining TYield

TYield represents every value exposed to consumers iterating over the generator (for example, via a for...of loop or repeated .next() calls).

function* countUp(): Generator<number, void, unknown> {
  yield 1;
  yield 2;
  yield 3;
}

In this case, the value property on the iterator result object will be of type number while the generator is running.

Defining TReturn

TReturn specifies the type of the value returned when the generator completes execution. If a generator does not explicitly return a value, TReturn should be typed as void.

function* produceResult(): Generator<number, string, unknown> {
  yield 1;
  yield 2;
  return "Completed successfully";
}

const iterator = produceResult();
iterator.next(); // { value: 1, done: false }
iterator.next(); // { value: 2, done: false }
const finalResult = iterator.next(); // { value: "Completed successfully", done: true }

When done becomes true, TypeScript recognizes that finalResult.value matches the TReturn type (string).

Defining TNext

TNext controls two-way communication. When you call .next(value), that value is passed back into the generator where execution paused at a yield expression.

function* interactiveGenerator(): Generator<string, void, number> {
  const initialValue = 0;
  // The yield expression evaluates to the value passed into .next()
  const step: number = yield `Initial value is ${initialValue}`;
  const nextValue = initialValue + step;
  yield `Next value is ${nextValue}`;
}

const iterator = interactiveGenerator();

// The first next() call initializes the generator; it cannot accept an argument
iterator.next(); // { value: "Initial value is 0", done: false }

// Subsequent next() calls require the argument to match TNext (number)
iterator.next(5); // { value: "Next value is 5", done: false }

Because the generator has not yet paused at a yield during the first invocation of .next(), TypeScript accepts void or undefined for the initial .next() call, but strictly enforces the TNext type on subsequent calls.

Default Types and Type Inference

If you do not explicitly annotate a generator, TypeScript attempts to infer the types:

  • TYield is inferred as the union of all yielded expressions.
  • TReturn is inferred from the return statements.
  • TNext defaults to unknown because TypeScript cannot infer what future callers will pass into .next().

To ensure strict type safety when using values returned from yield expressions, you should explicitly declare the Generator<TYield, TReturn, TNext> return type annotation on the function.

Typing Asynchronous Generators

For asynchronous generators declared with async function*, TypeScript provides the AsyncGenerator<TYield, TReturn, TNext> interface. It operates identically to Generator, but wrapping iterations in promises:

async function* fetchSequence(): AsyncGenerator<number, void, string> {
  const query: string = yield 1;
  yield 2;
}
