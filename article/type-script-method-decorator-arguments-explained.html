TypeScript Method Decorator Arguments Explained

In experimental TypeScript, a standard method decorator is applied to a method declaration and receives three specific runtime arguments: the target object, the member name, and the property descriptor. Understanding these parameters is essential for inspecting, modifying, or completely replacing method definitions at runtime using metadata and reflection.

The Three Arguments

When TypeScript invokes an experimental method decorator, it passes the following parameters in order:

  1. target (Object | Function) The first argument represents the host of the method. Its value depends on whether the decorated method is static or an instance member:

    • For an instance method: target is the prototype of the class (e.g., MyClass.prototype).
    • For a static method: target is the constructor function of the class itself (e.g., MyClass).

  2. propertyKey (string | symbol) The second argument is the name of the method being decorated. In most cases, this is a string, but it can also be a symbol if the method uses a computed symbol property.

  3. descriptor (TypedPropertyDescriptor<T>) The third argument is the standard JavaScript PropertyDescriptor for the method. It contains standard property attributes:

    • value: The actual function implementation of the method.
    • writable: A boolean indicating whether the method can be reassigned.
    • enumerable: A boolean determining if the method shows up during enumeration of the object's properties.
    • configurable: A boolean specifying whether the descriptor attributes can be modified or the property deleted.

Standard Signature and Usage

The TypeScript type definition for a method decorator function is:

type MethodDecorator = <T>(
  target: Object,
  propertyKey: string | symbol,
  descriptor: TypedPropertyDescriptor<T>
) => TypedPropertyDescriptor<T> | void;

Here is a practical example showing how these arguments are accessed:

function Log(
  target: any,
  propertyKey: string | symbol,
  descriptor: PropertyDescriptor
) {
  const originalMethod = descriptor.value;

  descriptor.value = function (...args: any[]) {
    console.log(`Calling ${String(propertyKey)} on`, target);
    return originalMethod.apply(this, args);
  };

  return descriptor;
}

class UserService {
  @Log
  getUser(id: number) {
    return { id, name: "Alice" };
  }
}

If a method decorator returns a value, that value is used as the new PropertyDescriptor for the method. If it returns undefined or nothing, the original descriptor remains in effect with any mutations applied directly to it.
