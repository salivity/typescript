Reduce Redux Boilerplate with TypeScript Inference

Redux Toolkit dramatically simplifies Redux development by leaning on TypeScript's inference engine to eliminate redundant type definitions. Traditionally, writing type-safe Redux required creating separate action type constants, interface definitions for every action, complex union types for reducers, and manual typing across component hooks. Redux Toolkit replaces this repetitive workflow by automatically deriving action types, payload structures, and dispatch capabilities directly from your implementation code, ensuring end-to-end type safety with minimal manual annotation.

State and Action Inference in createSlice

The primary way Redux Toolkit reduces boilerplate is through the createSlice API. Instead of requiring distinct types for action constants, action interfaces, and reducer functions, createSlice generates everything in one place using the PayloadAction<T> generic.

When you define a case reducer, you only need to annotate the payload of the incoming action:

import { createSlice, PayloadAction } from '@reduxjs/toolkit';

interface UserState {
  name: string;
  age: number;
}

const initialState: UserState = {
  name: '',
  age: 0,
};

const userSlice = createSlice({
  name: 'user',
  initialState,
  reducers: {
    setName(state, action: PayloadAction<string>) {
      state.name = action.payload;
    },
    setAge(state, action: PayloadAction<number>) {
      state.age = action.payload;
    },
  },
});

export const { setName, setAge } = userSlice.actions;
export default userSlice.reducer;

TypeScript automatically infers that setName is an action creator taking a string argument and returning an action of type user/setName. You do not need to create action type string constants, declare interfaces for the action objects, or write separate action creator functions.

Inferring Store Types Directly from Configuration

Legacy Redux setups frequently required manually maintaining a global RootState interface that mirrored every reducer in the application. Redux Toolkit eliminates this by leveraging TypeScript's ReturnType and typeof operators on the store instance itself:

import { configureStore } from '@reduxjs/toolkit';
import userReducer from './userSlice';

export const store = configureStore({
  reducer: {
    user: userReducer,
  },
});

export type RootState = ReturnType<typeof store.getState>;
export type AppDispatch = typeof store.dispatch;

As you add or modify slices in configureStore, RootState and AppDispatch update automatically. There is no need to manually update a root interface when the store structure changes.

Eliminating Selector Annotations with Pre-Typed Hooks

Rather than annotating the state parameter on every useSelector call across your component tree, Redux Toolkit recommends creating pre-typed hooks:

import { TypedUseSelectorHook, useDispatch, useSelector } from 'react-redux';
import type { RootState, AppDispatch } from './store';

export const useAppDispatch: () => AppDispatch = useDispatch;
export const useAppSelector: TypedUseSelectorHook<RootState> = useSelector;

Because RootState was inferred from the store, useAppSelector immediately provides full autocomplete and type checking for the entire state tree. Components consume state without requiring inline types:

// No type annotation needed on (state)
const userName = useAppSelector((state) => state.user.name);

Type-Safe Async Logic with createAsyncThunk

Handling asynchronous actions with createAsyncThunk removes the need to define separate REQUEST, SUCCESS, and FAILURE action types. By defining the return type and argument type within the thunk's generic signature, TypeScript infers the payload types for all generated lifecycle actions:

export const fetchUserById = createAsyncThunk<
  UserState, // Returned payload type
  string     // First argument type
>(
  'user/fetchById',
  async (userId) => {
    const response = await fetch(`/api/user/${userId}`);
    return (await response.json()) as UserState;
  }
);

When handling these actions in extraReducers using the builder callback notation, TypeScript automatically infers the payload of action.payload inside the fulfilled handler as UserState:

extraReducers: (builder) => {
  builder.addCase(fetchUserById.fulfilled, (state, action) => {
    // action.payload is automatically inferred as UserState
    state.name = action.payload.name;
    state.age = action.payload.age;
  });
}

The builder pattern avoids type-casting and switch-statement type guards entirely, relying instead on internal type mapping to enforce that reducers handle only the actions they declare.
