TypeScript Conditional Types Explained

Conditional types in TypeScript enable developers to create dynamic, flexible types that change based on relationships between other types. This article breaks down the syntax of conditional types, explains the exact mechanisms the TypeScript compiler uses to evaluate conditional expressions, and covers practical features including distributive evaluation and the infer keyword.

What Are Conditional Types?

At their core, conditional types introduce logic branching to TypeScript's type system using a syntax modeled after JavaScript's ternary operator:

T extends U ? TrueType : FalseType

In this expression, T is the type being tested, and U is the target type. If T is assignable to (or satisfies the constraint of) U, the type resolves to TrueType. Otherwise, it resolves to FalseType.

Consider a simple example:

type IsString<T> = T extends string ? true : false;

type A = IsString<string>; // true
type B = IsString<number>; // false

How the Compiler Evaluates Conditional Types

TypeScript evaluates conditional types during static type-checking using a multi-step resolution process depending on whether the input types are fully known or generic.

1. Direct Evaluation with Concrete Types

When the operands are concrete (non-generic) types, the compiler evaluates the expression immediately. It performs an assignability check to determine whether T is a subtype of U. If the check succeeds, it assigns TrueType; if it fails, it assigns FalseType.

2. Deferred Evaluation with Unresolved Generics

When T or U involves an unresolved type parameter (such as inside a generic function or generic interface before it is called), TypeScript cannot determine assignability right away. In this case:

  • The compiler defers evaluation and keeps the conditional type intact as an expression.
  • If subsequent code narrows T (via type guards or control flow), TypeScript re-evaluates the condition using the narrowed type.

3. Distributive Evaluation over Union Types

When the type being checked is a naked generic parameter (a type parameter not wrapped inside a tuple, array, or promise) and a union type is passed to it, the conditional type becomes distributive.

TypeScript automatically distributes the condition across each member of the union:

type ToArray<T> = T extends any ? T[] : never;

// Given a union:
type Result = ToArray<string | number>;

The compiler evaluates this expression by expanding the union into individual conditional checks:

type Result = (string extends any ? string[] : never) | (number extends any ? number[] : never);
// Result evaluates to: string[] | number[]

To prevent this distributive behavior, wrap both sides of the extends keyword in square brackets:

type ToArrayNonDistributive<T> = [T] extends [any] ? T[] : never;

type Result = ToArrayNonDistributive<string | number>;
// Result evaluates to: (string | number)[]

Type Inference with the infer Keyword

Conditional types also allow you to declare and extract type variables directly from the checked type using the infer keyword inside the extends clause.

When TypeScript evaluates an infer declaration:

  1. It attempts to match the structural shape of T against the pattern specified in U.
  2. If the pattern matches, TypeScript binds the corresponding sub-part to the declared variable and makes it available in the TrueType branch.
  3. If the pattern does not match, evaluation falls through to the FalseType branch.
type UnpackPromise<T> = T extends Promise<infer U> ? U : T;

type ResolvedString = UnpackPromise<Promise<string>>; // string
type NonPromise = UnpackPromise<number>;              // number

Through concrete evaluation, deferred resolution, union distribution, and pattern matching with infer, conditional types give TypeScript a declarative mechanism to express complex type transformations.
