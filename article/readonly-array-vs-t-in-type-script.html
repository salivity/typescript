ReadonlyArray vs T[] in TypeScript

TypeScript offers multiple ways to handle lists of data, with T[] and ReadonlyArray<T> representing mutable and immutable approaches respectively. While both types store ordered collections of elements of type T, they differ significantly in their mutation capabilities, method availability, type compatibility, and usage patterns. This article explains the technical differences between ReadonlyArray and standard mutable arrays (T[]), illustrates how the compiler enforces these rules, and highlights best practices for using each.

Core Differences at a Glance

The fundamental difference lies in mutability:

  • T[] (or Array<T>): Represents a standard, fully mutable JavaScript array. You can reassign elements, change the array's length, and invoke mutating methods like push(), pop(), splice(), and shift().
  • ReadonlyArray<T> (or readonly T[]): Represents an immutable view of an array. It omits all mutating methods from its type definition and prevents index-based reassignment.

Method and Property Restrictions

The TypeScript compiler removes mutating methods from the ReadonlyArray interface. Non-mutating methods (such as map, filter, slice, and concat) remain available because they return a new array rather than modifying the original in place.

// Mutable Array
const mutableNumbers: number[] = [1, 2, 3];
mutableNumbers.push(4); // Allowed
mutableNumbers[0] = 10; // Allowed

// Readonly Array
const readonlyNumbers: ReadonlyArray<number> = [1, 2, 3];
readonlyNumbers.push(4); // Error: Property 'push' does not exist on type 'readonly number[]'.
readonlyNumbers[0] = 10; // Error: Index signature in type 'readonly number[]' only permits reading.

Assignability and Type Compatibility

A mutable array is assignable to a read-only array, but a read-only array is not assignable to a mutable array. This ensures safety across function boundaries:

let standardArray: number[] = [1, 2, 3];
let readOnlyArray: ReadonlyArray<number> = [4, 5, 6];

// Allowed: A mutable array satisfies read-only requirements
readOnlyArray = standardArray;

// Error: Type 'readonly number[]' is 'readonly' and cannot be assigned to the mutable type 'number[]'
standardArray = readOnlyArray;

If a function requires a ReadonlyArray<T>, you can safely pass a T[] argument. This signals that the function will not alter the input array.

Syntax Variations: ReadonlyArray<T> vs readonly T[]

In modern TypeScript, readonly T[] is shorthand for ReadonlyArray<T>. They are structurally identical:

// These two declarations are equivalent
type ListA = ReadonlyArray<string>;
type ListB = readonly string[];

The shorthand readonly T[] is often preferred for readability, while ReadonlyArray<T> is commonly used in generic interfaces and type definitions.

Shallow Immutability Caveat

ReadonlyArray provides shallow immutability. While the array structure itself cannot be modified (no adding, removing, or reassigning items), the properties of objects contained within the array can still be mutated unless those objects are also typed as immutable.

interface User {
  name: string;
}

const users: ReadonlyArray<User> = [{ name: "Alice" }];

// Error: Cannot reassign array indices
users[0] = { name: "Bob" };

// Allowed: Inner object properties can still be modified
users[0].name = "Bob";

To enforce deep immutability, inner objects must also define their properties with the readonly modifier, or you can use utility types such as const assertions (as const).

Summary of When to Use Each

  • Use T[] when you need to construct, manipulate, or reorder a collection locally, such as inside a function body before returning a final result.
  • Use ReadonlyArray<T> for function parameters, public API surfaces, state management (e.g., Redux or React states), and whenever you want the compiler to guarantee that data will not be mutated unexpectedly.
