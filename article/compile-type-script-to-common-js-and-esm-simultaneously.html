Compile TypeScript to CommonJS and ESM Simultaneously

Publishing a modern TypeScript library often requires supporting both CommonJS (CJS) for legacy Node.js environments and ECMAScript Modules (ESM) for modern runtimes and bundlers. This guide demonstrates how to configure a single TypeScript codebase to compile to both module formats concurrently without relying on heavy external bundlers, relying solely on TypeScript's native compiler and proper package.json configuration.

Directory Structure

A clean directory structure keeps the build artifacts separated by module format:

my-library/
├── src/
│   └── index.ts
├── dist/
│   ├── cjs/
│   └── esm/
├── tsconfig.base.json
├── tsconfig.cjs.json
├── tsconfig.esm.json
└── package.json

Step 1: Configure TypeScript

Use a shared base configuration along with targeted configuration files for each build target.

1. tsconfig.base.json

Define compiler options shared between both outputs:

{
  "compilerOptions": {
    "target": "ES2020",
    "declaration": true,
    "declarationMap": true,
    "sourceMap": true,
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "forceConsistentCasingInFileNames": true,
    "rootDir": "./src"
  },
  "include": ["src/**/*"]
}

2. tsconfig.cjs.json

Extend the base configuration to produce CommonJS code:

{
  "extends": "./tsconfig.base.json",
  "compilerOptions": {
    "module": "CommonJS",
    "outDir": "./dist/cjs"
  }
}

3. tsconfig.esm.json

Extend the base configuration to output modern ESM code:

{
  "extends": "./tsconfig.base.json",
  "compilerOptions": {
    "module": "ESNext",
    "moduleResolution": "bundler",
    "outDir": "./dist/esm"
  }
}

Step 2: Configure package.json Exports

To allow consumer runtimes to resolve the correct files depending on whether they use import or require, define conditional exports in package.json.

{
  "name": "my-library",
  "version": "1.0.0",
  "type": "module",
  "main": "./dist/cjs/index.js",
  "module": "./dist/esm/index.js",
  "types": "./dist/esm/index.d.ts",
  "exports": {
    ".": {
      "types": {
        "import": "./dist/esm/index.d.ts",
        "require": "./dist/cjs/index.d.ts"
      },
      "import": "./dist/esm/index.js",
      "require": "./dist/cjs/index.js"
    }
  },
  "files": [
    "dist"
  ],
  "scripts": {
    "clean": "rm -rf dist",
    "build:cjs": "tsc -p tsconfig.cjs.json && echo '{\"type\": \"commonjs\"}' > dist/cjs/package.json",
    "build:esm": "tsc -p tsconfig.esm.json",
    "build": "npm run clean && npm run build:cjs && npm run build:esm"
  },
  "devDependencies": {
    "typescript": "^5.0.0"
  }
}

Critical Detail: The dist/cjs/package.json Hack

Because the root package.json sets "type": "module", Node.js assumes all .js files within the package are ESM by default. To prevent Node.js from misinterpreting the CommonJS output in dist/cjs, the build:cjs script writes an isolated package.json file inside dist/cjs/:

{
  "type": "commonjs"
}

This local file forces Node.js to interpret all .js files inside dist/cjs/ as CommonJS.

Step 3: Run the Build

Execute the build script:

npm run build

This command deletes old artifacts, runs both TypeScript configurations, and outputs:

  • Fully typed CommonJS files in dist/cjs/.
  • Fully typed ESM files in dist/esm/.

Consumers can now import your library seamlessly using either syntax:

// Works via "import" condition
import { feature } from "my-library";

// Works via "require" condition
const { feature } = require("my-library");
