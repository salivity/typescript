TypeScript with AMD and SystemJS Module Formats

TypeScript allows developers to write modern, standard ECMAScript module syntax (import and export) while compiling the output into different module formats, including Asynchronous Module Definition (AMD) and SystemJS. This article explains how TypeScript targets these two module loaders using the module compiler option, how it transforms code into their respective formats, and how single-file bundling works with each format using the --outFile flag.

TypeScript Module Compilation

Regardless of the target format, TypeScript source code always uses standard ES module syntax. The TypeScript compiler (tsc) handles the transformation of this syntax into the required runtime format based on the "module" setting in your tsconfig.json.

{
  "compilerOptions": {
    "target": "ES5",
    "module": "amd" // or "system"
  }
}

By changing this setting, TypeScript rewrites your import and export statements into the corresponding API calls used by AMD (such as RequireJS) or SystemJS.

Working with AMD

AMD is designed primarily for browser environments to load modules asynchronously. The most popular implementation of AMD is RequireJS.

How TypeScript Emits AMD

When "module": "amd" is configured, TypeScript wraps the compiled JavaScript file in a define() function call. This function lists dependencies as an array of strings and injects them into a factory function.

TypeScript source:

import { calculateTotal } from "./math";

export const orderTotal = calculateTotal(10, 2);

Compiled AMD output:

define(["require", "exports", "./math"], function (require, exports, math_1) {
    "use strict";
    Object.defineProperty(exports, "__esModule", { value: true });
    exports.orderTotal = void 0;
    exports.orderTotal = (0, math_1.calculateTotal)(10, 2);
});

AMD Bundling with outFile

A distinct capability of AMD in TypeScript is native file concatenation. When targeting AMD, the TypeScript compiler can combine multiple input files into a single output file using the "outFile" compiler option:

{
  "compilerOptions": {
    "module": "amd",
    "outFile": "./dist/bundle.js"
  }
}

In this mode, TypeScript assigns a name to each module inside the combined file (e.g., define("math", ...)), allowing a single network request to deliver all modules to the browser without requiring external bundlers like Webpack.

Working with SystemJS

SystemJS is a universal dynamic module loader designed to support modern module features, including ES6 module semantics, in older environments.

How TypeScript Emits SystemJS

When "module": "system" is configured, TypeScript wraps the output in a System.register() call. This format supports live bindings, circular dependencies, and asynchronous loading.

TypeScript source:

import { calculateTotal } from "./math";

export const orderTotal = calculateTotal(10, 2);

Compiled SystemJS output:

System.register(["./math"], function (exports_1, context_1) {
    "use strict";
    var math_1, orderTotal;
    var __moduleName = context_1 && context_1.id;
    return {
        setters: [
            function (math_1_1) {
                math_1 = math_1_1;
            }
        ],
        execute: function () {
            exports_1("orderTotal", orderTotal = (0, math_1.calculateTotal)(10, 2));
        }
    };
});

SystemJS uses a two-phase initialization process. The setters array updates local references when dependencies change (replicating live bindings), and the execute block runs the actual module code.

SystemJS Bundling with outFile

Like AMD, SystemJS modules can also be bundled directly by TypeScript using the "outFile" option:

{
  "compilerOptions": {
    "module": "system",
    "outFile": "./dist/bundle.js"
  }
}

TypeScript emits each file as an explicit System.register("moduleName", [...]) call within the combined output file.

AMD vs. SystemJS in TypeScript

  • Syntax Fidelity: SystemJS closely emulates ES module behavior, accurately handling circular dependencies and live export bindings. AMD relies on standard function wrappers and CommonJS-like export objects.
  • Runtime Loader: AMD requires an AMD-compliant loader like RequireJS. SystemJS requires the system.js runtime script.
  • Bundling Support: Both formats are the only two module formats that allow TypeScript's built-in --outFile option to concatenate modules into a single artifact without an external module bundler.
