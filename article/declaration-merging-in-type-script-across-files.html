Declaration Merging in TypeScript Across Files

Declaration merging in TypeScript allows multiple individual declarations with the same name to be combined into a single definition by the compiler. When applied to interfaces across multiple files, this feature enables developers to extend existing object shapes without modifying the original source code. However, the exact behavior of multi-file interface merging depends heavily on whether the files are treated as ambient global scripts or isolated ES modules.

Ambient Global Scope Merging

If files do not contain top-level import or export statements, TypeScript treats them as global scripts. In this environment, interfaces declared with identical names across different files merge automatically.

For example, if fileA.ts declares:

interface User {
  id: string;
  name: string;
}

And fileB.ts declares:

interface User {
  email: string;
}

The resulting User interface in the global scope contains all three properties: id, name, and email. Any variable typed as User in any file within the project compilation must satisfy all merged fields.

Module Scope and Module Augmentation

Modern TypeScript code primarily uses ES modules. When a file contains an import or export statement, all declarations inside that file are scoped locally to the module. Defining an interface named User in moduleA.ts and another named User in moduleB.ts will not automatically merge them; instead, they remain distinct, isolated types.

To merge an interface across module boundaries, you must use module augmentation. This requires wrapping the interface in a declare module block pointing to the target file or package:

// types/augmentation.ts
import './user';

declare module './user' {
  interface User {
    roles: string[];
  }
}

With this pattern, the imported User type gains the roles property across the entire project once the augmentation file is included in the compilation. This technique is commonly used to extend definitions provided by third-party npm packages or global objects like Window and ProcessEnv.

Merging Rules and Mechanics

When interfaces merge across files, TypeScript applies specific resolution rules:

  • Non-Function Members: Properties with identical names must have identical types. If fileA.ts defines age: number and fileB.ts defines age: string, the compiler will throw an error (Subsequent property declarations must have the same type).
  • Function Members (Method Overloading): Methods sharing the same name are treated as function overloads. Merged interfaces resolve overloads in reverse order: declarations in later-processed files take higher precedence. The exception is signatures with string literal parameters, which bubble up to the highest priority.

Practical Effects and Best Practices

Declaration merging across files provides a powerful mechanism for decoupling dependencies, enabling plugin architectures, and typing dynamic runtimes. However, relying on automatic merging in global scripts can lead to unintended side effects, hidden name collisions, and difficult-to-debug compilation errors. In production codebases, explicit module augmentation is preferred over global ambient merging because it clearly communicates intent and preserves module isolation.
