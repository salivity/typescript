JavaScript Type Checking with TypeScript checkJs

TypeScript provides a powerful compiler capable of analyzing codebases without requiring a full rewrite into .ts files. By enabling the checkJs compiler option, developers can leverage TypeScript’s static analysis engine directly on vanilla JavaScript files, catching syntax mistakes, type mismatches, and runtime bugs early while keeping their native .js workflow intact.

How checkJs Works

By default, the TypeScript compiler (tsc) ignores .js files or merely allows them to exist alongside TypeScript files when allowJs is enabled. When checkJs is activated, TypeScript actively parses JavaScript files and applies its internal type inference engine.

Instead of treating variables in JavaScript as an untyped any, the compiler analyzes assignments, function calls, and control flow to deduce exact types. If you assign a string to a variable and later attempt to call a numeric method on it, TypeScript flags it as an error just as it would in a native TypeScript file.

Enabling checkJs

There are two primary ways to turn on type checking for vanilla JavaScript:

1. Project-Wide Configuration

You can enable type checking across all JavaScript files in a project by adding "checkJs": true to a tsconfig.json or jsconfig.json file:

{
  "compilerOptions": {
    "allowJs": true,
    "checkJs": true,
    "noEmit": true
  },
  "include": ["src/**/*"]
}

Setting "noEmit": true ensures TypeScript only performs diagnostics and does not output compiled files, allowing you to run your vanilla JavaScript files directly in Node.js or the browser.

2. Per-File Activation

If you are working in an existing codebase and want an incremental adoption approach, you can enable checking on a single-file basis without a configuration file. Add the following comment to the very top line of any JavaScript file:

// @ts-check

Conversely, if checkJs is enabled globally, you can opt out individual files by adding // @ts-nocheck to the top of the file.

Adding Explicit Types with JSDoc

Because vanilla JavaScript lacks native type syntax, checkJs pairs with JSDoc comments to allow explicit typing. TypeScript interprets standard JSDoc tags to declare types, interfaces, and function signatures.

Commonly supported JSDoc annotations include:

  • @type: Declares the type of a variable or property.

    /** @type {number} */
let count = 10;

  • @param and @returns: Defines parameter types and return values for functions.

    /**
 * @param {string} name
 * @param {number} id
 * @returns {string}
 */
function formatUser(name, id) {
  return `${name} (#${id})`;
}

  • @typedef: Creates reusable custom object types or aliases.

    /**
 * @typedef {Object} User
 * @property {number} id
 * @property {string} email
 */

/** @type {User} */
const user = { id: 1, email: "user@example.com" };

Key Advantages of checkJs

  • Zero Build Step: Code remains standard JavaScript, meaning it runs directly in engines like Node.js or browsers without transpilation or bundling.
  • Editor Integration: Editors like Visual Studio Code use TypeScript under the hood for JavaScript IntelliSense. Enabling checkJs surfaces inline diagnostics, autocomplete, and refactoring tools automatically.
  • Incremental Migration: Teams can gradually improve code quality and transition toward TypeScript without a disruptive all-at-once migration.
