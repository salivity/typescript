Modeling a Type-Safe SQL Query Builder in TypeScript

Building a type-safe SQL query builder in TypeScript involves leveraging advanced type features—primarily generics, phantom types, mapped types, and method chaining—to track query state at compile time. By modeling the database schema as a collection of TypeScript types and updating generic parameters as clauses like SELECT, FROM, and JOIN are invoked, developers can catch invalid column selections, incorrect table joins, and mismatched data types before code ever executes.

1. Defining the Database Schema

The foundation of type safety is an accurate representation of the database schema. Tables are modeled as interfaces where keys correspond to column names and values correspond to their SQL data types mapped to TypeScript primitives.

interface UsersTable {
  id: number;
  name: string;
  email: string;
  created_at: Date;
}

interface PostsTable {
  id: number;
  user_id: number;
  title: string;
  content: string;
}

interface DatabaseSchema {
  users: UsersTable;
  posts: PostsTable;
}

2. Using Generics to Accumulate Query State

A query builder relies on a class with generic parameters that change as methods are chained. These generic parameters do not necessarily exist as runtime values; instead, they act as compile-time trackers for:

  1. TSchema: The full database schema.
  2. TActiveTables: The tables currently available in the query context (via FROM or JOIN).
  3. TResult: The shape of the final data returned by executing the query.
class QueryBuilder<
  TSchema,
  TActiveTables extends keyof TSchema = never,
  TResult = unknown
> {
  protected sqlParts: string[] = [];

  constructor(protected schema?: TSchema) {}
}

3. Implementing the from Method

The from method designates the primary table. It constrains input to valid table names within TSchema and sets TActiveTables to that table, enabling subsequent methods to autocomplete and validate against its columns.

class QueryBuilder<
  TSchema,
  TActiveTables extends keyof TSchema = never,
  TResult = Record<string, never>
> {
  protected query: { table?: string; columns: string[]; where: string[] } = {
    columns: [],
    where: [],
  };

  from<TTable extends keyof TSchema>(
    table: TTable
  ): QueryBuilder<TSchema, TTable, Record<string, never>> {
    const next = new QueryBuilder<TSchema, TTable, Record<string, never>>();
    next.query = { ...this.query, table: table as string };
    return next;
  }
}

4. Modeling Column Selection with select

The select method updates TResult based on the chosen columns. It should restrict selections to valid keys in TSchema[TActiveTables]. By using a rest parameter of keys, TypeScript can construct a picked type representing the selected columns.

select<K extends keyof TSchema[TActiveTables]>(
  ...columns: K[]
): QueryBuilder<TSchema, TActiveTables, Pick<TSchema[TActiveTables], K>> {
  const next = new QueryBuilder<
    TSchema,
    TActiveTables,
    Pick<TSchema[TActiveTables], K>
  >();
  next.query = { ...this.query, columns: columns as string[] };
  return next;
}

If multiple columns are passed, TypeScript infers a union of those keys (e.g., 'id' | 'name'), and Pick<UsersTable, 'id' | 'name'> creates { id: number; name: string }.

5. Adding Type-Safe Conditions with where

Filtering via where requires verifying that the specified column exists on active tables and that the comparison value matches the column's type:

where<K extends keyof TSchema[TActiveTables]>(
  column: K,
  operator: '=' | '!=' | '>' | '<',
  value: TSchema[TActiveTables][K]
): this {
  this.query.where.push(`${String(column)} ${operator} ${JSON.stringify(value)}`);
  return this;
}

If column is 'id', TypeScript requires value to be a number. Passing a string causes a compile-time type error.

6. Resolving and Executing Queries

The final execution step should return a Promise of the inferred TResult array.

async execute(): Promise<TResult[]> {
  const { table, columns, where } = this.query;
  const colSql = columns.length > 0 ? columns.join(', ') : '*';
  const whereSql = where.length > 0 ? ` WHERE ${where.join(' AND ')}` : '';
  const sql = `SELECT ${colSql} FROM ${table}${whereSql};`;

  // Internal execution mechanism (e.g., pg, mysql2)
  console.log('Executing SQL:', sql);
  return [] as TResult[];
}

7. Putting It Together

When combined, the API provides full auto-completion and prevents runtime schema errors:

const db = new QueryBuilder<DatabaseSchema>();

// Valid query
const users = await db
  .from('users')
  .select('id', 'name')
  .where('id', '=', 1)
  .execute();
// Type of `users`: Promise<{ id: number; name: string }[]>

// Compiler Errors:
// db.from('invalid_table');               // Error: Argument not assignable to 'users' | 'posts'
// db.from('users').select('non_existent');// Error: 'non_existent' not assignable to keyof UsersTable
// db.from('users').where('id', '=', '1'); // Error: string is not assignable to number

To extend this pattern further, support for joins can be added by expanding TActiveTables into a union of joined tables, and table-prefixed columns (e.g., users.id) can be modeled using TypeScript template literal types (${Table}.${Column}).
