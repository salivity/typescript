Type Custom Iterables with Symbol.iterator in TypeScript

This article provides a practical guide on how to type custom iterable data structures using Symbol.iterator in TypeScript. You will learn the fundamental interfaces TypeScript uses for iteration, how to manually implement and type the Iterable<T> contract on custom classes, and how to leverage generator methods for simpler, type-safe iteration.

Understanding TypeScript's Iteration Interfaces

To make any custom structure iterable in TypeScript—allowing it to be consumed by for...of loops or the spread operator (...)—it must satisfy the Iterable<T> interface.

TypeScript defines three primary built-in interfaces in its standard library for this purpose:

  1. Iterable<T>: Represents the data structure that can be iterated over. It requires a [Symbol.iterator]() method that returns an Iterator<T>.
  2. Iterator<T>: An object with a next() method that advances through the sequence.
  3. IteratorResult<T>: The return value of next(). It is a discriminated union of:
    • { done: false; value: T }
    • { done: true; value: undefined } (or an optional return value)

Method 1: Explicitly Implementing Iterable<T>

The standard way to type an iterable structure is to declare that your class implements Iterable<T> and explicitly type the return value of [Symbol.iterator]().

Here is an implementation of a custom NumberRange collection:

class NumberRange implements Iterable<number> {
  constructor(
    private start: number,
    private end: number,
    private step: number = 1
  ) {}

  [Symbol.iterator](): Iterator<number> {
    let current = this.start;
    const end = this.end;
    const step = this.step;

    return {
      next(): IteratorResult<number> {
        if (current <= end) {
          const value = current;
          current += step;
          return { done: false, value };
        }
        return { done: true, value: undefined };
      },
    };
  }
}

Usage and Type Inference

TypeScript automatically infers the loop variable's type based on the generic parameter supplied to Iterable<T>:

const range = new NumberRange(1, 5);

// 'n' is inferred as type 'number'
for (const n of range) {
  console.log(n); // 1, 2, 3, 4, 5
}

// Spreading works with correct array typing: number[]
const numbers: number[] = [...range];

Method 2: Using Generator Methods

Writing manual next() state machines can be verbose. Using a generator function prefixed with an asterisk (*) automatically satisfies both Iterator<T> and Iterable<T> via the IterableIterator<T> or Generator<T> types.

class Queue<T> implements Iterable<T> {
  private items: T[] = [];

  enqueue(item: T): void {
    this.items.push(item);
  }

  dequeue(): T | undefined {
    return this.items.shift();
  }

  // The generator return type can be Iterator<T>, IterableIterator<T>, or Generator<T>
  *[Symbol.iterator](): Iterator<T> {
    for (const item of this.items) {
      yield item;
    }
  }
}

Typing the Generator Signature

If you need explicit control over what the generator yields, returns, and receives via next(), use the standard Generator<TYield, TReturn, TNext> type:

*[Symbol.iterator](): Generator<T, void, unknown> {
  for (const item of this.items) {
    yield item;
  }
}

Typing Plain Object Iterables

You can also apply [Symbol.iterator] directly to plain object literals using the computed property syntax:

interface UserCollection {
  users: string[];
  [Symbol.iterator](): Iterator<string>;
}

const team: UserCollection = {
  users: ["Alice", "Bob", "Charlie"],
  [Symbol.iterator]() {
    let index = 0;
    const users = this.users;

    return {
      next(): IteratorResult<string> {
        if (index < users.length) {
          return { done: false, value: users[index++] };
        }
        return { done: true, value: undefined };
      },
    };
  },
};

for (const member of team) {
  console.log(member.toUpperCase()); // member is typed as string
}

Summary of Types to Use

  • Use Iterable<T> on classes or interfaces as the contract to enforce compatibility with JavaScript iteration protocols.
  • Use Iterator<T> or IteratorResult<T> when writing manual iterator objects with a custom next() method.
  • Use Generator<T, void, unknown> or IterableIterator<T> when implementing *[Symbol.iterator]() with yield.
