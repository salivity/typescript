Difference Between files and include in tsconfig.json

In TypeScript, both the files and include properties in tsconfig.json tell the compiler which source files to process. However, they differ significantly in how they resolve paths, support wildcards, handle missing files, and interact with the exclude property. Understanding these differences ensures your build pipeline compiles precisely the files your project requires without unexpected errors or missing types.

The files Property

The files setting accepts an array of exact relative or absolute file paths.

  • No Glob Patterns: It does not support wildcards or globbing patterns (such as * or **/*). Every file must be listed individually.
  • Strict Path Checking: If a path listed in files cannot be found on the filesystem, the TypeScript compiler immediately throws an error and halts execution.
  • Immune to exclude: Paths specified in the files list will always be compiled, even if a rule in the exclude array matches them.
  • Primary Use Case: Small projects with very few files, explicit entry points, or scenarios where strict validation of the presence of specific files is required.

Example:

{
  "compilerOptions": {
    "module": "commonjs",
    "target": "es6"
  },
  "files": [
    "src/index.ts",
    "src/types.d.ts"
  ]
}

The include Property

The include setting accepts an array of file names, directory names, or glob-like file patterns.

  • Glob Pattern Support: It fully supports wildcards:
    • * matches zero or more characters (excluding directory separators).
    • ? matches any one character (excluding directory separators).
    • **/ matches any directory nested to any depth.
  • Graceful Failure: If a glob pattern resolves to no files, the compiler does not throw an error; it simply includes nothing from that pattern.
  • Filtered by exclude: Any file matched by include can be omitted by rules defined in the exclude array. If a directory is specified without a file extension, TypeScript automatically appends allowed extensions (such as .ts, .tsx, and .d.ts).
  • Primary Use Case: Typical, scalable TypeScript applications where directories contain multiple evolving source files (e.g., standard src/ folders).

Example:

{
  "compilerOptions": {
    "module": "commonjs",
    "target": "es6"
  },
  "include": [
    "src/**/*"
  ],
  "exclude": [
    "src/**/*.spec.ts"
  ]
}

Key Differences at a Glance

  • Pattern Matching: files requires exact, explicit file names. include supports glob patterns like **/*.
  • Missing File Handling: files produces a compiler error if a listed file does not exist. include silently ignores patterns that match zero files.
  • Interaction with exclude: exclude only filters files discovered via include. It has no effect on files explicitly set in files.
  • Precedence: When both files and include are present, TypeScript compiles the union of both lists. Any file referenced by import statements within any included file will also be included automatically.
