TypeScript Object Dot Notation Path Extractor

This article explains how to build a compile-time ObjectDotNotation path extractor in TypeScript using recursive conditional types and template literal types. By transforming deeply nested object structures into a union of dot-separated string paths, you can enforce strict type safety for APIs like lodash's get, form state handlers, and nested database queries.

Understanding the Problem

TypeScript's standard keyof operator only extracts the top-level keys of an interface or type. When working with nested structures, manually maintaining a union of string paths like "user.profile.name" is error-prone and breaks whenever the data structure is refactored.

To automate this, TypeScript must inspect an object's keys, check whether the corresponding values are also objects, recursively extract those child keys, and concatenate the path segments using template literal types.

Basic Implementation

A recursive conditional type checks whether a value associated with a key is an object. If it is, the type recurses; otherwise, it resolves to the current key.

export type ObjectDotNotation<T> = T extends object
  ? {
      [K in keyof T & (string | number)]: T[K] extends object
        ? `${K}` | `${K}.${ObjectDotNotation<T[K]>}`
        : `${K}`;
    }[keyof T & (string | number)]
  : never;

In this implementation:

  1. keyof T & (string | number) filters out symbols, as symbols cannot be serialized into standard string dot paths.
  2. The mapped type iterates over each key K.
  3. If T[K] extends object, it returns a union of the current key ${K} and the concatenated path ${K}.${ObjectDotNotation<T[K]>}.
  4. Indexed access [keyof T & (string | number)] collapses the mapped object type into a union of all its property values.

Preventing Prototype Pollution and Depth Issues

Standard JavaScript objects often contain arrays, dates, or function references that inherit from object. Without guards, TypeScript will attempt to recursively traverse built-in prototype properties (such as array methods or Date prototypes), causing compiler performance degradation or hitting recursion limits.

To prevent this, define terminal types that should not be recursed:

type TerminalTypes = 
  | string 
  | number 
  | boolean 
  | bigint 
  | symbol 
  | null 
  | undefined 
  | Function 
  | Date 
  | RegExp;

export type Path<T> = T extends TerminalTypes
  ? never
  : {
      [K in keyof T & string]: T[K] extends TerminalTypes
        ? `${K}`
        : `${K}` | `${K}.${Path<T[K]>}`;
    }[keyof T & string];

Extracting Leaf Nodes Exclusively

In some scenarios—such as field validation—only the terminal properties (leaf nodes) should be valid paths, excluding intermediate paths like "user" or "user.profile".

To extract only leaf nodes, omit ${K} from the true branch of the recursive check:

export type LeafPath<T> = T extends TerminalTypes
  ? never
  : {
      [K in keyof T & string]: T[K] extends TerminalTypes
        ? `${K}`
        : `${K}.${LeafPath<T[K]>}`;
    }[keyof T & string];

Example Usage

Given a nested configuration object:

interface UserSettings {
  id: string;
  profile: {
    name: string;
    details: {
      age: number;
      active: boolean;
    };
  };
  preferences: {
    newsletter: boolean;
  };
}

// Includes intermediate and leaf paths
type AllPaths = Path<UserSettings>;
// Result: "id" | "profile" | "preferences" | "profile.name" | 
//         "profile.details" | "profile.details.age" | 
//         "profile.details.active" | "preferences.newsletter"

// Includes only terminal leaf paths
type OnlyLeaves = LeafPath<UserSettings>;
// Result: "id" | "profile.name" | "profile.details.age" | 
//         "profile.details.active" | "preferences.newsletter"

Creating a Type-Safe Getter Function

You can apply Path<T> directly to generic functions to provide full autocomplete and validation for property access:

function get<T, P extends Path<T>>(target: T, path: P): unknown {
  return path
    .split(".")
    .reduce((acc: any, key) => (acc ? acc[key] : undefined), target);
}

const settings: UserSettings = {
  id: "1",
  profile: {
    name: "Alex",
    details: { age: 30, active: true },
  },
  preferences: { newsletter: false },
};

// Valid
get(settings, "profile.details.age");

// Type Error: Argument of type '"profile.details.invalid"' is not assignable to parameter of type Path<UserSettings>.
get(settings, "profile.details.invalid");
