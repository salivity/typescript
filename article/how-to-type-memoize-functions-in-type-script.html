How to Type Memoize Functions in TypeScript

Memoization improves application performance by caching the return values of expensive operations based on their arguments. In TypeScript, creating a generic memoization wrapper often leads to type degradation, where distinct parameter types, labeled tuples, and return values collapse into loose any types. This guide demonstrates how to build a robust memoization wrapper that fully preserves input parameter names, tuple lengths, return types, and execution context.

The Problem: Type Erasure in Higher-Order Functions

A naive implementation of a memoization function typically resorts to Function or (...args: any[]) => any. While this allows any function to be passed in, it destroys the compiler's ability to enforce argument constraints or infer return types at the call site:

// Anti-pattern: Loses strict type checking
function memoize(fn: Function): Function {
  const cache = new Map();
  return (...args: any[]) => {
    const key = JSON.stringify(args);
    if (cache.has(key)) return cache.get(key);
    const result = fn(...args);
    cache.set(key, result);
    return result;
  };
}

The Solution: Generic Constraints with Tuples

To retain the exact signature, use generic parameters constrained to function shapes. Leveraging TypeScript's tuple types ensures that parameter order, optional parameters, and argument names are retained via labeled tuple elements.

export function memoize<Args extends unknown[], Return>(
  fn: (...args: Args) => Return,
  keyResolver?: (...args: Args) => string
): (...args: Args) => Return {
  const cache = new Map<string, Return>();

  return function (...args: Args): Return {
    const key = keyResolver ? keyResolver(...args) : JSON.stringify(args);

    if (cache.has(key)) {
      return cache.get(key)!;
    }

    const result = fn(...args);
    cache.set(key, result);
    return result;
  };
}

By defining Args extends unknown[], the returned function mirrors the exact tuple signature of the input function, including rest parameters and optional arguments.

Preserving this Context

If the target function relies on an execution context (this), you must extract and apply it using ThisParameterType<T> to prevent runtime errors or incorrect binding.

export function memoizeWithThis<
  Fn extends (this: any, ...args: any[]) => any
>(
  fn: Fn,
  keyResolver?: (...args: Parameters<Fn>) => string
): (this: ThisParameterType<Fn>, ...args: Parameters<Fn>) => ReturnType<Fn> {
  const cache = new Map<string, ReturnType<Fn>>();

  return function (
    this: ThisParameterType<Fn>,
    ...args: Parameters<Fn>
  ): ReturnType<Fn> {
    const key = keyResolver ? keyResolver(...args) : JSON.stringify(args);

    if (cache.has(key)) {
      return cache.get(key)!;
    }

    const result = fn.apply(this, args);
    cache.set(key, result);
    return result;
  };
}

In this variation:

  • Parameters<Fn> extracts the argument types as a tuple.
  • ReturnType<Fn> extracts the exact return type.
  • ThisParameterType<Fn> extracts the required context, ensuring this is correctly validated at compile time.

Handling Overloaded Functions

Higher-order functions in TypeScript cannot automatically infer all branches of an overloaded function. When passing an overloaded function into memoize, TypeScript resolves only the final signature (the implementation signature).

To retain signatures for overloaded functions, explicitly declare overloads on the memoize wrapper:

// Define explicit wrapper overloads if supporting a known overloaded API
function parse(input: string): number;
function parse(input: number): string;
function parse(input: string | number): string | number {
  return typeof input === "string" ? parseInt(input, 10) : String(input);
}

// Explicit casting retains overload fidelity when inference falls short
const memoizedParse = memoize(parse) as typeof parse;

Casting with as typeof fn forces the compiler to retain the original overloaded interface over the generalized implementation signature.
