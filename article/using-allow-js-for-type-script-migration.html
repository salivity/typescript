Using allowJs for TypeScript Migration

Migrating an existing JavaScript codebase to TypeScript can be an intimidating undertaking if approached as an all-or-nothing rewrite. The allowJs compiler option solves this problem by allowing JavaScript and TypeScript files to coexist and interoperate within the same project. This article explains how enabling allowJs facilitates an incremental migration, prevents workflow disruption, and allows development teams to adopt static typing gradually.

Enables Incremental Adoption

The primary advantage of the allowJs setting is that it eliminates the need for a massive, high-risk migration. In large codebases, rewriting every file from .js to .ts in a single release cycle is rarely feasible. When allowJs: true is set in the tsconfig.json file, the TypeScript compiler (tsc) processes both .js and .ts files concurrently. Teams can migrate individual files, modules, or features one at a time while standard product development continues uninterrupted.

Seamless File Interoperability

With allowJs enabled, TypeScript files can directly import JavaScript files, and JavaScript files can import compiled TypeScript modules. Developers do not need to construct complex build configurations or module aliases to bridge the gap between two different file types. TypeScript will parse the JavaScript files, attempt to infer types automatically, and surface type errors in the consuming TypeScript files if imported values are misused.

Unifies the Build Pipeline

Without allowJs, running a hybrid project often requires two parallel build tools: one compiler (such as Babel) to bundle JavaScript, and another (such as tsc) to handle TypeScript. Enabling allowJs allows the TypeScript compiler to manage the entire project pipeline. It will ingest both file types and emit standard JavaScript to the target directory, significantly reducing tooling complexity and configuration overhead.

Enhances Type Checking via JSDoc and checkJs

The allowJs flag acts as a foundation for other migration features, notably checkJs. When used together, developers can enforce type safety inside JavaScript files using JSDoc annotations without immediately converting file extensions to .ts. This step allows teams to catch bugs and document data structures in legacy code immediately, making the eventual conversion to pure TypeScript trivial.

Minimizes Team Disruption

Shifting an entire engineering team to TypeScript overnight can cause friction and lower velocity. allowJs lets developers adopt the language at a sustainable pace. Team members who are already proficient in TypeScript can write new features in .ts, while others continue to write or maintain .js code until they become comfortable with TypeScript syntax and concepts.
