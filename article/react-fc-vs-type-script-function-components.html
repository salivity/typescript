React.FC vs TypeScript Function Components

When typing components in React with TypeScript, developers primarily choose between the built-in React.FC (or React.FunctionComponent) generic type and standard TypeScript function signatures. While both approaches declare a functional component, they differ fundamentally in how they handle props like children, generic types, default parameters, and return type inference. Modern React development largely favors standard function signatures over React.FC due to better type safety, flexibility, and cleaner syntax.

1. Handling the children Prop

Historically, the most notable difference between the two approaches was how React.FC handled the children prop.

  • React.FC (Pre-React 18): React.FC automatically injected children?: React.ReactNode into your component's props definition. This meant a component would accept nested elements even if it was not designed to render them, bypassing compile-time safety. While React 18 removed implicit children from React.FC, older codebases still carry this legacy behavior.
  • Standard Functions: Standard functions never include children implicitly. If a component accepts children, you must explicitly declare it in the props interface or use the utility type React.PropsWithChildren<T>. This ensures strict type enforcement where only intended components accept nested content.
// Standard Function (explicit children)
interface CardProps {
  title: string;
  children: React.ReactNode;
}

function Card({ title, children }: CardProps) {
  return <div><h1>{title}</h1>{children}</div>;
}

2. Support for Generic Components

Components that accept dynamic, generic types are common in data tables, lists, and form controls.

  • React.FC: Typing a generic component with React.FC is cumbersome. Because React.FC is applied to the variable declaration, you cannot easily pass the component's generic type parameter directly to it without awkward workarounds or type assertions.
  • Standard Functions: Standard function declarations handle generics natively and cleanly, mirroring standard TypeScript generic syntax.
// Generic with standard function syntax
interface ListProps<T> {
  items: T[];
  renderItem: (item: T) => React.ReactNode;
}

function List<T>({ items, renderItem }: ListProps<T>) {
  return <ul>{items.map(renderItem)}</ul>;
}

3. Return Type Inference and Enforcement

React.FC provides an explicit return type contract, whereas standard functions rely on TypeScript's type inference by default.

  • React.FC: By definition, React.FC enforces that the function must return a ReactElement or null. It prevents the accidental return of non-renderable types like undefined or plain strings/numbers (though numbers and strings are valid JSX, React.FC strictly expects ReactElement | null).
  • Standard Functions: Standard functions infer their return type based on what is returned in the function body. TypeScript naturally verifies whether the return value is valid JSX. If explicit constraints are required, you can manually type the return as React.JSX.Element.

4. Default Props and ES6 Default Parameters

Handling default values differs between the two patterns:

  • React.FC: React.FC includes typings for static properties like defaultProps, displayName, and propTypes. However, defaultProps on React.FC often causes issues where TypeScript fails to infer that an optional prop will always have a value at runtime.
  • Standard Functions: Standard functions rely on native ES6 default parameter syntax ({ prop = defaultValue }: Props). TypeScript automatically recognizes the prop as non-nullable within the component scope, providing accurate type narrowing without external annotations.
// Standard function using ES6 defaults
interface ButtonProps {
  label: string;
  disabled?: boolean;
}

function Button({ label, disabled = false }: ButtonProps) {
  // TypeScript correctly infers 'disabled' as boolean, not boolean | undefined
  return <button disabled={disabled}>{label}</button>;
}

Summary of Differences

Feature React.FC Standard Function Typing
Syntax Style Requires const variable assignment Works with function or const
Generics Awkward and limited Fully and natively supported
children Prop Explicit in React 18+ (Implicit in <18) Always explicit
Return Type Fixed to ReactElement \| null Inferred automatically
Default Values Historically relied on defaultProps Uses standard ES6 default values

Because standard function declarations integrate seamlessly with native TypeScript features, they avoid the overhead and edge-case limitations associated with React.FC, making them the widely accepted convention in modern React applications.
