What Is next-env.d.ts in Next.js TypeScript Apps?

The next-env.d.ts file is an automatically generated TypeScript declaration file created in the root of a Next.js project whenever TypeScript is enabled. Its primary purpose is to ensure that the TypeScript compiler properly recognizes Next.js-specific global types, framework features, and static asset imports. This article explains the exact role of next-env.d.ts, the declarations it injects, how Next.js manages it, and how developers should handle it in version control.

The Role of next-env.d.ts

When building an application with TypeScript, the compiler must understand the structure of the environment, including framework-level globals and non-standard imports (such as importing .png or .css files into JavaScript or TypeScript modules).

Standard TypeScript does not understand these by default. The next-env.d.ts file bridges this gap by acting as an ambient declaration reference. It tells TypeScript where to find the type definitions that ship with the next package.

What Is Inside the File?

A typical next-env.d.ts file contains triple-slash reference directives rather than standard code:

/// <reference types="next" />
/// <reference types="next/image-types/global" />

// NOTE: This file should not be edited
// see https://nextjs.org/docs/app/api-reference/config/typescript for more information.

Depending on the Next.js version and configuration, it may also include references to routing or navigation types. These directives perform two main jobs:

  1. /// <reference types="next" />: Imports the core Next.js type definitions. This gives TypeScript knowledge about built-in components, API route handlers, data fetching methods, and environment variables configured via next.config.js.
  2. /// <reference types="next/image-types/global" />: Provides module declarations for static asset imports. This allows you to import images (such as .png, .jpg, .svg, and .webp) directly into your components without TypeScript throwing an error that the module cannot be found.

Automatic Generation and Management

Next.js automatically creates or updates next-env.d.ts whenever you run next dev or next build.

If the file is deleted, Next.js detects its absence and regenerates it automatically. If you upgrade Next.js to a version that requires updated global type references, Next.js automatically rewrites the file to match the new version's requirements.

Because Next.js actively manages the contents of this file, any custom changes or manual type additions you write into next-env.d.ts will be overwritten.

Best Practices: Editing and Version Control

  • Do not edit manually: If you need to declare your own custom global types, ambient modules, or extend Next.js interfaces, create a separate declaration file (such as types/global.d.ts or additional.d.ts) and include it in the include array of your tsconfig.json.
  • Commit to version control: The Next.js team recommends committing next-env.d.ts to Git. Keeping it in your repository ensures that continuous integration (CI) pipelines and other developers on your team have access to the exact environment types without requiring Next.js to regenerate them before running type checks (such as tsc --noEmit).
