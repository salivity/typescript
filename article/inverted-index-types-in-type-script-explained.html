Inverted Index Types in TypeScript Explained

An inverted index type in TypeScript is a mapped type utility that swaps the keys and values of an object type, transforming a structure of { [Key]: Value } into { [Value]: Key }. This article explains the purpose of inverted index types in compile-time data modeling and demonstrates how to construct them using TypeScript's advanced type-system features, including key remapping and conditional types.

What Is an Inverted Index Type?

In traditional computer science, an inverted index is a database structure that maps contents (such as words) to their locations (such as documents). In TypeScript's type system, an inverted index operates similarly at the type level: it takes an object type whose values can serve as valid keys (strings, numbers, or symbols) and produces a new type where those values become keys, and the original keys become the values.

This pattern is particularly useful when creating bidirectional mappings, such as translating between enum-like constants, route paths, configuration dictionaries, or event-to-handler maps, ensuring complete type safety across both lookup directions without manually duplicating definitions.

Constructing a Basic Inverted Index Type

TypeScript 4.1 introduced key remapping in mapped types using the as clause. This allows direct modification of keys during mapped type iteration.

To invert a record where every value is unique and conforms to PropertyKey (string | number | symbol), construct the type as follows:

type Invert<T extends Record<PropertyKey, PropertyKey>> = {
  [K in keyof T as T[K]]: K;
};

How It Works:

  1. T extends Record<PropertyKey, PropertyKey> ensures that both the keys and values of the input type T are valid object keys.
  2. [K in keyof T] iterates over each key K in the input type.
  3. as T[K] remaps the key to its corresponding value type T[K].
  4. : K assigns the original key K as the new value.

Example Usage:

const roles = {
  admin: "ROLE_ADMIN",
  user: "ROLE_USER",
  guest: "ROLE_GUEST",
} as const;

type Roles = typeof roles;
// Equivalent to:
// {
//   readonly admin: "ROLE_ADMIN";
//   readonly user: "ROLE_USER";
//   readonly guest: "ROLE_GUEST";
// }

type InvertedRoles = Invert<Roles>;
// Evaluates to:
// {
//   ROLE_ADMIN: "admin";
//   ROLE_USER: "user";
//   ROLE_GUEST: "guest";
// }

Handling Collisions with Multiple Keys

When multiple keys share the same value, the simple Invert<T> implementation overwrites identical keys with a union or an arbitrary selection depending on compiler evaluation. To handle many-to-one relationships predictably, you can invert the type so that duplicated values map to a union of all matching keys.

To group keys under identical values:

type InvertGrouped<T extends Record<PropertyKey, PropertyKey>> = {
  [V in T[keyof T]]: {
    [K in keyof T]: T[K] extends V ? K : never;
  }[keyof T];
};

How It Works:

  1. T[keyof T] creates a union of all values present in T.
  2. [V in T[keyof T]] sets each unique value as a new key in the resulting type.
  3. { [K in keyof T]: T[K] extends V ? K : never }[keyof T] checks each original key K. If T[K] matches the current value V, it retains K; otherwise, it outputs never. Accessing [keyof T] collapses the result into a clean union of all matching keys.

Example Usage:

const permissions = {
  read: "user",
  comment: "user",
  delete: "admin",
} as const;

type Permissions = typeof permissions;

type GroupedPermissions = InvertGrouped<Permissions>;
// Evaluates to:
// {
//   user: "read" | "comment";
//   admin: "delete";
// }

These utility types allow TypeScript developers to maintain a single source of truth for configuration mappings while deriving inverse lookup tables strictly verified at compile time.
