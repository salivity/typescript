How ConstructorParameters Works in TypeScript

TypeScript provides built-in utility types that inspect and transform types at compile time without executing any runtime code. Among these, ConstructorParameters<T> allows developers to inspect class definitions and extract the parameter types of a constructor as a tuple type. This article explores the mechanics behind ConstructorParameters, examining how TypeScript leverages construct signatures, conditional types, and the infer keyword to pull constructor metadata directly from class declarations.

The Underlying Definition

In the TypeScript standard library, ConstructorParameters<T> is declared as follows:

type ConstructorParameters<T extends abstract new (...args: any) => any> = 
  T extends abstract new (...args: infer P) => any ? P : never;

This compact definition combines three core TypeScript type-system features: generic constraints, construct signatures, and conditional type inference.

1. Construct Signatures and Generic Constraints

The type constraint T extends abstract new (...args: any) => any ensures that the utility type only accepts valid constructors.

In TypeScript, a function or class that can be invoked with the new operator possesses a construct signature, denoted by the new prefix. By prefixing the construct signature with abstract, the constraint allows both concrete classes (instantiable via new ClassName()) and abstract classes (which cannot be instantiated directly, but still define constructor signatures for subclasses).

If a type passed to ConstructorParameters<T> does not match this constructor pattern, the TypeScript compiler raises an error at the call site.

2. Pattern Matching via Conditional Types

The second part of the utility type, T extends abstract new (...args: infer P) => any ? P : never, uses a conditional type (A extends B ? TruePath : FalsePath).

Here, T is pattern-matched against the structural representation of a constructor function. Instead of checking a basic primitive, TypeScript evaluates the shape of T to see if it matches an object with a construct signature receiving an arbitrary list of arguments (...args) and returning any instance (any).

3. Argument Extraction with the infer Keyword

The actual metadata extraction is driven by the infer keyword inside (...args: infer P).

When TypeScript evaluates the conditional type and confirms that T matches the constructor shape, it stops treating P as a static type constraint. Instead, it instructs the compiler's type engine to deduce the exact types of the parameters passed to ...args and assign them to the type variable P.

Because rest parameters (...args) represent function arguments as an ordered list, P resolves to a tuple type containing the types of those arguments in order.

Practical Example

Consider a class with multiple constructor parameters:

class DatabaseConnection {
  constructor(host: string, port: number, secure: boolean) {}
}

type ConnectionParams = ConstructorParameters<typeof DatabaseConnection>;
// Result: [host: string, port: number, secure: boolean]

Note the use of typeof DatabaseConnection. Passing DatabaseConnection directly passes the instance type of the class, which has no construct signature. Passing typeof DatabaseConnection passes the constructor function itself (the static side of the class), which matches abstract new (...args: any) => any.

Handling Overloads

When a class constructor defines multiple function overloads, TypeScript's conditional type resolution pattern-matches against the last declared implementation signature. Because TypeScript evaluates conditional types sequentially, the inferred tuple in ConstructorParameters will reflect only the parameters of the final overload definition rather than a union of all possible overloads.
