TypeScript Asserts: Narrow Types Without a Boolean

TypeScript allows you to narrow types without returning a boolean by using assertion signatures with the asserts keyword. While standard type guards require a function to return a boolean evaluating value is Type, assertion functions typically return void (or throw an exception). When an assertion function completes without throwing, TypeScript assumes the asserted condition holds true and narrows the variable's type for the remainder of the containing scope.

Standard Type Guards vs. Assertion Functions

Standard user-defined type predicates use the value is Type syntax and must return a boolean value. Code consuming these functions relies on conditional blocks like if statements to narrow the type:

function isString(value: unknown): value is string {
  return typeof value === "string";
}

function processValue(val: unknown) {
  if (isString(val)) {
    // val is narrowed to string here
    console.log(val.toUpperCase());
  }
}

In contrast, assertion functions verify that a condition is met and throw an error if it is not. Instead of wrapping the subsequent code in a conditional block, you call the assertion function directly, and TypeScript narrows the type in the subsequent lines.

Syntax for Assertion Signatures

Assertion signatures use the asserts modifier in the return type annotation. There are two primary forms:

  1. Specific Type Narrowing (asserts value is Type): Narrows an argument to a specific target type.
  2. Condition Assertion (asserts condition): Asserts that an expression evaluates to truthy.

1. Narrowing with asserts value is Type

This form indicates that if the function returns normally, the specified parameter conforms to the target type:

function assertIsString(value: unknown): asserts value is string {
  if (typeof value !== "string") {
    throw new TypeError("Value must be a string");
  }
}

function handleInput(input: unknown) {
  assertIsString(input);
  
  // No if-statement required.
  // 'input' is automatically narrowed to 'string' below this point.
  console.log(input.toUpperCase());
}

The function returns void, not boolean. If input is not a string, execution halts due to the thrown error, ensuring the downstream code only runs when the type assertion holds.

2. General Assertions with asserts condition

You can also create generic assertion helpers that check whether a given condition evaluates to true:

function assert(condition: unknown, message?: string): asserts condition {
  if (!condition) {
    throw new Error(message || "Assertion failed");
  }
}

function processEntity(entity: { id: string } | null) {
  assert(entity !== null, "Entity cannot be null");

  // 'entity' is narrowed from '{ id: string } | null' to '{ id: string }'
  console.log(entity.id);
}

Key Requirements for Assertion Functions

To successfully use asserts without returning a boolean, follow these rules:

  • Return Types: Assertion functions must return void or never. They cannot return values or booleans to represent pass/fail states.
  • Failure Handling: The function must throw an exception if the check fails. If an assertion function simply exits without throwing, TypeScript still assumes the assertion passed.
  • Declaration Limitations: Assertion signatures can be declared on function declarations or function expressions assigned to typed identifiers, but they cannot be defined using plain untyped arrow functions without an explicit return type annotation.
