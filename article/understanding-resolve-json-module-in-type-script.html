Understanding resolveJsonModule in TypeScript

The resolveJsonModule compiler option in TypeScript enables developers to directly import .json files into TypeScript modules, automatically generating static types based on the structure and contents of the imported JSON data. This article explores how to enable this setting in your configuration, how TypeScript infers types from JSON files, and best practices for working with imported JSON data.

What is resolveJsonModule?

By default, TypeScript only understands files with extensions like .ts, .tsx, and .d.ts. If you attempt to import a .json file, the compiler will throw an error stating that it cannot find the module.

The resolveJsonModule setting is a boolean flag in your tsconfig.json that instructs the TypeScript compiler to parse and include .json files as valid modules.

To enable it, update your tsconfig.json under compilerOptions:

{
  "compilerOptions": {
    "moduleResolution": "node",
    "resolveJsonModule": true,
    "esModuleInterop": true
  }
}

Note: resolveJsonModule requires a compatible moduleResolution strategy, such as node, node16, nodenext, or bundler.

How TypeScript Types Imported JSON

When resolveJsonModule is enabled, TypeScript does not simply type the imported JSON as any. Instead, it inspects the static JSON file at compile time and automatically generates a detailed shape interface that accurately represents the data.

1. Primitive and Object Inference

Consider a file named config.json:

{
  "appName": "AnalyticsApp",
  "version": 2,
  "features": {
    "logging": true,
    "betaAccess": false
  },
  "tags": ["dashboard", "v2"]
}

When imported into a TypeScript file:

import config from "./config.json";

TypeScript automatically assigns config the following inferred type:

{
  appName: string;
  version: number;
  features: {
    logging: boolean;
    betaAccess: boolean;
  };
  tags: string[];
}

The resulting type provides full autocompletion and compile-time checking. If you attempt to access config.nonExistentKey, the TypeScript compiler flags it as an error.

2. Literal Values vs. Primitive Types

TypeScript types JSON properties as general primitives rather than literal types. In the previous example, version is typed as number, not the literal 2, and appName is typed as string, not "AnalyticsApp".

If your application requires literal types for specific properties, you must cast them manually in TypeScript:

import rawConfig from "./config.json";

interface AppConfig {
  appName: "AnalyticsApp";
  version: 2;
}

const config = rawConfig as AppConfig;

3. Readonly Considerations

By default, imported JSON objects are not marked as readonly. Properties can technically be mutated at runtime within memory, though changes are not written back to the source .json file. If immutability is required to prevent accidental modifications in your code, apply the as const assertion via a wrapper variable or define an explicit Readonly<T> interface.

Performance and Bundling Impact

Imported JSON files are included directly in the generated JavaScript bundle. For small files such as configuration settings or internationalization tokens, the performance impact is negligible. However, importing large datasets (such as multi-megabyte mock data files) directly into your code will significantly bloat the bundle size and increase TypeScript compilation times. In such scenarios, fetching the JSON asynchronously at runtime is preferred.
