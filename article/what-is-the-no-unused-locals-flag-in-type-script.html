What Is the noUnusedLocals Flag in TypeScript?

The noUnusedLocals compiler flag in TypeScript helps developers maintain clean, efficient, and bug-free codebases by detecting and reporting unused local variables. This article explains the core purpose of the noUnusedLocals setting, highlights the practical benefits of enabling it in your projects, demonstrates how to configure it in tsconfig.json, and outlines how to handle intentionally unused variables.

What Does noUnusedLocals Do?

When noUnusedLocals is enabled, the TypeScript compiler checks the scope of functions, blocks, and modules for local variables, constants, functions, classes, or imports that are declared but never read. If any such declarations are found, the compiler emits an error (e.g., TS6133: '[variable]' is declared but its value is never read).

By default, this setting is set to false, allowing unused declarations to exist without triggering compiler errors.

Why Use noUnusedLocals?

Enabling noUnusedLocals provides several direct advantages to software development workflows:

  • Preventing Logic Bugs: Often, an unused local variable is a symptom of an incomplete implementation or a typo. For example, a developer might compute a transformed value into a new variable but accidentally reference the original variable in subsequent logic.
  • Eliminating Dead Code: Codebases accumulate "cruft" during refactoring. Unused declarations clutter the code, making it harder for developers to read, understand, and maintain the actual logic.
  • Optimizing Bundle Size: Although modern bundlers often perform tree-shaking, unreferenced local declarations or unused imports can sometimes prevent optimal dead-code elimination, leading to unnecessary weight in the final JavaScript bundle.

How to Enable noUnusedLocals

To activate this feature, add or update the noUnusedLocals property inside the compilerOptions section of your tsconfig.json file:

{
  "compilerOptions": {
    "noUnusedLocals": true
  }
}

Once configured, any build or type-check executed through the TypeScript CLI (tsc) will flag unused local declarations.

Code Example

Consider the following function:

function calculateTotal(price: number, taxRate: number): number {
  const discount = 5; // TS6133: 'discount' is declared but its value is never read.
  const tax = price * taxRate;
  
  return price + tax;
}

With noUnusedLocals: true, the TypeScript compiler flags discount because it is declared within the local function scope but never referenced.

Handling Intentionally Unused Variables

In situations where a variable must be extracted but will not be used—such as destructuring an object—TypeScript permits prefixing the variable name with an underscore (_) to suppress the error:

const user = { id: 1, name: "Alice", role: "admin" };

// Destructure to remove 'role', keeping only the rest
const { role: _role, ...publicUserData } = user;

By prefixing the variable with _, you signal to both the TypeScript compiler and other developers that the value is intentionally ignored.

noUnusedLocals vs. noUnusedParameters

It is worth noting the distinction between noUnusedLocals and noUnusedParameters. While noUnusedLocals targets variables, imports, and definitions declared within a block or module, noUnusedParameters applies specifically to arguments passed into functions or methods. Enabling both options provides comprehensive protection against dead declarations across your codebase.
