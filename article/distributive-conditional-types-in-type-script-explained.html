Distributive Conditional Types in TypeScript Explained

Distributive conditional types are a core feature in TypeScript that automatically unpack union types across conditional expressions. When a conditional type is applied to a generic parameter that receives a union, TypeScript evaluates each member of that union individually rather than treating the union as a single, indivisible entity. This article breaks down how distributive conditional types work, the exact criteria that trigger distribution, real-world practical use cases, and how to disable this behavior when necessary.

Understanding Conditional Types

In TypeScript, a basic conditional type follows a ternary structure:

T extends U ? X : Y

If the type T is assignable to U, the type resolves to X; otherwise, it resolves to Y.

What Makes a Conditional Type Distributive?

Distribution occurs when a conditional type operates on a naked type parameter that receives a union type.

A "naked" type parameter is a generic type variable that is not wrapped in any other structure, such as a tuple, array, object, or Promise. When you provide a union A | B | C to a generic type T inside a conditional expression like T extends U ? X : Y, TypeScript distributes the condition over each member:

(A | B | C) extends U ? X : Y

Resolves automatically to:

(A extends U ? X : Y) | (B extends U ? X : Y) | (C extends U ? X : Y)

The results of each branch are collected and merged back into a single union type.

When Does Distribution Occur?

Distribution occurs if and only if two conditions are met simultaneously:

  1. The checked type is a generic parameter: The type being checked on the left-hand side of extends must be an unresolved generic type variable (e.g., T). Distribution does not happen on direct union literals (such as 'a' | 'b' extends string ? true : false).
  2. The generic parameter is "naked": The generic parameter must stand alone. If it is wrapped (for example, [T], Promise<T>, or { value: T }), distribution is suppressed.

Example: How Distribution Works

Consider a custom utility type designed to isolate string types:

type ToArray<T> = T extends any ? T[] : never;

type Result = ToArray<string | number>;
// Result is: string[] | number[]

Because ToArray features a naked T, the union string | number distributes into ToArray<string> | ToArray<number>, producing string[] | number[] instead of (string | number)[].

Real-World Applications

TypeScript's standard library relies heavily on distributive conditional types to implement built-in utility types.

The Exclude Utility Type

The built-in Exclude<T, U> removes types from T that are assignable to U:

type Exclude<T, U> = T extends U ? never : T;

type AvailableRoles = Exclude<'admin' | 'editor' | 'viewer', 'admin'>;
// Resolves to: 'editor' | 'viewer'

Step-by-step evaluation:

  • 'admin' extends 'admin' ? never : 'admin' \(\rightarrow\) never
  • 'editor' extends 'admin' ? never : 'editor' \(\rightarrow\) 'editor'
  • 'viewer' extends 'admin' ? never : 'viewer' \(\rightarrow\) 'viewer'

Since never is eliminated from unions automatically, the resulting type is 'editor' | 'viewer'.

How to Prevent Distribution

If you want to compare the entire union as a single entity rather than distributing across each variant, wrap both sides of the extends keyword in square brackets to form a tuple:

type NonDistributive<T> = [T] extends [string] ? true : false;

type Test1 = NonDistributive<string | number>; 
// Evaluates to: false (because [string | number] is not assignable to [string])

Compare this to the distributive version:

type Distributive<T> = T extends string ? true : false;

type Test2 = Distributive<string | number>; 
// Evaluates to: true | false (which simplifies to boolean)

Wrapping the generic type inside a tuple breaks the "naked" requirement, ensuring the union is evaluated as a cohesive whole.
