Static Accessors and Independent Typing in TypeScript

Static accessors allow developers to define getter and setter methods directly on a class constructor rather than on its instances. This article explains what static accessors are in TypeScript, demonstrates their implementation, and addresses whether getters and setters can have independent types, including the specific type-compatibility rules enforced by the TypeScript compiler.

What Are Static Accessors?

In TypeScript and JavaScript, static accessors are get and set methods prefixed with the static keyword inside a class definition. Unlike instance accessors, which are invoked on an instantiated object, static accessors exist on the class constructor itself. They allow you to encapsulate logic around reading or writing class-level state without needing to instantiate the class.

class Configuration {
  private static _timeout: number = 5000;

  static get timeout(): number {
    return Configuration._timeout;
  }

  static set timeout(value: number) {
    if (value < 0) {
      throw new Error("Timeout must be a positive number.");
    }
    Configuration._timeout = value;
  }
}

// Accessed directly from the class constructor
Configuration.timeout = 10000;
console.log(Configuration.timeout); // 10000

Can Static Accessors Be Typed Independently?

Yes, static accessors can be typed independently starting from TypeScript 4.3. Prior to TypeScript 4.3, both the getter and setter were required to share the exact same type. Modern versions of TypeScript allow write types (setters) to differ from read types (getters).

This is particularly useful when a setter can accept multiple formats or input types (such as a string or number) that are normalized internally into a single canonical type returned by the getter.

Example: Independent Types on Static Accessors

class CacheManager {
  private static _limit: number = 100;

  // Getter returns a strict number
  static get limit(): number {
    return CacheManager._limit;
  }

  // Setter accepts either a string or a number
  static set limit(value: string | number) {
    if (typeof value === "string") {
      CacheManager._limit = parseInt(value, 10);
    } else {
      CacheManager._limit = value;
    }
  }
}

// Valid usages:
CacheManager.limit = "250"; // Accepted via setter
CacheManager.limit = 500;   // Accepted via setter

const currentLimit: number = CacheManager.limit; // Typed as number

The Typing Constraint

While TypeScript allows independent types for accessors, there is a fundamental restriction: the getter's return type must be assignable to the setter's parameter type.

This constraint ensures operations like self-assignment remain type-safe:

// This must always be valid:
CacheManager.limit = CacheManager.limit;

Because the getter returns number, and the setter accepts string | number, number is assignable to string | number.

If you attempt the inverse—where the getter returns a type broader than what the setter accepts—TypeScript will throw a compilation error:

class InvalidExample {
  private static _val: string | number = 0;

  // Error: The return type of a 'get' accessor must be assignable to its 'set' accessor type.
  static get value(): string | number {
    return InvalidExample._val;
  }

  static set value(v: number) {
    InvalidExample._val = v;
  }
}

Static accessors in TypeScript provide powerful encapsulation for class-level properties, and TypeScript 4.3+ gives you the flexibility to type getters and setters independently, provided the getter type satisfies the setter's accepted input.
