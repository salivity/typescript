How to Extend HTMLElementTagNameMap in TypeScript

Extending the HTMLElementTagNameMap interface in TypeScript allows the compiler to recognize custom elements—such as Web Components—in standard DOM querying and creation methods. By using TypeScript's declaration merging feature, you map your custom tag names to their corresponding element classes, enabling full type safety, auto-completion, and accurate return types for methods like document.createElement(), document.querySelector(), and element.closest().

Understanding the Problem

When using custom elements without type definitions, standard DOM APIs return generic types. For example:

// Returns HTMLUnknownElement
const el1 = document.createElement('user-card');

// Returns Element | null
const el2 = document.querySelector('user-card');

TypeScript uses the internal HTMLElementTagNameMap interface to resolve tag names to their specific interface implementations (e.g., 'div' maps to HTMLDivElement). To make TypeScript recognize custom tags, you must merge your custom definitions into this map.

Step-by-Step Implementation

1. Define the Custom Element Class

Create your custom element by extending HTMLElement (or an existing built-in element subclass):

export class UserCardElement extends HTMLElement {
  userId: string = '';

  connectedCallback() {
    this.innerHTML = `<p>User ID: ${this.userId}</p>`;
  }

  updateStatus(status: string) {
    console.log(`Status updated to: ${status}`);
  }
}

customElements.define('user-card', UserCardElement);

2. Extend the Interface via Declaration Merging

How you declare the extension depends on whether you are working within a module or a global declaration file.

In a Module (Files with import or export)

If your file contains import or export statements, wrap the declaration in a declare global block to target the global scope:

declare global {
  interface HTMLElementTagNameMap {
    'user-card': UserCardElement;
  }
}

In an Ambient Declaration File (.d.ts without top-level imports/exports)

If you are defining types in an ambient declaration file that contains no top-level module statements, extend the interface directly without declare global:

interface HTMLElementTagNameMap {
  'user-card': UserCardElement;
}

Verifying Type Inference

Once the interface is augmented, TypeScript automatically infers the correct instance type across standard DOM methods:

// Strongly typed as UserCardElement
const card = document.createElement('user-card');
card.userId = '12345';
card.updateStatus('active');

// Strongly typed as UserCardElement | null
const existingCard = document.querySelector('user-card');
if (existingCard) {
  existingCard.userId = '67890';
}

In addition to document.createElement and document.querySelector, methods such as querySelectorAll('user-card') will infer NodeListOf<UserCardElement>, ensuring consistency across the entire DOM manipulation API.
