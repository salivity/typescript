declarationDir Without declaration in TypeScript

When configuring a TypeScript project, developers often organize build artifacts by outputting type definitions into a dedicated folder using the declarationDir option. However, setting declarationDir in your tsconfig.json without also enabling the declaration flag causes the TypeScript compiler to fail and throw a configuration error. This article explains the exact error that occurs, why the compiler enforces this rule, and how to resolve the issue properly.

The Result: Compiler Error TS5063

If you define declarationDir while declaration remains false (its default state) or omitted, the TypeScript compiler (tsc) will abort the build process and return the following error:

error TS5063: Option 'declarationDir' cannot be specified without specifying option 'declaration' or option 'composite'.

TypeScript requires an active directive to emit declaration files (.d.ts) before it allows you to specify where those files should be placed. Because declarationDir only affects .d.ts files, providing an output directory for files that the compiler is not instructed to produce is treated as an invalid configuration.

Why This Happens

The TypeScript compiler options serve distinct, dependent roles:

  • declaration: When set to true, it tells the compiler to generate .d.ts files for every TypeScript file in your project.
  • declarationDir: Specifies the directory path where those generated .d.ts files should be routed.

If declaration is not enabled, the compiler has no declaration files to write to disk. Rather than silently ignoring the declarationDir property, the compiler throws error TS5063 to prevent unintended build output behavior and misconfigured deployment pipelines.

How to Fix the Error

Depending on your project requirements, there are three ways to resolve this error:

1. Enable the declaration Flag

If your goal is to emit type definitions to the specified directory—which is typical when publishing libraries or packages—explicitly enable declaration in your tsconfig.json:

{
  "compilerOptions": {
    "outDir": "./dist",
    "declaration": true,
    "declarationDir": "./dist/types"
  }
}

2. Enable Project References with composite

If you are working within a monorepo setup using TypeScript project references, you can enable composite. Enabling composite automatically enforces and enables declaration under the hood:

{
  "compilerOptions": {
    "composite": true,
    "declarationDir": "./dist/types"
  }
}

3. Remove declarationDir

If you are building an application (such as a web app or backend service) where .d.ts files are not needed by external consumers, remove declarationDir from your configuration entirely. JavaScript output will continue to route to your configured outDir without generating type definition files.
