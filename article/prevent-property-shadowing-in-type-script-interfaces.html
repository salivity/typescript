Prevent Property Shadowing in TypeScript Interfaces

TypeScript prevents accidental property shadowing in extended interfaces by strictly enforcing structural subtyping and property compatibility at compile time. When an interface extends another, any overlapping properties must be assignable to the types defined in the parent interface. If an extended interface attempts to redefine an existing property with an incompatible type, the TypeScript compiler immediately flags it as a compilation error, ensuring that derived interfaces never inadvertently break the contract of their base types.

The Incompatible Extension Check

In TypeScript, interface inheritance follows the principle of structural subtyping. An instance of a child interface must always be valid where an instance of the parent interface is expected. Consequently, TypeScript does not allow a child interface to redefine an inherited property with an arbitrary or conflicting type.

Consider the following scenario:

interface User {
  id: string;
  name: string;
}

interface AdminUser extends User {
  id: number; // Error: Types of property 'id' are incompatible.
}

The compiler detects that number cannot be assigned to string and raises the error: Interface 'AdminUser' incorrectly extends interface 'User'. Types of property 'id' are incompatible. This compile-time check prevents developers from accidentally masking or changing the data type of an inherited field.

Safe Specialization Through Type Narrowing

TypeScript does not completely forbid redeclaring existing properties; rather, it forbids incompatible redeclarations. A child interface is allowed to narrow an inherited type to a more specific subtype. This ensures intentional refinement while preventing accidental, breaking overrides.

For example, narrowing a union type or refining a general type to a literal is permitted:

interface ApiResponse {
  status: string;
  data: unknown;
}

interface SuccessResponse extends ApiResponse {
  status: "success"; // Valid: "success" is a subtype of string
  data: Record<string, any>; // Valid: Record is assignable to unknown
}

Because "success" is assignable to string, any function that accepts an ApiResponse can safely consume a SuccessResponse without runtime surprises.

Interfaces (extends) vs. Type Intersections (&)

The safety mechanism provided by extends is uniquely designed to prevent accidental shadowing compared to type intersections (&).

When combining types using the intersection operator (&), conflicting property types do not cause immediate compiler errors at the declaration site. Instead, TypeScript merges the properties into an intersection:

type Base = { id: string };
type Derived = Base & { id: number };

// 'id' becomes: string & number, which evaluates to 'never'

In an intersection, the conflict results in the property type collapsing to never, which can hide bugs until the property is instantiated or assigned.

By using extended interfaces (interface Child extends Parent), TypeScript forces explicit structural compatibility at the point of declaration. Any conflicting property name is evaluated immediately, protecting your codebase from accidental property shadowing and hidden contract mismatches.
