TypeScript Structural Subtyping: Primitives and Objects

This article explores how TypeScript reconciles structural subtyping with JavaScript's distinction between primitive values and objects. You will learn how TypeScript models auto-boxing, why primitive types are assignable to certain object shapes, how prototype interfaces bridge the gap between values and shapes, and why this structural relationship is largely one-directional.

Structural Typing and the Primitive Divide

TypeScript relies on a structural type system, meaning compatibility is determined by the shape and members of a type rather than its explicit declaration. In JavaScript, however, runtime values fall into two distinct categories: primitives (such as string, number, boolean, symbol, and bigint) and reference objects.

Primitives do not inherently possess properties or methods at the machine level. Despite this, JavaScript provides seamless access to methods on primitives via auto-boxing (wrapping the primitive in a temporary object wrapper when accessing properties). TypeScript directly encodes this runtime behavior into its static type system, allowing primitives to act as structural subtypes of matching object types.

Property Access and Prototype Interfaces

TypeScript ships with built-in ambient declarations for the standard JavaScript library, including global interfaces such as String, Number, and Boolean. These interfaces declare the methods and properties found on the corresponding runtime prototypes (String.prototype, Number.prototype, etc.).

When TypeScript checks a primitive type (like string), it treats that type as possessing all the members defined in its matching interface (String). Because structural subtyping only checks whether the target type's required properties exist on the source type, a primitive value is assignable to an object type if the primitive's prototype interface satisfies that object type's contract.

// Valid: 'string' has a 'length' property via String.prototype
const hasLength: { length: number } = "hello world";

// Valid: 'number' has a 'toFixed' method via Number.prototype
const hasToFixed: { toFixed(fractionDigits?: number): string } = 42;

In these cases, TypeScript determines that the primitive satisfies the shape of the object.

Directionality: Primitives to Objects vs. Objects to Primitives

While a primitive can be assigned to an object type with matching properties, the reverse relationship is strictly forbidden. An object that happens to implement the entire interface of a primitive wrapper cannot be assigned to a primitive type:

// Valid: Primitive assigned to matching object shape
const obj: { length: number } = "example"; 

// Error: Type '{ length: number }' is not assignable to type 'string'
const str: string = { length: 7 };

Primitives in TypeScript are atomic value types. Even if an object provides every method of String.prototype, it lacks the fundamental primitive identity required by the runtime. TypeScript preserves this boundary to avoid runtime type errors where operations specifically expect a raw JavaScript primitive rather than an object.

Wrapper Objects vs. Primitive Types

TypeScript makes a strict distinction between primitive types and their wrapper object types:

  • Lowercase types (string, number, boolean): Represent the actual primitive values.
  • Uppercase types (String, Number, Boolean): Represent the wrapper interfaces defined by the standard library.

A primitive type is a subtype of its corresponding wrapper type:

let primitiveStr: string = "test";
let wrapperStr: String = primitiveStr; // Valid

However, a wrapper object is not a subtype of the primitive:

let wrapperStr: String = new String("test");
// Error: Type 'String' is not assignable to type 'string'
let primitiveStr: string = wrapperStr;

String is an object type, and allowing it to satisfy string would break type safety around runtime identity and operations like typeof.

The Special Roles of Object, {}, and object

The interaction between primitives and objects is governed by three specific general types:

  1. Object: Represents the methods provided by Object.prototype. All primitives (except null and undefined) inherit these properties and are assignable to Object.
  2. {} (Empty Object Type): Represents any value that is not null or undefined. Because primitives have no required missing properties to satisfy {}, any primitive can be assigned to {}.
  3. object (lowercase): Explicitly represents non-primitive types (typeof x === "object" or "function"). Primitives cannot be assigned to object.
const a: Object = "text"; // Valid: String has Object.prototype methods
const b: {} = 123;        // Valid: 123 is not null or undefined
// Error: Type 'string' is not assignable to type 'object'
const c: object = "text";

Through this mechanism, TypeScript mirrors JavaScript's auto-boxing behavior: primitives act structurally like objects when properties are read, but remain distinct values that cannot be simulated simply by creating object literals.
