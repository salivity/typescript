What Is a SourceFile Node in TypeScript AST?

This article provides a comprehensive overview of the SourceFile node in the TypeScript Abstract Syntax Tree (AST), explaining its definition, core properties, and practical applications. Readers will learn how the TypeScript Compiler API models a complete source file as the root AST node, how to inspect its structural properties, and how to utilize it to parse, traverse, and transform TypeScript source code programmatically.

In the TypeScript Compiler API, an Abstract Syntax Tree (AST) represents source code hierarchically as a tree of nodes. The SourceFile node is the outermost, top-level node of this tree, representing an entire individual file—such as a .ts, .tsx, .js, or .d.ts file. Every other construct within that file, including imports, interfaces, functions, statements, and comments, exists as a descendant node beneath the SourceFile root.

Core Properties of a SourceFile Node

A SourceFile implements the ts.Node interface but adds file-level metadata and functionality essential for parsing and compilation:

  • fileName: A string representing the absolute or relative path of the file being parsed.
  • text: The entire, unmodified raw source code of the file as a string.
  • statements: A NodeArray<Statement> containing top-level statements, declarations, classes, and imports defined directly inside the file.
  • languageVariant: Indicates whether the file contains standard TypeScript/JavaScript or JSX (Standard vs. JSX).
  • isDeclarationFile: A boolean flag indicating whether the file is a TypeScript definition file (.d.ts).
  • languageVersion: The target ECMAScript version used during parsing (e.g., ScriptTarget.ES2020).
  • endOfFileToken: A token marking the end of the file stream.

Creating and Inspecting a SourceFile

You can generate a SourceFile node using the createSourceFile method provided by the TypeScript compiler API:

import * as ts from "typescript";

const sourceCode = `const greeting: string = "Hello, World!";`;
const sourceFile = ts.createSourceFile(
  "example.ts",
  sourceCode,
  ts.ScriptTarget.Latest,
  /* setParentNodes */ true
);

console.log(sourceFile.fileName); // "example.ts"
console.log(sourceFile.statements.length); // 1

Setting setParentNodes to true ensures that each child node maintains a reference back to its parent, up to the SourceFile itself.

Role in AST Traversal and Transformation

Because the SourceFile node is the root of the hierarchy, it serves as the entry point for code analysis tools, linters, and AST transformations:

  • AST Traversal: Functions like ts.forEachChild accept the SourceFile as their initial parameter to recursively inspect declarations, expressions, and tokens across the entire file.
  • Position Mapping: The SourceFile provides utility methods such as getLineAndCharacterOfPosition() to translate raw character offsets in the code string into human-readable line and column numbers.
  • Code Transformation: When writing custom compiler transformers, a transformation pipeline receives a SourceFile and returns a modified SourceFile with updated, added, or removed nodes.
  • Printing: The ts.createPrinter() utility requires a SourceFile to serialize modified AST nodes back into formatted JavaScript or TypeScript text.
