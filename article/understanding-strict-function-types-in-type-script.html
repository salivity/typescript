Understanding strictFunctionTypes in TypeScript

The strictFunctionTypes flag is a TypeScript compiler option that enforces stricter, safer type checking for function parameters. When enabled, it switches the comparison of function parameter types from bivariant (allowing both wider and narrower types) to contravariant (allowing only wider or identical types). This article explores how this flag works, why the default behavior exists, and how enabling it prevents subtle runtime errors in your TypeScript applications.

What is strictFunctionTypes?

Introduced in TypeScript 2.6 and enabled by default under the --strict suite, strictFunctionTypes dictates how TypeScript verifies whether one function type can be assigned to another.

By default, TypeScript checks function parameters bivariantly. This means a parameter type can be either a subtype (narrower) or a supertype (broader) of the expected parameter type. Enabling strictFunctionTypes forces parameters to be checked contravariantly, ensuring that a target function can only be assigned a function whose parameters are identical or broader than what the caller provides.

Default Behavior: Bivariant Parameter Checking

Without strictFunctionTypes, TypeScript allows unsafe function assignments. Consider a hierarchy involving an Animal base class and a Dog subclass:

class Animal {
    name: string = "Animal";
}

class Dog extends Animal {
    bark() {
        console.log("Woof");
    }
}

If you have a function that expects a Dog and attempts to assign it to a callback that provides an Animal:

let handleAnimal: (a: Animal) => void;
let handleDog = (d: Dog) => {
    d.bark();
};

// Allowed when strictFunctionTypes is false:
handleAnimal = handleDog;

// Runtime error:
handleAnimal(new Animal()); // Calls d.bark(), which does not exist on Animal!

Under bivariant checking, the assignment handleAnimal = handleDog passes compilation even though calling handleAnimal with an ordinary Animal causes an unhandled runtime error.

Strict Behavior: Contravariant Parameter Checking

When strictFunctionTypes is set to true, the assignment above fails at compile time:

Type '(d: Dog) => void' is not assignable to type '(a: Animal) => void'.
  Types of parameters 'd' and 'a' are incompatible.
    Property 'bark' is missing in type 'Animal' but required in type 'Dog'.

Under contravariant rules, you may only assign a function whose parameter requirements are equal to or less demanding than the target signature:

let processAnimal = (a: Animal) => {
    console.log(a.name);
};

let processDog: (d: Dog) => void;

// Valid under strictFunctionTypes:
processDog = processAnimal; 

processDog(new Dog()); // Safe: Dog has a 'name' property

Because processAnimal only requires an Animal, it is guaranteed to safely handle any Dog passed to processDog.

Method Syntax Exception

It is important to note that strictFunctionTypes applies exclusively to function signatures written as properties or standalone function types (such as x: (a: T) => void). Methods declared using shorthand syntax (such as x(a: T): void) remain bivariant even when the flag is enabled.

interface AnimalHandler {
    handle(a: Animal): void; // Method syntax: remains bivariant
}

interface StrictAnimalHandler {
    handle: (a: Animal) => void; // Function property: checked contravariantly
}

This exception was deliberately maintained to preserve compatibility with existing structural patterns in JavaScript libraries, notably array mutation methods like Array.prototype.push. To ensure maximum safety across your codebase, prefer using function property signatures over method syntax when defining interfaces.
