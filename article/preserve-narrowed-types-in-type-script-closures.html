Preserve Narrowed Types in TypeScript Closures

In TypeScript, narrowing a mutable variable using control flow checks often fails to carry that narrowed type into nested callbacks and closures. Because mutable variables can be reassigned at any time prior to closure execution, the TypeScript compiler intentionally widens their types back to prevent runtime errors. Declaring values with const, either at the initial declaration or by capturing a narrowed reference in a local constant, locks the binding and guarantees immutability, allowing TypeScript to safely preserve narrowed types across closures.

The Closure Narrowing Problem

TypeScript relies on control flow analysis to narrow types. When you check if a variable of type string | null is not null, the compiler narrows the type to string within that conditional block. However, if you reference that variable inside a nested function, callback, or asynchronous operation, TypeScript may discard the narrowed type.

Consider the following scenario using a mutable let variable:

function processData(value: string | null) {
  let data = value;

  if (data !== null) {
    setTimeout(() => {
      // Error: 'data' is possibly 'null'.
      console.log(data.toUpperCase());
    }, 1000);

    // 'data' could be reassigned here before the timeout executes
    data = null;
  }
}

Because data is declared with let, it is mutable. TypeScript cannot guarantee that the value of data inside the setTimeout callback will remain a string when the callback eventually executes. To maintain safety, TypeScript widens data back to its original union type inside the closure.

How const Preserves Narrowed Types

A const variable creates an immutable binding that cannot be reassigned. When TypeScript narrows a const variable, it knows the value can never be replaced with a different type later in the scope. Consequently, closures referencing a const retain the narrowed type safely.

To preserve the narrowed type in a closure, capture the narrowed value into a const before entering the nested function:

function processData(value: string | null) {
  let data = value;

  if (data !== null) {
    const safeData = data; // safeData is locked as 'string'

    setTimeout(() => {
      // TypeScript knows safeData is always 'string'
      console.log(safeData.toUpperCase());
    }, 1000);

    data = null; // safeData remains unaffected
  }
}

By aliasing data to safeData via const, the reference captured by the closure is immune to subsequent reassignments. The compiler preserves the string type without requiring explicit type assertions (as string) or non-null assertion operators (!).

Preserving Object Properties Across Closures

The same issue occurs when narrowing object properties. Because object properties are mutable by default, TypeScript cannot guarantee that another function or external process will not mutate a property before a closure runs:

interface UserProfile {
  id: string;
  email?: string;
}

function sendNotification(user: UserProfile) {
  if (user.email) {
    const email = user.email; // Extracted to a const

    fetch('/api/notify', {
      method: 'POST',
      body: JSON.stringify({ to: email })
    }).then(() => {
      // 'email' reliably stays 'string'
      console.log(`Sent to ${email.toLowerCase()}`);
    });
  }
}

Destructuring or storing the property into a local const immediately snapshots the value and freezes its narrowed type for any subsequent closures.

Summary

Whenever a closure must access a narrowed type:

  • Avoid referencing outer let variables or mutable object properties directly inside the closure.
  • Extract or alias the narrowed value to a const binding before defining the closure.
  • Rely on TypeScript's immutability guarantees for const to keep types narrow without type assertions.
