How TypeScript Checks Exhaustive Returns

This article explains how TypeScript verifies that all execution branches within a function return an expected value. It covers TypeScript's built-in control flow analysis, the role of compiler options like noImplicitReturns, how explicit return types enforce completeness, and how developers can utilize the never type to achieve compile-time exhaustive checks over complex data structures like discriminated unions.

Control Flow Analysis

TypeScript relies on Control Flow Analysis (CFA) to track the execution paths of your code. When a function executes, the compiler constructs a control flow graph evaluating every conditional statement (if/else), loop (for, while), switch statement, and error-handling block (try/catch/finally).

Through this graph, TypeScript determines whether every reachable path terminates with a return statement, throws an error, or calls a function that returns the never type (such as an infinite loop or a process exit). If any reachable path falls through to the end of the function without an explicit return, TypeScript flags it based on your type annotations and compiler settings.

Explicit Return Types

The most direct way TypeScript checks for exhaustive returns is through explicit return type annotations. When you explicitly declare a return type on a function, TypeScript validates that every potential branch returns a value assignable to that type:

function getStatus(code: number): string {
  if (code === 200) {
    return "OK";
  } else if (code === 404) {
    return "Not Found";
  }
  // Error: Function lacks ending return statement and return type does not include 'undefined'.
}

If an execution path fails to return a value, the implicit result of that branch in JavaScript is undefined. Because undefined is not assignable to string, the compiler raises a type error.

The noImplicitReturns Compiler Option

By default, if a function lacks an explicit return type and does not return on all paths, TypeScript infers a union type that includes undefined (or infers void if there are no returns). To prevent functions from silently dropping off without returning, enable the noImplicitReturns flag in tsconfig.json:

{
  "compilerOptions": {
    "noImplicitReturns": true
  }
}

With noImplicitReturns enabled, TypeScript ensures that if any branch returns a value, all branches must explicitly return a value, even if no explicit return type was provided on the function signature:

function calculateDiscount(isMember: boolean) {
  if (isMember) {
    return 0.2;
  }
  // Error: Not all code paths return a value.
}

Exhaustive Checks with Discriminated Unions and never

When dealing with discriminated unions, control flow analysis narrows the types based on discriminant properties (such as a kind or type field). TypeScript allows you to enforce exhaustive handling using the never type, which represents a state that should never occur.

By assigning the unhandled state to a variable typed as never in a default case or fallback branch, TypeScript checks if any variant was missed:

type Shape = 
  | { kind: "circle"; radius: number }
  | { kind: "square"; size: number }
  | { kind: "triangle"; base: number; height: number };

function getArea(shape: Shape): number {
  switch (shape.kind) {
    case "circle":
      return Math.PI * shape.radius ** 2;
    case "square":
      return shape.size ** 2;
    default:
      // If "triangle" is not handled, shape is narrowed to { kind: "triangle", ... }
      // Error: Type 'Shape' is not assignable to type 'never'.
      const _exhaustiveCheck: never = shape;
      throw new Error(`Unhandled shape: ${_exhaustiveCheck}`);
  }
}

If a new variant is added to the Shape union in the future, TypeScript's control flow analysis will detect that the default block is reachable with the new type, triggering a compile-time error until a corresponding case and return are implemented.

Terminal Branches: Errors and Infinite Loops

TypeScript recognizes operations that prevent a function from finishing normally. A branch is considered exhaustively terminated if it ends with:

  • A throw statement.
  • A call to a function with an explicit return type of never.
function fail(message: string): never {
  throw new Error(message);
}

function parseInput(input: string | null): string {
  if (input !== null) {
    return input.trim();
  }
  
  // This branch is considered terminated because fail() returns never
  fail("Input cannot be null");
}

Because TypeScript understands that execution cannot continue past fail(), it does not require an additional return statement after the function call.
