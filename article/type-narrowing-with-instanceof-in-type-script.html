Type Narrowing with instanceof in TypeScript

In TypeScript, the instanceof operator acts as a built-in type guard that narrows union types down to specific class instances within conditional execution blocks. By leveraging JavaScript's runtime prototype inspection, TypeScript's compiler tracks the check at compile time, safely exposing class-specific properties and methods within the guarded block while eliminating those types from subsequent else branches.

How the Mechanism Operates

The instanceof operator works through a dual mechanism combining JavaScript's runtime behavior with TypeScript's static analysis:

  1. Runtime Verification: JavaScript inspects the prototype chain of an object to determine whether the prototype property of a constructor function appears anywhere along that chain:

    value instanceof Constructor

  2. Compile-Time Narrowing: TypeScript monitors control flow. When it detects an instanceof check inside an if condition, it automatically re-types the variable within that branch to the constructor's instance type (or a subtype). In the alternative branch (else), TypeScript automatically removes that constructor's type from the union.

Basic Example: Differentiating Classes

Consider a scenario where a function can accept different class instances:

class CustomError {
  constructor(public message: string) {}
}

class HttpError extends CustomError {
  constructor(message: string, public statusCode: number) {
    super(message);
  }
}

class ValidationError extends CustomError {
  constructor(message: string, public invalidFields: string[]) {
    super(message);
  }
}

function handleError(error: HttpError | ValidationError) {
  if (error instanceof HttpError) {
    // Inside this block, error is narrowed to HttpError
    console.error(`HTTP ${error.statusCode}: ${error.message}`);
  } else {
    // TypeScript knows error must be ValidationError here
    console.error(`Validation failed on: ${error.invalidFields.join(", ")}`);
  }
}

Prior to the if statement, accessing error.statusCode causes a compilation error because statusCode does not exist on ValidationError. Once wrapped in error instanceof HttpError, TypeScript narrows the type, allowing direct access to statusCode.

Type Elimination in Fallback Branches

TypeScript’s control-flow analysis continues after each guard. If all possibilities in a union are accounted for via instanceof, the variable is reduced to the never type, enabling exhaustive type checking:

function processError(error: HttpError | ValidationError) {
  if (error instanceof HttpError) {
    // error: HttpError
    return;
  }
  
  if (error instanceof ValidationError) {
    // error: ValidationError
    return;
  }

  // error: never
  const _unreachable: never = error;
}

Key Limitations

  • Interfaces and Types: The instanceof operator relies on JavaScript constructor functions present at runtime. Because TypeScript interfaces and type aliases are erased during compilation, using instanceof with an interface results in a compile-time error. For interfaces, use custom type predicates (is) or discriminant properties instead.
  • Execution Realms: If an object is created within a different execution context (such as an <iframe> or a separate Node.js vm context), the prototype chains will reference different constructor instances, causing instanceof to return false despite identical structures.
