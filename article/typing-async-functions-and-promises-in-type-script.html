Typing Async Functions and Promises in TypeScript

This article provides a concise overview of how TypeScript handles asynchronous code, detailing how the Promise<T> generic models deferred values, how async functions enforce and infer asynchronous return types, and how the Awaited<T> utility type handles recursive promise unwrapping at compile time.

The Promise<T> Generic Type

In TypeScript, deferred results are represented using the generic interface Promise<T>, where T specifies the type of the value resolved upon success.

function fetchUserId(): Promise<number> {
  return new Promise((resolve) => {
    resolve(42);
  });
}

When you define an explicit return type of Promise<T>, TypeScript ensures that any value passed to the resolve callback matches T.

Typing async Functions

Any function declared with the async keyword in JavaScript inherently returns a Promise. TypeScript strictly enforces this behavior: the return type of an async function must always be a Promise.

If you write a regular return statement within an async function, TypeScript automatically wraps the inferred return type in a Promise:

// Return type is inferred as Promise<string>
async function getGreeting() {
  return "Hello, World!";
}

If you explicitly define the return type, it must be declared as Promise<T>, not T:

// Valid
async function getStatus(): Promise<boolean> {
  return true;
}

// Error: The return type of an async function or method must be the global Promise<T> type.
async function getInvalidStatus(): boolean {
  return true;
}

Promise Resolution with await

When the await operator is used inside an async function, TypeScript extracts the resolved type T from Promise<T>:

async function processData() {
  const userId = await fetchUserId(); // Inferred as type 'number'
  console.log(userId.toFixed(2));
}

If you apply await to a non-promise value, TypeScript evaluates the expression as the value's immediate type rather than raising an error, mimicking JavaScript's runtime behavior.

Recursive Unwrapping with Awaited<T>

At runtime, native JavaScript promises automatically unwrap nested promises. For example, resolving a Promise<Promise<string>> yields a string, not a Promise<string>.

To match this behavior at the type level, TypeScript provides the intrinsic Awaited<T> utility type (introduced in TypeScript 4.5). It recursively strips away promise layers:

type DeepPromise = Promise<Promise<Promise<number>>>;
type Resolved = Awaited<DeepPromise>; // number

TypeScript uses Awaited<T> internally to infer the return types of functions like Promise.all, Promise.race, and statements using await.

Error Handling and Rejections

TypeScript does not statically type Promise rejections or caught errors as part of the function signature. Because JavaScript allows any value to be thrown, caught errors in try/catch blocks or Promise .catch() handlers default to unknown (or any, depending on the useUnknownInCatchVariables compiler flag).

async function execute() {
  try {
    await fetchUserId();
  } catch (error: unknown) {
    if (error instanceof Error) {
      console.error(error.message);
    }
  }
}
