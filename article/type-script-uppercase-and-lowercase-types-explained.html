TypeScript Uppercase and Lowercase Types Explained

TypeScript provides four built-in utility types for modifying string literal types at compile time: Uppercase, Lowercase, Capitalize, and Uncapitalize. Introduced alongside template literal types in TypeScript 4.1, these utilities allow developers to transform the casing of string types directly within the type system. This article explains how each of these intrinsic types functions, how they interact with unions and template literals, and how they enforce stricter type safety in real-world code.

The Four Intrinsic String Manipulation Types

Unlike traditional TypeScript utility types implemented via conditional types or mapped types in standard library files, these four utilities are keyword-level "intrinsic" types. This means their transformation logic is baked directly into the TypeScript compiler for optimal performance and accurate Unicode mapping.

1. Uppercase<StringType>

The Uppercase type converts every character within a string literal type to its uppercase equivalent.

type Direction = "north" | "south" | "east" | "west";
type UppercaseDirection = Uppercase<Direction>;
// Result: "NORTH" | "SOUTH" | "EAST" | "WEST"

type Greeting = Uppercase<"hello world">;
// Result: "HELLO WORLD"

2. Lowercase<StringType>

The Lowercase type converts every character in a string literal type to lowercase. It is commonly used to normalize inputs or handle case-insensitive configuration keys.

type Role = "ADMIN" | "USER" | "GUEST";
type NormalizedRole = Lowercase<Role>;
// Result: "admin" | "user" | "guest"

3. Capitalize<StringType>

The Capitalize type converts only the first character of the provided string literal to uppercase, leaving the rest of the string unchanged.

type Action = "create" | "update" | "delete";
type FormattedAction = Capitalize<Action>;
// Result: "Create" | "Update" | "Delete"

4. Uncapitalize<StringType>

The Uncapitalize type converts the first character of the string literal to lowercase while preserving the casing of all subsequent characters.

type ComponentName = "Button" | "Card" | "Modal";
type PropName = Uncapitalize<ComponentName>;
// Result: "button" | "card" | "modal"

How They Work with Union Types

All four string manipulation types are distributive over union types. When a union of string literals is passed into any of these types, TypeScript automatically maps over each member of the union individually and returns a new union containing the transformed values.

type Status = "pending" | "approved" | "rejected";
type UpperStatus = Uppercase<Status>;
// Result: "PENDING" | "APPROVED" | "REJECTED"

Practical Application: Combining with Template Literal Types

The primary strength of these types lies in generating dynamic property names, event handlers, and API routes when combined with template literal types.

Generating Event Handler Names

A common pattern in UI libraries is prefixing actions with on and converting the event name into PascalCase:

type Events = "click" | "hover" | "focus";

type EventHandlerNames = `on${Capitalize<Events>}`;
// Result: "onClick" | "onHover" | "onFocus"

type EventListeners = {
  [K in Events as `on${Capitalize<K>}`]: (event: any) => void;
};
// Result:
// {
//   onClick: (event: any) => void;
//   onHover: (event: any) => void;
//   onFocus: (event: any) => void;
// }

Generating Getter and Setter Methods

These types can also automatically derive property accessors for state management objects:

interface State {
  name: string;
  age: number;
}

type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
};

type StateGetters = Getters<State>;
// Result:
// {
//   getName: () => string;
//   getAge: () => number;
// }

Behavior with Non-Literal Types

When applied to generic types such as string, the operation cannot evaluate specific characters. In such cases:

  • Uppercase<string> returns string.
  • Capitalize<string> returns string.
  • Uppercase<any> returns any.
  • Uppercase<never> returns never.

These utilities strictly operate on string literal types or template literal types; they do not alter runtime values unless paired with runtime functions that mirror their logic.
