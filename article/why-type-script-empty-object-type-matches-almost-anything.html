Why TypeScript Empty Object Type Matches Almost Anything

In TypeScript, the empty object type {} represents any value that is not null or undefined, allowing primitives such as numbers, strings, and booleans to be assigned to it without compiler errors. This article explains the mechanics behind this behavior, detailing how TypeScript’s structural type system interacts with JavaScript’s primitive wrappers, why null and undefined are excluded, and which alternative types you should use when strictly targeting non-primitive data structures.

Structural Typing and Property Requirements

TypeScript operates on a structural typing system, often described as compile-time duck typing. Under this system, type compatibility is determined entirely by the members a type declares rather than explicit declarations of inheritance or interface implementation. When a variable is assigned to a target type, the compiler verifies whether the assigned value provides all the properties required by that target.

The empty object type literal {} declares zero required properties. Consequently, the compiler's check asks a straightforward question: Does the assigned value satisfy all properties required by {}? Because zero properties are required, any value that can legally have properties inspected at runtime will satisfy the contract.

JavaScript's Object Wrapper Coercion

In JavaScript, primitive types—including string, number, boolean, symbol, and bigint—can access properties and methods. When code accesses a property like .toString() or .toFixed() on a primitive, JavaScript temporarily wraps the primitive in its corresponding object wrapper (such as String, Number, or Boolean).

Because these primitive values expose properties and prototype methods, TypeScript treats them as having properties. Since primitives can be treated structurally as objects with members, they satisfy the empty criteria of {}:

const a: {} = "hello";   // Valid: strings have properties (e.g., .length)
const b: {} = 42;        // Valid: numbers have properties (e.g., .toFixed)
const c: {} = true;      // Valid: booleans have properties (e.g., .valueOf)
const d: {} = () => {};  // Valid: functions are objects
const e: {} = [];        // Valid: arrays are objects

Why Null and Undefined Are Excluded

The only values in JavaScript that cannot be coerced into objects and have no properties are null and undefined. Attempting to access any property on null or undefined results in a runtime TypeError.

When the strictNullChecks compiler flag is enabled, TypeScript actively prevents assigning null and undefined to {}:

const f: {} = null;      // Error: Type 'null' is not assignable to type '{}'
const g: {} = undefined; // Error: Type 'undefined' is not assignable to type '{}'

Because of this rule, {} effectively functions as the "non-nullish" type in TypeScript, equivalent to the utility type NonNullable<unknown>.

Common Alternatives for Stricter Typing

Because {} rarely matches the developer's intuitive expectation of an object, TypeScript provides specialized alternatives depending on the intended use case:

  • object (lowercase): Represents any non-primitive value. It explicitly excludes primitives like strings, numbers, and booleans, while accepting arrays, functions, and standard objects.
  • Record<string, unknown>: Ideal for representing a generic key-value dictionary where keys are strings and values can be of any type.
  • Record<string, never>: Represents a literal empty object that cannot contain any user-defined keys.
