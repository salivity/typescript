How TypeScript Organize Imports Works

The organizeImports feature in the TypeScript language service is an automated code refactoring tool that detects, removes, coalesces, and sorts import declarations within a source file. This article details the internal pipeline used by the TypeScript compiler API—specifically within the language service layer—to transform messy, duplicated, or unused imports into a clean, canonical structure while preserving code semantics.

Triggering the Service and AST Inspection

When a user or editor invokes "Organize Imports," the editor sends a request to the TypeScript Language Service method organizeImports. The language service accesses the corresponding SourceFile node in the Abstract Syntax Tree (AST).

The process begins by scanning top-level statements in the file to identify all import constructs, primarily:

  • Standard ES6 imports (ImportDeclaration)
  • TypeScript import-equals statements (import x = require('x'))
  • Type-only imports (import type { A } from 'b')

Side-effect-only imports (such as import "./styles.css";) are flagged early because they execute global code and their relative ordering can alter application runtime behavior.

Detecting and Removing Unused Imports

Once imports are gathered, the language service uses the TypeScript type checker to identify unused symbols.

  1. Symbol Resolution: The checker resolves the bindings introduced by each import specifier (default imports, namespace imports, and individual named specifiers).
  2. Reference Checking: The service checks whether references exist for those symbols within the rest of the AST.
  3. Pruning: Unreferenced named specifiers are marked for removal. If all specifiers within an import declaration are unused, the entire statement is discarded—unless it is a side-effect import.

Coalescing and Merging Imports

After eliminating unused symbols, the service groups the remaining imports by their module specifier (the string literal representing the path or package). If multiple declarations import from the same path, the service merges them:

  • Combining Named Imports: Distinct named imports from the same module are merged into a single specifier list.
  • Handling Default and Namespace Imports: Default imports and named imports can be merged into a single clause (e.g., import React, { useState } from 'react'). If an import includes a namespace import (* as Foo), it cannot be combined with named imports in standard ES syntax, so it remains separate or merges only with a default import if valid.
  • Type-Only Import Segregation: Imports marked explicitly with the type keyword at the declaration level (import type { X } from 'foo') are either kept distinct or normalized using inline type specifiers, depending on the configured compiler options like verbatimModuleSyntax.

Sorting Logic

After merging, the remaining imports and their internal specifiers are sorted. The TypeScript compiler applies a deterministic, multi-tiered sorting algorithm:

  1. Top-Level Declaration Sorting:
    • Side-effect imports are typically grouped or preserved in their original relative positions to prevent breaking runtime initialization order.
    • Non-relative imports (external modules like node_modules packages) are prioritized over relative imports (e.g., ./utils or ../types).
    • Paths are compared using a deterministic ordinal comparison based on Unicode code points or locale-agnostic comparisons, placing shorter or root-relative paths consistently.
  2. Named Specifier Sorting:
    • Within each import declaration, named specifiers inside { ... } are sorted alphabetically (e.g., { b, a } becomes { a, b }).
    • Type-only specifiers inside a combined import are typically sorted alphabetically alongside values, retaining their type modifier.

Generating Text Changes

The language service does not rewrite the entire file. Instead, it computes the exact span covering the original imports and calculates the replacement string using the project's formatting settings (such as indentation, quote styles, and trailing commas).

It returns an array containing a single TextChange object to the client editor. This change replaces the old block of imports with the coalesced, sorted block, ensuring fast execution and minimal disruption to the file's undo history.
