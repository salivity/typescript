How inlineSources Embeds TypeScript in Sourcemaps

The inlineSources setting in TypeScript is a compiler flag that instructs tsc to bundle the literal, uncompiled TypeScript source code directly into generated source map files instead of referencing external .ts files. By populating the source map's standard sourcesContent field with the original source text as raw strings, TypeScript creates self-contained debugging assets. This article explains how the TypeScript compiler handles this process under the hood, how the resulting source map is structured, and how debuggers utilize this embedded data.

The Role of inlineSources in tsconfig.json

When compiling TypeScript to JavaScript, enabling source maps via "sourceMap": true generates a separate .js.map file. By default, this map file only contains paths pointing to the original .ts files on the disk or web server.

When you add "inlineSources": true to your tsconfig.json:

{
  "compilerOptions": {
    "target": "ES2022",
    "module": "commonjs",
    "sourceMap": true,
    "inlineSources": true
  }
}

The TypeScript compiler changes how it constructs the source map object, capturing the file contents during the emit phase.

How the Embedding Mechanism Works

Source maps follow the Source Map Revision 3 Proposal specification. In this standard, the metadata mapping compiled JavaScript back to TypeScript is represented as a JSON object containing keys such as version, sources, mappings, and optionally sourcesContent.

Here is the step-by-step process of how inlineSources operates:

  1. Source File Reading: During compilation, the TypeScript compiler reads your .ts files into memory to create the Abstract Syntax Tree (AST).
  2. Emitting JavaScript and Mapping: The compiler transforms the AST into target JavaScript and calculates the line and column coordinate deltas, encoded in the base64-VLQ mappings string.
  3. Populating sourcesContent: Normally, the sources array simply lists filenames (e.g., ["src/index.ts"]). With inlineSources enabled, the compiler serializes the original raw string content of each source file and pushes it into a parallel array called sourcesContent.

The Resulting Source Map Structure

A standard .js.map generated with inlineSources looks like this:

{
  "version": 3,
  "file": "index.js",
  "sourceRoot": "",
  "sources": [
    "index.ts"
  ],
  "names": [],
  "mappings": "AAAA,MAAM,CAAC,GAAG,QAAQ...",
  "sourcesContent": [
    "const greeting: string = 'Hello World';\nconsole.log(greeting);\n"
  ]
}

The index in sourcesContent matches the index in sources. In the example above, sourcesContent[0] contains the exact content of sources[0] (index.ts).

How Debuggers Read Embedded Sources

When a browser (like Chrome or Firefox) or a runtime (like Node.js) executes the transpiled JavaScript, it looks for the sourcemap comment at the bottom of the file (e.g., //# sourceMappingURL=index.js.map).

  1. The debugger loads and parses index.js.map.
  2. When a breakpoint is hit or an error stack trace is evaluated, the debugger inspects mappings to find the corresponding TypeScript coordinates.
  3. The debugger checks the sourcesContent array first. Because the raw text is stored there, the debugger reconstructs the original .ts file inside the developer tools interface immediately. It does not need to send an HTTP request to fetch the original .ts file from a server or local disk.

inlineSources vs. inlineSourceMap

It is common to confuse inlineSources with inlineSourceMap:

  • inlineSources: Places the TypeScript source code inside the source map file (populates sourcesContent). The source map itself can still be a separate .map file.
  • inlineSourceMap: Takes the entire source map JSON structure and inlines it directly into the generated .js file as a Base64-encoded Data URI at the bottom of the code.

Combining both options ("inlineSourceMap": true and "inlineSources": true) creates a completely self-contained JavaScript file containing the compiled code, the mapping coordinates, and the original TypeScript source code in one file.
