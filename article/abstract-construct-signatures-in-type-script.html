Abstract Construct Signatures in TypeScript

This article provides an overview of abstract construct signatures in TypeScript, a type-system feature introduced in TypeScript 4.2. You will learn what an abstract construct signature is, how its syntax differs from standard construct signatures, the specific type-checking problem it solves, and the primary scenarios—such as mixin patterns and generic factory constraints—where it is applied.

What Is a Construct Signature?

In TypeScript, a construct signature describes a type that can be invoked using the new operator. For regular, concrete classes, a construct signature typically looks like this:

type Constructor<T> = new (...args: any[]) => T;

When a type uses this signature, TypeScript requires that the target class can be instantiated directly. If you attempt to pass an abstract class to a parameter expecting a standard construct signature, the compiler throws an error (e.g., Cannot assign an abstract constructor type to a non-abstract constructor type).

What Is an Abstract Construct Signature?

An abstract construct signature indicates that a constructor function may produce an instance of a type, but it might not be directly instantiable itself. It uses the abstract modifier before the new keyword:

type AbstractConstructor<T = object> = abstract new (...args: any[]) => T;

This signature acts as a supertype to standard construct signatures. While a standard new (...args: any[]) => T only matches concrete classes, an abstract new (...args: any[]) => T matches both concrete classes and abstract classes.

The Problem It Solves

Before TypeScript 4.2, there was no clean way to express that a function or generic constraint could accept an abstract class constructor without instantiating it immediately.

Consider this scenario:

abstract class Shape {
  abstract getArea(): number;
}

class Circle extends Shape {
  constructor(public radius: number) {
    super();
  }
  getArea(): number {
    return Math.PI * this.radius ** 2;
  }
}

// Standard constructor type
type ConcreteConstructor<T> = new (...args: any[]) => T;

function registerClass<T>(target: ConcreteConstructor<T>) {
  // ...
}

// Error: Type 'typeof Shape' is not assignable to type 'ConcreteConstructor<Shape>'.
// Cannot assign an abstract constructor type to a non-abstract constructor type.
registerClass(Shape);

Because Shape is abstract, it cannot satisfy new (...args: any[]) => T. Applying the abstract keyword to the signature resolves the issue:

type AnyConstructor<T> = abstract new (...args: any[]) => T;

function registerClass<T>(target: AnyConstructor<T>) {
  // Valid for both abstract and concrete classes
}

registerClass(Shape);  // OK
registerClass(Circle); // OK

Where Abstract Construct Signatures Are Used

1. TypeScript Mixin Patterns

The most prominent use case for abstract construct signatures is writing mixins that can extend abstract classes. Without abstract construct signatures, mixins could only extend concrete base classes.

type GConstructor<T = {}> = abstract new (...args: any[]) => T;

function Activatable<TBase extends GConstructor>(Base: TBase) {
  abstract class ActivatableClass extends Base {
    isActive = false;

    activate() {
      this.isActive = true;
    }

    deactivate() {
      this.isActive = false;
    }
  }
  return ActivatableClass;
}

abstract class UIElement {
  abstract render(): void;
}

// UIElement can be passed directly into the mixin
class Button extends Activatable(UIElement) {
  render() {
    console.log("Rendering button");
  }
}

2. Class Decorators and Metadata Registries

Frameworks that register classes for dependency injection, object-relational mapping (ORM), or routing often accept abstract definitions as tokens or schemas:

type ClassToken<T> = abstract new (...args: any[]) => T;

const registry = new Map<ClassToken<any>, any>();

function registerService<T>(token: ClassToken<T>, implementation: new (...args: any[]) => T) {
  registry.set(token, implementation);
}

abstract class DatabaseService {
  abstract query(sql: string): Promise<any>;
}

class PostgresService extends DatabaseService {
  async query(sql: string) {
    return [];
  }
}

// Uses DatabaseService (abstract) as an identifier
registerService(DatabaseService, PostgresService);

3. Generic Constraints for Type Narrowing

When building utility functions that inspect class types—such as checking whether an object is an instance of an abstract class—an abstract construct signature ensures the type argument behaves properly:

function isInstanceOf<T>(
  value: unknown,
  targetClass: abstract new (...args: any[]) => T
): value is T {
  return value instanceof targetClass;
}

const item: unknown = new Circle(10);

if (isInstanceOf(item, Shape)) {
  // item is narrowed to Shape
  console.log(item.getArea());
}
