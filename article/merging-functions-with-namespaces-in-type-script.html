Merging Functions with Namespaces in TypeScript

TypeScript allows a function declaration to merge with a namespace declaration to attach strongly typed static properties to that function. This feature, known as declaration merging, enables developers to define a callable entity that also hosts related properties, configuration values, or utility methods on a single identifier. This article explains how this merging behavior works, how to implement it correctly, and key considerations when using it in modern TypeScript projects.

How Function and Namespace Merging Works

In JavaScript, functions are first-class objects, meaning they can have properties assigned directly to them. While traditional JavaScript allows ad-hoc property assignments like myFunction.property = "value", TypeScript’s strict type system normally flags these assignments as errors because the property does not exist on the standard Function interface.

To solve this without resorting to type assertions or any, TypeScript uses declaration merging. When a function and a namespace share the exact same identifier in the same scope, the compiler merges their definitions. The function provides the callable implementation, while the exported members of the namespace become typed properties on that function.

Basic Implementation

To merge a function with a namespace, the function declaration must precede the namespace declaration. All properties intended to serve as static members on the function must be explicitly marked with the export keyword inside the namespace.

// 1. Declare the callable function
function formatName(name: string): string {
    return `${formatName.prefix} ${name}`;
}

// 2. Declare the namespace with matching name to add static properties
namespace formatName {
    export let prefix: string = "User:";
    
    export function resetPrefix(): void {
        prefix = "User:";
    }
}

// Usage
console.log(formatName("Alice")); // Output: "User: Alice"

formatName.prefix = "Admin:";
console.log(formatName("Bob"));   // Output: "Admin: Bob"

formatName.resetPrefix();
console.log(formatName("Charlie")); // Output: "User: Charlie"

Key Rules for Merging Functions and Namespaces

For the TypeScript compiler to merge declarations successfully, certain conditions must be met:

  1. Declaration Order: The function declaration must come before the namespace declaration in the source code.
  2. Matching Identifiers: Both declarations must share the exact same name within the same lexical scope.
  3. Export Requirement: Only values, types, or functions explicitly marked with export inside the namespace become accessible as properties on the merged function.
  4. Standard Declarations Only: This pattern applies to standard function declarations. It does not work directly with arrow functions or function expressions assigned to variables (const myFunc = () => {}).

When to Use This Pattern

Merging a function with a namespace is particularly useful in several scenarios:

  • Factory Functions with Configuration Defaults: You can expose default configuration objects or state on the factory function itself.
  • Component-Based Architectures: Libraries like React often use callable components that also host sub-components (such as Card and Card.Header).
  • Typing Legacy JavaScript Libraries: When writing TypeScript definition files (.d.ts) for existing JavaScript libraries that assign utilities or constants directly to a main function, declaration merging provides an idiomatic and clean type definition.

Modern Considerations

While function-namespace merging is fully supported by the TypeScript compiler, modern ECMAScript development relies heavily on ES modules. Namespaces were originally designed before ES modules were standardized, and some modern build tools (such as certain Babel configurations or SWC presets) require specific plugins to compile TypeScript namespaces properly.

If your toolchain discourages namespaces, you can achieve a similar result using Object.assign:

function formatName(name: string): string {
    return `${formatName.prefix} ${name}`;
}

const formatNameWithProps = Object.assign(formatName, {
    prefix: "User:"
});

However, native function-namespace merging remains the most direct way to get full compiler verification, unified documentation, and IDE autocompletion for static properties on functions in pure TypeScript environments.
