Integrate vue-tsc in CI/CD for Vite Projects

This article explains how to enforce strict type safety in Vite-based TypeScript and Vue applications by adding vue-tsc or tsc to automated CI/CD pipelines. Because Vite intentionally bypasses type checking during builds to maximize bundling speed, integrating a dedicated type-checking step into continuous integration prevents broken, type-invalid code from reaching staging or production environments.

Why Vite Requires External Type Checking

Vite uses esbuild to transpile TypeScript files into JavaScript. While esbuild is extremely fast, it only strips TypeScript types without performing AST-level type validation. Similarly, Vite's production build command (vite build) relies on Rollup and does not validate types on its own.

To catch type errors before deployment, developers must run the TypeScript compiler explicitly with the --noEmit flag:

  • Use tsc --noEmit for standard TypeScript projects (React, Vanilla, Svelte).
  • Use vue-tsc --noEmit for Vue 3 Single File Component (SFC) projects, as standard tsc cannot parse .vue templates and script blocks.

Step 1: Configure package.json

Add a dedicated type-checking script to your project's package.json.

For a Vue project:

{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "type-check": "vue-tsc --noEmit"
  }
}

For a standard TypeScript project without Vue SFCs:

{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "type-check": "tsc --noEmit"
  }
}

Step 2: Verify tsconfig.json

Ensure your TypeScript configuration covers the required files and is optimized for type verification.

{
  "compilerOptions": {
    "target": "ESNext",
    "module": "ESNext",
    "moduleResolution": "Bundler",
    "strict": true,
    "noEmit": true,
    "skipLibCheck": true
  },
  "include": ["src/**/*.ts", "src/**/*.d.ts", "src/**/*.tsx", "src/**/*.vue"]
}

Setting "skipLibCheck": true speeds up CI execution by preventing the compiler from checking all third-party .d.ts files inside node_modules.

Step 3: Implement in GitHub Actions

In your CI configuration, run the type check command before the build step or concurrently alongside testing and linting jobs.

Below is an example workflow for GitHub Actions (.github/workflows/ci.yml):

name: CI Pipeline

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  type-check:
    name: Run Type Checking
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Code
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'npm'

      - name: Install Dependencies
        run: npm ci

      - name: Validate Types
        run: npm run type-check

  build:
    name: Build Application
    needs: type-check
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Code
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'npm'

      - name: Install Dependencies
        run: npm ci

      - name: Build Assets
        run: npm run build

Step 4: Implement in GitLab CI/CD

If using GitLab CI, add the check to your .gitlab-ci.yml:

stages:
  - test
  - build

type_check:
  stage: test
  image: node:20
  before_script:
    - npm ci
  script:
    - npm run type-check

build_project:
  stage: build
  image: node:20
  needs: ["type_check"]
  before_script:
    - npm ci
  script:
    - npm run build

Optimizing Performance in CI

  1. Parallel Execution: Run npm run type-check, linting (eslint), and unit testing (vitest) as separate parallel jobs within the same pipeline stage to minimize pipeline duration.
  2. Incremental Builds: For large codebases, configure "incremental": true in tsconfig.json and cache the .tsbuildinfo file between CI runs to reduce type-checking times.
