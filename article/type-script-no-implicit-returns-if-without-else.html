TypeScript noImplicitReturns: If Without Else

When TypeScript's noImplicitReturns compiler option is enabled, any function containing an if statement that returns a value without an accompanying else branch or a trailing return statement will trigger a compiler error. This article explains how the flag operates, why TypeScript flags an omitted else branch, and how to resolve the resulting compile-time error.

The Behavior of noImplicitReturns

The noImplicitReturns setting is configured in your tsconfig.json file. Its purpose is to ensure that all code paths within a function explicitly return a value if any code path returns one.

In JavaScript, if a function execution reaches the end of its body without hitting a return keyword, the engine implicitly returns undefined. Under standard TypeScript rules, this is often permitted even if you specify a return type. However, enabling noImplicitReturns disallows this behavior to prevent accidental runtime errors caused by missing return paths.

The Error: TS7030

Consider the following function where a value is returned only inside an if block:

function getDiscount(isMember: boolean): number {
  if (isMember) {
    return 0.2;
  }
  // No else block and no fallback return
}

When noImplicitReturns is set to true, the TypeScript compiler flags this code with:

error TS7030: Not all code paths return a value.

Because isMember could evaluate to false, execution can bypass the if block and reach the end of the function body. The compiler detects that the false path implicitly returns undefined, which violates the declared number return type.

How to Resolve the Issue

There are several standard patterns to fix this error depending on your application's intent:

1. Provide a Fallback Return

The most common approach is to provide a default return value outside the if statement:

function getDiscount(isMember: boolean): number {
  if (isMember) {
    return 0.2;
  }
  return 0;
}

2. Use an Explicit Else Block

You can add an else block that ensures every branch explicitly concludes with a return statement:

function getDiscount(isMember: boolean): number {
  if (isMember) {
    return 0.2;
  } else {
    return 0;
  }
}

3. Throw an Error

If reaching the end of the condition represents an invalid or unreachable state, throw an error. TypeScript's control flow analysis recognizes throw as an exit point:

function getDiscount(isMember: boolean): number {
  if (isMember) {
    return 0.2;
  }
  throw new Error("Invalid membership status");
}

4. Explicitly Return Undefined

If returning nothing is valid business logic, update the return type to include undefined and explicitly return it:

function getDiscount(isMember: boolean): number | undefined {
  if (isMember) {
    return 0.2;
  }
  return undefined;
}

By enforcing explicit returns on all paths, noImplicitReturns eliminates unintentional undefined leaks and makes function outputs predictable.
