TypeScript sourceRoot Guide: Debugger Paths

The sourceRoot option in TypeScript specifies the base path or URL where a debugger should search for original .ts source files instead of relying on default relative paths. When compiling TypeScript with source maps enabled, this setting alters the metadata inside generated .js.map files, allowing debuggers in browsers, IDEs, and runtimes like Node.js to accurately reconstruct directory structures and map executed JavaScript lines back to their corresponding TypeScript source lines across different runtime environments.

How sourceRoot Modifies Source Maps

When TypeScript compiles code with "sourceMap": true, it produces a JSON source map file containing:

  • sources: An array of relative paths to the original source files (for example, ["main.ts", "utils/math.ts"]).
  • sourceRoot: A string prepended to every path in the sources array.

By default, sourceRoot is empty, causing debuggers to resolve file locations relative to the directory containing the .js.map file. When you set sourceRoot in tsconfig.json, the compiler writes that value directly into the "sourceRoot" field of the output map:

{
  "compilerOptions": {
    "target": "ES6",
    "module": "commonjs",
    "sourceMap": true,
    "outDir": "./dist",
    "sourceRoot": "http://localhost:8080/sources/"
  }
}

The resulting .js.map output will include:

{
  "version": 3,
  "file": "main.js",
  "sourceRoot": "http://localhost:8080/sources/",
  "sources": ["main.ts"],
  "mappings": "..."
}

How Debuggers Resolve Paths

When a debugger (such as Chrome DevTools, Edge DevTools, or VS Code) evaluates a source map, it performs path concatenation:

resolved_source_path = sourceRoot + sources[i]

If sourceRoot is set to http://localhost:8080/sources/ and sources[0] is main.ts, the debugger requests http://localhost:8080/sources/main.ts.

If sourceRoot is an absolute filesystem path like /app/src/, the debugger looks for files at /app/src/main.ts.

If sourceRoot is a relative path like ../src/, the debugger resolves the path relative to the hosting URL or filesystem location of the .js.map file itself.

Common Scenarios for Using sourceRoot

1. Hosting Source Files on a Dedicated URL or CDN

In production or staging web applications, source maps may be deployed with your compiled JavaScript, but the original source code may be hosted on a separate internal server or behind an authenticated CDN. Setting sourceRoot to an absolute URL directs browser developer tools to fetch original sources from that remote server.

2. Remote and Containerized Debugging

When executing TypeScript in a Docker container or a remote virtual machine, the file paths inside the running container (such as /var/app/src) often differ from the local paths on your development machine (such as C:\projects\app\src or /Users/dev/app/src). Setting sourceRoot ensures that the runtime debugger points to the correct internal container path, which can then be matched with host path mappings in your IDE's launch configuration.

3. Decoupling Output Layouts from Source Layouts

Complex build pipelines that move .js and .js.map files to heavily nested or flattened distribution directories can cause standard relative path calculations to fail. Setting sourceRoot explicitly establishes an unambiguous base path that survives file rearrangement.

sourceRoot vs. mapRoot

It is important not to confuse sourceRoot with mapRoot:

  • sourceRoot: Defines where the debugger looks for original .ts source files.
  • mapRoot: Defines where the debugger looks for .js.map source map files when the //# sourceMappingURL= comment is parsed in compiled JavaScript.
