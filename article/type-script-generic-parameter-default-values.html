TypeScript Generic Parameter Default Values

TypeScript allows you to assign default types to generic parameters, making those type arguments optional when invoking functions, creating instances, or defining types. This article covers the exact syntax for setting generic defaults, combining defaults with type constraints, and applying them across functions, interfaces, and type aliases.

The Basic Syntax

The syntax for assigning a default value to a generic type parameter uses the equals sign (=), placed immediately after the type parameter name:

<T = DefaultType>

When a generic parameter has a default, consumers of the type or function do not need to explicitly provide a type argument.

Examples in Practice

1. Type Aliases and Interfaces

You can define defaults on interfaces and type aliases so consumers can omit the generic parameter:

// Interface with a default generic type
interface ApiResponse<T = Record<string, unknown>> {
  status: number;
  data: T;
}

// Uses the default: Record<string, unknown>
const genericResponse: ApiResponse = {
  status: 200,
  data: { message: "Success" }
};

// Overrides the default with a custom type
interface User {
  id: string;
  name: string;
}

const userResponse: ApiResponse<User> = {
  status: 200,
  data: { id: "123", name: "Alice" }
};

2. Functions

Generic defaults can be applied to functions, which is useful when type inference cannot deduce the generic parameter automatically:

function createList<T = string>(): T[] {
  return [];
}

const defaultList = createList();        // Type is string[]
const numberList = createList<number>(); // Type is number[]

3. Classes

Classes follow the exact same syntax:

class StateStore<T = null> {
  private state: T;

  constructor(initialState: T) {
    this.state = initialState;
  }

  getState(): T {
    return this.state;
  }
}

const defaultStore = new StateStore(null); // StateStore<null>

Combining Defaults with Constraints

You can constrain a generic parameter using the extends keyword and still provide a fallback default. The constraint must appear before the default value assignment:

<T extends BaseType = DefaultType>

The specified default type must satisfy the constraint:

interface HasId {
  id: number;
}

// T must have an 'id' property, defaulting to an object with only an id
type EntityStore<T extends HasId = { id: number }> = {
  entities: T[];
};

const store: EntityStore = {
  entities: [{ id: 1 }, { id: 2 }]
};

Rules for Multiple Type Parameters

Much like optional function arguments in JavaScript, generic parameters with default values must appear after required generic parameters without defaults:

// Correct: Required parameter first, optional parameter second
type KeyValuePair<K, V = string> = {
  key: K;
  value: V;
};

// Incorrect: Causes a TypeScript compiler error
// type KeyValuePair<V = string, K> = { ... }
