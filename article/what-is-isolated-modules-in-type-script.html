What Is isolatedModules in TypeScript?

The isolatedModules setting is a TypeScript compiler option that ensures source code can be safely transpiled by single-file build tools such as Babel, esbuild, SWC, or Vite. When enabled, TypeScript flags language features and patterns that rely on full-program type analysis to generate valid JavaScript, preventing unexpected runtime errors or broken builds when using modern, multi-threaded transpilation pipelines.

Why isolatedModules Exists

By default, the TypeScript compiler (tsc) analyzes your entire project simultaneously. This global knowledge allows it to distinguish between runtime values and type definitions, enabling features like resolving imports and inlining constants across different files.

However, many modern bundlers and build tools do not use tsc for emitting JavaScript. Instead, they use specialized single-file transpilers to achieve significantly faster build times. Because these tools process each file independently in isolation, they cannot look up information in other files. Without isolatedModules, code that compiles successfully with tsc might produce broken code when processed by an isolated transpiler.

Setting "isolatedModules": true in your tsconfig.json instructs tsc to enforce rules that guarantee every file can be transpiled on its own without needing type information from dependencies.

Common Issues Flagged by isolatedModules

When isolatedModules is enabled, TypeScript produces compile-time errors for several specific patterns:

1. Ambiguous Type Re-exports

When re-exporting a type, a single-file transpiler cannot know whether the identifier represents a type or a JavaScript value. If it leaves the export in the JavaScript output, a runtime ReferenceError occurs because the imported entity does not exist at runtime.

  • Invalid:

    export { SomeType } from "./types";

  • Valid:

    export type { SomeType } from "./types";

    Using explicit export type syntax guarantees that single-file transpilers know to strip the statement entirely from the output.

2. Ambient const enum Declarations

Standard const enum members are completely inlined into the resulting JavaScript at compile time. A single-file transpiler cannot read the enum definition from another file to inline the value.

With isolatedModules enabled, declaring or using const enum without third-party plugins will trigger an error, prompting you to use standard enum or plain objects instead.

3. Files Without Imports or Exports

In TypeScript, a file without top-level import or export statements is treated as a global script, not a module. In module-based build setups, treating files as scripts can lead to scope pollution.

isolatedModules requires every file to be a module. If a file does not import or export anything, you must add an empty export:

export {};

When to Enable isolatedModules

You should enable isolatedModules whenever your build pipeline relies on any tool other than tsc to transpile TypeScript to JavaScript. This includes projects built with Vite, Next.js, Webpack using ts-loader in transpileOnly mode, esbuild, or Babel. Enabling the flag ensures your code remains fully compatible with fast, isolated compilation pipelines while preserving TypeScript's type-checking guarantees.
