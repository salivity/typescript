TypeScript Nullish Coalescing and Type Narrowing

The nullish coalescing operator (??) in TypeScript provides targeted type narrowing by eliminating only null and undefined from a type union while preserving other falsy values such as 0, "", and false. This article explores how TypeScript’s control flow analysis handles expressions using ??, compares its narrowing behavior against the logical OR operator (||), and demonstrates how to leverage it for precise fallback assignments and type safety.

How the Nullish Coalescing Operator Works

In JavaScript and TypeScript, the expression a ?? b evaluates to b if and only if a is strictly null or undefined. If a holds any other value—including falsy values like false, 0, NaN, or an empty string ""—the expression evaluates to a.

TypeScript mirrors this runtime behavior directly within its static type system via control flow analysis.

Type Inference with ??

When you apply the nullish coalescing operator to an expression, TypeScript computes the resulting type by taking the left-hand operand's type, removing null and undefined, and creating a union with the right-hand operand's type:

type Result = NonNullable<TypeOfLeft> | TypeOfRight;

Example: Basic Narrowing

Consider a variable with a nullable type:

function getPort(customPort: number | null | undefined): number {
  const port = customPort ?? 3000;
  return port;
}

In this case:

  1. customPort has the type number | null | undefined.
  2. TypeScript narrows the left side by stripping null and undefined, leaving number.
  3. The fallback 3000 is a number.
  4. The inferred type of port becomes number | number, which simplifies directly to number.

?? vs. ||: The Difference in Type Narrowing

The logical OR operator (||) falls back on any falsy value, whereas ?? only falls back on nullish values. This fundamental difference drastically alters how TypeScript narrows types.

function configureTimeout(timeout: number | undefined) {
  // Using logical OR:
  // If timeout is 0, it falls back to 5000 at runtime.
  const orTimeout = timeout || 5000; 

  // Using nullish coalescing:
  // If timeout is 0, 0 is retained.
  const nullishTimeout = timeout ?? 5000; 
}

When literal types or unions containing falsy values are involved, the type distinctions become critical:

type Status = "active" | "" | null;

function handleStatus(input: Status) {
  // Logical OR removes "" along with null
  // The resulting type is "active" | "default"
  const orResult = input || "default";

  // Nullish coalescing preserves ""
  // The resulting type is "active" | "" | "default"
  const nullishResult = input ?? "default";
}

TypeScript recognizes that "" is not nullish, so it preserves the empty string in the final union type for nullishResult.

Chained Operations and Optional Chaining

Nullish coalescing is frequently paired with optional chaining (?.). TypeScript tracks narrowing through the entire chain:

interface UserProfile {
  settings?: {
    theme?: string | null;
  };
}

function getTheme(profile: UserProfile): string {
  // profile.settings?.theme has type: string | null | undefined
  // theme will be narrowed to: string
  const theme = profile.settings?.theme ?? "light";
  return theme;
}

At each ?. step, TypeScript accounts for potential undefined values. The terminal ?? resolves all accumulated null and undefined possibilities in one operation.

Assertions and Unreachable Fallbacks

If the left operand cannot be nullish, TypeScript detects this during type checking. In strict mode (strictNullChecks: true), providing a fallback for a non-nullable type will either result in an unused branch or a compiler warning if the code is unreachable:

function printName(name: string) {
  // TypeScript knows 'name' is already 'string'.
  // 'fallback' is unreachable at runtime.
  const resolvedName = name ?? "Anonymous"; 
  // resolvedName is inferred strictly as string.
}

If you enable the ESLint rule @typescript-eslint/no-unnecessary-condition or similar compiler linting flags, TypeScript-aware linters will flag name ?? "Anonymous" as redundant.

Summary of Narrowing Rules

  • Left-hand side contains null or undefined: TypeScript extracts NonNullable<T> from the left-hand type and unions it with the right-hand type.
  • Falsy values (0, "", false): These are retained by the left-hand type and do not trigger the right-hand fallback type.
  • Non-nullable left-hand side: The right-hand expression is treated as redundant, and the resulting type matches the left-hand operand.
