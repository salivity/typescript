How DefinitelyTyped and @types Work in TypeScript

TypeScript requires type definitions to validate code and offer features like autocomplete, but many popular JavaScript libraries are published without native types. DefinitelyTyped and the @types scope on npm solve this issue by providing a community-driven repository of external type declarations. This article explains the relationship between DefinitelyTyped, the automated publishing process of @types packages, how the TypeScript compiler automatically locates these declarations, and why this system is essential for maintaining type safety across the JavaScript ecosystem.

The Challenge of Untyped JavaScript

When TypeScript projects import external JavaScript libraries, the TypeScript compiler cannot inherently verify function signatures, return types, or object shapes. Without type information, these imported packages are treated as having the any type, which disables type checking and eliminates tooling benefits like IntelliSense. While library authors can bundle declaration files (.d.ts) directly within their packages, many maintainers choose not to, or the libraries were written before TypeScript became standard.

What is DefinitelyTyped?

DefinitelyTyped is a massive, open-source GitHub repository where developers collaborate to write and maintain declaration files for thousands of third-party JavaScript libraries. Instead of requiring each individual library author to adopt TypeScript, the community supplies high-quality .d.ts files to DefinitelyTyped. These declaration files define the shapes, interfaces, functions, and classes of existing libraries without altering their original runtime code.

The @types Publishing Pipeline

To make definitions from DefinitelyTyped easy to consume, Microsoft maintains an automated build and publishing tool called Type-Publisher. This automation monitors the DefinitelyTyped repository for updates and runs the following workflow:

  1. Validation: It runs type checks and tests against the submitted declaration files to ensure accuracy and prevent regressions.
  2. Packaging: It packages the declaration files into standard npm module structures.
  3. Publishing: It automatically publishes each set of declarations to npm under the @types scoped organization. For example, the types for the lodash library are published as @types/lodash.

Because these packages only contain declaration files, they are typically installed as development dependencies (npm install --save-dev @types/package-name) and have zero impact on the final production bundle size.

How the TypeScript Compiler Resolves @types

The TypeScript compiler (tsc) is designed to automatically detect and integrate packages installed in the @types directory without requiring manual imports of the declaration files. By default, the compiler performs the following lookup:

  • Automatic Scanning: During module resolution, the compiler searches node_modules/@types in the current folder and every parent directory.
  • Matching: When an import statement such as import _ from 'lodash' is encountered, TypeScript first checks if the lodash package provides its own types via the types or typings field in its package.json. If native types are absent, the compiler looks for node_modules/@types/lodash/index.d.ts.
  • Configuration: Developers can control this resolution process using the typeRoots and types compiler options in tsconfig.json. The typeRoots property specifies which directories to scan for type definitions, while the types array explicitly lists which scoped packages should be globally included.

This architecture ensures that developers get full static analysis, refactoring support, and accurate error detection when working with untyped JavaScript libraries in a TypeScript environment.
