TypeScript ReturnType Utility Type Explained

This article explores the ReturnType utility type in TypeScript, detailing how it extracts return types from function signatures, how to apply it using the typeof operator, and how it handles asynchronous functions and overloads. By reading further, you will understand how to leverage this utility to keep your codebase DRY and automatically infer types directly from your application's logic.

What Does ReturnType Resolve?

The ReturnType<T> utility type extracts and resolves the output type returned by a function type T. Under the hood, TypeScript uses conditional types and the infer keyword to inspect the function signature and isolate the type of the value returned at runtime.

If T represents a function signature matching (...args: any[]) => R, then ReturnType<T> resolves directly to R.

Basic Usage with Function Types

ReturnType operates strictly on TypeScript types, not JavaScript runtime values. To extract the return type of a concrete function, you must pair ReturnType with the typeof type query operator.

function createUser() {
  return {
    id: 1,
    name: "Jane Doe",
    isActive: true,
  };
}

// Resolves to: { id: number; name: string; isActive: boolean; }
type User = ReturnType<typeof createUser>;

You can also pass standalone function signatures directly without typeof:

type Greeter = (name: string) => string;

// Resolves to: string
type Greeting = ReturnType<Greeter>;

Resolving Asynchronous Functions

When dealing with async functions, TypeScript wraps the return value in a Promise. Consequently, ReturnType resolves to the Promise<T> wrapper rather than the resolved underlying value.

async function fetchScore() {
  return 100;
}

// Resolves to: Promise<number>
type ScorePromise = ReturnType<typeof fetchScore>;

To extract the unwrapped value inside the promise, combine ReturnType with the Awaited utility type:

// Resolves to: number
type Score = Awaited<ReturnType<typeof fetchScore>>;

Behavior with Function Overloads

When applied to overloaded functions, ReturnType resolves to the return type of the last overload signature. This is because TypeScript evaluates overload signatures sequentially, and the final implementation or signature takes precedence during inference.

function processInput(input: number): string;
function processInput(input: string): boolean;
function processInput(input: any): any {
  return input;
}

// Resolves to: boolean (the last declared overload signature)
type ProcessedResult = ReturnType<typeof processInput>;

Key Use Cases

  1. Third-Party Libraries: Infer complex return types from library methods when the library does not explicitly export the interface or type.
  2. Factory Functions: Define types dynamically based on factory outputs to ensure that modifications to the implementation automatically propagate throughout the codebase without manual updates.
  3. Redux / State Management: Automatically derive action payloads and state shapes from action creators and reducer functions.
