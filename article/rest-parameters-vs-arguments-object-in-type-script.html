Rest Parameters vs Arguments Object in TypeScript

Both rest parameters and the arguments object handle functions with a variable number of parameters, but rest parameters represent the modern, type-safe approach in TypeScript. While the legacy arguments object is an untyped, array-like structure inherited from JavaScript, rest parameters produce standard JavaScript arrays that seamlessly integrate with TypeScript's type system. This article breaks down the technical differences between the two, covering type safety, array functionality, arrow function support, and syntax.

1. Type Safety and TypeScript Integration

Rest parameters integrate natively with TypeScript's static typing. You can strictly type the captured arguments as an array or a tuple, allowing the compiler to catch type mismatches at compile time:

function calculateSum(...numbers: number[]): number {
    return numbers.reduce((total, n) => total + n, 0);
}

calculateSum(1, 2, 3); // Valid
calculateSum(1, "two", 3); // Compiler Error

In contrast, the arguments object is typed internally as IArguments. It lacks specific type information for individual members, often treating values as any, which bypasses type checking:

function calculateSumOld(): number {
    // arguments is of type IArguments, losing element-level type safety
    let total = 0;
    for (let i = 0; i < arguments.length; i++) {
        total += arguments[i];
    }
    return total;
}

2. Real Array vs. Array-Like Object

Rest parameters produce a true JavaScript Array instance. This means standard array methods like .map(), .filter(), .reduce(), and .forEach() can be used directly:

function processTags(...tags: string[]) {
    return tags.map(tag => tag.toLowerCase());
}

The arguments object is only "array-like." It has a length property and indexed access, but it does not inherit from Array.prototype. To use array methods on arguments, you must first convert it:

function processTagsOld() {
    // Requires conversion to a real array
    const argsArray = Array.from(arguments);
    return argsArray.map(tag => tag.toLowerCase());
}

3. Arrow Function Support

Rest parameters function identically across all function types, including standard function declarations, function expressions, and arrow functions:

const logItems = (...items: string[]) => {
    console.log(items.join(", "));
};

The arguments object is not bound in arrow functions. Referencing arguments inside an arrow function either results in a TypeScript compiler error or resolves to the enclosing non-arrow function's arguments scope.

4. Selective Capture

Rest parameters allow you to distinguish explicitly named parameters from additional trailing arguments. The rest parameter must always be the last parameter in the signature:

function sendEmail(to: string, subject: string, ...attachments: string[]) {
    // 'to' and 'subject' are isolated; 'attachments' holds the rest
}

The arguments object always contains every single argument passed to the function, regardless of how many named parameters exist. This makes it difficult to separate leading parameters from remaining options without manual index slicing.

Conclusion

In TypeScript, rest parameters are strictly preferred over the arguments object. Rest parameters provide compile-time type validation, direct access to array methods, complete compatibility with arrow functions, and cleaner syntax. The arguments object should only be encountered when maintaining legacy codebases.
