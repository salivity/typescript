How as const Changes Type Inference in TypeScript

In TypeScript, the as const assertion—introduced as const assertions—instructs the compiler to infer the narrowest and most specific type possible for an expression. By default, TypeScript widens types to allow for future mutations, turning string literals into string or arrays into mutable lists. Applying as const fundamentally alters this behavior by preventing type widening, setting all properties of objects and arrays to readonly, and transforming standard array literals into fixed-length, immutable tuples.

Preventing Type Widening

When you define a variable or an object property without an explicit type, TypeScript widens the inferred type to a broader primitive type. This allows the value to be reassigned later.

// Inferred as { role: string }
const user = {
  role: "admin",
};

user.role = "editor"; // Allowed

Applying as const prevents this widening. TypeScript retains the literal value as the exact type:

// Inferred as { readonly role: "admin" }
const user = {
  role: "admin",
} as const;

// Error: Cannot assign to 'role' because it is a read-only property.
user.role = "editor";

Turning Arrays into Readonly Tuples

Normally, array literals are inferred as mutable arrays of a union type, regardless of how many elements they contain.

// Inferred as (string | number)[]
const coordinates = ["north", 42];

coordinates.push("south"); // Allowed

With as const, TypeScript locks the length, order, and exact values of the array, converting it into a readonly tuple:

// Inferred as readonly ["north", 42]
const coordinates = ["north", 42] as const;

// Error: Property 'push' does not exist on type 'readonly ["north", 42]'.
coordinates.push("south");

Deep Readonly Enforcement

The as const expression applies recursively to nested data structures. Every nested property, array, and literal within the expression becomes deeply immutable at the type level.

const config = {
  endpoint: "https://api.example.com",
  retry: {
    attempts: 3,
    codes: [500, 502],
  },
} as const;

/*
Inferred type:
{
  readonly endpoint: "https://api.example.com";
  readonly retry: {
    readonly attempts: 3;
    readonly codes: readonly [500, 502];
  };
}
*/

Extracting Types from Const Assertions

A primary benefit of as const is the ability to extract type definitions directly from runtime values, eliminating the need to maintain redundant types and arrays manually.

const HTTP_METHODS = ["GET", "POST", "PUT", "DELETE"] as const;

// Type: "GET" | "POST" | "PUT" | "DELETE"
type HttpMethod = typeof HTTP_METHODS[number];

function request(url: string, method: HttpMethod) {
  // ...
}

request("/users", "GET");  // Valid
request("/users", "PATCH"); // Error: Argument of type '"PATCH"' is not assignable to parameter of type 'HttpMethod'.

By switching TypeScript's type inference from mutable broad types to immutable literal types, as const enables stricter type-checking, prevents unintended mutations, and serves as a single source of truth for runtime constants and compile-time types.
