Understanding TypeScript InstanceType for Constructors

This article explains TypeScript's built-in InstanceType<Type> utility type, focusing on how it interacts with constructor functions and classes. You will learn what InstanceType returns, how TypeScript distinguishes between static constructor types and instance types, and how to apply this utility type in practical development scenarios such as factory functions.

What InstanceType Returns

When applied to a constructor function or class, the InstanceType<Type> utility type returns the type of the object that the constructor creates when invoked with the new operator. In short, it extracts the return type of a constructor.

Under the hood, TypeScript defines InstanceType using conditional types and type inference:

type InstanceType<T extends abstract new (...args: any) => any> = 
  T extends abstract new (...args: any) => infer R ? R : any;

This definition checks whether T is a constructible function type. If it is, TypeScript infers the returned instance type R and yields it.

Class Constructors vs. Instance Types

To understand why InstanceType is necessary, it helps to understand how TypeScript handles class identifiers. In TypeScript, a class declaration introduces two distinct types:

  1. The Instance Type: Represented simply by the class identifier (e.g., User). This describes what an instantiated object looks like.
  2. The Constructor (Static) Type: Represented by querying the identifier with typeof (e.g., typeof User). This describes the class constructor function itself, including any static properties or methods.

Because InstanceType<T> expects a constructor signature for T, you must pass the constructor type (typeof Class) rather than the instance type directly.

class Car {
  make: string;
  model: string;

  constructor(make: string, model: string) {
    this.make = make;
    this.model = model;
  }

  drive() {
    console.log(`Driving a ${this.make} ${this.model}`);
  }
}

// Resulting type is Car (the instance shape)
type CarInstance = InstanceType<typeof Car>;

const myCar: CarInstance = {
  make: "Toyota",
  model: "Corolla",
  drive() {
    console.log("Custom drive implementation");
  },
};

If you pass Car directly instead of typeof Car (i.e., InstanceType<Car>), TypeScript raises a type error stating that type Car does not satisfy the constraint abstract new (...args: any) => any.

Practical Application: Factory Functions

The most common use case for InstanceType is inside generic factory functions, dependency injection containers, or registries where a constructor is passed as an argument.

class DatabaseConnection {
  connect() {
    return "Connected to database";
  }
}

function createInstance<T extends new (...args: any[]) => any>(
  Constructor: T,
  ...args: ConstructorParameters<T>
): InstanceType<T> {
  return new Constructor(...args);
}

// The returned variable is automatically typed as DatabaseConnection
const db = createInstance(DatabaseConnection);
console.log(db.connect());

In this pattern, TypeScript automatically infers T as typeof DatabaseConnection. Using InstanceType<T> as the return type ensures that the caller receives a strongly typed instance matching the constructor provided.
