TypeScript Structural Subtyping and Fewer Properties

TypeScript uses a structural type system to determine type compatibility based entirely on an object's shape rather than its explicit declaration. This article explains how TypeScript evaluates whether an object satisfies an interface with fewer properties, detailing the mechanics of width subtyping, how member-by-member verification works, and the distinct role of excess property checks during object literal assignment.

The Core Principle: Width Subtyping

In TypeScript, interfaces define a minimum contract rather than an exhaustive boundary. When an interface has fewer properties than an object being compared against it, the compiler applies a rule known in type theory as width subtyping.

Under width subtyping, a type B is considered a subtype of type A if B contains all the properties defined in A, along with matching or narrower types for those properties. Any additional properties present in B are simply ignored during the compatibility evaluation. The system asks: "Does this object have at least the required properties with compatible types?" If the answer is yes, the type check passes.

Step-by-Step Evaluation Process

When the TypeScript compiler verifies whether an object variable satisfies a target interface, it executes the following steps:

  1. Target Interface Inspection: The compiler reads the target interface and builds a list of its required and optional property keys along with their associated types.
  2. Member-by-Member Verification: For each property defined in the target interface, the compiler checks the source object to confirm that the key exists.
  3. Type Compatibility Check: For each matching key, the compiler verifies that the value's type on the source object can be assigned to the type defined in the target interface (handling covariance).
  4. Acceptance: If all keys required by the interface exist on the source object and their types are compatible, the check succeeds. The compiler does not fail the operation simply because the source object has extra, unspecified properties.

Consider this example using existing references:

interface Point2D {
  x: number;
  y: number;
}

const point3D = {
  x: 10,
  y: 20,
  z: 30, // Extra property
};

// Valid: point3D possesses both 'x' and 'y' as numbers
const target: Point2D = point3D;

Because point3D contains x and y, it fulfills the contract of Point2D. The presence of z does not prevent target from safely executing any operation defined for a Point2D.

The Exception: Excess Property Checking

While structural subtyping allows objects to have extra properties, TypeScript introduces a deliberate safety mechanism known as Excess Property Checking for fresh object literals.

If you pass an object literal directly to a variable declaration or a function parameter with a defined type, TypeScript assumes that any property not explicitly declared in the interface is likely a typo or an error:

// Error: Object literal may only specify known properties, and 'z' does not exist in type 'Point2D'
const directPoint: Point2D = {
  x: 10,
  y: 20,
  z: 30,
};

This check does not mean structural subtyping has stopped working. Instead, it is a design-time heuristic applied specifically to "fresh" object literals. Because the literal is created on the spot and not referenced elsewhere, defining properties that the target type cannot access represents dead code or a misspelling.

Summary of Rules

  • Intermediary References: When an object is assigned to an intermediate variable first, TypeScript applies pure structural subtyping. If the object has all required properties, it satisfies an interface with fewer properties.
  • Direct Literals: When assigning an object literal directly, TypeScript triggers excess property checks to guard against developer error, rejecting unexpected keys even if the required keys are present.
  • Open Shapes: Interfaces in TypeScript remain open-ended by design, allowing specialized data structures with many fields to be passed seamlessly to functions expecting simpler, general-purpose shapes.
