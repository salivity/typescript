TypeScript Template Literal Unions and Combinations

Template literal types in TypeScript allow developers to build flexible string types by embedding expressions directly inside string literals. When combined with union types, TypeScript automatically calculates the Cartesian product of the inputs to produce every valid string permutation. This article explains how template literal unions work, breaks down the mechanics behind cross-product generation, and explores practical applications and performance considerations.

What Are Template Literal Types?

Introduced in TypeScript 4.1, template literal types mirror JavaScript's template literal syntax using backticks (`) and the ${} placeholder. Instead of evaluating runtime values, TypeScript evaluates them at compile time within the type system:

type World = "world";
type Greeting = `hello ${World}`; // Type is "hello world"

When string literal types are inserted, the resulting type is a strictly defined, single-string literal.

How Unions Trigger Cross-Product Combinations

The true power of template literal types emerges when union types are passed into the interpolation slots. When TypeScript encounters a union within a template literal, it distributes over each member of that union.

If multiple unions are used in the same template literal type, TypeScript calculates the Cartesian product (or cross-product), pairing every constituent of the first union with every constituent of each subsequent union:

type VerticalAlignment = "top" | "bottom";
type HorizontalAlignment = "left" | "right";

type Position = `${VerticalAlignment}-${HorizontalAlignment}`;

The resulting Position type resolves to:

"top-left" | "top-right" | "bottom-left" | "bottom-right"

The Distribution Mechanism

The cross-product behavior occurs because TypeScript resolves template literal types by distributing unions one by one from left to right:

  1. It takes the first member of VerticalAlignment ("top") and combines it with every member of HorizontalAlignment ("left", "right"), generating "top-left" and "top-right".
  2. It takes the next member of VerticalAlignment ("bottom") and repeats the process, generating "bottom-left" and "bottom-right".
  3. It joins all individual results into a single flattened union.

Adding a third union multiplies the total permutations accordingly:

type Device = "mobile" | "desktop";
type Layout = `${Device}-${Position}`;

// Results in 8 permutations:
// "mobile-top-left" | "mobile-top-right" | ... | "desktop-bottom-right"

Built-in String Manipulation Utilities

TypeScript includes intrinsic string utility types that can be combined with template literal unions to format generated variants:

  • Uppercase<StringType>
  • Lowercase<StringType>
  • Capitalize<StringType>
  • Uncapitalize<StringType>
type Action = "create" | "update" | "delete";
type Resource = "user" | "order";

type HandlerName = `handle${Capitalize<Action>}${Capitalize<Resource>}`;
// "handleCreateUser" | "handleCreateOrder" | "handleUpdateUser" | ...

Practical Applications

Cross-product generation via template literals is useful across several real-world architectures:

  • Design Systems and CSS Utilities: Generate all permutations of component classes, such as btn-primary-large or padding-x-4.
  • Event Systems: Strongly type event listeners dynamically, such as mapping "change" and "input" to "onChange" and "onInput".
  • API Routing: Create strongly typed endpoints combining resource names, versions, and sub-routes (e.g., /api/v1/users/profile).

Managing Combinatorial Explosion

Because template literal unions generate Cartesian products, the number of generated types grows exponentially:

\[\text{Total Types} = |A| \times |B| \times |C|\]

If three unions contain 10, 10, and 10 members respectively, the resulting type contains 1,000 members. TypeScript enforces limits on union size to maintain compiler performance. Exceeding these limits can trigger compiler errors such as Expression produces a union type that is too complex to represent. Keep input unions small and focused on genuine use cases to maintain fast type-checking times.
