What Is the noResolve Flag in TypeScript?

The noResolve configuration flag is a TypeScript compiler setting that stops the compiler from automatically discovering and adding files to a project through import statements or triple-slash reference directives. This article explains how the noResolve flag works, the differences between default file resolution and noResolve mode, common use cases for using it, and how to enable it in your configuration.

How TypeScript Resolves Files by Default

By default, the TypeScript compiler (tsc) automatically expands its compilation set. When it compiles an entry file, it analyzes all import, export, and /// <reference path="..." /> directives found inside that file. If an imported file is not already in the project's list of source files, TypeScript resolves its location on disk and silently adds it to the compilation context.

This behavior allows developers to specify only an entry point (such as index.ts), letting the compiler locate the entire dependency tree automatically.

How the noResolve Flag Works

When you enable noResolve, TypeScript disables this automatic discovery mechanism. The compiler will not append any newly discovered files to the compilation list through imports or reference paths.

Under noResolve: true:

  • The compiler only processes files explicitly specified in the files array or matched directly by the include glob patterns in your tsconfig.json.
  • If a compiled file imports a module or file that was not explicitly provided upfront, TypeScript cannot resolve the module and produces a compilation error (such as Cannot find module...).
  • Triple-slash directives like /// <reference path="..." /> will no longer pull the referenced file into the program.

Why Use noResolve?

While rarely needed for standard web or Node.js applications, noResolve serves specific architectural requirements:

  • Custom Build Orchestrators: Advanced build tools (such as Bazel, custom Webpack loaders, or internal build engines) often precompute exact dependency graphs. In these environments, allowing tsc to traverse the file system dynamically can lead to redundant work or out-of-order compilation.
  • Strict Dependency Boundaries: It enforces that every source file must be declared explicitly, preventing code from accidentally importing unauthorized or untracked local modules.
  • Compiler Performance: In massive monorepos, skipping deep file-system resolution passes can slightly improve compiler throughput when the list of exact inputs is already known.

How to Configure noResolve

You can enable the flag inside your tsconfig.json under the compilerOptions property:

{
  "compilerOptions": {
    "noResolve": true
  },
  "files": [
    "src/index.ts",
    "src/utils.ts"
  ]
}

Alternatively, you can pass the flag directly to the TypeScript command-line interface:

tsc --noResolve index.ts utils.ts

When using noResolve, always ensure that every source file required for type-checking and code generation is fully enumerated in your inputs.
