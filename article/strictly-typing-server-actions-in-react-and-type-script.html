Strictly Typing Server Actions in React and TypeScript

Server Actions in React Server Components (RSC) allow developers to execute backend logic directly from UI components, but ensuring robust end-to-end type safety across the network boundary requires deliberate implementation. This article explains how to strictly type Server Actions using TypeScript by defining explicit return types, safely handling FormData, integrating runtime validation schemas, and managing typed states with client-side React hooks.

Typing Direct Server Action Arguments and Return Values

When invoking a Server Action programmatically (rather than binding directly to a standard HTML form submission), you can define TypeScript types directly on the function signature. Always define an explicit return type—often using a discriminated union—to handle both success and error outcomes deterministically.

'use server';

type ActionResponse<T> = 
  | { success: true; data: T }
  | { success: false; error: string; fieldErrors?: Record<string, string[]> };

interface UpdateUserInput {
  id: string;
  name: string;
  email: string;
}

export async function updateUser(
  input: UpdateUserInput
): Promise<ActionResponse<{ id: string }>> {
  try {
    // Database or business logic here
    return { success: true, data: { id: input.id } };
  } catch (err) {
    return { success: false, error: 'Failed to update user.' };
  }
}

Safely Parsing and Typing FormData

When Server Actions are triggered by form submissions, they automatically receive a native FormData instance as their first argument. Because FormData.get() returns FormDataEntryValue | null, you should use a runtime validation library such as Zod to parse untyped input into a strictly typed structure.

'use server';

import { z } from 'zod';

const CreatePostSchema = z.object({
  title: z.string().min(1, 'Title is required'),
  content: z.string().min(10, 'Content must be at least 10 characters'),
});

export type CreatePostInput = z.infer<typeof CreatePostSchema>;

export async function createPost(formData: FormData) {
  const rawData = {
    title: formData.get('title'),
    content: formData.get('content'),
  };

  const validation = CreatePostSchema.safeParse(rawData);

  if (!validation.success) {
    return {
      success: false,
      fieldErrors: validation.error.flatten().fieldErrors,
    };
  }

  const { title, content } = validation.data;
  // Execution continues with fully typed data
  return { success: true, data: { title, content } };
}

Typing Server Actions with useActionState

React provides the useActionState hook (formerly useFormState) to manage stateful Server Actions on the client. For strict typing, both the action handler and the hook must share the same state interface.

'use client';

import { useActionState } from 'react';

interface FormState {
  message: string;
  error?: string;
}

// The server action signature: (prevState: FormState, formData: FormData) => Promise<FormState>
async function submitFeedback(
  prevState: FormState,
  formData: FormData
): Promise<FormState> {
  'use server';
  const feedback = formData.get('feedback');

  if (!feedback) {
    return { message: '', error: 'Feedback cannot be empty.' };
  }

  return { message: 'Feedback received successfully!' };
}

export function FeedbackForm() {
  const initialState: FormState = { message: '' };
  const [state, formAction, isPending] = useActionState(submitFeedback, initialState);

  return (
    <form action={formAction}>
      <textarea name="feedback" />
      {state.error && <p className="error">{state.error}</p>}
      {state.message && <p className="success">{state.message}</p>}
      <button type="submit" disabled={isPending}>Submit</button>
    </form>
  );
}

Enforcing Strict Types via Action Wrappers

For larger applications, repetitive parsing and error-handling logic can lead to regressions. You can create a higher-order function to encapsulate authentication, schema validation, and typed execution into a single reusable utility.

import { z } from 'zod';

type ServerActionHandler<TSchema extends z.ZodType, TResult> = (
  data: z.infer<TSchema>
) => Promise<TResult>;

export function createSafeAction<TSchema extends z.ZodType, TResult>(
  schema: TSchema,
  handler: ServerActionHandler<TSchema, TResult>
) {
  return async (input: unknown) => {
    const parsed = schema.safeParse(input);

    if (!parsed.success) {
      return {
        success: false as const,
        errors: parsed.error.flatten().fieldErrors,
      };
    }

    try {
      const data = await handler(parsed.data);
      return { success: true as const, data };
    } catch (error) {
      return {
        success: false as const,
        errors: { _root: ['Internal server error'] },
      };
    }
  };
}

This pattern ensures that every Server Action built through the wrapper receives validated, inferred types directly into the handler and returns a standardized, strictly typed response payload to the caller.
