How Array.isArray Narrows Types in TypeScript

TypeScript utilizes control flow analysis and built-in type predicates to accurately differentiate between arrays and scalar values within union types. When processing a union consisting of scalar types (such as string, number, or primitive objects) and array types (such as string[] or number[]), the Array.isArray() method acts as a native type guard. Invoking this check refines the union so that the array types are isolated in the truthy branch and the scalar types are isolated in the falsy branch, eliminating the need for manual type assertions.

The Mechanism: Type Predicates

TypeScript's core library defines Array.isArray() using a type predicate. In standard TypeScript definitions, its signature resembles:

isArray(arg: any): arg is any[];

Or, in more recent versions supporting read-only collections:

isArray(arg: unknown): arg is readonly unknown[];

The arg is ... return signature informs the TypeScript compiler that if the function returns true, the checked variable is guaranteed to be an array type. During compilation, the control flow analysis engine uses this information to update the variable's type within that specific execution path.

Narrowing Unions of Scalars and Arrays

Consider a common scenario where a function accepts either a single scalar value or an array of those values, such as string | string[]:

function processInput(input: string | string[]) {
  if (Array.isArray(input)) {
    // TypeScript narrows 'input' to: string[]
    console.log(`Array length: ${input.length}`);
    input.forEach(item => console.log(item.toUpperCase()));
  } else {
    // TypeScript narrows 'input' to: string
    console.log(`Single string: ${input.toUpperCase()}`);
  }
}

In the if block, TypeScript filters the union string | string[] to only include types assignable to readonly unknown[]. The scalar string does not satisfy this condition, leaving only string[].

In the else block, TypeScript removes the array component from the union through exclusion. Because string[] was satisfied in the if branch, the remaining type must be the scalar string.

Handling Complex Scalar Unions

The same mechanism applies to unions with multiple distinct scalar types and array types:

type MixedData = number | boolean | string[];

function handleData(data: MixedData) {
  if (Array.isArray(data)) {
    // Narrowed to: string[]
    return data.join(", ");
  }
  
  // Narrowed to: number | boolean
  return data.toString();
}

Here, Array.isArray successfully filters out all non-array candidates at once. The else branch retains all scalar members (number | boolean), allowing you to perform subsequent narrowing checks (such as typeof data === "number") on the remaining primitives.

Behavior with Generics and Readonly Arrays

When dealing with generics or readonly arrays, Array.isArray() handles narrowing predictably:

  1. Tuples and Arrays: If a union contains a tuple, a standard array, and a scalar (e.g., [string, number] | string[] | number), Array.isArray() narrows the truthy branch to the union of the tuple and array types ([string, number] | string[]).
  2. Readonly Arrays: TypeScript recognizes that mutable arrays extend readonly unknown[]. Consequently, types defined as readonly T[] are also captured properly by the guard.

By leveraging Array.isArray(), TypeScript safely untangles collections from singular values at runtime while automatically aligning compile-time types with the corresponding runtime logic.
