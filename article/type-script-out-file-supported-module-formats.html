TypeScript outFile: Supported Module Formats

The outFile option in TypeScript is a compiler setting designed to concatenate all compiled JavaScript output into a single file, acting as a lightweight built-in bundler. This article explains how the outFile setting works, identifies the specific module formats it supports, highlights which common formats are unsupported, and provides practical configuration guidance for modern development.

What Is the outFile Option?

Defined in tsconfig.json under compilerOptions, outFile instructs the TypeScript compiler (tsc) to bundle all global scripts or modules into one specified output file rather than generating a distinct .js file for every .ts file.

{
  "compilerOptions": {
    "module": "amd",
    "outFile": "./dist/bundle.js"
  }
}

When targeting non-module environments (plain scripts), TypeScript simply concatenates the files in dependency order based on triple-slash references (/// <reference path="..." />). When dealing with modules, it wraps each file in the designated module loader format within the single output file.

Supported Module Formats

TypeScript's outFile option does not support all module systems due to the architectural requirements of module resolution and concatenation. It only supports the following module formats:

  • None: Used for non-modular code (global scripts). All files are concatenated together directly in the global scope.
  • AMD (Asynchronous Module Definition): Formats modules using the define() wrapper, making them suitable for browser runtimes using module loaders like RequireJS.
  • System: Formats modules using System.register(), intended for use with the SystemJS dynamic module loader.

If you specify outFile without setting module to amd or system (or omitting module when code contains imports/exports), the TypeScript compiler will throw an error: TS6082: Only 'amd' and 'system' modules are supported with the '--outFile' flag.

Unsupported Module Formats

outFile cannot be used with the most common modern module targets:

  • CommonJS: The runtime semantics of Node.js require individual file evaluation via require(), which makes simple concatenation unsupported by tsc.
  • ES6 / ES2015 / ESNext: Standard ECMAScript modules (ESM) rely on static file-based imports (import / export) that cannot be trivially concatenated into a single flat file without tree-shaking, scope renaming, and runtime polyfills.

Modern Alternatives

Because outFile is restricted to AMD and SystemJS, it is rarely used in modern web development. To bundle TypeScript projects using CommonJS or standard ES modules into a single distributable file, developers use dedicated third-party bundlers such as Vite, esbuild, Rollup, or Webpack. In those workflows, TypeScript is typically configured with "moduleResolution": "bundler" or "module": "esnext", leaving the concatenation step to the bundler.
