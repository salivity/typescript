Can Unique Symbol Be Used with Let in TypeScript?

In TypeScript, you cannot use the unique symbol type annotation with let declarations. This article explains why the TypeScript compiler restricts unique symbol exclusively to const bindings, the specific compiler error generated when attempting to use it with let, and the standard alternatives available when mutable symbol references are required.

The Rule and the Compiler Error

In TypeScript, unique symbol is a special subtype of symbol created to treat individual symbols as distinct, nominal types. Because a unique symbol represents an unforgeable, singular identity, TypeScript strictly enforces that the variable holding it cannot be reassigned.

If you attempt to annotate a let variable with unique symbol, the compiler produces error TS1332:

// Compiler Error: A variable whose type is a 'unique symbol' type must be 'const'. (ts1332)
let myKey: unique symbol = Symbol("key");

The same restriction applies to variables declared with var.

Why the Restriction Exists

A unique symbol type is inextricably tied to the specific variable declaration itself. TypeScript uses the variable's identity to track the type:

const keyA: unique symbol = Symbol("identifier");
const keyB: unique symbol = Symbol("identifier");

// keyA and keyB have completely incompatible types
// typeof keyA !== typeof keyB

Allowing let declarations with unique symbol would contradict the type system's guarantees. Because let allows reassignment, the reference could change to another symbol at runtime, breaking the compile-time guarantee that the type refers to one exact, unchanging symbol.

Allowed Contexts for unique symbol

To use unique symbol, TypeScript requires immutable declarations:

  1. const variable declarations at the top level or block scope:

    const validKey: unique symbol = Symbol("valid");

  2. readonly static properties inside classes:

    class Registry {
  static readonly entityId: unique symbol = Symbol("entityId");
}

What to Use When Reassignment Is Needed

If a variable must be declared with let so that it can be reassigned, use the general symbol type annotation instead:

let currentKey: symbol = Symbol("initial");
currentKey = Symbol("updated"); // Allowed

The general symbol type represents any arbitrary symbol. While it cannot be used to declare unique nominal object keys or branded interfaces in the way unique symbol can, it correctly reflects the mutable nature of a let binding.
