How to Use the TypeScript Record Utility Type

The Record utility type in TypeScript provides an efficient and concise way to define structured object types with explicitly typed keys and values. This guide covers how Record<Keys, Type> works, how it enforces key completeness using union types, how it compares to traditional index signatures, and how to apply it in real-world scenarios to ensure strict type safety across structured data models.

What is the Record Utility Type?

The Record<Keys, Type> utility type constructs an object type whose property keys are Keys and property values are Type. Under the hood, TypeScript defines it using mapped types:

type Record<K extends keyof any, T> = {
    [P in K]: T;
};

Here, K must be assignable to string, number, or symbol, while T can be any valid TypeScript type, including primitives, interfaces, unions, or other records.

Defining Objects with Dynamic Keys

A common use case for Record is creating dictionary-like structures or lookup tables where the specific keys are not known beforehand, but their type is consistent:

// A lookup table where keys are strings and values are numbers
const productInventory: Record<string, number> = {
    laptop: 12,
    keyboard: 45,
    mouse: 80,
};

// A cache where keys are numbers (IDs) and values are strings
const userCache: Record<number, string> = {
    101: "Alice",
    102: "Bob",
};

Enforcing Strict Property Sets with Union Types

The primary advantage of Record over a standard index signature ({ [key: string]: T }) is its ability to restrict keys to a specific union of string literals. When defined with a union, TypeScript requires every key in that union to be present on the object, preventing accidental omissions.

type UserRole = "admin" | "editor" | "viewer";

interface RolePermissions {
    canEdit: boolean;
    canDelete: boolean;
}

// Every key in UserRole must be defined
const roleConfig: Record<UserRole, RolePermissions> = {
    admin: { canEdit: true, canDelete: true },
    editor: { canEdit: true, canDelete: false },
    viewer: { canEdit: false, canDelete: false },
};

If a developer adds a new role to UserRole, TypeScript flags a compile-time error at roleConfig until the new role's configuration is provided.

Record vs. Index Signatures

While index signatures allow open-ended property access, Record provides broader flexibility:

  1. Union Support: Index signatures do not allow union types as keys (e.g., { [key: UserRole]: string } results in an error). Record<UserRole, string> handles unions natively.
  2. Readability: Record<string, User> is more concise and easier to scan than { [key: string]: User }.
  3. Composability: Record works seamlessly with other utility types, such as Partial, Readonly, or Pick.
// Making every key in a Record optional
type OptionalRoleConfig = Partial<Record<UserRole, RolePermissions>>;

const partialRoles: OptionalRoleConfig = {
    admin: { canEdit: true, canDelete: true },
    // "editor" and "viewer" are not required here
};

Nested Records

You can nest Record types to represent multidimensional key-value pairs, such as translations or permission matrices:

type Locale = "en" | "es" | "fr";
type TranslationKey = "welcome" | "logout";

const translations: Record<Locale, Record<TranslationKey, string>> = {
    en: {
        welcome: "Welcome",
        logout: "Log out",
    },
    es: {
        welcome: "Bienvenido",
        logout: "Cerrar sesión",
    },
    fr: {
        welcome: "Bienvenue",
        logout: "Se déconnecter",
    },
};

By leveraging Record<Keys, Type>, developers can define scalable, self-documenting object structures that reduce boilerplate while maximizing compile-time safety.
