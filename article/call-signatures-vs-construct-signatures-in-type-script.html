Call Signatures vs Construct Signatures in TypeScript

In TypeScript, interfaces can describe not only object properties but also how functions and classes behave. The core difference between a call signature and a construct signature lies in how the underlying entity is invoked: call signatures describe things that can be invoked like standard functions using parentheses, while construct signatures define entities that must be instantiated using the new operator. This article breaks down their syntax, practical use cases, behavioral differences, and how they can be combined to model complex JavaScript objects.

Understanding Call Signatures

A call signature in an interface defines the parameters and return type of a callable function. When an object implements or satisfies an interface with a call signature, it can be executed directly.

The syntax resembles a standard function signature without a method name:

interface Formatter {
  (input: string): string;
}

const toUpperCase: Formatter = (input: string) => input.toUpperCase();

// Calling the interface-typed object
console.log(toUpperCase("hello")); // "HELLO"

Call signatures are commonly used for callback functions, higher-order functions, or objects that act as functions while also storing additional properties.

interface GreeterWithState {
  (name: string): string;
  defaultGreeting: string;
}

const greet: GreeterWithState = (name: string) => `${greet.defaultGreeting}, ${name}!`;
greet.defaultGreeting = "Welcome";

Understanding Construct Signatures

A construct signature dictates that an entity can be invoked with the new keyword to produce an instance of a specified type. These signatures represent class constructors or factory functions.

The syntax is identical to a call signature, with the addition of the new prefix:

interface Point {
  x: number;
  y: number;
}

interface PointConstructor {
  new (x: number, y: number): Point;
}

class ConcretePoint implements Point {
  constructor(public x: number, public y: number) {}
}

// Function that expects a constructor
function createPoint(ctor: PointConstructor, x: number, y: number): Point {
  return new ctor(x, y);
}

const point = createPoint(ConcretePoint, 10, 20);

TypeScript separates class static types from class instance types. While an implements clause checks the instance side of a class, construct signatures are required to type-check the constructor (static) side.

Key Differences

Feature Call Signature Construct Signature
Syntax (args): ReturnType; new (args): InstanceType;
Invocation fn(...) new fn(...)
Target Type Standard functions, callbacks Classes, constructor functions
Runtime Failure Attempting new fn() may fail or produce unintended prototypes Invoking without new causes a compile-time TypeScript error

Combining Call and Construct Signatures

JavaScript provides built-in objects that can be both called directly and instantiated with new. Standard examples include Date, Number, and RegExp:

  • Calling Date() returns a string representation of the current time.
  • Calling new Date() returns a Date object instance.

TypeScript supports this dual behavior by allowing both signatures within the same interface:

interface DateOrDateString {
  // Call signature: returns string
  (): string;
  // Construct signature: returns Date instance
  new (): Date;
  new (value: number): Date;
}

declare const CustomDate: DateOrDateString;

const dateStr = CustomDate();        // Type: string
const dateObj = new CustomDate();   // Type: Date

Call signatures handle standard functional execution, whereas construct signatures guarantee that an object represents an instantiable constructor requiring the new keyword.
