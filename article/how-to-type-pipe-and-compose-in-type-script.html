How to Type Pipe and Compose in TypeScript

Typing pipe and compose functions in TypeScript requires ensuring that the return value of each function matches the input parameter of the next. This article covers how to achieve end-to-end type safety for variable argument pipelines using traditional function overloads for maximum compiler performance, followed by modern recursive variadic tuple types for handling arbitrary chain lengths dynamically.

The Core Challenge

A pipeline passes a value through a series of transformations:

  • pipe(x, f, g, h) executes left-to-right: h(g(f(x)))
  • compose(h, g, f)(x) executes right-to-left: h(g(f(x)))

When typing these utilities, the output type of function \(N\) must match the input type of function \(N+1\). If intermediate types change (e.g., string \(\to\) number \(\to\) boolean), a simple array signature like ((arg: any) => any)[] will erase type information and return any.

Method 1: Function Overloads (Recommended for Production)

Function overloading is the most reliable and performant method, and it is the standard approach used by libraries like RxJS and Ramda. It provides instant IDE autocomplete and clear error messages.

Here is a fully-typed pipe implementation using overloads:

// Overloads for 1 to 4 functions (extend as needed)
export function pipe<T>(input: T): T;
export function pipe<T, A>(input: T, fn1: (arg: T) => A): A;
export function pipe<T, A, B>(input: T, fn1: (arg: T) => A, fn2: (arg: A) => B): B;
export function pipe<T, A, B, C>(
  input: T,
  fn1: (arg: T) => A,
  fn2: (arg: A) => B,
  fn3: (arg: B) => C
): C;
export function pipe<T, A, B, C, D>(
  input: T,
  fn1: (arg: T) => A,
  fn2: (arg: A) => B,
  fn3: (arg: B) => C,
  fn4: (arg: C) => D
): D;

// Implementation
export function pipe(input: any, ...fns: Array<(arg: any) => any>): any {
  return fns.reduce((acc, fn) => fn(acc), input);
}

Usage Example

const trim = (s: string) => s.trim();
const getLength = (s: string) => s.length;
const isEven = (n: number) => n % 2 === 0;

// Type inferred as boolean
const result = pipe("  hello  ", trim, getLength, isEven);

If you pass a function expecting a boolean directly after trim, TypeScript will throw a compile-time error pointing to the mismatched argument.

Method 2: Recursive Variadic Tuple Types

For scenarios where defining manual overloads is impractical, modern TypeScript allows you to recursively validate an arbitrary tuple of unary functions.

Implementing Recursive Pipe

To validate that every function's input matches the previous function's output, define a recursive constraint:

type AnyUnary = (arg: any) => any;

// Recursively verifies that each function accepts the return type of the preceding one
type Pipeline<Fns extends AnyUnary[], CurrentInput = any> = Fns extends [
  (arg: infer Arg) => infer Return,
  ...infer Rest extends AnyUnary[]
]
  ? [Arg] extends [CurrentInput]
    ? [ (arg: Arg) => Return, ...Pipeline<Rest, Return> ]
    : [ (arg: CurrentInput) => any, ...AnyUnary[] ] // Highlights the invalid parameter
  : Fns;

// Extracts the final return type of the chain
type LastReturnType<Fns extends AnyUnary[], Default> = Fns extends [
  ...AnyUnary[],
  (...args: any[]) => infer R
]
  ? R
  : Default;

With these helper types, apply them to the pipe signature:

export function pipe<T, Fns extends AnyUnary[]>(
  input: T,
  ...fns: Pipeline<Fns, T>
): LastReturnType<Fns, T> {
  return fns.reduce((acc, fn) => fn(acc), input) as LastReturnType<Fns, T>;
}

Typing compose (Right-to-Left)

compose executes functions in reverse order. While you can construct reverse recursive types, overloads remain the clearest and most readable pattern:

export function compose<A, B>(fn1: (arg: A) => B): (arg: A) => B;
export function compose<A, B, C>(
  fn2: (arg: B) => C,
  fn1: (arg: A) => B
): (arg: A) => C;
export function compose<A, B, C, D>(
  fn3: (arg: C) => D,
  fn2: (arg: B) => C,
  fn1: (arg: A) => B
): (arg: A) => D;

export function compose(...fns: Array<(arg: any) => any>) {
  return (initialValue: any) =>
    fns.reduceRight((acc, fn) => fn(acc), initialValue);
}

Usage Example

const toString = (val: number): string => `${val}`;
const double = (n: number): number => n * 2;

// Inferred as (arg: number) => string
const doubleToString = compose(toString, double);

const output = doubleToString(10); // "20"

Summary of Best Practices

  1. Use function overloads for standard utility libraries. They offer faster compiler evaluation and provide the clearest error messages when a stage in the pipeline fails.
  2. Use recursive variadic tuple types when dynamic pipeline depth is strictly necessary and cannot be constrained to a predetermined maximum number of arguments.
