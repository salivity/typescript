What Is maxNodeModuleJsDepth in TypeScript?

The maxNodeModuleJsDepth setting in TypeScript controls how deeply the compiler searches inside the node_modules directory to inspect and infer types from untyped JavaScript files. This article explains the purpose of the setting, how it operates alongside the allowJs compiler option, and the performance considerations you need to be aware of when configuring it.

In TypeScript projects, third-party libraries installed in node_modules typically provide type definitions via .d.ts files or through @types packages. However, when a JavaScript library lacks these declarations, TypeScript normally treats the imported module as having the any type. To improve developer tooling and type safety without writing custom declaration files, TypeScript can attempt to infer types directly from raw JavaScript source code.

The maxNodeModuleJsDepth option sets the maximum dependency depth that TypeScript will traverse under node_modules to automatically load and analyze these JavaScript files.

Prerequisites and Default Behavior

The setting is closely tied to the allowJs compiler option:

  • Requires allowJs: maxNodeModuleJsDepth only takes effect if "allowJs": true is enabled in your tsconfig.json. If allowJs is disabled, TypeScript will not inspect JavaScript files in node_modules regardless of this setting.
  • Default Value: The default value is 0. With a depth of 0, TypeScript disables automatic JavaScript module resolution inside node_modules, treating untyped JavaScript packages as untyped or requiring an ambient module declaration.

How Depth Levels Work

When you increase the value, the compiler steps down the dependency tree:

  • Depth 1: TypeScript inspects only the immediate JavaScript files of the imported package inside node_modules.
  • Depth 2: TypeScript inspects the package and any secondary JavaScript dependencies that the package itself imports from node_modules.
  • Depth N: The compiler continues traversing nested imports up to N levels deep.

Here is how the configuration is defined in a tsconfig.json file:

{
  "compilerOptions": {
    "allowJs": true,
    "maxNodeModuleJsDepth": 1
  }
}

Performance Considerations

While increasing maxNodeModuleJsDepth can provide type inference and auto-completion for JavaScript libraries lacking type definitions, it comes with a significant performance cost.

JavaScript parsing and type inference are resource-intensive. Deeply nested dependency trees can cause TypeScript to parse thousands of untyped files, dramatically increasing compilation times and degrading language server responsiveness in your code editor. For this reason, the value should rarely exceed 1 or 2. If type definitions are still missing at that depth, the recommended best practice is to install community-maintained types via DefinitelyTyped (npm install -D @types/package-name) or manually declare a minimal type definition file in your project.
