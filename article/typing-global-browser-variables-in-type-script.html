Typing Global Browser Variables in TypeScript

TypeScript types global variables in a browser environment by modeling the global execution context through built-in Document Object Model (DOM) definitions and extensible global interfaces. By leveraging declaration merging, ambient declarations, and global namespace augmentation, TypeScript allows developers to read and modify standard browser APIs like window and document while securely introducing custom global properties without type errors.

The Built-In Browser Environment

TypeScript provides out-of-the-box typings for the browser environment via its standard library definitions. When you enable "DOM" in the lib array of your tsconfig.json, TypeScript automatically loads declarations for all standard browser interfaces, including Window, Document, and Web APIs:

{
  "compilerOptions": {
    "lib": ["DOM", "ESNext"]
  }
}

In this environment, TypeScript maps the global scope to the Window interface. Standard globals like localStorage, fetch, and console are defined as properties on this interface or as ambient declarations within the global scope.

Augmenting the Window Interface

To add custom properties to the global window object, TypeScript relies on declaration merging. The implementation depends on whether your code is running inside a module (a file with import or export statements) or a script.

In a Module File

Because ES modules have their own scope, you must use the declare global block to target the global scope:

// globals.d.ts or any module file
export {};

declare global {
  interface Window {
    analyticsToken: string;
    customTracker: (event: string) => void;
  }
}

Once declared, the compiler recognizes these properties on window:

window.analyticsToken = "xyz123";
window.customTracker("page_view");

In a Non-Module Script

If a file has no top-level import or export statements, it operates entirely within the global scope. You can augment Window directly:

// env.d.ts
interface Window {
  configUrl: string;
}

Declaring Standalone Global Variables

Sometimes variables are injected at runtime (e.g., via <script> tags or build-time tools like Webpack DefinePlugin) and accessed without the window. prefix. You type these using ambient declarations with declare const, declare let, or declare var.

Using a Dedicated Declaration File

Create a file named globals.d.ts (ensuring it is included in your tsconfig.json's include paths):

declare const __APP_VERSION__: string;
declare let userSessionId: string | undefined;

This allows direct access to the variables anywhere in your project:

console.log(__APP_VERSION__);
userSessionId = "session_456";

Inside a Module

To declare standalone global variables from within a module file, wrap the declaration inside declare global:

declare global {
  const API_BASE_URL: string;
}

export const fetchData = async () => {
  return fetch(`${API_BASE_URL}/users`);
};

Typing globalThis

Modern JavaScript and TypeScript support globalThis as a standardized way to access the global object across any JavaScript environment. In the browser, globalThis points to window.

You can augment globalThis in the same way as Window:

declare global {
  var runtimeEnv: "development" | "production";
}

// Accessible universally
console.log(globalThis.runtimeEnv);
console.log(runtimeEnv);

Using var inside declare global ensures that the variable is added both to the root global namespace and to globalThis.
