Reverse Mappings in TypeScript Numeric Enums

In TypeScript, numeric enums feature an automatic bidirectional lookup mechanism known as reverse mapping. This feature allows developers to access the name of an enum member using its numeric value, in addition to retrieving the value using the member's name. This article explains how TypeScript implements reverse mappings under the hood, how the compiled JavaScript executes, and the practical implications for developers.

The Concept of Reverse Mapping

When you define a numeric enum in TypeScript, the compiler creates an object that supports bidirectional access. For example:

enum Status {
  Active = 1,
  Inactive = 2,
}

// Forward mapping (Key to Value)
console.log(Status.Active); // Output: 1

// Reverse mapping (Value to Key)
console.log(Status[1]); // Output: "Active"

In this example, retrieving Status.Active yields 1, while passing the index 1 to Status yields "Active".

How the Compiled JavaScript Works

TypeScript achieves reverse mapping through a specific assignment pattern during compilation. When the Status enum is compiled to JavaScript, it generates an Immediately Invoked Function Expression (IIFE):

var Status;
(function (Status) {
    Status[Status["Active"] = 1] = "Active";
    Status[Status["Inactive"] = 2] = "Inactive";
})(Status || (Status = {}));

The core mechanism lies in the line:

Status[Status["Active"] = 1] = "Active";

This single statement performs two distinct assignments due to how JavaScript evaluates expressions:

  1. Inner Assignment: Status["Active"] = 1 sets the key "Active" to 1. In JavaScript, an assignment expression evaluates to the assigned value, which means this expression returns 1.
  2. Outer Assignment: The expression effectively simplifies to Status[1] = "Active", creating a second property where the key is the number 1 and the value is the string "Active".

The resulting runtime JavaScript object contains both sets of keys:

{
  "1": "Active",
  "2": "Inactive",
  "Active": 1,
  "Inactive": 2
}

Numeric Enums vs. String Enums

Reverse mappings are exclusive to numeric enums. String-initialized enums do not generate reverse mappings:

enum Direction {
  Up = "UP",
  Down = "DOWN",
}

This compiles to:

var Direction;
(function (Direction) {
    Direction["Up"] = "UP";
    Direction["Down"] = "DOWN";
})(Direction || (Direction = {}));

Because string enum values often match member names or overlap with other domain strings, generating reverse mappings could lead to naming collisions. TypeScript therefore limits reverse mapping to numeric values.

Important Considerations

Iteration Quirks

Because the compiled object contains both keys and values as properties, using utilities like Object.keys() or Object.values() returns twice as many entries as defined in TypeScript:

console.log(Object.keys(Status));
// Output: ["1", "2", "Active", "Inactive"]

To iterate solely over keys or values, filter out the numeric keys manually using isNaN() or typeof.

const enum Limitations

If an enum is declared with the const modifier (const enum), TypeScript does not generate a runtime object. Instead, member values are inlined wherever they are referenced. Consequently, reverse mappings cannot be used with const enum declarations.
