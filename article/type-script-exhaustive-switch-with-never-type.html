TypeScript Exhaustive Switch with Never Type

In TypeScript, using the never type inside the default branch of a switch statement enables compile-time exhaustive checking. This pattern ensures that every possible variant of a discriminated union is explicitly handled. If a developer adds a new member to the union later, the TypeScript compiler immediately flags the unhandled case as a type error, preventing runtime bugs before the code reaches production.

The Problem of Missing Cases

When working with discriminated unions, standard switch statements can silently fail if a case is omitted:

type Shape = 
  | { kind: "circle"; radius: number }
  | { kind: "square"; size: number };

function getArea(shape: Shape): number {
  switch (shape.kind) {
    case "circle":
      return Math.PI * shape.radius ** 2;
    case "square":
      return shape.size ** 2;
  }
}

If a new member—such as { kind: "triangle"; base: number; height: number }—is added to Shape, the switch statement silently returns undefined for triangles unless TypeScript's strict null-checking detects an implicit return issue. When the function does not return a value or handles complex branching, missing cases can easily slip through unnoticed.

How the never Type Solves This

In TypeScript's type system, never represents the type of values that never occur. If narrowing eliminates all possible types of a union, the remaining type is narrowed down to never.

By attempting to assign the remaining value to a variable of type never in the default case, you force the compiler to verify that no possible values remain:

type Shape = 
  | { kind: "circle"; radius: number }
  | { kind: "square"; size: number }
  | { kind: "triangle"; base: number; height: number };

function getArea(shape: Shape): number {
  switch (shape.kind) {
    case "circle":
      return Math.PI * shape.radius ** 2;
    case "square":
      return shape.size ** 2;
    default:
      // Type Error: Type 'Triangle' is not assignable to type 'never'.
      const _exhaustiveCheck: never = shape;
      return _exhaustiveCheck;
  }
}

Because triangle is not handled, shape in the default block has the type { kind: "triangle"; base: number; height: number } rather than never. The compiler rejects the assignment, immediately highlighting the omission.

Using an assertNever Helper Function

A common best practice is to encapsulate this logic into an assertNever helper function. This approach provides both a compile-time check and a runtime safety net:

function assertNever(value: never): never {
  throw new Error(`Unhandled discriminated union member: ${JSON.stringify(value)}`);
}

function getArea(shape: Shape): number {
  switch (shape.kind) {
    case "circle":
      return Math.PI * shape.radius ** 2;
    case "square":
      return shape.size ** 2;
    case "triangle":
      return (shape.base * shape.height) / 2;
    default:
      return assertNever(shape);
  }
}

Key Benefits

  • Compile-Time Guarantees: Catches missing logic instantly during refactoring or when extending domain models.
  • Self-Documenting Code: Explicitly indicates to other developers that the switch statement must cover all members of the union.
  • Runtime Fallback: Throws an explicit error if unexpected data bypasses TypeScript's type system at runtime (such as untyped API payloads).
