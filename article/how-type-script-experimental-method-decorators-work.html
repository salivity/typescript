How TypeScript Experimental Method Decorators Work

This article explores how method decorators operate in TypeScript under the experimentalDecorators flag. You will learn the necessary compiler configuration, the signature and parameters of a method decorator function, how to inspect and manipulate property descriptors, and how to implement a practical decorator factory to intercept and modify class method behavior at runtime.

To use experimental method decorators, you must first enable the feature in your tsconfig.json file:

{
  "compilerOptions": {
    "target": "ES6",
    "experimentalDecorators": true
  }
}

In TypeScript's experimental implementation, a method decorator is a function applied directly before a method declaration. It receives three parameters when invoked:

  1. target: Either the constructor function of the class for a static method, or the prototype of the class for an instance method.
  2. propertyKey: The name of the member being decorated (string | symbol).
  3. descriptor: The PropertyDescriptor of the method, matching the ECMAScript object property descriptor structure.

The signature of a method decorator looks like this:

function Log(
  target: any,
  propertyKey: string,
  descriptor: PropertyDescriptor
): PropertyDescriptor | void {
  // Decorator logic
}

Method decorators run once when the class is defined, not when instances of the class are created. Their primary power lies in their ability to read, alter, or replace the PropertyDescriptor.

The descriptor.value property contains the original function implementation. By reassigning descriptor.value, you can wrap the original method with custom logic, such as error handling, performance timing, or logging.

Here is a practical example of a method decorator that logs execution time:

function Measure(
  target: any,
  propertyKey: string,
  descriptor: PropertyDescriptor
) {
  const originalMethod = descriptor.value;

  descriptor.value = function (...args: any[]) {
    const start = performance.now();
    const result = originalMethod.apply(this, args);
    const end = performance.now();
    console.log(`${propertyKey} took ${(end - start).toFixed(2)}ms to execute.`);
    return result;
  };

  return descriptor;
}

class Database {
  @Measure
  fetchData() {
    // Simulating processing
    for (let i = 0; i < 1e6; i++) {}
    return "Data loaded";
  }
}

If your decorator requires configuration options, you can use a decorator factory. A decorator factory is a higher-order function that returns the decorator function itself:

function LogPrefix(prefix: string) {
  return function (
    target: any,
    propertyKey: string,
    descriptor: PropertyDescriptor
  ) {
    const originalMethod = descriptor.value;

    descriptor.value = function (...args: any[]) {
      console.log(`[${prefix}] Calling ${propertyKey}`);
      return originalMethod.apply(this, args);
    };

    return descriptor;
  };
}

class UserService {
  @LogPrefix("AUTH")
  login(username: string) {
    return `Logged in as ${username}`;
  }
}

When returning a new or mutated PropertyDescriptor from the decorator function, TypeScript passes that descriptor to Object.defineProperty, effectively replacing the class method's definition. If the decorator returns nothing (void), TypeScript keeps the existing property descriptor, but any mutations made directly to descriptor.value will still persist.
