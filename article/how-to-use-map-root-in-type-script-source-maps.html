How to Use mapRoot in TypeScript Source Maps

This article explains what the mapRoot compiler option is in TypeScript, how it alters source map resolution, and how to configure it to point debuggers to remote locations. By overriding the default relative paths in compiled JavaScript files, mapRoot enables teams to host sensitive source maps on separate internal servers or content delivery networks (CDNs) while serving lean production assets to users.

What Is mapRoot?

mapRoot is a TypeScript compiler option specified in the tsconfig.json file. When you compile TypeScript with source maps enabled ("sourceMap": true), the compiler automatically outputs .js.map files alongside your .js files. By default, the compiled JavaScript file includes a comment at the very bottom pointing to the map file relative to its current directory:

//# sourceMappingURL=app.js.map

The mapRoot option overrides this default behavior. Instead of assuming the .map file resides next to the .js file on the same server, mapRoot allows you to define an alternative path—either an absolute URL or a specific directory path—where the debugger should locate the generated source maps.

Why Specify Remote Locations for Source Maps?

In production environments, deploying source maps directly alongside application code exposes your original TypeScript source code, directory structures, and business logic to the public. Setting a remote location via mapRoot provides several advantages:

  • Security and Intellectual Property: You can host .map files on an internal, firewall-protected server or an authenticated S3 bucket, preventing unauthorized public access.
  • Separation of Concerns: You can serve JavaScript files from a public CDN while directing error-tracking services (such as Sentry or Datadog) and internal developer tools to a separate storage location.
  • Bandwidth Optimization: Production clients never need to download or probe for map files unless a developer opens developer tools configured to access the remote host.

Configuring mapRoot in tsconfig.json

To specify a remote location, assign the base URL of your remote storage to mapRoot within the compilerOptions of your tsconfig.json:

{
  "compilerOptions": {
    "target": "ES6",
    "module": "commonjs",
    "sourceMap": true,
    "outDir": "./dist",
    "mapRoot": "https://internal-assets.example.com/sourcemaps/"
  }
}

When TypeScript compiles the code with this configuration, it rewrites the sourceMappingURL comment using the URL prefix specified in mapRoot:

//# sourceMappingURL=https://internal-assets.example.com/sourcemaps/app.js.map

When a developer inspects the code or an error tracking service captures an exception, the browser or monitoring tool fetches the .map file directly from https://internal-assets.example.com/sourcemaps/app.js.map.

mapRoot vs. sourceRoot

It is common to confuse mapRoot with sourceRoot:

  • mapRoot: Defines where the debugger can find the .js.map file. It modifies the //# sourceMappingURL= directive written into the .js file.
  • sourceRoot: Defines where the debugger can find the original .ts source files. It modifies the "sourceRoot" property inside the .js.map file itself.

If both your .map files and your original .ts files are hosted remotely in different directories, you can combine both properties:

{
  "compilerOptions": {
    "sourceMap": true,
    "mapRoot": "https://maps.example.com/",
    "sourceRoot": "https://sources.example.com/"
  }
}

Key Considerations

  1. Trailing Slashes: Always ensure mapRoot ends with a trailing slash (/) when specifying a URL or directory path. TypeScript concatenates this path directly with the filename.
  2. CORS Headers: If your source maps are hosted on a different domain than your primary web application, the remote server must return appropriate Cross-Origin Resource Sharing (CORS) headers (e.g., Access-Control-Allow-Origin) so browser developer tools can fetch the files.
