Check Property Existence in TypeScript Using Reflect

Checking whether a property exists on an object is a fundamental task in JavaScript and TypeScript development. While developers traditionally rely on the in operator or Object.prototype.hasOwnProperty(), the modern ECMAScript Reflect API provides an alternative via Reflect.has(). This article explains how Reflect.has() works in TypeScript, how it handles prototype chains, how TypeScript types the method, and how to implement custom type guards to achieve proper type narrowing.

Understanding Reflect.has()

The Reflect object is a built-in ES2015 global object that provides interceptable methods for JavaScript operations. The Reflect.has() method functions as a functional equivalent to the in operator.

The method signature is defined as follows:

Reflect.has(target: object, propertyKey: PropertyKey): boolean
  • target: The target object in which to look for the property. If the target is not an object, a TypeError is thrown.
  • propertyKey: The name of the property (either a string, number, or symbol) to check.
  • Return value: A boolean indicating whether the target object or its prototype chain contains the property.

Basic Usage

interface User {
  id: number;
  name: string;
}

const user: User = { id: 1, name: "Alice" };

console.log(Reflect.has(user, "name")); // true
console.log(Reflect.has(user, "email")); // false

Prototype Chain Traversal

Like the in operator, Reflect.has() traverses the object's prototype chain. If a property is not defined directly on the target instance but exists on its prototype, the method returns true.

class Animal {
  breathe() {
    return true;
  }
}

class Dog extends Animal {
  bark() {
    return true;
  }
}

const myDog = new Dog();

console.log(Reflect.has(myDog, "bark")); // true (own property on prototype)
console.log(Reflect.has(myDog, "breathe")); // true (inherited from Animal)
console.log(Reflect.has(myDog, "toString")); // true (inherited from Object.prototype)

If checking only for an object's own properties without traversing the prototype chain is required, use Object.hasOwn() instead.

TypeScript Type Narrowing with Reflect.has()

By default, TypeScript's standard library defines Reflect.has() to return a general boolean. Unlike the in operator, standard calls to Reflect.has() do not automatically act as type guards.

For example:

function printValue(obj: unknown) {
  if (typeof obj === "object" && obj !== null) {
    if (Reflect.has(obj, "title")) {
      // TypeScript does NOT automatically narrow obj to include 'title'
      // console.log(obj.title); // Error: Property 'title' does not exist on type 'object'.
    }
  }
}

Implementing a Custom Type Guard

To narrow types dynamically using Reflect.has(), define a custom user-defined type guard:

function hasProperty<T extends object, K extends PropertyKey>(
  obj: T,
  prop: K
): obj is T & Record<K, unknown> {
  return Reflect.has(obj, prop);
}

function processData(input: object) {
  if (hasProperty(input, "payload")) {
    // TypeScript now knows 'payload' exists on input
    console.log(input.payload); 
  }
}

This custom guard combines the functional benefits of the Reflect API with TypeScript's static analysis system, providing both runtime verification and compile-time type safety.
