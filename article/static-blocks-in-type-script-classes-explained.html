Static Blocks in TypeScript Classes Explained

Static initialization blocks in TypeScript allow developers to execute complex, multi-statement initialization logic for static class properties at the time a class is evaluated. Introduced in TypeScript 4.4 to align with ECMAScript Class Static Block specifications, this feature provides a dedicated scope for running setup code, handling exceptions, and accessing private class internals without exposing them to the external module.

Syntax and Basic Usage

A static block is defined using the static keyword followed by a block of code enclosed in curly braces {} within the class body. It executes automatically once when the class is loaded into memory, rather than when an instance of the class is constructed.

class DatabaseConfig {
  static connectionString: string;
  static isInitialized: boolean;

  static {
    try {
      this.connectionString = process.env.DB_URL ?? "localhost:5432";
      this.isInitialized = true;
    } catch (error) {
      this.connectionString = "default";
      this.isInitialized = false;
    }
  }
}

Key Capabilities and Behavior

1. Complex Initialization and Error Handling

Prior to static blocks, initializing static properties was limited to simple inline assignments, while complex logic had to be executed outside the class declaration. Static blocks bring this initialization inside the class boundary, enabling the use of loops, conditional branches, and try/catch error-handling structures.

2. Access to Private Static Fields

One of the most powerful features of static blocks is their ability to access private static and private instance members. Because the block exists inside the class declaration, it has full access to #private identifiers, making it possible to share private data across instances or export privileged capabilities without making members public.

class SecretKeeper {
  static #internalKey: string;

  static {
    SecretKeeper.#internalKey = generateSecureKey();
  }

  static validate(key: string): boolean {
    return key === SecretKeeper.#internalKey;
  }
}

3. Execution Context and this

Inside a static block, the this keyword refers directly to the constructor function (the class itself), not an instance. You can reference static properties directly using this.propertyName or by using the class name.

4. Multiple Blocks and Execution Order

A class can contain multiple static blocks interleaved with static property declarations. TypeScript executes these blocks in the exact order they are declared, from top to bottom.

class ExecutionOrder {
  static first = 1;

  static {
    console.log(this.first); // Prints: 1
  }

  static second = 2;

  static {
    console.log(this.second); // Prints: 2
  }
}

5. Inheritance and super

Static blocks in derived classes can use the super keyword to access static properties of the base class. The base class's static blocks will always execute before the derived class's static blocks, ensuring that inherited static properties are fully prepared before child initialization begins.

Compilation Target

When targeting modern ECMAScript versions (ES2022 or later), TypeScript emits static blocks as native JavaScript static blocks. When compiling down to older targets (such as ES2015 or ES5), TypeScript transpiles the block into immediate post-class invocation logic, ensuring backward compatibility across all environments.
