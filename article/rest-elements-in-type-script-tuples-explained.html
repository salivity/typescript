Rest Elements in TypeScript Tuples Explained

In TypeScript, rest elements allow tuples to model flexible, variable-length array structures while preserving strict type ordering. Using the spread operator (...), rest elements represent an indefinite number of elements of a specified type within a tuple type definition. This article explains how rest elements work in TypeScript tuples, how their positioning rules evolved, and where they can be placed in modern TypeScript code.

What Are Rest Elements in Tuples?

A tuple type in TypeScript typically represents an array with a fixed number of elements whose types are known at specific positions. However, real-world data structures often contain variable segments—such as a function that accepts one leading identifier followed by an arbitrary number of numerical arguments.

Rest elements solve this by incorporating array types via the spread syntax (...Type[]) inside the tuple declaration. This indicates that zero, one, or more items of that type can appear in that segment of the tuple.

type StringThenNumbers = [string, ...number[]];

const valid1: StringThenNumbers = ["total", 1, 2, 3];
const valid2: StringThenNumbers = ["empty"];

Where Can Rest Elements Be Positioned?

Prior to TypeScript 4.0, rest elements were strictly restricted to the final position in a tuple. In modern TypeScript (version 4.0 and later), rest elements can be positioned anywhere in a tuple: at the end, in the middle, or at the beginning.

1. At the End of a Tuple

This is the classic pattern. The tuple requires a fixed set of leading elements, followed by zero or more elements of the rest type.

type NameAndScores = [string, ...number[]];

const playerScores: NameAndScores = ["Alice", 95, 88, 100];

2. At the Beginning of a Tuple

A rest element can appear at the start of a tuple. This requires all elements matching the rest type first, ending with fixed trailing elements.

type TagsAndCount = [...string[], number];

const data1: TagsAndCount = ["typescript", "javascript", 2];
const data2: TagsAndCount = [0]; // Valid: zero strings, followed by a number

3. In the Middle of a Tuple

Placing a rest element in the middle allows you to define required prefix and suffix elements with an arbitrary number of items in between.

type BoundedList = [boolean, ...string[], number];

const validMiddle1: BoundedList = [true, "item1", "item2", 42];
const validMiddle2: BoundedList = [false, 0]; // Valid: zero strings in the middle

Constraints and Limitations

While TypeScript allows flexible positioning, there is one critical limitation: a tuple can only contain one unbounded rest element.

An unbounded rest element is one backed by an open-ended array type, such as ...string[]. If a tuple contains two unbounded rest elements, TypeScript cannot determine where one sequence ends and the next begins, resulting in a compile-time error.

// Error: A rest element cannot follow another rest element.
type InvalidTuple = [...string[], ...number[]];

However, you can spread multiple fixed-length tuples into a single tuple, because their lengths are statically known:

type Pair = [string, number];
type Combined = [...Pair, boolean, ...Pair]; // Valid: length is fixed
