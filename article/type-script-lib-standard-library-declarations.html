TypeScript Lib: Standard Library Declarations

The lib compiler option in TypeScript determines which built-in JavaScript API and runtime environment type declarations are included during compilation. By modifying this setting in your tsconfig.json, you tell the TypeScript compiler which global objects, methods, and environment-specific interfaces—such as the DOM or modern ECMAScript features—exist in your target runtime. This article explains default lib behaviors, how explicit configuration works, and how to tailor declarations for specific execution environments like Node.js or browsers.

How the lib Setting Works

TypeScript ships with a collection of standard declaration files (ending in .d.ts) that represent standard JavaScript features and web platform APIs. When you configure the lib array in tsconfig.json, you dictate which of these standard files TypeScript loads into the compilation context.

If an API's declaration file is omitted, TypeScript treats references to that API as unknown symbols, resulting in compilation errors like Cannot find name 'Promise' or Cannot find name 'document'.

Default Inheritance Based on target

When the lib property is omitted from your configuration, TypeScript automatically selects a default set of standard libraries based on the target property:

  • Targeting ES5: TypeScript defaults to ["dom", "es5", "scripthost"].
  • Targeting ES6 / ES2015: TypeScript defaults to ["dom", "es6", "dom.iterable", "scripthost"].
  • Targeting newer targets (e.g., ES2022, ESNext): TypeScript includes the corresponding ES standard library along with standard browser APIs (dom, dom.iterable).

Relying on defaults is often sufficient for standard web applications matching their target runtime, but it introduces issues in non-browser environments or polyfilled runtimes.

Overriding the Defaults

Specifying the lib option in tsconfig.json completely overrides the default list. TypeScript will load only the declaration files explicitly declared in the array.

{
  "compilerOptions": {
    "target": "es5",
    "lib": ["es5", "es2015.promise", "dom"]
  }
}

In the configuration above, even though the code compiles down to ECMAScript 5 syntax, the type checker allows modern Promise usage because "es2015.promise" is explicitly declared.

Common Standard Library Categories

Standard library definitions are generally categorized into runtime environments and language versions:

1. ECMAScript Language Levels

These libraries represent core JavaScript features specified by the ECMAScript standard:

  • Whole versions: es5, es6 (or es2015), es2020, esnext
  • Modular sub-features: es2015.core, es2015.promise, es2015.iterable, es2017.string, es2020.bigint

Modular libraries allow you to support specific modern features (often provided via polyfills) without declaring the entire future specification.

2. Environment APIs

These libraries expose APIs provided by execution environments rather than the ECMAScript specification itself:

  • dom: Declares browser APIs, including global objects like window, document, and HTML element types.
  • dom.iterable: Provides iterable definitions for DOM objects, such as NodeList iteration with for...of.
  • webworker: Declares global APIs available within Web Workers.
  • scripthost: Declares APIs for Windows Script Host.

Tailoring Declarations to Your Runtime

Configuring lib is critical for avoiding false positives and runtime errors.

Node.js Applications

Node.js environments do not have access to browser globals. Relying on default settings that include dom can lead to errors where code accidentally references window or document without the compiler warning you. For Node.js, omit DOM-related declarations:

{
  "compilerOptions": {
    "target": "es2022",
    "lib": ["es2022"]
  }
}

Decoupling Syntax from APIs

The target flag controls the output JavaScript syntax (such as arrow functions or optional chaining), while lib controls available runtime APIs. If your deployment environment supports modern APIs natively or via polyfills, but requires older JavaScript syntax for tool compatibility, decouple them:

{
  "compilerOptions": {
    "target": "es5",
    "lib": ["es2021", "dom"]
  }
}

This configuration ensures TypeScript downlevels modern syntax to ES5 while allowing code to use ECMAScript 2021 APIs without compilation errors.
