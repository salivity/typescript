Async Iterators and Symbol.asyncIterator in TypeScript

This article provides an overview of asynchronous iterators in JavaScript and explains how TypeScript defines, types, and validates the Symbol.asyncIterator protocol. You will learn the mechanics behind handling asynchronous streams of data, the core interfaces provided by TypeScript's standard library, and how to configure your project to use them effectively.

What Are Async Iterators?

An async iterator is an object that allows iteration over asynchronous data sources, such as streams, paginated API responses, or event emitters. Unlike standard synchronous iterators which immediately return a { value, done } object, an async iterator returns a Promise that resolves to an iterator result:

Promise<IteratorResult<T, TReturn>>

Async iterators are consumed using the for await...of loop syntax. Each iteration pauses execution until the promise returned by the iterator's next() method settles.

The Role of Symbol.asyncIterator

For an object to be recognized as an async iterable by JavaScript runtimes and language constructs like for await...of, it must implement a method keyed by the well-known symbol Symbol.asyncIterator.

const asyncIterable = {
  [Symbol.asyncIterator]() {
    return {
      async next() {
        return { value: 1, done: false };
      }
    };
  }
};

When a for await...of loop executes, it invokes the [Symbol.asyncIterator]() factory method on the target object to obtain the iterator instance.

How TypeScript Types Symbol.asyncIterator

TypeScript models this mechanism through standard library declarations, primarily defined in lib.es2018.asynciterable.d.ts.

1. The Symbol Definition

TypeScript defines the property on the global SymbolConstructor interface:

interface SymbolConstructor {
  readonly asyncIterator: unique symbol;
}

This guarantees that [Symbol.asyncIterator] is treated as a unique, strongly typed symbol property on objects.

2. Core Async Iteration Interfaces

TypeScript exposes three primary interfaces to model asynchronous data iteration:

interface AsyncIterator<T, TReturn = any, TNext = undefined> {
  next(...args: [] | [TNext]): Promise<IteratorResult<T, TReturn>>;
  return?(value?: TReturn | PromiseLike<TReturn>): Promise<IteratorResult<T, TReturn>>;
  throw?(e?: any): Promise<IteratorResult<T, TReturn>>;
}

interface AsyncIterable<T> {
  [Symbol.asyncIterator](): AsyncIterator<T>;
}

interface AsyncIterableIterator<T> extends AsyncIterator<T> {
  [Symbol.asyncIterator](): AsyncIterableIterator<T>;
}
  • AsyncIterator<T>: Represents the object producing sequence values. Its next() method yields a promise resolving to IteratorResult<T>.
  • AsyncIterable<T>: Represents any data structure containing a [Symbol.asyncIterator]() method that returns an AsyncIterator<T>.
  • AsyncIterableIterator<T>: Combines both interfaces, typical for async generator functions where the iterator instance is itself an iterable.

3. Implementing Async Iterables in TypeScript

To create a type-safe custom async iterable, implement the AsyncIterable<T> interface:

class NumberStream implements AsyncIterable<number> {
  constructor(private limit: number) {}

  [Symbol.asyncIterator](): AsyncIterator<number> {
    let current = 0;
    const limit = this.limit;

    return {
      async next(): Promise<IteratorResult<number>> {
        if (current < limit) {
          return { value: current++, done: false };
        }
        return { value: undefined, done: true };
      }
    };
  }
}

async function run() {
  const stream = new NumberStream(3);
  for await (const num of stream) {
    console.log(num); // Yields 0, 1, 2 with type 'number'
  }
}

4. Async Generator Functions

TypeScript also infers types automatically when using async generator functions (async function*). The return type of an async generator is typed as AsyncGenerator<T, TReturn, TNext>, which extends AsyncIterableIterator<T>:

async function* generateData(): AsyncGenerator<string> {
  yield "first";
  yield "second";
}

Compiler Requirements

Because Symbol.asyncIterator was introduced in ECMAScript 2018, ensure your tsconfig.json includes the appropriate standard library definitions:

{
  "compilerOptions": {
    "target": "ES2018",
    "lib": ["ES2018", "DOM"]
  }
}

If targeting older ECMAScript targets like ES5 or ES6, add "es2018.asynciterable" directly to the "lib" array and set "downlevelIteration": true to ensure code compiles and transpiles correctly.
