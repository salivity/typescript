Object.defineProperty vs Assignment in TypeScript

This article provides an overview of the fundamental differences between Object.defineProperty semantics (define semantics) and assignment semantics (set semantics) when initializing class fields in TypeScript. While both approaches place properties on an instantiated class, they diverge significantly in how they handle prototype chains, setters, property attributes, and inheritance. Understanding these differences is essential when configuring TypeScript’s useDefineForClassFields compiler flag and managing modern ECMAScript compliance.

The Core Concept: [[Define]] vs [[Set]]

JavaScript specifies two internal methods for adding or updating object properties: [[DefineOwnProperty]] and [[Set]].

  • Assignment semantics ([[Set]]): Operates like standard property assignment (this.foo = value). It searches the prototype chain for an existing property. If a setter exists on the prototype, that setter is invoked.
  • Define semantics ([[Define]]): Operates like Object.defineProperty(this, "foo", { ... }). It creates a new "own" property directly on the instance, bypassing any inherited accessors or properties on the prototype chain.

1. Prototype Setters and Inheritance

The most critical functional difference involves base class setters.

Under assignment semantics, initializing a derived class property triggers any matching setter defined on a parent class:

class Base {
  set prop(value: string) {
    console.log("Setter called:", value);
  }
}

class Derived extends Base {
  prop = "hello";
}

// Assignment semantics:
// Outputs "Setter called: hello"
new Derived();

Under define semantics (the ECMAScript standard), the property is created directly on the instance using Object.defineProperty. The base class setter is completely ignored and will not run:

// Define semantics:
// The setter is bypassed. An own property 'prop' is created on the instance.
new Derived(); // No console output

2. Uninitialized Properties

A subtle difference appears when declaring class properties without an initial value, such as foo!: string;.

  • Assignment semantics: TypeScript emits nothing for uninitialized fields. They do not exist on the object until a value is assigned.
  • Define semantics: ECMAScript dictates that every declared field exists on the instance. TypeScript emits Object.defineProperty(this, "foo", { value: undefined }), meaning the property will explicitly exist on the instance with the value undefined. This can affect operations like Object.keys() or 'foo' in instance.

3. Readonly and Non-Writable Properties

When a base class defines a read-only property (a getter without a setter, or a non-writable descriptor):

  • Assignment ([[Set]]): Attempting to initialize the field in a subclass throws a TypeError in strict mode because you cannot assign to a non-writable property via [[Set]].
  • Define ([[Define]]): Object.defineProperty successfully creates a new own property on the subclass instance, overriding the inherited descriptor without throwing an error.

The Role of useDefineForClassFields

Historically, TypeScript used assignment semantics to align with early class proposals. When TC39 finalized the class fields specification using define semantics, TypeScript introduced the useDefineForClassFields compiler option in tsconfig.json.

  • useDefineForClassFields: false: TypeScript transpiles class fields to constructor assignments (this.x = 1).
  • useDefineForClassFields: true: TypeScript transpiles class fields using Object.defineProperty, matching official ECMAScript behavior.

This flag defaults to true when the target is set to ES2022 or later (including ESNext), and false for older targets unless explicitly specified.

Summary

The difference between define and assignment semantics determines whether class fields run prototype accessors or create direct instance properties. Assignment semantics behaves like traditional imperative code (this.x = value), whereas define semantics creates explicit, isolated own properties on the instance using Object.defineProperty.
