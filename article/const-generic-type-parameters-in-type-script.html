Const Generic Type Parameters in TypeScript

TypeScript 5.0 introduced const generic type parameters, allowing developers to enforce const-like literal inference directly at the declaration site. By prepending a type parameter with the const modifier, TypeScript automatically infers the most specific literal and immutable type for arguments passed to a function, eliminating the need for callers to manually append as const to their data.

Basic Syntax

To declare a const generic type parameter, place the const keyword immediately before the type parameter identifier inside the angle brackets:

function functionName<const T>(param: T): T {
  return param;
}

This syntax applies to function declarations, arrow functions, methods, and classes:

// Arrow function syntax
const createConfig = <const T>(config: T): T => config;

// Method syntax
class Builder {
  setOptions<const T>(options: T): T {
    return options;
  }
}

How It Works

Without the const modifier, TypeScript widens literal types when values are passed as generic arguments. For example, an array of strings is inferred as string[], and object properties are inferred as general primitive types such as string or number.

// Standard Generic
function getRoles<T extends readonly string[]>(roles: T): T {
  return roles;
}

// Inferred as string[]
const roles1 = getRoles(["admin", "editor"]);

To preserve the exact literal tuple ["admin", "editor"], you would traditionally have to write getRoles(["admin", "editor"] as const).

With const type parameters, literal inference is applied automatically:

// Const Generic
function getRoles<const T extends readonly string[]>(roles: T): T {
  return roles;
}

// Inferred as readonly ["admin", "editor"]
const roles2 = getRoles(["admin", "editor"]);

Constraints and Object Types

You can combine const type parameters with extends constraints. When defining constraints on arrays or objects, use readonly types to ensure full compatibility with the inferred immutable values:

type Route = {
  readonly path: string;
  readonly method: "GET" | "POST";
};

function defineRoute<const T extends Route>(route: T): T {
  return route;
}

const myRoute = defineRoute({
  path: "/users",
  method: "GET",
});
// Inferred as: { readonly path: "/users"; readonly method: "GET" }

Key Considerations

  1. Readonly Inferences: Values inferred through const generics become deeply readonly. For example, [1, 2, 3] is inferred as readonly [1, 2, 3].
  2. Call Site Only: The const modifier only changes inference for literals created at the call site. If a variable is defined beforehand without as const and then passed into the function, TypeScript retains the widened type of the pre-existing variable.
