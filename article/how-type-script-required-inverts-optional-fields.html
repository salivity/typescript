How TypeScript Required Inverts Optional Fields

TypeScript's Required<T> utility type transforms an existing type by making all of its optional properties strictly mandatory. This article explains how Required<T> achieves this inversion under the hood using mapped types and the -? mapping modifier, details the distinction between optional tokens and undefined types, and covers its shallow behavior.

The Definition of Required<T>

In the TypeScript standard library, Required<T> is defined as a mapped type:

type Required<T> = {
    [P in keyof T]-?: T[P];
};

This definition consists of three primary components:

  1. keyof T: Captures all property keys (strings, numbers, symbols) belonging to the source type T.
  2. [P in keyof T]: Iterates over each property key P in T, replicating the structure of the original object.
  3. T[P]: Uses indexed access to look up and retain the original value type associated with property P.

The -? Mapping Modifier

The core mechanism that inverts optional fields into required fields is the -? modifier.

In TypeScript mapped types, you can add or remove property modifiers using + or - prefixes. When declaring properties in an interface, appending ? marks a field as optional:

interface UserProfile {
    id: string;
    displayName?: string; // Optional
    bio?: string;         // Optional
}

By default, mapped types preserve the existing modifiers of the source type. When transforming a type, TypeScript allows you to explicitly alter these modifiers:

  • +? (or simply ?): Explicitly adds the optional modifier to every mapped property.
  • -?: Explicitly strips the optional modifier from every mapped property.

When Required<T> executes [P in keyof T]-?, the compiler iterates through every field. If a field contains the optional token ?, the -? instruction removes it. If a field is already required, -? has no effect and leaves it required.

type CompleteUserProfile = Required<UserProfile>;

// Resulting structure:
// type CompleteUserProfile = {
//     id: string;
//     displayName: string;
//     bio: string;
// }

How -? Affects undefined

Removing the optional token has a direct effect on whether a property accepts undefined.

When a property is declared with ? (such as bio?: string), TypeScript implicitly creates a union between the declared type and undefined (bio?: string | undefined), while also allowing the key to be omitted entirely.

When -? removes the optional token:

  1. The property key becomes required on the object; it can no longer be omitted.
  2. The implicit undefined introduced by the ? modifier is removed from the value type.

However, if a property is explicitly declared with undefined without the optional token, -? will not remove undefined:

interface Example {
    a?: string;            // Becomes `string` in Required<Example>
    b: string | undefined; // Remains `string | undefined` in Required<Example>
}

In the case of property b, the key is already required, and the undefined is an explicit part of the type definition rather than a consequence of the ? modifier. Consequently, Required<T> requires the key b to be present, but its value may still be undefined.

Shallow Transformation Behavior

Required<T> is a shallow utility type. It only iterates over the top-level keys of T. If an object contains nested objects with optional properties, those nested properties will remain optional:

interface Settings {
    theme?: string;
    notifications?: {
        email?: boolean;
        push?: boolean;
    };
}

type RequiredSettings = Required<Settings>;

In RequiredSettings, both theme and notifications are required keys. However, notifications.email and notifications.push retain their optional status because Required<T> does not recursively traverse nested structures. For deep enforcement, a custom recursive mapped type using -? at each level is required.
