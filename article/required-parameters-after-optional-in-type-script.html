Required Parameters After Optional in TypeScript

In TypeScript, required parameters cannot follow optional parameters in standard function declarations. Because JavaScript and TypeScript map function arguments strictly by position, placing an optional parameter before a required parameter creates ambiguity during function invocation and triggers a compiler error. This article explains why TypeScript enforces this restriction and outlines the standard approaches to work around it.

The TypeScript Restriction

When you define a function where an optional parameter (denoted with ?) precedes a required parameter, TypeScript generates a compile-time error:

// Compiler Error: A required parameter cannot follow an optional parameter. (TS1016)
function createUser(nickname?: string, email: string) {
    return { nickname, email };
}

Because function arguments in JavaScript are positional, there is no syntax to omit the first argument while providing the second without explicitly passing undefined.

Solutions and Workarounds

There are three primary ways to handle scenarios where an optional value conceptually precedes a required one.

1. Reorder the Parameters

The most direct solution is to place all required parameters first, moving all optional parameters to the end of the parameter list.

function createUser(email: string, nickname?: string) {
    return { email, nickname };
}

// Valid invocations:
createUser("user@example.com");
createUser("user@example.com", "coder123");

2. Use Object Destructuring

When a function accepts multiple arguments, wrapping them in a single object removes positional constraints entirely. Properties within an object can be required or optional regardless of the order in which they are written.

interface UserConfig {
    nickname?: string;
    email: string;
}

function createUser({ nickname, email }: UserConfig) {
    return { nickname, email };
}

// Valid invocation:
createUser({ email: "user@example.com" });
createUser({ nickname: "coder123", email: "user@example.com" });

This is the recommended pattern in modern TypeScript for functions that take more than two or three arguments or need flexible ordering.

3. Use Default Values with Explicit undefined

If a parameter has a default value instead of being explicitly marked with ?, TypeScript technically allows it to precede a required parameter. However, the caller must explicitly pass undefined to use the default value:

function calculateDiscount(rate: number = 0.1, price: number) {
    return price * (1 - rate);
}

// Caller must pass undefined to trigger the default rate:
calculateDiscount(undefined, 100);

While syntactically valid, this pattern generally degrades developer experience and code readability compared to reordering parameters or using object destructuring.
