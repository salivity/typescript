Type-Safe Proxy Method Interception in TypeScript

This article explains how to build a type-safe Proxy wrapper in TypeScript that intercepts object method calls while preserving exact parameter types, return types, and IDE autocompletion. By leveraging TypeScript generics, conditional types, and standard ES6 Proxy handlers, you can cleanly intercept, log, or mutate method execution without degrading the target instance to any or breaking this context bindings.

The Challenge with Standard Proxies

By default, wrapping an object with new Proxy(target, handler) returns the original type T, but TypeScript's built-in type definitions do not validate dynamic modifications made inside proxy traps. When intercepting method invocations via the get trap, returning a modified function often introduces type discrepancies, loses generic method constraints, or breaks method context if this is unbound.

To solve this, the proxy factory must enforce two guarantees:

  1. The return type must exactly mirror the target's interface T.
  2. The interception logic must be strongly typed against the target's callable keys.

Defining the Method Interceptor Types

First, create utility types to extract only method keys from a given object and specify the signature of the interceptor callback:

type MethodNames<T> = {
  [K in keyof T]: T[K] extends (...args: any[]) => any ? K : never;
}[keyof T];

type MethodArgs<T, K extends MethodNames<T>> = T[K] extends (...args: infer A) => any ? A : never;

type MethodReturn<T, K extends MethodNames<T>> = T[K] extends (...args: any[]) => infer R ? R : never;

export type MethodInterceptor<T extends object> = <K extends MethodNames<T>>(
  methodName: K,
  originalMethod: (...args: MethodArgs<T, K>) => MethodReturn<T, K>,
  args: MethodArgs<T, K>,
  target: T
) => MethodReturn<T, K>;
  • MethodNames<T> filters out non-function properties from T.
  • MethodArgs<T, K> and MethodReturn<T, K> preserve the precise arguments and return types for each respective method.
  • MethodInterceptor<T> ensures that the interception hook receives the correct arguments and returns the expected type for the intercepted method.

Implementing the Typed Proxy Factory

With the types in place, implement the proxy wrapper function. The get trap identifies whether the requested property is a function. If it is, the trap returns a wrapped function that routes execution through the typed interceptor while maintaining correct this binding:

export function createMethodProxy<T extends object>(
  target: T,
  interceptor: MethodInterceptor<T>
): T {
  return new Proxy(target, {
    get(obj, prop, receiver) {
      const originalValue = Reflect.get(obj, prop, receiver);

      if (typeof originalValue === 'function') {
        const methodName = prop as MethodNames<T>;

        return (...args: any[]) => {
          const boundMethod = originalValue.bind(obj);
          return interceptor(
            methodName,
            boundMethod,
            args as MethodArgs<T, typeof methodName>,
            obj
          );
        };
      }

      return originalValue;
    },
  });
}

Using Reflect.get(obj, prop, receiver) ensures inherited properties and getters on the prototype chain resolve correctly. Calling originalValue.bind(obj) guarantees that internal references to this inside class methods remain bound to the actual target instance rather than the proxy handler.

Practical Usage Example

Consider a service class handling database operations:

class UserService {
  constructor(private prefix: string) {}

  getUser(id: number): { id: number; name: string } {
    return { id, name: `${this.prefix}_User_${id}` };
  }

  saveUser(user: { id: number; name: string }): boolean {
    return true;
  }
}

const service = new UserService("Prod");

const proxiedService = createMethodProxy(service, (methodName, originalMethod, args) => {
  console.log(`Executing ${String(methodName)} with arguments:`, args);
  
  const startTime = performance.now();
  const result = originalMethod(...args);
  const duration = performance.now() - startTime;

  console.log(`${String(methodName)} completed in ${duration.toFixed(2)}ms`);
  return result;
});

Type Verification

When calling methods on proxiedService, full type safety is retained:

// Correct call: Fully typed autocompletion, no type errors
const user = proxiedService.getUser(101); 

// TypeScript Error: Argument of type 'string' is not assignable to parameter of type 'number'.
proxiedService.getUser("invalid_id");

// Return type is recognized as { id: number; name: string }
console.log(user.name);

This pattern preserves all method signatures, parameter validations, and return values without requiring manual type assertions at call sites.
