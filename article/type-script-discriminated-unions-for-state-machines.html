TypeScript Discriminated Unions for State Machines

This article explains what discriminated unions are in TypeScript and why they are the standard recommendation for modeling finite state machines. You will learn how the combination of literal types, a shared discriminant property, and exhaustive type checking prevents invalid application states, simplifies state transitions, and guarantees compile-time safety across your state-driven logic.

What Is a Discriminated Union?

A discriminated union (also known as a tagged union or algebraic data type) is a pattern in TypeScript where multiple object types are combined into a single union type, with each member sharing a common literal property known as the "discriminant" or "tag."

TypeScript evaluates this discriminant property to narrow down the specific type within the union automatically.

type Circle = { kind: "circle"; radius: number };
type Square = { kind: "square"; sideLength: number };

type Shape = Circle | Square;

function getArea(shape: Shape): number {
  switch (shape.kind) {
    case "circle":
      return Math.PI * shape.radius ** 2; // TypeScript knows this is Circle
    case "square":
      return shape.sideLength ** 2;       // TypeScript knows this is Square
  }
}

Why Discriminated Unions Excel in State Machines

A state machine relies on a fundamental principle: a system can only exist in one of a finite set of states at any given moment, and transitions between these states must be explicit. Discriminated unions are the ideal vehicle for this pattern for three major reasons:

1. Making Impossible States Unrepresentable

A common anti-pattern in state management is grouping all potential properties into a single interface with optional fields:

// Anti-pattern: prone to invalid states
interface RequestState {
  status: "idle" | "loading" | "success" | "error";
  data?: ResponseData;
  error?: Error;
}

In the model above, nothing stops a bug from producing a state where status is "loading", but both data and error are populated.

With discriminated unions, each state explicitly defines only the data it is allowed to carry:

type RequestState =
  | { status: "idle" }
  | { status: "loading" }
  | { status: "success"; data: ResponseData }
  | { status: "error"; error: Error };

This guarantees that an "idle" or "loading" state can never accidentally access data or error, eliminating runtime undefined errors before code reaches production.

2. Built-in Exhaustive Type Checking

When writing transition logic or state handlers, TypeScript enforces that every possible state is accounted for. By asserting the unhandled state against the never type, the compiler alerts you immediately if a new state is introduced without updating every handler.

function handleState(state: RequestState): string {
  switch (state.status) {
    case "idle":
      return "Ready to start.";
    case "loading":
      return "Loading data...";
    case "success":
      return `Loaded: ${state.data.title}`;
    case "error":
      return `Failed: ${state.error.message}`;
    default: {
      const _exhaustiveCheck: never = state;
      return _exhaustiveCheck;
    }
  }
}

If you add a new state—such as { status: "cancelled" }—to RequestState, the default branch will fail compilation because state cannot be assigned to never.

3. Clear State Transitions

Discriminated unions make finite state transition functions deterministic and safe. You can easily map current states and incoming actions to valid next states:

type Action =
  | { type: "FETCH" }
  | { type: "RESOLVE"; payload: ResponseData }
  | { type: "REJECT"; error: Error };

function transition(state: RequestState, action: Action): RequestState {
  switch (state.status) {
    case "idle":
      if (action.type === "FETCH") return { status: "loading" };
      return state;

    case "loading":
      if (action.type === "RESOLVE") {
        return { status: "success", data: action.payload };
      }
      if (action.type === "REJECT") {
        return { status: "error", error: action.error };
      }
      return state;

    case "success":
    case "error":
      if (action.type === "FETCH") return { status: "loading" };
      return state;
  }
}

By accurately restricting what data belongs to which phase, discriminated unions align TypeScript's type system directly with the mathematical definition of a state machine, replacing ambiguous runtime checks with strict compile-time guarantees.
