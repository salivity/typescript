Numeric vs String Enums Serialization in TypeScript

In TypeScript, enums allow developers to define sets of named constants, but numeric and string enums compile to fundamentally different JavaScript structures, leading to distinct serialization behaviors. While numeric enums serialize to raw numbers and generate bidirectional runtime objects, string enums serialize to meaningful string literals with forward-only mappings. Understanding these differences is critical when transmitting data over networks, storing state, or working with JSON payloads.

Compiled JavaScript Representation

The root cause of serialization differences lies in how the TypeScript compiler emits JavaScript for each enum type.

Numeric Enums

Numeric enums generate a reverse mapping by default. This allows lookups from enum name to value, and from value back to name:

enum Status {
  Pending, // 0
  Active,  // 1
}

Compiles to:

var Status;
(function (Status) {
    Status[Status["Pending"] = 0] = "Pending";
    Status[Status["Active"] = 1] = "Active";
})(Status || (Status = {}));

At runtime, the Status object evaluates to:

{
  "0": "Pending",
  "1": "Active",
  "Pending": 0,
  "Active": 1
}

String Enums

String enums do not create reverse mappings because string keys cannot map back unambiguously in a standard runtime pattern without adding unnecessary overhead:

enum Status {
  Pending = "PENDING",
  Active = "ACTIVE",
}

Compiles to:

var Status;
(function (Status) {
    Status["Pending"] = "PENDING";
    Status["Active"] = "ACTIVE";
})(Status || (Status = {}));

At runtime, the Status object evaluates strictly to:

{
  "Pending": "PENDING",
  "Active": "ACTIVE"
}

Serializing Enum Values in JSON

When an enum property on an object is serialized using JSON.stringify(), the output directly reflects the enum member's assigned value.

Numeric Enum Value Serialization

When serializing an object containing a numeric enum value, the JSON output contains only the assigned integer:

enum Role {
  User,
  Admin,
}

const account = { id: 1, role: Role.Admin };
console.log(JSON.stringify(account));
// Output: {"id":1,"role":1}
  • Advantage: Minimal payload size. Integers occupy fewer bytes than strings.
  • Disadvantage: Low readability. External consumers of the API cannot infer what 1 means without consulting documentation or schema definitions.

String Enum Value Serialization

When serializing an object containing a string enum value, the output preserves the underlying string value:

enum Role {
  User = "USER",
  Admin = "ADMIN",
}

const account = { id: 1, role: Role.Admin };
console.log(JSON.stringify(account));
// Output: {"id":1,"role":"ADMIN"}
  • Advantage: Self-documenting payloads. Network tabs, logs, and database records remain easily readable without schema translation.
  • Disadvantage: Slightly larger network payload compared to integers.

Serializing the Enum Object Itself

If an application attempts to serialize the entire enum definition object (for example, sending all possible options to a frontend dropdown), the differences are significant:

  • Numeric Enums: JSON.stringify(Role) outputs both directions:

    {"0":"User","1":"Admin","User":0,"Admin":1}

    Iterating over this serialized output requires filtering out numeric keys to avoid duplicating options.

  • String Enums: JSON.stringify(Role) outputs a clean key-value dictionary:

    {"User":"USER","Admin":"ADMIN"}

Deserialization and Runtime Safety

During deserialization (JSON.parse()):

  1. Numeric Enums: Any number can bypass loose runtime validations, and missing values can easily lead to invalid states if payload numbers change or shift due to reordered enum definitions.
  2. String Enums: Payloads are bound to explicit strings. Reordering definitions in TypeScript does not change the serialized value, preventing silent data corruption across API updates.
