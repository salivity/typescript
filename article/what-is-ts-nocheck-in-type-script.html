What Is ts-nocheck in TypeScript?

The // @ts-nocheck directive in TypeScript is a special comment placed at the top of a file to completely disable type checking for that specific file. While TypeScript normally inspects your code for type errors, missing properties, and syntax anomalies, this directive tells the compiler to bypass all type validation within the file. This guide explains what the directive does, how to use it, its most common use cases, and how it compares to other suppression comments.

How ts-nocheck Works

When the TypeScript compiler encounters // @ts-nocheck at the beginning of a source file, it suppresses all type-related diagnostic errors that would normally be reported for that file.

To use the directive, add it as a single-line comment at the very top of your file:

// @ts-nocheck

let count: number = "this is a string"; // No error reported
count.nonExistentMethod();             // No error reported

Even though the assignment and method call are invalid according to TypeScript's type system, the compiler produces zero errors during compilation.

Common Use Cases

While bypassing TypeScript's safety features is generally discouraged, there are specific scenarios where // @ts-nocheck is practical:

  • Migrating Legacy JavaScript Projects: When converting a large JavaScript codebase to TypeScript, converting every file simultaneously can cause hundreds of compiler errors. Using // @ts-nocheck allows you to rename .js files to .ts and re-enable type checks incrementally over time.
  • Auto-Generated Files: Code produced by external generators or build tools may not always adhere to your project's strict TypeScript configuration. Adding this directive prevents generated code from breaking your build.
  • Rapid Prototyping: During early experimentation, you may want to focus on runtime logic without spending time defining complex types or interfaces.
  • Troubleshooting and Debugging: Temporarily adding the directive helps isolate whether a build failure is caused by runtime issues or purely static type mismatches.

Difference Between ts-nocheck and ts-ignore

TypeScript offers several comment directives to control error reporting. The primary difference lies in their scope:

  • // @ts-nocheck: Disables all type checking for the entire file. It must be placed at the top of the file to take effect.
  • // @ts-ignore: Suppresses errors only on the immediate next line of code. The rest of the file continues to be type-checked.
  • // @ts-expect-error: Suppresses errors on the immediate next line, but will trigger an error if the suppressed line does not actually contain a type error.

Risks and Best Practices

Using // @ts-nocheck removes the safety guarantees that TypeScript provides. Code inside an unchecked file can introduce runtime crashes that the compiler would normally prevent, such as accessing undefined properties or passing incorrect arguments.

Best practices when using the directive include:

  1. Treat it as temporary: Whenever possible, use // @ts-nocheck as a placeholder during migrations with a plan to remove it later.
  2. Prefer localized suppression: If only one or two lines are causing issues, use // @ts-expect-error instead of turning off checks for the whole file.
  3. Audit files regularly: Track which files in your repository contain // @ts-nocheck to ensure technical debt does not accumulate unnoticed.
