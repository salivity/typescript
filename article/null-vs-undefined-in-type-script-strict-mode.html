Null vs Undefined in TypeScript Strict Mode

In TypeScript's strict mode—specifically when the strictNullChecks flag is enabled—null and undefined become distinct, separate types that are no longer automatically assignable to other domain types. Semantically, undefined represents the default absence of a value (such as an uninitialized variable or missing argument), while null represents the deliberate, intentional absence of an object value. Enforcing strict mode prevents unexpected runtime crashes, such as the infamous "cannot read properties of undefined," by forcing developers to explicitly declare and narrow nullable types.

The Core Semantic Difference

  • undefined: Indicates that a variable has been declared but has not yet been assigned a value, an object property is missing, or a function does not explicitly return a value. It is the JavaScript runtime default for uninitialized states.
  • null: Indicates an intentional, programmatic absence of any object value. It is assigned purposefully by developers or APIs to signal "no value" or an empty reference.
let unassigned: undefined; // implicitly or explicitly undefined
let empty: null = null;    // intentionally cleared or empty

Behavior Without Strict Mode vs. With Strict Mode

In standard TypeScript (with strictNullChecks: false), null and undefined are treated as subtypes of all other types. A variable typed as string or number can accept null or undefined without the compiler raising an error:

// strictNullChecks: false
let username: string = "Alice";
username = null;      // Allowed
username = undefined; // Allowed

When strict mode is enabled (strict: true or strictNullChecks: true), null and undefined become their own isolated types. Assigning them to primitive or object types results in a compile-time error:

// strictNullChecks: true
let username: string = "Alice";
username = null;      // Error: Type 'null' is not assignable to type 'string'.
username = undefined; // Error: Type 'undefined' is not assignable to type 'string'.

Explicit Union Types

To allow a variable to hold null or undefined under strict mode, you must explicitly declare a union type:

let nullableUser: string | null = null;
let optionalUser: string | undefined = undefined;

This enforces explicit design decisions. If an API returns string | null, you are forced by the compiler to check for null before accessing string methods.

Optional Properties and Parameters

TypeScript treats optional properties and parameters with special affinity toward undefined, not null. Using the ? modifier automatically appends | undefined to the type:

interface UserProfile {
  name: string;
  bio?: string; // Type is string | undefined
}

const userA: UserProfile = { name: "Alice", bio: undefined }; // Valid
const userB: UserProfile = { name: "Alice" };                  // Valid
const userC: UserProfile = { name: "Alice", bio: null };       // Error: Type 'null' is not assignable to type 'string | undefined'.

Equality and Type Narrowing

Because JavaScript treats null and undefined differently depending on the operator used, strict TypeScript adheres to the same logic:

  • Loose Equality (==): null == undefined evaluates to true. Using value == null checks for both null and undefined at once.
  • Strict Equality (===): null === undefined evaluates to false.
function processValue(text: string | null | undefined) {
  // Loose check eliminates both null and undefined
  if (text == null) {
    return;
  }
  // TypeScript narrows 'text' to 'string' here
  console.log(text.toUpperCase());
}

Modern TypeScript code typically handles both values cleanly using:

  • Optional Chaining (?.): Short-circuits and returns undefined if the operand is either null or undefined.
  • Nullish Coalescing (??): Falls back to an alternative expression only if the left-hand side is null or undefined.
