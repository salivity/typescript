Manage TypeScript Private State Using WeakMaps

Managing private state using WeakMap objects in TypeScript offers true runtime encapsulation while preventing memory leaks through automatic garbage collection. This pattern decouples private data from the class instance itself by storing state externally, keyed to the object reference. This article explains how to implement WeakMap-based private state in TypeScript, demonstrates the pattern with clean type-safe code, and covers key architectural benefits and edge cases.

The WeakMap Private Pattern

A WeakMap is a collection of key-value pairs where keys must be objects and are held weakly. When an object used as a key is dereferenced elsewhere in your application, its entry in the WeakMap becomes eligible for garbage collection.

By keeping the WeakMap instance scoped inside a module and not exporting it, external code cannot access the map. Consequently, external code cannot access the private properties associated with an instance, even through reflection APIs like Object.getOwnPropertyNames() or Reflect.ownKeys().

Implementing Typed Private State

To implement this pattern safely in TypeScript, define an interface for the private state and instantiate a typed WeakMap at the module level.

// Define the shape of your private state
interface UserPrivateState {
    passwordHash: string;
    loginAttempts: number;
}

// Module-scoped WeakMap, not exported
const privateState = new WeakMap<User, UserPrivateState>();

export class User {
    public readonly username: string;

    constructor(username: string, initialPasswordHash: string) {
        this.username = username;

        // Initialize private state
        privateState.set(this, {
            passwordHash: initialPasswordHash,
            loginAttempts: 0,
        });
    }

    public authenticate(attemptHash: string): boolean {
        const state = privateState.get(this);

        if (!state) {
            throw new Error("Instance state not initialized or destroyed.");
        }

        if (state.passwordHash === attemptHash) {
            state.loginAttempts = 0;
            return true;
        }

        state.loginAttempts += 1;
        return false;
    }

    public get attempts(): number {
        const state = privateState.get(this);
        return state ? state.loginAttempts : 0;
    }
}

Encapsulation and TypeScript Type Safety

In standard TypeScript, marking a member private only enforces compile-time restrictions; the property still exists on the JavaScript object at runtime. JavaScript native private fields (#field) solve runtime visibility, but WeakMap provides unique structural advantages:

  1. True Runtime Privacy: No reflection mechanism in JavaScript can traverse from the key (this) to the WeakMap value without direct access to the WeakMap identifier.
  2. Decoupled Architecture: State schemas can be declared separately from class signatures, keeping public interfaces clean and free of implementation details.
  3. Immutability of the Instance Structure: The instance itself does not mutate its own property list when updating private state, making instances structurally stable for engine optimizations.

Handling State Initialization and Inheritance

When dealing with class inheritance, child classes do not automatically inherit access to a parent's WeakMap unless the map is explicitly shared via protected helper functions or an internal module export.

export class AdvancedUser extends User {
    // AdvancedUser instances inherit the parent constructor, 
    // populating the WeakMap, but cannot directly inspect privateState.
    public resetAccount(): void {
        // Must interact through public/protected methods on User
        // Direct access to state.passwordHash is impossible here
    }
}

If inheritance requires shared access to private state across subclasses within the same module, expose explicit helper functions that validate the instance type before performing .get() or .set() operations.
