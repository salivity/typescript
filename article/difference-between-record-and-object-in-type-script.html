Difference Between Record and object in TypeScript

In TypeScript, both object and the Record utility type represent non-primitive data structures, but they serve fundamentally different purposes regarding type safety and property access. While object represents any non-primitive value without defining specific properties, Record<Keys, Type> is a generic mapped type that explicitly defines both the allowed property keys and their corresponding value types. This article breaks down how each type functions, their core differences, and how to choose the right one for your code.

The object Type

The object type (lowercase) was introduced in TypeScript 2.2 to represent any non-primitive value. A non-primitive is anything that is not a string, number, bigint, boolean, symbol, null, or undefined.

When you type a variable as object, TypeScript knows that it is a complex data structure (such as an object, array, or function), but it knows nothing about the properties inside it. As a result, TypeScript prevents you from reading or writing arbitrary properties on that value.

let data: object;

data = { name: "Alice", age: 30 }; // Valid
data = [1, 2, 3];                  // Valid (arrays are objects)
data = () => {};                   // Valid (functions are objects)
data = "hello";                    // Error: Type 'string' is not assignable to type 'object'

// Property access fails:
console.log(data.name); 
// Error: Property 'name' does not exist on type 'object'.

The primary purpose of object is to restrict functions or APIs to non-primitive arguments, such as in Object.create(proto).

The Record<Keys, Type> Utility Type

Record is a built-in generic utility type defined as:

type Record<K extends keyof any, T> = {
    [P in K]: T;
};

It takes two type arguments:

  1. Keys: The allowed key types, typically a union of string, number, or symbol literals (or generic string, number).
  2. Type: The data type assigned to each key's value.

Unlike object, Record gives TypeScript full knowledge of the keys and their associated value types, enabling type checking and property access.

// A dictionary mapping string keys to number values
const scores: Record<string, number> = {
  math: 95,
  science: 88,
};

console.log(scores.math); // Valid, returns number

// A strict mapping using union keys
type UserRole = "admin" | "editor" | "guest";

const rolePermissions: Record<UserRole, string[]> = {
  admin: ["read", "write", "delete"],
  editor: ["read", "write"],
  guest: ["read"],
};

Key Differences

Feature object Record<Keys, Type>
Type Category TypeScript primitive type keyword Built-in generic mapped utility type
Property Access Disallowed; properties cannot be read or written directly Allowed and type-checked based on the provided keys
Key Typing Not configurable Configurable via Keys parameter
Value Typing Not configurable Configurable via Type parameter
Accepts Functions/Arrays Yes (both are non-primitives) Only if the structure satisfies the key-value contract

When to Use Each

  • Use object when you need to ensure an argument or variable is not a primitive value, but you do not need to interact with its properties directly (e.g., weakly-typed utility functions, prototype manipulation, or metadata storage).
  • Use Record when you are creating key-value stores, lookup tables, dictionaries, or mapping a known set of keys (such as union types) to specific values with full type safety and auto-completion.
