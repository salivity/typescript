TypeScript ReadonlyMap vs Map: Key Differences

In TypeScript, Map and ReadonlyMap represent key-value collections with distinct mutability constraints. While the standard Map allows dynamic addition, modification, and removal of entries, ReadonlyMap enforces compile-time immutability by stripping away all mutating methods. This article breaks down the technical differences between these two types, examines their assignability rules, and highlights how to use them effectively to ensure data integrity in your applications.

What is the Standard Map?

The standard Map<K, V> type in TypeScript represents the native ECMAScript 6 Map object. It provides a full set of read and write operations for managing key-value pairs.

A standard Map includes:

  • Mutating methods: set(key, value), delete(key), clear()
  • Reading methods: get(key), has(key), size
  • Iteration methods: entries(), keys(), values(), forEach(), [Symbol.iterator]()

Because it allows mutation, any part of your codebase with access to a Map instance can alter its contents directly:

const userRoles = new Map<string, string>();
userRoles.set("alice", "admin");
userRoles.delete("alice");
userRoles.clear();

What is ReadonlyMap?

ReadonlyMap<K, V> is a built-in TypeScript interface designed to prevent accidental modifications to a map collection. It is purely a compile-time construct—not a separate runtime class.

The ReadonlyMap interface includes only the non-mutating members of Map:

  • Inspection properties: size
  • Lookup methods: get(key), has(key)
  • Iteration methods: entries(), keys(), values(), forEach(), [Symbol.iterator]()

It completely omits set(), delete(), and clear(). Calling any of these methods on a ReadonlyMap produces a compile-time error:

const readOnlyRoles: ReadonlyMap<string, string> = new Map([["alice", "admin"]]);

console.log(readOnlyRoles.get("alice")); // Allowed: "admin"
console.log(readOnlyRoles.size);         // Allowed: 1

// Compile error: Property 'set' does not exist on type 'ReadonlyMap<string, string>'.
readOnlyRoles.set("bob", "editor");

// Compile error: Property 'delete' does not exist on type 'ReadonlyMap<string, string>'.
readOnlyRoles.delete("alice");

Key Differences

1. Mutability and API Surface

  • Map provides a complete API for reading and writing data.
  • ReadonlyMap provides a restricted subset of the Map API, hiding all mutation methods at compile time.

2. Subtyping and Assignability

A standard Map<K, V> implements the ReadonlyMap<K, V> interface. Because Map possesses all the methods defined on ReadonlyMap, you can safely assign a Map to a variable or parameter typed as ReadonlyMap:

const mutableMap = new Map<number, string>([[1, "one"]]);
const readonlyReference: ReadonlyMap<number, string> = mutableMap; // Valid

However, the reverse is not true. You cannot assign a ReadonlyMap to a standard Map without an explicit type assertion because ReadonlyMap lacks the mutating methods:

function updateMap(map: Map<number, string>) {
  map.set(2, "two");
}

// Compile error: Argument of type 'ReadonlyMap<number, string>' is not assignable to 'Map<number, string>'.
updateMap(readonlyReference);

3. Runtime Existence

ReadonlyMap exists solely within the TypeScript type system. At runtime, the compiled JavaScript contains a standard Map instance. As a result:

  • You cannot instantiate a ReadonlyMap directly using new ReadonlyMap(). You must instantiate a new Map() and type-annotate it as ReadonlyMap.
  • JavaScript code or external libraries that bypass TypeScript's type checking can still mutate the underlying object.

4. Shallow Immutability

ReadonlyMap provides shallow protection. While the collection itself cannot have keys added, deleted, or reassigned, any mutable objects stored as values inside the map can still be modified:

interface UserProfile {
  name: string;
}

const profiles: ReadonlyMap<string, UserProfile> = new Map([
  ["u1", { name: "Alice" }]
]);

// This is still permitted because the object reference itself is mutable:
profiles.get("u1")!.name = "Bob";

To prevent this, values must also be typed with Readonly<T> (for example, ReadonlyMap<string, Readonly<UserProfile>>).

When to Use Each Type

  • Use Map internally within a class, module, or function when you need to construct, populate, or update key-value state.
  • Use ReadonlyMap in public APIs, function signatures, and class getters where a caller needs to read data or iterate over it, but should not be allowed to modify the underlying collection.
