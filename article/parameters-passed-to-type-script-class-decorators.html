Parameters Passed to TypeScript Class Decorators

In TypeScript, the parameters passed to a class decorator depend on whether your project uses legacy experimental decorators or the modern ECMAScript standard decorators introduced in TypeScript 5.0. This article details the specific arguments provided to class decorators in both systems, breaking down their types, contents, and practical applications.

Standard Decorators (TypeScript 5.0+)

Under the ECMAScript standard decorators (used when "experimentalDecorators": false or omitted in modern TypeScript), a class decorator receives exactly two parameters:

function myClassDecorator(value: Function, context: ClassDecoratorContext) {
  // ...
}

1. value (Function)

The first parameter is the class constructor itself that is being decorated. You can inspect static members, replace the constructor by returning a new subclass, or augment the class prototype directly.

2. context (ClassDecoratorContext)

The second parameter is an object containing metadata and utility methods related to the decorated class. The ClassDecoratorContext object contains:

  • kind: A string literal with the value 'class', identifying the decorator target type.
  • name: The name of the class as a string, or undefined if the class is anonymous.
  • addInitializer(initializer: () => void): A callback method that registers a custom initialization function. This function runs immediately after the class definition has been fully evaluated and its static elements initialized.

Legacy Decorators (experimentalDecorators)

If your project enables legacy decorators via the "experimentalDecorators": true flag in tsconfig.json, the implementation follows the older stage 2 decorator proposal.

In this legacy mode, a class decorator receives only a single parameter:

function myLegacyClassDecorator<T extends { new (...args: any[]): {} }>(target: T) {
  // ...
}

1. target (Function)

The sole parameter is the constructor function of the target class.

In legacy mode:

  • There is no second context argument.
  • The decorator can mutate the constructor (e.g., adding prototype methods).
  • The decorator can return a new constructor function to replace the original class definition.

Summary of Differences

Feature Legacy (experimentalDecorators) Standard (TypeScript 5.0+)
Number of Parameters 1 2
First Parameter target (Class Constructor) value (Class Constructor)
Second Parameter None context (ClassDecoratorContext)
Context Metadata Not available natively Includes kind, name, and addInitializer
