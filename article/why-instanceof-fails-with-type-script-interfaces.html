Why instanceof Fails With TypeScript Interfaces

The JavaScript instanceof operator evaluates whether an object's prototype chain contains the prototype property of a constructor function. When developers attempt to use instanceof to validate TypeScript interfaces, the code fails either at compile time or during runtime. This article explains the underlying mechanism of TypeScript's type erasure, why instanceof requires runtime values, and the standard patterns developers use to validate interface structures at runtime.

Understanding Type Erasure

TypeScript is a syntactic superset of JavaScript that adds static typing. However, JavaScript engines do not natively understand TypeScript syntax. To run in a browser or Node.js environment, TypeScript code must pass through a compiler (like tsc or Babel) that strips away all type annotations.

This process is known as type erasure. Interfaces, type aliases, and abstract method signatures exist purely for compile-time verification. When TypeScript compiles to JavaScript, every interface declaration is completely eliminated. Nothing is generated in the output JavaScript file to represent the interface.

How instanceof Operates at Runtime

The instanceof operator is a native JavaScript operator, not a TypeScript-exclusive feature. It requires a specific syntax:

object instanceof ConstructorFunction

During execution, instanceof reads the .prototype property of the entity on the right-hand side and walks the prototype chain of the object on the left-hand side to find a match.

Because TypeScript interfaces do not compile into JavaScript objects or constructor functions, using an interface with instanceof creates a fundamental conflict:

  1. At Compile Time: The TypeScript compiler detects that you are treating a type as a runtime value and flags error TS2693: 'User' only refers to a type, but is being used as a value here.
  2. At Runtime (if bypassed): If you bypass the compiler checks, the JavaScript engine throws a ReferenceError: User is not defined because no variable, class, or function named User exists in the execution environment.

Interfaces vs. Classes

Unlike interfaces, TypeScript class declarations generate actual JavaScript code. When you define a class:

class UserAccount {
  constructor(public name: string) {}
}

The compiler produces a corresponding JavaScript constructor function. Because UserAccount exists in memory as a function with a prototype at runtime, instanceof UserAccount works properly:

const account = new UserAccount("Alex");
console.log(account instanceof UserAccount); // true

Alternatives for Validating Interfaces at Runtime

Since instanceof cannot verify interfaces, alternative techniques are used to inspect and validate shapes at runtime.

1. User-Defined Type Guards

Custom type guards allow you to check properties manually using the in operator or typeof checks while narrowing the type within TypeScript:

interface User {
  id: string;
  name: string;
}

function isUser(obj: any): obj is User {
  return (
    typeof obj === "object" &&
    obj !== null &&
    typeof obj.id === "string" &&
    typeof obj.name === "string"
  );
}

if (isUser(data)) {
  console.log(data.name); // Safely typed as User
}

2. Discriminated Unions

If you need to differentiate between several related interfaces, add a literal property to act as a tag:

interface SuccessResponse {
  status: "success";
  data: string[];
}

interface ErrorResponse {
  status: "error";
  message: string;
}

type ApiResponse = SuccessResponse | ErrorResponse;

function handleResponse(response: ApiResponse) {
  if (response.status === "success") {
    console.log(response.data);
  } else {
    console.error(response.message);
  }
}

3. Schema Validation Libraries

When handling external data like API responses, validation libraries such as Zod or Yup define schemas that exist at runtime and can infer TypeScript types automatically:

import { z } from "zod";

const UserSchema = z.object({
  id: z.string(),
  name: z.string(),
});

type User = z.infer<typeof UserSchema>;

const result = UserSchema.safeParse(data);
if (result.success) {
  const user: User = result.data;
}

In summary, instanceof fails on TypeScript interfaces because interfaces are removed during compilation and provide no runtime constructor for JavaScript to inspect. To perform runtime assertions, rely on classes, type guards, or dedicated schema validation.
