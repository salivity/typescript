Combining satisfies and as const in TypeScript

TypeScript allows developers to enforce strict type contracts while preserving exact literal types and deep immutability by combining the satisfies operator with the as const assertion. This article explains how these two features interact, the correct syntax for chaining them, and why using them together provides superior type safety and developer ergonomics compared to using either feature on its own.

Can They Be Combined?

Yes, the satisfies operator and the as const assertion can be combined directly in a single declaration.

TypeScript evaluates as const first to produce a fully readonly, deeply narrowed literal type, and then evaluates satisfies to verify that this narrowed type conforms to a predefined interface or type definition without widening it.

The Syntax and Precedence

To use them together, place as const before satisfies:

type Palette = {
  primary: string;
  secondary: string;
  modes: readonly string[];
};

const theme = {
  primary: "#0070f3",
  secondary: "#111111",
  modes: ["light", "dark"],
} as const satisfies Palette;

In this example:

  1. as const converts all properties into readonly values and infers literal string types ("#0070f3", "#111111", readonly ["light", "dark"]) rather than generic string and string[].
  2. satisfies Palette ensures that the object matches the shape of Palette. If a required key is missing or misspelled, TypeScript throws a compile-time error.

Writing them in reverse (satisfies Palette as const) is invalid syntax and will produce a compiler error. The expression must first be asserted with as const before the resulting type is validated with satisfies.

Why Combine Both Features?

Using either feature in isolation leaves a gap in strictness:

1. Using satisfies alone

Using only satisfies validates the object shape and retains literal types for primitive values, but it does not make objects or arrays deeply immutable (readonly). Arrays, for instance, remain mutable tuples or arrays, which can lead to accidental mutations later in the codebase.

// Validated, but arrays are mutable
const theme = {
  modes: ["light", "dark"],
} satisfies { modes: string[] };

theme.modes.push("contrast"); // Allowed

2. Using as const alone

Using only as const creates full immutability and literal types, but it performs no validation against an intended shape or interface. If a required property is omitted or a typo is introduced, TypeScript will not flag it at the declaration site.

// Immutable, but no contract validation
const theme = {
  primry: "#0070f3", // Typo goes unnoticed
} as const;

3. Combining both

Combining as const satisfies Type delivers the benefits of both:

  • Contract Validation: Guarantees all required fields exist and conform to the specified type structure.
  • Literal Narrowing: Keeps the most specific types possible instead of widening to primitives like string or number.
  • Deep Immutability: Marks every property, nested object, and array as readonly, preventing runtime mutation bugs.
  • Exact Autocomplete: Enables IDEs to provide exact literal string suggestions based on the object's specific values.
