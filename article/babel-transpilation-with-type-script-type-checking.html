Babel Transpilation with TypeScript Type Checking

Using Babel exclusively for transpilation while relying on TypeScript for type checking provides the fastest possible build speeds without sacrificing type safety. In this setup, Babel ignores type errors, strips TypeScript-specific syntax, and transpiles your code to your target JavaScript environments using @babel/preset-typescript. Simultaneously, the TypeScript compiler (tsc) runs purely as a type-checking linter using the --noEmit flag. This separation of concerns allows build tools and bundlers to leverage Babel's optimized compilation pipelines and plugins, while automated checks and CI/CD pipelines enforce type correctness independently.

1. Install Required Dependencies

To establish this workflow, install the core Babel packages alongside the TypeScript preset, as well as TypeScript itself:

npm install --save-dev @babel/core @babel/cli @babel/preset-env @babel/preset-typescript typescript

2. Configure Babel for Transpilation

Create a babel.config.json file in the root of your project. Configure it with @babel/preset-env for syntax transpilation and @babel/preset-typescript to handle TypeScript files.

{
  "presets": [
    "@babel/preset-env",
    "@babel/preset-typescript"
  ]
}

Because Babel handles each file individually and purely strips types, it does not validate interfaces, types, or syntax validity according to TypeScript rules. It simply converts .ts and .tsx files into standard JavaScript.

3. Configure TypeScript for Type Checking

Generate or modify your tsconfig.json file. Two settings are critical for this workflow: noEmit and isolatedModules.

{
  "compilerOptions": {
    "target": "ESNext",
    "module": "ESNext",
    "moduleResolution": "node",
    "strict": true,
    "noEmit": true,
    "isolatedModules": true,
    "skipLibCheck": true
  },
  "include": ["src/**/*"]
}
  • noEmit: true: Tells the TypeScript compiler not to generate JavaScript output files (.js), ensuring that only Babel writes build artifacts.
  • isolatedModules: true: Enforces rules that prevent using TypeScript features that cannot be safely transpiled by single-file transpilers like Babel (such as const enum or legacy namespace merging).

4. Set Up NPM Scripts

Update your package.json to define explicit scripts for type checking, building, and running both tasks together:

{
  "scripts": {
    "type-check": "tsc --noEmit",
    "type-check:watch": "tsc --noEmit --watch",
    "build:js": "babel src --out-dir dist --extensions \".ts,.tsx\"",
    "build": "npm run type-check && npm run build:js"
  }
}
  • npm run type-check: Scans your source files and outputs any type or syntax errors to the terminal.
  • npm run build:js: Tells Babel to transpile all matching files into the dist directory.
  • npm run build: Chains both processes, ensuring a build succeeds only if the code passes both type checks and transpilation.

Considerations

Because Babel transpiles files in isolation, you must avoid TypeScript-only features that require full project-type awareness:

  • Avoid const enum declarations; use standard enum or object literals with as const instead.
  • Avoid namespace exports (namespace Foo {}).
  • Use explicit type-only imports and exports (import type { User } from './types') to ensure Babel completely removes them from the compiled output.
