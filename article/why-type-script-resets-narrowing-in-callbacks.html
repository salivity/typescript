Why TypeScript Resets Narrowing in Callbacks

TypeScript invalidates type narrowing inside nested callback functions because it cannot guarantee when the callback will execute or whether the narrowed variable will be mutated beforehand. To prevent runtime type errors caused by asynchronous execution or variable reassignment, TypeScript's control flow analysis takes a conservative approach and resets the variable's type back to its un-narrowed declaration inside closures.

The Problem: Deferred Execution and Mutability

Consider a common scenario where you check if a variable is defined before executing a callback:

let message: string | null = "Hello";

if (message !== null) {
  // Inside this block, message is narrowed to 'string'
  setTimeout(() => {
    console.log(message.toUpperCase()); // Error: 'message' is possibly 'null'
  }, 1000);
}

Even though you narrowed message to string right before registering the callback, TypeScript reports an error inside setTimeout.

This occurs because TypeScript separates the declaration of a function from its execution. A callback function might run immediately (like Array.prototype.forEach), or it might run asynchronously at a later time (like setTimeout, promises, or event listeners). Because message is declared using let, it is mutable. TypeScript recognizes that between the time the callback is created and the time it executes, other code could run and set message back to null.

How Property Mutation Affects Narrowing

The same behavior applies to object properties, even when the parent object is stored in a const binding:

interface User {
  name?: string;
}

function greet(user: User) {
  if (user.name) {
    [1, 2, 3].forEach(() => {
      console.log(user.name.toUpperCase()); // Error: 'user.name' is possibly 'undefined'
    });
  }
}

Although forEach runs synchronously, TypeScript generally applies closure narrowing rules across all callbacks regardless of their execution timing. It assumes any external function call or nested callback could invoke side effects that mutate user.name.

How to Fix Invalidated Narrowing

The most reliable way to preserve narrowing inside callbacks is to capture the narrowed value into an immutable local reference.

1. Assign to a const Variable

Variables declared with const cannot be reassigned. Because the reference is immutable, TypeScript guarantees its type will not change before the callback executes:

let message: string | null = "Hello";

if (message !== null) {
  const safeMessage = message; // safeMessage is inferred as 'string'
  setTimeout(() => {
    console.log(safeMessage.toUpperCase()); // Works cleanly
  }, 1000);
}

2. Destructure Object Properties

For object properties, destructuring creates a local const variable that retains its narrowed type inside any closure:

function greet(user: User) {
  const { name } = user;
  if (name) {
    [1, 2, 3].forEach(() => {
      console.log(name.toUpperCase()); // Works cleanly
    });
  }
}

By ensuring that values passed into closures cannot be altered after narrowing, you satisfy TypeScript's control flow analyzer and avoid unexpected runtime exceptions.
