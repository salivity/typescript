How TypeScript Types the Arguments Object

In TypeScript, standard non-arrow functions automatically expose the implicit arguments object, which is typed using the built-in IArguments interface. This article explains the structure of the IArguments type, how TypeScript handles indexed access and iteration for function arguments, and why modern TypeScript development generally favors rest parameters over the legacy arguments object for stricter type safety.

The Built-in IArguments Interface

When you reference arguments inside a standard function declaration or expression, TypeScript assigns it the global IArguments type defined in its standard library (lib.es5.d.ts):

interface IArguments {
    [index: number]: any;
    length: number;
    callee: Function;
    [Symbol.iterator](): IterableIterator<any>;
}

This interface defines arguments as an "array-like" object rather than an actual JavaScript Array.

Key Characteristics of IArguments

  1. Indexed Access Returns any: The index signature [index: number]: any allows numeric indexing (e.g., arguments[0], arguments[1]), but every retrieved value is typed as any. TypeScript does not infer specific parameter types from the function signature into the arguments indices.
  2. Standard Array Methods Are Absent: Because IArguments does not inherit from Array.prototype, methods like .map(), .filter(), .forEach(), and .slice() do not exist on the object and will trigger compile-time errors if called directly.
  3. Array-Like Properties: It provides a length property representing the number of arguments passed to the function at runtime, and a callee property pointing to the executing function.
  4. Iterable: In modern compilation targets (ES2015 and later), IArguments includes [Symbol.iterator], allowing it to be used in for...of loops or spread into a real array with [...arguments].

Scope and Availability

TypeScript enforces runtime JavaScript rules regarding where arguments can be used:

  • Standard Functions: Permitted in function declarations (function foo() {}) and standard function expressions (const foo = function() {}).
  • Arrow Functions: TypeScript flags arguments inside arrow functions because arrow functions do not bind their own arguments object, referring instead to the enclosing lexical scope's arguments.

Rest Parameters as the Type-Safe Alternative

Because IArguments resolves element types to any, it circumvents TypeScript's type checking. To achieve strict typing for variable numbers of arguments, use ES6 rest parameters instead of the arguments object:

// Rest parameters allow precise array or tuple typing
function sum(...numbers: number[]): number {
    return numbers.reduce((total, n) => total + n, 0);
}

Rest parameters provide true Array instances with complete type safety and direct access to native array methods.
