declare const enum vs declare enum in TypeScript

In TypeScript, ambient enums defined with the declare keyword inform the compiler about enum structures that exist in an external environment without generating code for their definition. The fundamental difference between a declare const enum and a standard declare enum is how member access is compiled: declare enum generates runtime property accesses against a presumed global or ambient object, while declare const enum inlines the member values directly as literals at compile time, eliminating any runtime object lookup.

Standard declare enum

A standard declare enum tells the TypeScript compiler that an enum object exists at runtime elsewhere (such as via a <script> tag or a global library), but no definition code should be emitted in the current file.

When your code accesses a member of a declare enum, TypeScript preserves the member access expression as a standard object lookup in the emitted JavaScript.

Example

TypeScript:

declare enum Direction {
  Up = 0,
  Down = 1,
}

const move = Direction.Up;

Compiled JavaScript:

"use strict";
const move = Direction.Up;

Because TypeScript emits Direction.Up, a real JavaScript object named Direction must exist in the runtime scope where this code runs. If that object is missing at runtime, the code throws a ReferenceError.

declare const enum

A declare const enum combines ambient declaration behavior with constant enum behavior. It instructs the compiler that the enum exists conceptually for type-checking and provides concrete compile-time constants, but no runtime object needs to be referenced.

When your code references a member of a declare const enum, TypeScript replaces the identifier with its actual literal value (number or string) directly at the call site.

Example

TypeScript:

declare const enum Direction {
  Up = 0,
  Down = 1,
}

const move = Direction.Up;

Compiled JavaScript:

"use strict";
const move = 0;

Because the value 0 is inlined directly, no Direction object is ever referenced or needed in the runtime environment.

Summary of Key Differences

Feature declare enum declare const enum
Code Generation for Members Compiles to a property lookup (e.g., Direction.Up). Inlines the literal value directly (e.g., 0).
Runtime Dependency Requires an actual Direction object in the global/runtime scope. Requires no runtime object; references are completely replaced.
Bundle Size & Performance Retains property access operations in the output JS. Slightly smaller and faster due to direct literal replacement.
Transpiler Compatibility Supported by single-file transpilers (e.g., Babel, SWC) if configured. Often problematic under --isolatedModules unless values are purely numeric/string and known locally.

When to Use Which

Use a standard declare enum when you are writing type definitions for an existing JavaScript library that exposes a real object at runtime containing reverse mappings or when you need to pass the enum object itself as a parameter.

Use a declare const enum when you are defining external constants where you want zero runtime overhead, guaranteed inlining, and you do not require a physical JavaScript object to back the values at execution time.
