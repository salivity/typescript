How to Type JavaScript Using JSDoc and TypeScript

JSDoc comments allow developers to provide rich static typing information directly inside standard JavaScript files, which the TypeScript compiler can read and validate without requiring a compilation step. This article explains how the TypeScript compiler interprets JSDoc annotations, how to enable type-checking in JavaScript files, and how to use key JSDoc tags to define primitives, functions, custom types, and generics.

Enabling TypeScript in JavaScript

TypeScript includes a built-in JavaScript language service that natively understands JSDoc. To enable type checking on JavaScript files, you can add a comment at the very top of any individual .js file:

// @ts-check

Alternatively, you can enable it globally across a project by configuring tsconfig.json or jsconfig.json:

{
  "compilerOptions": {
    "allowJs": true,
    "checkJs": true,
    "noEmit": true
  }
}

When enabled, TypeScript parses JSDoc comment blocks (/** ... */) and reports errors directly in your editor or during build-time checks just as it would with .ts files.

Basic Variable Typing with @type

The @type tag defines the type of a variable, constant, or property. You enclose the type name in curly braces.

/** @type {string} */
let username = "alex123";

/** @type {number[]} */
const scores = [95, 88, 72];

/** @type {string | number} */
let identifier = "A-102";

Function Signatures with @param and @returns

Function parameters and return values are typed using @param and @returns (or @return). You can also denote optional parameters using square brackets.

/**
 * Calculates a discounted price.
 * @param {number} price - The original price.
 * @param {number} [discount=0.1] - The discount percentage.
 * @returns {number} The final price.
 */
function calculateTotal(price, discount = 0.1) {
  return price - price * discount;
}

Defining Complex Types with @typedef and @property

To avoid repeating complex object signatures, you can create reusable types using @typedef alongside @property. This functions similarly to a TypeScript type alias or interface.

/**
 * @typedef {Object} User
 * @property {number} id - Unique identifier.
 * @property {string} name - User's full name.
 * @property {string} [email] - Optional email address.
 */

/** @type {User} */
const currentUser = {
  id: 1,
  name: "Jane Doe"
};

Importing Types from Other Files

JSDoc allows you to import types from TypeScript declaration files (.d.ts) or other JavaScript files using the import() syntax:

/** @type {import('./types').ConfigOptions} */
const config = {
  retries: 3,
  timeout: 5000
};

You can also create a local alias for an imported type:

/** @typedef {import('./types').ResponseData} ResponseData */

/** @param {ResponseData} data */
function handleResponse(data) {
  console.log(data);
}

Generics with @template

Generics allow functions to handle multiple types while maintaining type safety. The @template tag introduces a generic type parameter:

/**
 * Returns the first element of an array.
 * @template T
 * @param {T[]} items
 * @returns {T | undefined}
 */
function getFirstItem(items) {
  return items[0];
}

const num = getFirstItem([1, 2, 3]); // Type inferred as number | undefined
const str = getFirstItem(["a", "b"]); // Type inferred as string | undefined

Type Assertions and Casting

When TypeScript cannot infer the type accurately, you can cast an expression by wrapping it in parentheses preceded by a @type tag:

const myCanvas = /** @type {HTMLCanvasElement} */ (document.getElementById("main-canvas"));

By using JSDoc annotations, projects gain the full benefits of TypeScript's static analysis, auto-completion, and refactoring tools while preserving a plain JavaScript runtime that requires no transpilation tooling.
