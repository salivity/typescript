Why Check for Null with typeof Object in TypeScript

In JavaScript and TypeScript, executing typeof null unexpectedly evaluates to "object" due to a legacy design quirk in JavaScript's original engine. Because TypeScript reflects JavaScript's actual runtime behavior, performing a type guard using only typeof value === 'object' narrows the type to object | null rather than purely object. To prevent unexpected runtime crashes when accessing properties on a value that might be null, developers must explicitly combine the type check with a null check, such as value !== null && typeof value === 'object'.

The Root Cause: A Legacy JavaScript Quirk

The requirement stems from JavaScript's original implementation in 1995. Values were stored with a type tag in their lowest bits to identify their data type. The type tag for an object reference was 0. Because null was represented as the NULL pointer (0x00), its type tag was also read as 0, causing the typeof operator to report "object" instead of "null".

console.log(typeof null); // "object"

Fixing this behavior in modern ECMAScript would break backward compatibility for millions of existing web applications, so the behavior remains permanently standard.

How TypeScript Handles typeof Narrowing

TypeScript adheres to runtime JavaScript semantics. When static analysis evaluates typeof value === 'object', it cannot safely narrow an unknown or nullable type directly to a non-null object.

Consider this example with strictNullChecks enabled:

function inspectValue(val: Record<string, unknown> | null) {
  if (typeof val === 'object') {
    // TypeScript knows 'val' can still be 'null'
    // Attempting to access properties can cause issues
  }
}

If val is null, the condition evaluates to true. Without an explicit null check, attempting to read properties or call methods on val will throw a runtime error:

TypeError: Cannot read properties of null (reading 'someProperty')

The Correct Type Guard Pattern

To safely narrow a variable to a usable object type, you must explicitly eliminate null:

function processData(data: unknown) {
  if (data !== null && typeof data === 'object') {
    // 'data' is safely narrowed to 'object' (non-null)
    console.log(Object.keys(data));
  }
}

Alternatively, you can write a reusable custom type guard function:

function isObject(value: unknown): value is Record<string, unknown> {
  return value !== null && typeof value === 'object';
}

By ensuring that null is explicitly rejected before treating a variable as a true object, you prevent runtime exceptions and allow TypeScript's type inference system to accurately narrow the type.
