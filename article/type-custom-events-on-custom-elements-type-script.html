Type Custom Events on Custom Elements TypeScript

Typing custom events on custom elements in TypeScript ensures end-to-end type safety when dispatching and listening to events. The standard and most robust solution involves declaring your custom event detail type, subclassing or typing CustomEvent, and leveraging TypeScript declaration merging to augment the global HTMLElementEventMap interface. This allows native methods like addEventListener to automatically infer the correct event payload without manual type casting.

Step 1: Define the Event Payload Interface

Start by defining the structure of the data passed inside the event's detail property:

export interface UserSelectedDetail {
  userId: string;
  role: 'admin' | 'user';
}

export type UserSelectedEvent = CustomEvent<UserSelectedDetail>;

Step 2: Augment the Global HTMLElementEventMap

To make TypeScript recognize your custom event name when using addEventListener or removeEventListener, augment the global HTMLElementEventMap. This ensures full type inference across the DOM API.

declare global {
  interface HTMLElementEventMap {
    'user-selected': UserSelectedEvent;
  }
}

If your code is organized into ES modules (containing import or export), wrapping the interface inside declare global is required. If your file is a pure script without top-level imports or exports, you can omit declare global and directly declare interface HTMLElementEventMap.

Step 3: Implement the Custom Element

When dispatching the event from inside your custom element, instantiate a standard CustomEvent typed with your payload interface. Setting bubbles: true and composed: true ensures the event traverses through the Shadow DOM boundaries if needed.

export class UserCardElement extends HTMLElement {
  connectedCallback(): void {
    this.render();
  }

  private emitUserSelected(userId: string, role: 'admin' | 'user'): void {
    const event: UserSelectedEvent = new CustomEvent('user-selected', {
      bubbles: true,
      composed: true,
      detail: { userId, role },
    });

    this.dispatchEvent(event);
  }

  private render(): void {
    const button = document.createElement('button');
    button.textContent = 'Select User';
    button.addEventListener('click', () => {
      this.emitUserSelected('usr_123', 'admin');
    });
    this.appendChild(button);
  }
}

customElements.define('user-card', UserCardElement);

declare global {
  interface HTMLElementTagNameMap {
    'user-card': UserCardElement;
  }
}

Step 4: Consuming the Typed Event

Because HTMLElementEventMap was augmented, calling addEventListener on the element or anywhere up the DOM tree automatically infers the event parameter as UserSelectedEvent.

const userCard = document.querySelector('user-card');

if (userCard) {
  // 'e' is automatically inferred as UserSelectedEvent
  userCard.addEventListener('user-selected', (e) => {
    console.log(`Selected User: ${e.detail.userId}, Role: ${e.detail.role}`);
  });
}

Scoping Events to a Specific Element

If you want the event to be available strictly on your custom element class rather than every HTMLElement, override addEventListener and removeEventListener directly on your class:

export interface UserCardEventMap {
  'user-selected': UserSelectedEvent;
}

export class UserCardElement extends HTMLElement {
  addEventListener<K extends keyof UserCardEventMap>(
    type: K,
    listener: (this: UserCardElement, ev: UserCardEventMap[K]) => void,
    options?: boolean | AddEventListenerOptions
  ): void;
  addEventListener(
    type: string,
    listener: EventListenerOrEventListenerObject,
    options?: boolean | AddEventListenerOptions
  ): void {
    super.addEventListener(type, listener, options);
  }

  removeEventListener<K extends keyof UserCardEventMap>(
    type: K,
    listener: (this: UserCardElement, ev: UserCardEventMap[K]) => void,
    options?: boolean | EventListenerOptions
  ): void;
  removeEventListener(
    type: string,
    listener: EventListenerOrEventListenerObject,
    options?: boolean | EventListenerOptions
  ): void {
    super.removeEventListener(type, listener, options);
  }
}

Augmenting HTMLElementEventMap remains the recommended baseline for bubbling events, while class-level overrides offer stricter typing for component-specific APIs.
