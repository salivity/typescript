TypeScript Class Member Access Modifiers

This article provides a clear overview of the access modifiers available for class members in TypeScript, explaining how they control the visibility and accessibility of properties and methods. You will learn the specific behaviors of the public, protected, and private keywords, along with modern JavaScript private identifiers (#) and how the readonly modifier complements encapsulation.

The public Modifier

The public modifier is the default visibility for all class members in TypeScript. A public member can be accessed from anywhere—inside the class, by derived subclasses, and externally by instances of the class.

class User {
  public name: string;

  constructor(name: string) {
    this.name = name;
  }
}

const user = new User("Alice");
console.log(user.name); // Accessible

Because it is the default, explicitly writing the public keyword is optional, though developers often include it for clarity or when using constructor parameter properties.

The protected Modifier

Members marked as protected are accessible only within the declaring class and its subclasses (derived classes). They cannot be accessed from instances outside the class hierarchy.

class Employee {
  protected salary: number;

  constructor(salary: number) {
    this.salary = salary;
  }
}

class Manager extends Employee {
  public getBonusDetails() {
    // Accessible within subclass
    return this.salary * 0.2;
  }
}

const emp = new Employee(50000);
// emp.salary; // Error: Property 'salary' is protected

The protected modifier is ideal when you want to hide internal implementation details from external consumers while still allowing inheritance and customization.

The private Modifier

The private modifier restricts visibility strictly to the class that declares the member. Even subclasses cannot access private members directly.

class BankAccount {
  private balance: number;

  constructor(initialBalance: number) {
    this.balance = initialBalance;
  }

  public getBalance() {
    return this.balance; // Accessible within the class
  }
}

const account = new BankAccount(100);
// account.balance; // Error: Property 'balance' is private

Note: TypeScript's private keyword only enforces access control at compile time. Once the code compiles to JavaScript, the member behaves like a regular property and can technically be accessed at runtime.

ECMAScript Private Fields (#)

TypeScript also supports native ECMAScript private fields using the # prefix. Unlike TypeScript’s private keyword, native private fields enforce hard privacy both at compile time and at runtime.

class SecureVault {
  #secretCode: string;

  constructor(code: string) {
    this.#secretCode = code;
  }

  public unlock(code: string) {
    return this.#secretCode === code;
  }
}

const vault = new SecureVault("1234");
// vault.#secretCode; // Syntax Error: Property is not accessible outside class

Native private fields cannot be accessed outside the class body, even through standard JavaScript inspection methods.

The readonly Modifier

While not strictly an access modifier, the readonly modifier controls mutability and works alongside access modifiers. A readonly property can only be assigned during initialization or inside the constructor.

class Configuration {
  public readonly apiKey: string;

  constructor(key: string) {
    this.apiKey = key;
  }
}

const config = new Configuration("xyz-123");
// config.apiKey = "new-key"; // Error: Cannot assign to 'apiKey' because it is a read-only property

Parameter Properties Shorthand

TypeScript provides a shorthand to declare and initialize class members directly in the constructor arguments by prefixing them with an access modifier or readonly.

class Product {
  constructor(
    public id: number,
    private cost: number,
    protected category: string
  ) {}
}

This automatically creates and assigns the respective members to the class instance without needing explicit property declarations or assignments.
