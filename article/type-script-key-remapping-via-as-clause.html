TypeScript Key Remapping via as Clause

This article explores how TypeScript utilizes key remapping through the as clause in mapped types to transform, filter, and generate new object property names. Introduced in TypeScript 4.1, key remapping provides fine-grained control over property keys during type transformations. By combining the as clause with template literal types, utility types, and conditional types, developers can manipulate object shapes with precision, whether by renaming keys, excluding specific properties dynamically, or reshaping API models.

Understanding the Syntax

Standard mapped types iterate through a set of keys using the [Key in Keys] syntax. By appending the as clause, you intercept the iteration and provide an entirely new type for the key:

type MappedTypeWithNewKeys<T> = {
  [Key in keyof T as NewKeyType]: T[Key];
};

Here, Key represents the original key from T, while NewKeyType defines what the key becomes in the resulting object. The expression for NewKeyType must resolve to a valid property key type (string, number, or symbol).

Modifying Key Names with Template Literals

One of the most common applications of key remapping is altering key names using TypeScript's intrinsic string manipulation types: Uppercase, Lowercase, Capitalize, and Uncapitalize.

For example, generating "getter" methods for an interface:

interface User {
  name: string;
  age: number;
}

type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
};

type UserGetters = Getters<User>;
// Result:
// {
//   getName: () => string;
//   getAge: () => number;
// }

In this pattern, string & K constrains K to a string type so it can safely be consumed by the Capitalize helper.

Filtering Keys with the never Type

Key remapping can conditionally omit properties. When a key resolves to never via a conditional type inside the as clause, TypeScript removes that property from the resulting type entirely.

interface Product {
  id: number;
  title: string;
  inStock: boolean;
  internalCode: string;
}

// Retain only string properties
type StringPropertiesOnly<T> = {
  [K in keyof T as T[K] extends string ? K : never]: T[K];
};

type FilteredProduct = StringPropertiesOnly<Product>;
// Result:
// {
//   title: string;
//   internalCode: string;
// }

This approach replaces the need for combining Pick and custom utility types, offering a self-contained, readable syntax for property extraction.

Remapping Keys Over Arbitrary Unions

Mapped types are not limited to iterating over keyof T. They can iterate over any union of types, utilizing the as clause to extract a specific property to act as the key.

type Event =
  | { type: "click"; x: number; y: number }
  | { type: "hover"; element: string };

type EventMap<E extends { type: string }> = {
  [Item in E as Item["type"]]: (event: Item) => void;
};

type Handlers = EventMap<Event>;
// Result:
// {
//   click: (event: { type: "click"; x: number; y: number }) => void;
//   hover: (event: { type: "hover"; element: string }) => void;
// }

By indexing the iterated member (Item["type"]), the mapped type dynamically designates that member's value as the property name for the newly created structure.
