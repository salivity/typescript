How NonNullable Strips Nullability in TypeScript

TypeScript's NonNullable<T> utility type removes null and undefined from an existing type to produce a safe, non-nullable equivalent. This article explores how NonNullable<T> is defined internally, the mechanics of conditional and distributive types that make it work, and how the TypeScript compiler eliminates unwanted empty values from union types.

The Internal Definition of NonNullable

Under the hood, TypeScript defines NonNullable<T> in its standard library using a conditional type:

type NonNullable<T> = T extends null | undefined ? never : T;

This single line of code leverages two core TypeScript features: conditional types and the never type.

How Conditional Types Work

The syntax T extends null | undefined ? never : T acts as a type-level ternary expression:

  1. Check Condition: The compiler checks whether a given type T is assignable to null | undefined.
  2. True Branch (never): If T can be assigned to null or undefined, the expression resolves to never.
  3. False Branch (T): If T is neither null nor undefined, the type remains unchanged as T.

Distributive Conditional Types

When NonNullable<T> is applied to a union type, TypeScript applies distributive conditional type behavior. Instead of checking the entire union at once, the compiler distributes the condition across each individual member of the union.

Consider the following type alias:

type Input = string | null | undefined;
type Result = NonNullable<Input>;

TypeScript evaluates each member of the Input union independently:

  • string extends null | undefined ? never : string evaluates to string
  • null extends null | undefined ? never : null evaluates to never
  • undefined extends null | undefined ? never : undefined evaluates to never

The intermediate result is the union string | never | never.

Union Reduction with the never Type

In TypeScript, the never type represents an empty set—a value that can never occur. When never is part of a union type, the compiler automatically filters it out because combining any type with an empty set leaves the original type unchanged:

string | never | never  =>  string

Through this automatic union reduction, all null and undefined constituents are replaced with never and subsequently pruned from the final type signature.
