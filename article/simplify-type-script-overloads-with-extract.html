Simplify TypeScript Overloads with Extract

Function overloads in TypeScript allow you to define multiple call signatures for a single function, but implementing them often leads to messy type assertions and redundant union types within the implementation body. The Extract utility type simplifies this process by isolating specific member types from broader unions based on a shared discriminant or structural match. By leveraging Extract, developers can maintain a single source of truth for parameters and return types, significantly reducing boilerplate and unsafe type assertions in overload implementations.

The Challenge of Overload Implementations

When authoring function overloads, TypeScript requires a list of public overload signatures followed by a single implementation signature. The implementation signature must be broad enough to accommodate all preceding overloads.

Consider an event handler that accepts an event name and a corresponding payload:

type AppEvent =
  | { type: "login"; payload: { userId: string } }
  | { type: "logout"; payload: { reason: string } }
  | { type: "upload"; payload: { file: Blob; progress: number } };

// Overload signatures
function sendEvent(type: "login", payload: { userId: string }): void;
function sendEvent(type: "logout", payload: { reason: string }): void;
function sendEvent(type: "upload", payload: { file: Blob; progress: number }): void;

// Implementation signature
function sendEvent(type: string, payload: any): void {
  // Implementation details...
}

In traditional implementations, developers often resort to typing the parameters as any, unknown, or an untied union of all payloads. This compromises type safety inside the function body and forces manual type guards or unsafe type casting (as ...) whenever interacting with specific event payloads.

How Extract Solves the Problem

The Extract<Type, Union> utility type filters out all members of Type that are assignable to Union. Its syntax is defined as:

type Extract<T, U> = T extends U ? T : never;

When dealing with discriminated unions, Extract can pull out the exact object shape associated with a specific discriminant key. Instead of manually retyping payload structures across overloads and inside the implementation, you can derive them directly from the primary union type:

type EventPayload<T extends AppEvent["type"]> = Extract<AppEvent, { type: T }>["payload"];

Implementing Overloads with Extract

By utilizing Extract, you can make the overload declarations concise while keeping the implementation signature and body strongly typed without duplicating interfaces:

// Overload signatures
function sendEvent(type: "login", payload: EventPayload<"login">): void;
function sendEvent(type: "logout", payload: EventPayload<"logout">): void;
function sendEvent(type: "upload", payload: EventPayload<"upload">): void;

// Implementation signature
function sendEvent(
  type: AppEvent["type"],
  payload: AppEvent["payload"]
): void {
  if (type === "upload") {
    // Safely narrow the payload using Extract for internal logic
    const uploadPayload = payload as Extract<AppEvent, { type: "upload" }>["payload"];
    console.log(`Uploading: ${uploadPayload.file.size} bytes`);
    return;
  }

  console.log(`Dispatched event: ${type}`);
}

Simplifying Tuple-Based Overload Implementations

Extract is also useful when function signatures are modeled as a union of parameter tuples. This pattern allows you to represent all possible overload shapes in a single unified type and extract subsets as needed:

type OperationArgs =
  | [action: "read", path: string]
  | [action: "write", path: string, content: string]
  | [action: "delete", path: string, force: boolean];

// Overload signatures
function performOp(...args: Extract<OperationArgs, ["read", ...any[]]>): Promise<string>;
function performOp(...args: Extract<OperationArgs, ["write", ...any[]]>): Promise<void>;
function performOp(...args: Extract<OperationArgs, ["delete", ...any[]]>): Promise<boolean>;

// Unified implementation
async function performOp(...args: OperationArgs): Promise<unknown> {
  const [action, path] = args;

  switch (action) {
    case "read":
      return `Content of ${path}`;
    case "write": {
      const [, , content] = args; // Fully typed as string
      return;
    }
    case "delete": {
      const [, , force] = args; // Fully typed as boolean
      return force;
    }
  }
}

Key Benefits

  • Single Source of Truth: Changes to the underlying data contracts automatically propagate to all overload signatures and extraction points, avoiding desynchronized types.
  • Elimination of Duplicated Interfaces: Overload parameter signatures are derived programmatically rather than duplicated across multiple signatures.
  • Safer Function Bodies: Inside the function implementation, developers can selectively extract types for local variables or helpers instead of falling back on any.
