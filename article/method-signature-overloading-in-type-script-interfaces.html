Method Signature Overloading in TypeScript Interfaces

Method signature overloading in TypeScript interfaces allows developers to declare multiple call signatures for a single method name, enabling different parameter combinations and return types while preserving strict type safety. This article covers how TypeScript processes overloaded interface signatures, the rules governing resolution order, and the requirements for implementing these interfaces in classes and object literals.

Defining Overloaded Signatures

Inside a TypeScript interface, you overload a method by writing the method signature multiple times with the same name, each with a different set of parameters or return types. You only define the types, not the implementation logic.

interface DataFetcher {
  fetch(id: number): Promise<string>;
  fetch(tag: string): Promise<string[]>;
  fetch(id: number, format: "json" | "xml"): Promise<object>;
}

In this example, the DataFetcher interface exposes three distinct ways to invoke fetch. TypeScript's type checker uses these signatures to validate arguments and infer the correct return type at compile time.

Signature Resolution Order

TypeScript evaluates overloaded method signatures sequentially from top to bottom. When a call expression is checked, the compiler chooses the first signature whose parameters are compatible with the supplied arguments.

Because of this top-to-bottom evaluation, you must arrange signatures from the most specific to the most general. If a broader signature is listed before a narrower one, the narrower one may be unreachable:

interface Processor {
  // Correct: specific literal type comes first
  process(action: "reset"): boolean;
  process(action: string): void;
}

If process(action: string) were placed first, any call passing "reset" would match string immediately, and the return type would resolve to void instead of boolean.

Implementing Overloaded Interfaces

When a class implements an interface containing overloaded method signatures, the class does not provide multiple separate implementations. Instead, it provides a single, unified implementation with a signature broad enough to encompass all interface overloads.

class ApiClient implements DataFetcher {
  fetch(input: number | string, format?: "json" | "xml"): Promise<any> {
    if (typeof input === "number") {
      if (format) {
        return Promise.resolve({ data: "payload", format });
      }
      return Promise.resolve("single result");
    }
    return Promise.resolve(["result1", "result2"]);
  }
}

The implementing signature must account for all variations defined in the interface. However, callers interacting through the interface type only see the defined overloads, not the generic fallback implementation signature.

Declaration Merging with Overloads

TypeScript supports declaration merging, meaning multiple interface declarations sharing the same name in the same scope are merged into a single definition. When method overloads are merged across multiple declarations of the same interface, signatures from later declarations take precedence and are ordered before earlier ones. The single exception is that signatures containing string or type literals are always hoisted above signatures with non-literal types to preserve specificity.
