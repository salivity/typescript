DeepFreezer Utility Type for TypeScript Immutability

TypeScript's built-in Readonly<T> utility provides shallow immutability, leaving nested properties vulnerable to mutation. This article demonstrates how to construct a recursive DeepFreezer<T> utility type using conditional and mapped types to enforce strict, compile-time immutability across complex nested objects, arrays, and standard collections.

The Limitation of Shallow Readonly

In standard TypeScript, applying the native Readonly<T> modifier prevents reassignment of top-level properties, but nested structures remain mutable:

interface UserSettings {
  theme: string;
  notifications: {
    email: boolean;
  };
}

const config: Readonly<UserSettings> = {
  theme: "dark",
  notifications: { email: true }
};

// config.theme = "light"; // Error: Cannot assign to 'theme' because it is a read-only property.
config.notifications.email = false; // Compiles successfully!

Because Readonly<T> is non-recursive, changes to nested objects bypass the type checker.

Implementing the DeepFreezer Utility Type

To enforce immutability down the entire object tree, you can define a recursive type that checks each property's structure and wraps it accordingly.

export type DeepFreezer<T> = T extends Function | boolean | number | string | null | undefined | symbol | bigint
  ? T
  : T extends ReadonlyArray<infer U>
  ? ReadonlyArray<DeepFreezer<U>>
  : T extends ReadonlyMap<infer K, infer V>
  ? ReadonlyMap<DeepFreezer<K>, DeepFreezer<V>>
  : T extends ReadonlySet<infer M>
  ? ReadonlySet<DeepFreezer<M>>
  : T extends object
  ? { readonly [K in keyof T]: DeepFreezer<T[K]> }
  : T;

How DeepFreezer Works

The utility operates using conditional type branching:

  1. Primitive & Function Handling: Primitive types and functions do not contain assignable sub-properties in this context. If T extends a primitive or function, it is returned untouched.
  2. Array Traversal: If T extends an array, it infers the item type U, recursively transforms U with DeepFreezer<U>, and returns a ReadonlyArray.
  3. Map and Set Collections: If T extends a Map or Set, their generic parameters are recursively wrapped and returned as ReadonlyMap or ReadonlySet. This removes mutating methods like .set(), .add(), and .delete().
  4. Recursive Object Mapping: If T matches a general object, a mapped type applies the readonly modifier to all keys [K in keyof T] while recursively invoking DeepFreezer<T[K]> on every value.

Compile-Time Enforcement in Practice

When applying DeepFreezer<T>, any attempt to alter a nested property, push to an array, or modify a map fails during compilation:

interface AppState {
  version: number;
  routes: string[];
  metadata: {
    owner: {
      name: string;
    };
  };
}

const state: DeepFreezer<AppState> = {
  version: 1,
  routes: ["/home", "/dashboard"],
  metadata: {
    owner: {
      name: "Admin"
    }
  }
};

// Compile-time errors:
state.version = 2; 
// Error: Cannot assign to 'version' because it is a read-only property.

state.routes.push("/settings"); 
// Error: Property 'push' does not exist on type 'readonly string[]'.

state.metadata.owner.name = "SuperAdmin"; 
// Error: Cannot assign to 'name' because it is a read-only property.

Combining Compile-Time and Runtime Safety

While DeepFreezer<T> secures the type layer during compilation, TypeScript types are erased at runtime. To ensure runtime safety alongside compile-time safety, pair the type with a recursive deepFreeze function:

function deepFreeze<T>(obj: T): DeepFreezer<T> {
  Object.keys(obj as object).forEach((prop) => {
    const value = (obj as any)[prop];
    if (value && typeof value === "object") {
      deepFreeze(value);
    }
  });
  return Object.freeze(obj) as DeepFreezer<T>;
}

This dual approach guarantees that the data structure is fully immutable both during development and execution.
