TypeScript lib: Understanding DOM and DOM.Iterable

This article explains the specific roles of the DOM and DOM.Iterable values in TypeScript’s lib configuration setting. In TypeScript, the lib array in tsconfig.json tells the compiler which built-in JavaScript and browser API declarations to include during type checking. By understanding how DOM injects standard browser APIs and how DOM.Iterable enables modern ES6 iteration protocols over DOM collections, developers can configure their projects effectively for browser environments.

The Role of the lib Compiler Option

When TypeScript compiles code, it needs type definitions for standard runtime environments. By default, TypeScript automatically loads definitions based on your specified target (such as ES6 or ESNext). If you define the lib array manually, you override these defaults and must explicitly declare every type library your code relies on.

{
  "compilerOptions": {
    "target": "ES2020",
    "lib": ["ES2020", "DOM", "DOM.Iterable"]
  }
}

The Role of "DOM"

The "DOM" library provides TypeScript with ambient declarations for standard browser objects and APIs.

Key responsibilities of "DOM" include:

  • Global Browser Objects: Provides types for globals such as window, document, navigator, and localStorage.
  • HTML Element Interfaces: Defines elements like HTMLElement, HTMLDivElement, HTMLInputElement, and their standard attributes and methods.
  • Web APIs: Supplies type definitions for browser-specific APIs including fetch, Event, CustomEvent, WebSocket, and setTimeout.

Without "DOM" in your lib array, statements like const el = document.getElementById("app"); will cause TypeScript to throw errors such as Cannot find name 'document'.

The Role of "DOM.Iterable"

The "DOM.Iterable" library enhances the base "DOM" types by adding iteration capabilities introduced in ECMAScript 2015 (ES6).

In standard web browsers, collections like NodeList, HTMLCollection, DOMTokenList, FormData, and Headers implement the iterable protocol via the [Symbol.iterator] method. However, the base "DOM" definitions in TypeScript historically separate these modern iteration types to support older runtimes that lack native Symbol support.

"DOM.Iterable" makes these browser collections compatible with:

  • for...of loops: Iterating over document.querySelectorAll() results directly.
  • Array Spread Operators: Converting a NodeList to an array using [...document.querySelectorAll("div")].
  • Collection Iterators: Calling .entries(), .keys(), or .values() on DOM types like FormData or URLSearchParams.

Without "DOM.Iterable", attempting to spread a NodeList or loop through it using for...of will result in a compiler error indicating that the type is not an array type or does not have a [Symbol.iterator]() method.

Why They Are Kept Separate

TypeScript separates "DOM" and "DOM.Iterable" to provide granular control over runtime compatibility:

  1. Target Compatibility: Older ECMAScript targets (like ES5) do not have native Symbol.iterator support without polyfills. Splitting the declarations ensures older applications do not accidentally use unsupported language features.
  2. Modularity: Developers targeting non-standard or partially compliant environments can opt into standard DOM interfaces without assuming modern iteration protocols are present.

For modern front-end web development targeting modern browsers, both "DOM" and "DOM.Iterable" should almost always be included together in the lib array.
