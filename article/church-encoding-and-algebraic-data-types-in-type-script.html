Church Encoding and Algebraic Data Types in TypeScript

TypeScript provides a rich type system capable of expressing advanced functional programming concepts with strict compile-time safety. This article explores how to model Algebraic Data Types (ADTs) using discriminated unions and records, and how to represent data structures purely through functions using Church encoding. By examining both paradigms, you will learn how to implement robust domain models and represent fundamental functional constructs natively in TypeScript.

Modeling Algebraic Data Types (ADTs)

Algebraic Data Types are composite types formed by combining other types. The two primary classes of ADTs are Product types (combining values together) and Sum types (choosing between mutually exclusive variations).

1. Product Types

A product type represents a structure that contains multiple values simultaneously (AND logic). In TypeScript, product types are modeled using interfaces, object types, or tuples.

// Product type as an interface
interface User {
  readonly id: number;
  readonly name: string;
  readonly email: string;
}

// Product type as a tuple
type Point2D = readonly [x: number, y: number];

2. Sum Types (Coproducts)

A sum type represents a value that can be one of several distinct variants (OR logic). TypeScript models sum types via discriminated unions, using a shared literal property (a discriminant tag) to distinguish between variants.

A canonical example is the Option (or Maybe) type:

type None = { readonly _tag: 'None' };
type Some<A> = { readonly _tag: 'Some'; readonly value: A };

type Option<A> = None | Some<A>;

// Smart constructors
const none: Option<never> = { _tag: 'None' };
const some = <A>(value: A): Option<A> => ({ _tag: 'Some', value });

// Pattern matching function
function matchOption<A, R>(
  option: Option<A>,
  onNone: () => R,
  onSome: (value: A) => R
): R {
  switch (option._tag) {
    case 'None':
      return onNone();
    case 'Some':
      return onSome(option.value);
  }
}

Discriminated unions enable the TypeScript compiler to perform exhaustive checks, ensuring that all possible cases are handled.

Modeling Church Encoding

Church encoding represents data and operators purely using lambda calculus (higher-order functions), without relying on primitive data types or composite structures like objects or arrays. In TypeScript, this is achieved using generic function types.

1. Church Booleans

In Church encoding, a boolean is a function that accepts two arguments and returns one of them. True selects the first argument, while False selects the second.

type ChurchBoolean = <T>(thenBranch: T) => (elseBranch: T) => T;

const churchTrue: ChurchBoolean = (thenBranch) => (elseBranch) => thenBranch;
const churchFalse: ChurchBoolean = (thenBranch) => (elseBranch) => elseBranch;

// Logical operations
const churchNot = (b: ChurchBoolean): ChurchBoolean => 
  (t) => (f) => b(f)(t);

const churchAnd = (a: ChurchBoolean) => (b: ChurchBoolean): ChurchBoolean =>
  (t) => (f) => a(b(t)(f))(f);

// Conversion to a native TypeScript boolean
const toNativeBoolean = (b: ChurchBoolean): boolean => b(true)(false);

console.log(toNativeBoolean(churchTrue)); // true
console.log(toNativeBoolean(churchNot(churchTrue))); // false

2. Church Numerals

A Church numeral \(N\) is a higher-order function that takes a function f and a value x, and applies f to x \(N\) times.

type ChurchNat = <T>(f: (x: T) => T) => (x: T) => T;

const zero: ChurchNat = (f) => (x) => x;
const one: ChurchNat = (f) => (x) => f(x);
const two: ChurchNat = (f) => (x) => f(f(x));

// Successor function: adds 1 to a Church numeral
const succ = (n: ChurchNat): ChurchNat => 
  (f) => (x) => f(n(f)(x));

// Addition: adds two Church numerals
const add = (n: ChurchNat) => (m: ChurchNat): ChurchNat => 
  (f) => (x) => n(f)(m(f)(x));

// Conversion to a native JavaScript number
const toNativeNumber = (n: ChurchNat): number => n((x) => x + 1)(0);

const three = succ(two);
console.log(toNativeNumber(three)); // 3
console.log(toNativeNumber(add(two)(three))); // 5

3. Church Pairs

Pairs can be modeled as functions that accept a selector function and pass the two stored values into it.

type ChurchPair<A, B> = <R>(selector: (first: A, second: B) => R) => R;

const pair = <A, B>(a: A, b: B): ChurchPair<A, B> => 
  (selector) => selector(a, b);

const first = <A, B>(p: ChurchPair<A, B>): A => 
  p((a, b) => a);

const second = <A, B>(p: ChurchPair<A, B>): B => 
  p((a, b) => b);

const myPair = pair('TypeScript', 2026);
console.log(first(myPair));  // "TypeScript"
console.log(second(myPair)); // 2026

Summary of Differences

  • Algebraic Data Types in TypeScript rely on structural typing and tagged objects. They represent data directly, provide clear runtime debugging representations, and are the standard idiomatic choice for modern application architecture.
  • Church Encoding models values and data operations purely as functional dispatch mechanisms. While less practical for standard production applications due to call-stack overhead and debugging opacity, it demonstrates the universal computational power of functions and TypeScript's ability to handle complex generic type signatures.
