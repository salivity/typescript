Logical OR vs Nullish Coalescing in TypeScript

In TypeScript, both the logical OR operator (||) and the nullish coalescing operator (??) provide fallback values, but they differ fundamentally in how they evaluate conditions and resolve types. While || falls back when the left operand is any falsy value (such as false, 0, "", null, or undefined), ?? only falls back when the left operand is strictly nullish (null or undefined). Consequently, TypeScript's type checker narrows the types of expressions differently depending on which operator is used.

The Core Difference: Falsy vs. Nullish

To understand type resolution, it is essential to distinguish between falsy and nullish definitions in JavaScript and TypeScript:

  • Falsy values: false, 0, -0, 0n, "", null, undefined, and NaN.
  • Nullish values: null and undefined.

When resolving the type of a || b, TypeScript removes all known falsy types from the type of a when considering what passes through to the left side. When resolving a ?? b, TypeScript only removes null and undefined (equivalent to applying the NonNullable<T> utility type to the left operand).

Type Resolution with || (Logical OR)

The logical OR operator evaluates whether the left-hand side is truthy. In type resolution, TypeScript narrows the type of the left operand by filtering out falsy primitives.

function getPort(inputPort: number | undefined): number {
  return inputPort || 3000;
}

If inputPort is 0, 0 is falsy at runtime, meaning inputPort || 3000 evaluates to 3000.

Consider an example with a union containing falsy literals:

type Status = "active" | "" | null;

function resolveStatus(status: Status, fallback: string) {
  const result = status || fallback;
  // Type of result: string
}

Because "" and null are falsy, TypeScript's control flow analysis excludes both from the resulting type on the left, resolving the expression to string.

Type Resolution with ?? (Nullish Coalescing)

The nullish coalescing operator only checks for null and undefined. Valid values like 0, false, and "" are preserved both at runtime and in type inference.

type Config = {
  timeout: number | null;
  debug: boolean | undefined;
  prefix: string | null;
};

function parseConfig(config: Config) {
  const timeout = config.timeout ?? 5000; // Type: number
  const debug = config.debug ?? true;     // Type: boolean
  const prefix = config.prefix ?? "app";  // Type: string
}

If config.timeout is 0, 0 ?? 5000 returns 0. Similarly, if config.debug is false, false ?? true returns false.

Literal Types and Narrowing Behavior

The difference becomes most apparent when dealing with union types that include literal falsy values:

type Value = 0 | 1 | undefined;

declare const val: Value;

// Using Logical OR:
const orResult = val || 2;
// Runtime: If val is 0, orResult becomes 2.
// Type of orResult: 1 | 2 (0 is discarded because it is falsy)

// Using Nullish Coalescing:
const nullishResult = val ?? 2;
// Runtime: If val is 0, nullishResult remains 0.
// Type of nullishResult: 0 | 1 | 2 (0 is retained)

With ||, TypeScript eliminates the literal 0 from the inferred union type. With ??, TypeScript retains 0 because it is neither null nor undefined.

Summary of Best Practices

  • Use ?? when handling optional settings, numbers, booleans, or empty strings where 0, false, or "" are valid states. TypeScript will preserve these values in the resolved type.
  • Use || only when any falsy value—including empty strings and zero—should explicitly trigger the fallback and be omitted from the resolved type.
