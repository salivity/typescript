Unknown vs Any for Dynamic Property Access in TypeScript

In TypeScript, both any and unknown can represent any JavaScript value, but they behave radically differently when you attempt to access dynamic properties. While any disables all type-checking and allows immediate, unvalidated dynamic property access, unknown enforces strict type safety by disallowing property indexing until the value is narrowed or explicitly cast. This article breaks down the mechanics of dynamic property access for both types, highlights the runtime risks of any, and demonstrates the safe narrowing patterns required for unknown.

Dynamic Access with any

The any type acts as an escape hatch from the TypeScript compiler. When a variable is typed as any, TypeScript assumes that whatever property you are trying to access exists and is valid.

const data: any = { username: "alice" };
const dynamicKey = "username";

// Permitted without errors
const value = data[dynamicKey]; 

// Also permitted, but fails at runtime
const missing = data["nonExistentKey"];
const willCrash = data[dynamicKey].nestedProperty.deepValue;

Key Characteristics of any:

  • No Compile-Time Errors: You can use bracket notation with strings, numbers, or symbols without the compiler complaining.
  • Resulting Type is any: The retrieved property value automatically inherits the any type, propagating unchecked operations downstream.
  • Runtime Vulnerability: If the property does not exist or the target is null or undefined, your code will fail at runtime.

Dynamic Access with unknown

The unknown type represents a value whose structure is completely unverified. Unlike any, the compiler does not allow you to read properties—dynamically or statically—directly from an unknown variable.

const data: unknown = { username: "alice" };
const dynamicKey = "username";

// TypeScript Error: 'data' is of type 'unknown'.
const value = data[dynamicKey];

To access dynamic keys on an unknown value, you must first verify that the value is an object capable of being indexed.

Safe Dynamic Access via Type Narrowing

To read dynamic properties from an unknown variable safely, use a custom type guard or narrow the value to a Record type.

1. Checking with a Custom Type Guard

function isObject(val: unknown): val is Record<string, unknown> {
  return typeof val === "object" && val !== null;
}

const response: unknown = JSON.parse('{"status": "success"}');
const key = "status";

if (isObject(response) && key in response) {
  // Safe: TypeScript knows 'response' can be indexed with string keys
  const statusValue = response[key]; 
}

2. Using Type Assertion (When the Shape is Guaranteed)

If you are confident in the runtime shape of the object, you can assert it to an indexable type:

const config: unknown = fetchConfig();
const settingKey = "theme";

// Cast to an indexable record
const theme = (config as Record<string, unknown>)[settingKey];

Summary of Differences

Feature any unknown
Direct Dynamic Access Allowed (obj[key]) Blocked by compiler
Type Safety None Enforced at compile time
Resulting Property Type Always any Dependent on narrowing (e.g., unknown)
Required Developer Action None (unsafe) Validation, narrowing, or explicit cast

When handling unknown payloads such as API responses or user input, choose unknown over any. It forces you to write defensive checks before performing dynamic lookups, preventing runtime exceptions like TypeError: Cannot read properties of undefined.
