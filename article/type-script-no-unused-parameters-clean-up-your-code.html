TypeScript noUnusedParameters: Clean Up Your Code

The noUnusedParameters compiler option in TypeScript automatically flags any function parameter that is declared but never referenced within the function body. Enabling this setting helps developers eliminate dead code, prevent subtle logical errors, and reduce cognitive load across a codebase. By forcing the cleanup of obsolete arguments during development, TypeScript ensures that function signatures accurately reflect the data they actually require.

Enabling the Option

To activate this rule, set the noUnusedParameters flag to true inside the compilerOptions block of your tsconfig.json file:

{
  "compilerOptions": {
    "noUnusedParameters": true
  }
}

Once enabled, the TypeScript compiler will emit an error (such as TS6133: 'param' is declared but its value is never read) whenever a function declares a parameter it does not use.

Eliminating Dead Code and Refactoring Debris

Functions often evolve as application requirements change. A parameter required in an earlier version of a function might become redundant after logic moves to a different service or utility. Without automated checks, these obsolete parameters frequently stay in the function signature indefinitely.

Leaving unused parameters in place misleads other developers into thinking the argument affects the function's execution. Enforcing noUnusedParameters prompts developers to prune these arguments immediately during refactoring, keeping function signatures minimal and truthful.

Preventing Logical Bugs

An unused parameter can indicate an unintentional mistake rather than just stale code. For instance, a developer might pass an argument to a function intending to use it, but accidentally reference an outer-scoped variable with a similar name inside the implementation.

let id = "default-id";

function processUser(id: string) {
  // Developer mistakenly uses the global 'id' or forgets to use the argument
  fetchData(); 
}

With noUnusedParameters active, TypeScript flags id as unused, immediately alerting the developer that the argument was never applied to the function's logic.

Handling Required Interface Signatures

In some scenarios, a parameter must exist to satisfy a callback type or interface contract, even if the current implementation does not need it (such as event handlers or Express middleware).

TypeScript provides a standard solution for this pattern: prefixing the unused parameter name with an underscore (_).

// 'res' and 'next' are needed, but 'req' is not used in this specific route
app.get("/health", (_req, res) => {
  res.status(200).send("OK");
});

The compiler recognizes the leading underscore as an intentional marker for an unused parameter, allowing the code to satisfy the required signature without triggering a compilation error.

Streamlining Code Reviews and Maintenance

Automating the detection of unused variables shifts formatting and hygiene checks away from human reviewers and into the build pipeline. Code reviews can focus on architecture and business logic rather than hunting down abandoned variables. Over time, projects using noUnusedParameters maintain lighter, more cohesive APIs that are significantly easier to read, test, and maintain.
