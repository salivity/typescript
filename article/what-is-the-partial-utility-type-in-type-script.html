What Is the Partial Utility Type in TypeScript?

The Partial utility type in TypeScript is a built-in feature designed to transform all properties of an existing type into optional properties. This article explains the core function of Partial<T>, details its internal mechanics through mapped types, demonstrates practical use cases such as updating data objects, and highlights key limitations like its shallow nature.

How Partial<T> Works

When developing in TypeScript, you often define strict interfaces where properties are required by default. However, scenarios frequently arise where you only need a subset of those properties. The Partial<T> utility type takes an existing type T and returns a new type where every property of T is marked with the optional modifier (?).

Under the hood, TypeScript defines Partial<T> using a mapped type:

type Partial<T> = {
    [P in keyof T]?: T[P];
};

This definition iterates over every key P in the provided type T using keyof T and appends a ? to each property, allowing the value to be either its original type T[P] or undefined.

Practical Example: Partial Updates

The most common use case for Partial is creating update functions, such as handling PATCH requests or updating application state, where you do not need to provide every field of an entity.

interface User {
    id: string;
    name: string;
    email: string;
    role: string;
}

// Without Partial, all fields would be required:
function updateUser(id: string, updates: Partial<User>): void {
    // Implementation logic to update user fields
    console.log(`Updating user ${id} with:`, updates);
}

// Valid usage: only updating the email
updateUser("usr_123", {
    email: "newemail@example.com"
});

// Valid usage: passing an empty object
updateUser("usr_123", {});

Without Partial<User>, the updates parameter would force the caller to supply id, name, email, and role, defeating the purpose of a partial update.

Common Use Cases

  1. Object Mutation and Patches: Updating persistent records in databases or state stores where only a subset of fields change at a given time.
  2. Configuration Defaults: Allowing functions to accept optional configuration overrides while falling back to default values internally.
  3. Form Handling: Managing multi-step forms where an entity's fields are gathered incrementally across multiple steps rather than all at once.

Limitation: Shallow Optionality

Partial<T> only applies to the top-level properties of an object. If your interface contains nested objects, those nested properties remain required unless explicitly wrapped.

interface Profile {
    username: string;
    preferences: {
        theme: string;
        notifications: boolean;
    };
}

const userProfile: Partial<Profile> = {
    // Valid: 'preferences' itself is optional
    preferences: {
        theme: "dark"
        // Error: Property 'notifications' is missing and required
    }
};

To make nested properties optional, a custom recursive type—often referred to as DeepPartial—is required instead of the standard Partial utility.
