object vs Object vs {} in TypeScript

In TypeScript, object, Object, and {} appear similar at first glance, but they represent fundamentally different type concepts. Understanding their distinctions is crucial for writing strict, type-safe code. This guide breaks down the technical differences among the lowercase object type (non-primitives), the uppercase Object type (the JavaScript runtime prototype), and the empty type {} (any non-nullish value), helping you choose the right type for your application.

The object Type (Lowercase)

Introduced in TypeScript 2.2, the lowercase object represents any non-primitive type. A primitive in JavaScript is any value that is not an object and has no methods: string, number, boolean, bigint, symbol, null, and undefined.

When you type a variable as object, it strictly rejects all primitive values:

let value: object;

value = { name: "Alice" }; // Valid
value = [1, 2, 3];         // Valid (arrays are objects)
value = () => {};          // Valid (functions are objects)

value = 42;                // Error: Type 'number' is not assignable to type 'object'
value = "hello";           // Error: Type 'string' is not assignable to type 'object'
value = null;              // Error: Type 'null' is not assignable to type 'object'
value = undefined;         // Error: Type 'undefined' is not assignable to type 'object'

Use object when you need an API to accept only structured data or references (such as in Object.create()) and reject raw primitives.

The {} Type (Empty Object)

The {} type describes an object that has no declared properties of its own. However, in TypeScript, {} represents any value that is not null or undefined.

Because primitives in JavaScript can access prototype methods via auto-boxing, TypeScript considers primitive values assignable to {}:

let value: {};

value = { name: "Alice" }; // Valid
value = 42;                // Valid
value = "hello";           // Valid
value = true;              // Valid

value = null;              // Error: Type 'null' is not assignable to type '{}'
value = undefined;         // Error: Type 'undefined' is not assignable to type '{}'

While you can assign primitives and objects to {}, you cannot access custom properties on them because the type definition contains no keys:

const user: {} = { name: "Alice" };
console.log(user.name); // Error: Property 'name' does not exist on type '{}'

The Object Type (Uppercase)

The uppercase Object type refers to the JavaScript Object constructor interface. It defines properties common to all JavaScript objects through the global Object.prototype, such as hasOwnProperty(), toString(), and valueOf().

Like {}, the Object type accepts any value except null and undefined:

let value: Object;

value = { a: 1 };  // Valid
value = 100;       // Valid
value = "text";    // Valid

value = null;      // Error
value = undefined; // Error

Because Object describes the runtime prototype methods rather than a specific data structure, using it directly provides minimal type safety and is generally discouraged in modern TypeScript.

Best Practices

  • Avoid Object and {}: Due to their broad acceptance of primitive values, using Object or {} often introduces unexpected bugs where primitives bypass type checks.
  • Use object for non-primitives: If a function must accept reference types only, use object.
  • Use Record<string, unknown> for dynamic objects: When defining a generic dictionary or key-value pair, prefer Record<string, unknown> over object or {} to retain strict property-checking.
