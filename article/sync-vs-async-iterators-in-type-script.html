Sync vs Async Iterators in TypeScript

TypeScript models the structural differences between synchronous and asynchronous iterators by mapping directly to JavaScript's iteration protocols through separate, parallel interface hierarchies. The primary architectural divide lies in execution timing: synchronous iterators immediately return an iteration result object containing the current value and completion state, whereas asynchronous iterators return a Promise resolving to that result object. TypeScript enforces this distinction through dedicated standard library types—Iterable<T> versus AsyncIterable<T>, and Iterator<T> versus AsyncIterator<T>—alongside their corresponding unique symbol properties, Symbol.iterator and Symbol.asyncIterator.

Core Interface Signatures

TypeScript defines the foundational iteration types in its core library definitions (lib.es2015.iterable.d.ts and lib.es2018.asynciterable.d.ts). The structural divergence begins at the IteratorResult level and propagates upward through the iterator and iterable abstractions.

// Shared result structure
type IteratorResult<T, TReturn = any> = 
  | IteratorYieldResult<T> 
  | IteratorReturnResult<TReturn>;

interface IteratorYieldResult<TYield> {
  done?: false;
  value: TYield;
}

interface IteratorReturnResult<TReturn> {
  done: true;
  value: TReturn;
}

Synchronous Iterator Interfaces

A synchronous iterator yields its values directly:

interface Iterator<T, TReturn = any, TNext = any> {
  next(...[args]: [] | [TNext]): IteratorResult<T, TReturn>;
  return?(value?: TReturn): IteratorResult<T, TReturn>;
  throw?(e?: any): IteratorResult<T, TReturn>;
}

interface Iterable<T> {
  [Symbol.iterator](): Iterator<T>;
}

Asynchronous Iterator Interfaces

An asynchronous iterator wraps the exact same IteratorResult in a Promise:

interface AsyncIterator<T, TReturn = any, TNext = any> {
  next(...[args]: [] | [TNext]): Promise<IteratorResult<T, TReturn>>;
  return?(value?: TReturn | PromiseLike<TReturn>): Promise<IteratorResult<T, TReturn>>;
  throw?(e?: any): Promise<IteratorResult<T, TReturn>>;
}

interface AsyncIterable<T> {
  [Symbol.asyncIterator](): AsyncIterator<T>;
}

Key Structural Differences

1. Method Return Types

The most significant divergence is the return type of the next(), return(), and throw() methods.

  • Synchronous methods execute on the main call stack and synchronously return IteratorResult<T, TReturn>.
  • Asynchronous methods return Promise<IteratorResult<T, TReturn>>, allowing consumers to await asynchronous I/O, timers, or stream chunks before evaluating value and done.

2. Protocol Identification via Symbols

TypeScript treats the property key that exposes the iterator factory method as a strict structural discriminator:

  • Iterable<T> mandates the presence of the [Symbol.iterator] method.
  • AsyncIterable<T> mandates the presence of the [Symbol.asyncIterator] method.

Because these symbols are distinct global symbols in JavaScript, an object implementing only Iterable<T> cannot be directly passed to APIs requiring AsyncIterable<T>, and vice versa, preserving strict type safety at compile time.

Language-Level Syntax Integration

TypeScript's type checker maps language constructs to these interfaces distinctly:

  • for...of loops: Exclusively accept objects conforming to Iterable<T>. Attempting to use a type matching only AsyncIterable<T> produces a compiler error (TS2488).
  • for await...of loops: Primarily designed for AsyncIterable<T>. However, TypeScript also permits for await...of over synchronous Iterable<Promise<T>> or Iterable<T>, automatically wrapping synchronous values in a resolution handler matching JavaScript runtime behavior.
  • Generators:
    • function* declarations automatically infer the return type Generator<T, TReturn, TNext>, which extends Iterator<T, TReturn, TNext>.
    • async function* declarations infer AsyncGenerator<T, TReturn, TNext>, extending AsyncIterator<T, TReturn, TNext>.

Type Compatibility and Assignment

Because AsyncIterator requires methods to return a Promise, an Iterator<T> is structurally incompatible with AsyncIterator<T>. The compiler prevents accidental synchronous consumption of asynchronous streams and ensures that asynchronous boundaries are handled explicitly with await or promise chaining.
