How TypeScript outDir Structures Output Files

The outDir compiler option in TypeScript dictates where the compiler places emitted JavaScript and declaration files while attempting to preserve the directory structure of the source files. This article explains how TypeScript calculates the output folder hierarchy, the critical role the rootDir option plays in that process, and how to avoid common nesting pitfalls when organizing compiled files.

The Role of outDir

When you specify outDir in tsconfig.json, the TypeScript compiler (tsc) routes all generated output files—such as .js, .jsx, .d.ts, and .js.map files—into that target folder instead of placing them alongside the original .ts source files. By default, the compiler does not flatten your project structure into a single directory; instead, it replicates the folder hierarchy of your inputs within the specified output path.

How Directory Structure Is Determined

To determine how to mirror files into outDir, the compiler looks for the longest common path among all non-declaration input files. This common path becomes the base directory from which the output hierarchy is mirrored.

For example, consider a project with the following structure:

my-project/
├── tsconfig.json
└── src/
    ├── index.ts
    └── utils/
        └── helpers.ts

If your tsconfig.json contains:

{
  "compilerOptions": {
    "outDir": "./dist"
  }
}

Because all input files reside under src/, TypeScript recognizes src as the common root directory. The compiled files will be mirrored directly under dist/ without an extra src folder:

dist/
├── index.js
└── utils/
    └── helpers.js

The Common Ancestor Problem

The output structure can change unexpectedly if a source file outside your intended source folder is included in the build. For example, if you add a file at scripts/build.ts or tests/index.test.ts and it is included in the compilation:

my-project/
├── tsconfig.json
├── scripts/
│   └── build.ts
└── src/
    └── index.ts

Because src/ is no longer the common ancestor of all source files, the longest common path shifts upward to the project root (my-project/). Consequently, TypeScript restructures dist to mirror both folders:

dist/
├── scripts/
│   └── build.js
└── src/
    └── index.js

This sudden nesting of dist/src/ often breaks deployment scripts and import paths that expect index.js to reside directly at dist/index.js.

Controlling Output Structure with rootDir

To prevent unexpected nesting, you can explicitly configure the rootDir option alongside outDir:

{
  "compilerOptions": {
    "rootDir": "./src",
    "outDir": "./dist"
  }
}

By defining rootDir, you tell the compiler exactly which directory represents the root of your source code. The folder structure inside rootDir is then mapped 1:1 into outDir.

Furthermore, defining rootDir adds a safeguard: if any included TypeScript file lives outside the specified rootDir, the compiler will throw an error (TS6059: File is not under 'rootDir') rather than silently altering the output folder layout. To resolve this, exclude the external files using the exclude array or move them to a separate project managed by TypeScript project references.
