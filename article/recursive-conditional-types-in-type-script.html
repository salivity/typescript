Recursive Conditional Types in TypeScript

Recursive conditional types combine TypeScript's conditional logic with self-referential type definitions, enabling the type system to iterate through data until a specified base condition is met. This article explains the core mechanics of recursive conditional types and demonstrates how to utilize them to traverse, extract, and manipulate deeply nested data structures such as multi-layered promises, multidimensional arrays, and dot-notated object path strings.

Understanding Recursive Conditional Types

A standard conditional type in TypeScript takes the form of a ternary expression:

type IsString<T> = T extends string ? true : false;

A conditional type becomes recursive when the true or false branch references the type alias itself with a modified type parameter. This creates a type-level loop that processes data layer-by-layer until it reaches a terminating condition (a base case).

TypeScript introduced official support for recursive conditional types in version 4.1, relaxing previous restrictions against circular references in conditional evaluation.

Unwrapping Nested Data Layers

A fundamental use case for recursive conditional types is unwrapping unknown depths of wrapping types, such as nested arrays or promises.

Example: Deeply Unwrapping Arrays

To extract the primitive element type from an array of arbitrary depth (e.g., number[][][] to number):

type DeepFlatten<T> = T extends Array<infer Element>
  ? DeepFlatten<Element>
  : T;

type NestedNumbers = number[][][];
type Flat = DeepFlatten<NestedNumbers>; // Evaluates to: number

In this implementation:

  1. T extends Array<infer Element> checks if T is an array and captures its inner element.
  2. If true, DeepFlatten<Element> recursively invokes itself with the unwrapped inner type.
  3. If false, the base case is reached, and the non-array type T is returned.

Parsing Nested Object Paths

Recursive conditional types can be paired with template literal types to parse and generate dot-notation paths for nested object properties.

Generating Deep Keys

To produce a union of all accessible key paths within a deeply nested object:

type NestedPaths<T> = T extends object
  ? {
      [K in keyof T & (string | number)]: T[K] extends object
        ? `${K}` | `${K}.${NestedPaths<T[K]>}`
        : `${K}`;
    }[keyof T & (string | number)]
  : never;

type UserProfile = {
  id: string;
  preferences: {
    theme: string;
    notifications: {
      email: boolean;
      sms: boolean;
    };
  };
};

type Keys = NestedPaths<UserProfile>;
// Evaluates to: "id" | "preferences" | "preferences.theme" | 
// "preferences.notifications" | "preferences.notifications.email" | 
// "preferences.notifications.sms"

Retrieving a Type via a Dot-Notation String

To look up the type of a value located at a specific dot-notated string path:

type GetDeepValue<T, Path extends string> = 
  Path extends `${infer Head}.${infer Tail}`
    ? Head extends keyof T
      ? GetDeepValue<T[Head], Tail>
      : never
    : Path extends keyof T
      ? T[Path]
      : never;

type NotificationEmailType = GetDeepValue<UserProfile, "preferences.notifications.email">;
// Evaluates to: boolean

In this example:

  1. Path extends\({infer Head}.\){infer Tail}`` splits the string by the first dot delimiter.
  2. Head extends keyof T verifies that the current segment exists on object T.
  3. If valid, the type passes the nested child T[Head] and the remaining string Tail back into GetDeepValue.
  4. When no dot remains, the base case Path extends keyof T ? T[Path] : never returns the target type.

Compiler Limits and Performance

TypeScript enforces a recursion depth limit (typically around 50 steps depending on the complexity of the operation) to prevent compiler stack overflows. When designing recursive types:

  • Ensure every branch has a clear termination path to prevent infinite recursion.
  • Keep intermediate structural types minimal to avoid exceeding compiler memory limits during large-scale code generation.
