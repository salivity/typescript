How TypeScript Compiles Async/Await to ES5

This article explores how the TypeScript compiler transforms modern async/await syntax into ECMAScript 5 (ES5) compatible JavaScript. Because ES5 lacks both native async/await and ES6 generator functions (function*), TypeScript bridges this gap by rewriting asynchronous functions into a state-machine architecture managed by two core helper routines: __awaiter and __generator.

The Challenge of ES5 Downleveling

Targeting ES5 requires eliminating all syntax features introduced in ES2015 and later. While an ES6 target can simply compile async/await into standard generator functions paired with a promise runner, targeting ES5 means generators themselves must be simulated.

To overcome this, TypeScript uses:

  1. __awaiter: A promise-management wrapper that drives the execution forward.
  2. __generator: A state-machine simulator that mimics generator behavior (yield, next, throw, and return) using standard switch/case control flow.

The Role of __awaiter

The __awaiter helper acts like a coroutine runner (similar to the popular co library). Its primary responsibility is wrapping the execution of an asynchronous task in a native or polyfilled Promise.

When an async function is invoked, __awaiter immediately returns a new Promise. It defines an internal stepping mechanism, typically named step, which recursively calls the generator's next() or throw() methods.

When the generator yields a value (which corresponds to an expression evaluated in an await statement):

  • If the yielded promise resolves, __awaiter calls step("next", resolvedValue), resuming execution.
  • If the yielded promise rejects, __awaiter calls step("throw", rejectionError) to let the state machine handle the error or reject the outer promise.
  • When the state machine completes (done: true), __awaiter resolves the outer promise with the final return value.

The Role of __generator

The __generator helper replaces native ES6 generator mechanics (function* and yield). It receives a function body containing a large switch statement, where each case corresponds to an execution step between suspension points (the await expressions).

The helper maintains an internal state object (commonly designated as _) that tracks:

  • label: The instruction pointer (the current case in the switch statement).
  • sent: The value returned to the generator when execution resumes (the resolved value of an awaited promise).
  • trys and ops**: Arrays tracking exception handlers, nested try/catch/finally blocks, and call-stack unwinding.

Every time await is used in your code, TypeScript splits the function into discrete blocks. It sets _.label to point to the next block, and returns an operation indicating that execution should pause.

The Transformation in Action

Consider this simple TypeScript function:

async function fetchUser(id: number) {
    const response = await fetch(`/api/user/${id}`);
    const data = await response.json();
    return data;
}

When compiled to ES5, the code is restructured into the following functional layout:

function fetchUser(id) {
    return __awaiter(this, void 0, void 0, function () {
        var response, data;
        return __generator(this, function (_a) {
            switch (_a.label) {
                case 0:
                    return [4 /*yield*/, fetch("/api/user/" + id)];
                case 1:
                    response = _a.sent();
                    return [4 /*yield*/, response.json()];
                case 2:
                    data = _a.sent();
                    return [2 /*return*/, data];
            }
        });
    });
}

Deconstructing the Compiled Output

  1. State 0: Execution begins. The code calls fetch("/api/user/" + id). The helper returns [4, fetch(...)], where opcode 4 represents a yield. __awaiter intercepts this promise and pauses execution.
  2. State 1: Once the fetch promise resolves, __awaiter invokes _a.sent() to retrieve the result, assigns it to response, and evaluates response.json(). It yields again via [4, response.json()].
  3. State 2: When response.json() resolves, its result is assigned to data. The function encounters return [2, data], where opcode 2 signals completion (return). __awaiter marks the generator as complete and resolves the outer promise.

Error Handling Downleveling

When try/catch/finally blocks wrap await calls, TypeScript extends the state machine by populating the trys array in the generator's state. Each entry records the start label, end label, catch label, and finally label.

If an error is thrown internally or fed into the generator via step("throw", err), __generator checks the current label against the trys table. If the execution point is within a monitored block, it jumps to the catch label; otherwise, it bubbles the error up, causing __awaiter to reject the outer promise.
