TypeScript outDir and rootDir Conflicts Explained

Configuring rootDir and outDir in your tsconfig.json dictates how TypeScript maps your input source files to emitted JavaScript build files. When these paths conflict—whether through overlapping directories, attempting to compile files outside the defined root, or accidentally including emitted files back into compilation—the TypeScript compiler (tsc) typically throws compilation errors like TS5055 or TS6059, or generates distorted, unexpectedly nested output directory structures.

The Roles of outDir and rootDir

  • rootDir: Defines the base directory of your TypeScript source code. TypeScript uses this path to determine the directory structure when mirroring source files into the output directory.
  • outDir: Defines the destination folder where the generated .js, .d.ts, and .js.map files will be placed.

Conflict Scenarios and Compiler Behavior

1. Overwriting Source Files (Error TS5055)

If outDir is set to the same directory as rootDir (or omitted entirely, defaulting output to the source locations), TypeScript risks overwriting your original files. This issue commonly surfaces when allowJs is enabled or declaration files are emitted:

Cannot write file 'path/to/file.js' because it would overwrite input file. (TS5055)

The compiler blocks execution to safeguard your source code from being permanently replaced by generated output.

2. Source Files Outside the Root (Error TS6059)

When rootDir is explicitly defined, every single file included in the compilation program must reside inside that directory. If a file inside rootDir imports a file located outside of it (such as a shared utility in a monorepo or a root-level config file), compilation immediately fails:

File '.../shared/util.ts' is not under 'rootDir' '.../src'. 'rootDir' is expected to contain all source files. (TS6059)

TypeScript requires all input sources to share a common root so it can cleanly mirror the folder hierarchy inside outDir.

3. Unexpected Output Nesting

If rootDir is left unspecified, TypeScript automatically calculates the common root directory among all input files. If a file outside your primary source folder is accidentally imported, TypeScript recalculates the common root one level higher. Consequently, your outDir structure will unexpectedly change from dist/index.js to dist/src/index.js to preserve the wider directory tree.

4. Recursive Build Loops

If outDir is placed inside rootDir (for example, rootDir: "./" and outDir: "./dist") without properly excluding the build folder, subsequent builds may attempt to process the emitted JavaScript or declaration files inside dist. This causes circular compilation issues, duplicated declaration files, or build slowdowns.

How to Resolve and Prevent Conflicts

  1. Keep Source and Output Separate: Establish distinct folders for inputs and outputs. Set "rootDir": "./src" and "outDir": "./dist".

  2. Exclude the Output Folder: Add your output path to the exclude array in tsconfig.json to prevent the compiler from reading emitted files:

    "exclude": ["node_modules", "dist"]

  3. Use Project References for External Files: If you need to import files that live outside rootDir, do not expand rootDir to the repository root. Instead, split the project using TypeScript Project References with composite configurations to compile each directory independently.
