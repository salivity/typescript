TypeScript Constructor Parameter Properties Shorthand

TypeScript parameter properties shorthand is a syntactic feature that enables developers to declare and initialize class member fields directly within the constructor parameter list. Instead of writing separate property declarations and assignment statements inside the constructor body, prefixing a constructor argument with an accessibility modifier or readonly keyword instructs the TypeScript compiler to automatically generate both the property declaration and its assignment. This concise pattern significantly cuts down boilerplate code in class definitions.

The Traditional Approach vs. Parameter Properties

In standard TypeScript or traditional object-oriented programming, defining properties on a class typically requires three distinct steps: declaring the property, defining the constructor parameter, and assigning the parameter value to the instance property.

class User {
  public name: string;
  private age: number;

  constructor(name: string, age: number) {
    this.name = name;
    this.age = age;
  }
}

While clear, this approach introduces redundancy, particularly for classes with numerous fields or dependency-injected services.

By using parameter properties shorthand, you can achieve the exact same behavior in a single step:

class User {
  constructor(public name: string, private age: number) {}
}

Supported Modifiers

To trigger the parameter property behavior, you must prefix a constructor parameter with at least one of the following modifiers:

  • public: Explicitly creates a public property accessible from anywhere.
  • private: Creates a private property accessible only within the declaring class.
  • protected: Creates a protected property accessible within the declaring class and its subclasses.
  • readonly: Creates a property that cannot be reassigned outside the constructor.

Modifiers can also be combined. For example, using public readonly or private readonly assigns both accessibility and immutability:

class Product {
  constructor(
    public readonly id: string,
    public title: string,
    private costPrice: number
  ) {}
}

If a parameter lacks any of these keywords, TypeScript treats it as a standard constructor argument that only exists within the scope of the constructor function.

Compiled JavaScript Output

Under the hood, TypeScript transforms parameter properties into standard JavaScript property assignments. The compiled JavaScript for the User shorthand class looks like this:

class User {
  constructor(name, age) {
    this.name = name;
    this.age = age;
  }
}

Because TypeScript strips out types and accessibility modifiers during compilation, the resulting JavaScript output is identical to the traditional approach, ensuring zero runtime overhead.

Key Benefits

  • Reduced Boilerplate: Eliminates repetitive property declarations and assignment lines (this.x = x).
  • Readability: Keeps data classes and dependency-injected services concise and focused.
  • Maintainability: Adding or renaming a property requires modifying code in only one location instead of three.
