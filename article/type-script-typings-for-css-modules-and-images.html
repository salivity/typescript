TypeScript Typings for CSS Modules and Images

TypeScript is designed to compile JavaScript and TypeScript files, meaning it natively lacks the ability to interpret non-code assets such as images and stylesheets. To prevent compilation errors when importing these static files, TypeScript uses ambient module declarations defined in declaration files (.d.ts). This article explains how TypeScript recognizes non-code assets via ambient typings, how to configure declarations for images and CSS modules, and how these declarations integrate into the TypeScript compiler workflow.

The Import Problem for Non-Code Assets

When an application bundles assets using tools like Webpack, Vite, or Rollup, developers often import assets directly into their code:

import logo from './logo.svg';
import styles from './Button.module.css';

By default, the TypeScript compiler checks the local file system for a corresponding .ts, .tsx, or .d.ts file. Since logo.svg and Button.module.css are not recognized source files, the compiler produces error TS2307: Cannot find module '...' or its corresponding type declarations.

Ambient Module Declarations

TypeScript resolves this limitation using ambient declarations via the declare module syntax. Ambient declarations describe the shape of an imported module without providing an implementation. By utilizing wildcard module names (pattern matching), developers can define typing rules for entire categories of file extensions.

These definitions are conventionally stored in a declaration file, such as globals.d.ts or declarations.d.ts, placed within the project's source directory.

Declaring Static Image Assets

For static image formats (such as .svg, .png, .jpg, or .webp), bundlers typically resolve the import to a string representing the public URL or file path. The ambient declaration mirrors this behavior:

declare module '*.svg' {
  const content: string;
  export default content;
}

declare module '*.png' {
  const content: string;
  export default content;
}

declare module '*.jpg' {
  const content: string;
  export default content;
}

With this declaration in scope, any import matching *.png or *.svg is assigned a type where the default export is a string.

Declaring CSS Modules

CSS modules generate scoped class names at build time and export an object mapping original class names to their hashed, unique equivalents. The ambient declaration for CSS modules models this key-value structure:

declare module '*.module.css' {
  const classes: { readonly [key: string]: string };
  export default classes;
}

declare module '*.module.scss' {
  const classes: { readonly [key: string]: string };
  export default classes;
}

This wildcard typing allows arbitrary property access on the imported styles object (e.g., styles.buttonContainer), returning a string for each accessed class.

Generating Exact Types for CSS Modules

While a generic Record<string, string> stops TypeScript from throwing errors, it does not provide autocomplete or protect against typos in class names. To achieve strict type safety for CSS modules, developers use specialized tooling rather than a single wildcard declaration:

  1. Build-Time Generators: Tools like typed-css-modules or bundler plugins automatically generate dedicated .d.ts files alongside each stylesheet (e.g., creating Button.module.css.d.ts alongside Button.module.css).
  2. IDE Integration: Plugins such as the TypeScript CSS Modules Language Service allow editors to read the underlying CSS files directly and provide real-time type inference without polluting the source tree with generated files.

Configuring TypeScript to Read Declarations

For TypeScript to recognize ambient declarations, the .d.ts file must be included in the compiler's compilation context. This is managed in the tsconfig.json file via the include array:

{
  "compilerOptions": {
    "target": "ESNext",
    "module": "ESNext",
    "moduleResolution": "node"
  },
  "include": [
    "src/**/*",
    "src/declarations.d.ts"
  ]
}

As long as the ambient declaration file matches the paths specified in include, TypeScript applies these typings globally across the project, allowing seamless imports of static assets.
