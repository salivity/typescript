Leading and Middle Rest Elements in TypeScript Tuples

TypeScript provides flexible tuple manipulation by supporting rest elements at the beginning, middle, or end of a tuple type. This guide explains the mechanics of leading and middle rest elements, their syntax, type inference rules, constraints, and how they enhance typing for complex JavaScript function signatures.

Syntax and Core Behavior

Prior to TypeScript 4.2, rest elements (...T[]) could only appear at the end of a tuple. TypeScript expanded this capability, allowing a rest element to be placed anywhere within a tuple definition, provided it is bounded by fixed elements.

Leading Rest Elements

A leading rest element appears at the start of a tuple, followed by one or more fixed elements. This pattern represents zero or more items of a specific type, terminated by definitive types.

type TrailingNumberTuple = [...string[], number];

// Valid assignments:
const example1: TrailingNumberTuple = [1];
const example2: TrailingNumberTuple = ["hello", 2];
const example3: TrailingNumberTuple = ["a", "b", "c", 3];

// Type Error: The last element must be a number
// const invalid: TrailingNumberTuple = ["a", "b"];

Middle Rest Elements

A middle rest element is sandwiched between fixed leading and trailing elements. This defines an array structure that must begin and end with specific types, while containing an arbitrary number of elements in between.

type BoundedList = [boolean, ...number[], string];

// Valid assignments:
const valid1: BoundedList = [true, "end"];
const valid2: BoundedList = [false, 1, 2, 3, "end"];

// Type Error: Missing the trailing string
// const invalid: BoundedList = [true, 1, 2];

Function Signatures and Argument Handling

Leading and middle rest elements are particularly useful for typing higher-order functions and variadic arguments that enforce a trailing argument, such as a callback function or an options object.

function executePipeline(...args: [...string[], () => void]): void {
  const callback = args.pop() as () => void;
  const stages = args as string[];
  
  stages.forEach(stage => console.log(`Running: ${stage}`));
  callback();
}

// Valid calls:
executePipeline(() => console.log("Done"));
executePipeline("Build", "Test", "Deploy", () => console.log("Pipeline Finished"));

In this scenario, TypeScript automatically infers that the final parameter passed must match the trailing tuple element (() => void), while all preceding parameters correspond to the rest element (string[]).

Rules and Limitations

To prevent ambiguity in type resolution, TypeScript enforces strict limitations on rest elements within tuples:

  1. Only One Rest Element Allowed: A tuple type cannot contain more than one rest element. A definition like [...string[], ...number[]] is invalid because the compiler cannot determine where the boundary between the two variable-length types lies.
  2. Optional Elements Cannot Follow Rest Elements: A rest element represents an open-ended number of items. Consequently, optional elements (element?: Type) cannot be declared after a rest element, as their presence would be impossible to validate deterministically.
  3. Destructuring Constraints: When destructuring arrays typed with middle rest elements, TypeScript preserves the underlying types accurately, resolving trailing elements relative to the end of the array.
