TypeScript Default Parameters and Type Inference

TypeScript streamlines function design by automatically inferring types for parameters that have default values, while treating those parameters as inherently optional. This article explains how TypeScript deduces types from assigned default values, how explicit annotations interact with these defaults, the role of undefined in triggering fallback values, and the impact of parameter placement on function signatures.

Automatic Type Inference

When you assign a default value to a function parameter without explicitly annotating its type, TypeScript infers the parameter's type from the assigned value.

function setPort(port = 3000) {
  // TypeScript infers 'port' as type number
  console.log(`Server running on port ${port}`);
}

setPort(8080); // Valid
setPort("8080"); // Error: Argument of type 'string' is not assignable to parameter of type 'number'.

The type is inferred as the base primitive or literal type depending on the context, ensuring strict type safety without redundant code.

Optional Parameter Semantics

Any parameter with a default value is automatically considered optional by the TypeScript compiler. This means callers can omit the argument entirely.

function greet(name = "Guest") {
  return `Hello, ${name}!`;
}

greet(); // Returns "Hello, Guest!"
greet("Alice"); // Returns "Hello, Alice!"

Under the hood, TypeScript generates a signature equivalent to name?: string, allowing the argument to be omitted.

The Role of undefined vs null

A default value is triggered only when the parameter receives undefined or is omitted. Passing null does not trigger the default value.

function displayStatus(status = "active") {
  console.log(status);
}

displayStatus(undefined); // Outputs: "active"
displayStatus(null); // Error (under strictNullChecks): Argument of type 'null' is not assignable to parameter of type 'string | undefined'.

If strictNullChecks is enabled, passing null to a parameter whose default value is a string causes a compile error, as null is not compatible with string.

Combining Explicit Types with Defaults

You can explicitly annotate a parameter's type alongside a default value. This is useful when you want to allow a wider set of types than the default value alone provides, such as union types.

function format(input: string | number = "N/A") {
  return String(input);
}

format(); // Uses "N/A"
format(42); // Valid
format("Custom"); // Valid

TypeScript ensures that the default value satisfies the declared type annotation. If the default value does not match the explicit type, the compiler issues an error at compile time.

Parameter Positioning and Ordering

Parameters with default values do not strictly need to be placed at the end of the parameter list. However, if a defaulted parameter precedes a required parameter, callers must explicitly pass undefined to utilize the default value.

function createRequest(timeout = 5000, endpoint: string) {
  return `Fetching ${endpoint} with timeout ${timeout}ms`;
}

// To use the default timeout, undefined must be explicitly passed
createRequest(undefined, "/api/data");

To maintain clean and ergonomic call signatures, it is standard practice to position parameters with default values at the end of the parameter list.
