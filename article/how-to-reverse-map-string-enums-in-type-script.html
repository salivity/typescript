How to Reverse Map String Enums in TypeScript

TypeScript natively generates reverse mappings (mapping values back to keys) for numeric enums, but it omits this feature for string enums to prevent runtime overhead and potential value collisions. This article explains how to manually emulate reverse mapping for string enums in TypeScript using lookup objects and reusable generic utility functions, enabling you to safely retrieve an enum key from its string value.

Why String Enums Lack Reverse Mapping

When compiling a numeric enum, TypeScript creates a two-way mapping object at runtime where both Enum[key] = value and Enum[value] = key exist. With string enums, TypeScript only generates a unidirectional mapping (Enum[key] = value).

To look up the key corresponding to a string enum value, you must generate the reverse relationship yourself.

Method 1: Creating a Precomputed Reverse Lookup Object

If you need fast \(O(1)\) lookups, precompute an inverted dictionary when the application initializes.

enum LogLevel {
  Info = "INFO",
  Warn = "WARN",
  Error = "ERROR",
}

type LogLevelKey = keyof typeof LogLevel;

// Create the reverse mapping object
const ReverseLogLevel: Record<LogLevel, LogLevelKey> = Object.entries(LogLevel).reduce(
  (accumulator, [key, value]) => {
    accumulator[value as LogLevel] = key as LogLevelKey;
    return accumulator;
  },
  {} as Record<LogLevel, LogLevelKey>
);

// Usage:
const key = ReverseLogLevel[LogLevel.Warn]; 
console.log(key); // Output: "Warn"

This method is ideal for high-throughput scenarios where accessing the key must happen in constant time.

Method 2: Generic Reverse Lookup Helper Function

When you only need occasional lookups across multiple enums, a generic utility function avoids the need to define separate lookup tables.

function getEnumKeyByValue<T extends Record<string, string>>(
  enumObj: T,
  value: string
): keyof T | undefined {
  const entries = Object.entries(enumObj) as [keyof T, string][];
  const found = entries.find(([_, val]) => val === value);
  return found ? found[0] : undefined;
}

enum OrderStatus {
  Pending = "PENDING",
  Shipped = "SHIPPED",
  Delivered = "DELIVERED",
}

// Usage:
const statusKey = getEnumKeyByValue(OrderStatus, "SHIPPED");
console.log(statusKey); // Output: "Shipped"

const invalidKey = getEnumKeyByValue(OrderStatus, "UNKNOWN");
console.log(invalidKey); // Output: undefined

This function performs an \(O(n)\) search across the enum entries and retains strict type safety by returning keyof T | undefined.

Alternative: Using as const Objects

Many modern TypeScript codebases prefer plain objects with const assertions over TypeScript enums. Reverse mapping on as const objects works using the same inverted dictionary approach:

const UserRole = {
  Admin: "ADMIN",
  User: "USER",
  Guest: "GUEST",
} as const;

type ValueOf<T> = T[keyof T];
type UserRoleValue = ValueOf<typeof UserRole>;
type UserRoleKey = keyof typeof UserRole;

const ReverseUserRole = Object.fromEntries(
  Object.entries(UserRole).map(([key, value]) => [value, key])
) as Record<UserRoleValue, UserRoleKey>;

console.log(ReverseUserRole["ADMIN"]); // Output: "Admin"

Using Object.fromEntries provides a concise way to flip the keys and values while preserving type definitions.
