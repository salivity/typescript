How to Use Array filter as a Type Guard in TypeScript

In TypeScript, using Array.prototype.filter does not automatically narrow the type of an array, even if the filter condition removes invalid or unwanted values. To properly narrow the resulting array's type, you must define the filter callback as a custom type guard using the value is Type predicate syntax. This article explains why the default behavior occurs and provides clear, practical examples of how to define and use custom type guards with the filter method.

The Default Filtering Problem

By default, the TypeScript signature for Array.prototype.filter infers the return type based on whether the predicate uses a type predicate. If you use a standard boolean-returning function, TypeScript retains the original element type:

const mixedValues: (string | null | undefined)[] = ["hello", null, "world", undefined];

// Type remains (string | null | undefined)[]
const filtered = mixedValues.filter((item) => item !== null && item !== undefined);

Even though non-string elements are removed at runtime, the compiler still treats filtered as (string | null | undefined)[].

Typing the Callback with a Type Guard

To fix this, write the callback function using a type predicate in its return position: (item: InputType): item is TargetType. TypeScript includes an overload for Array.prototype.filter that recognises this signature:

filter<S extends T>(predicate: (value: T, index: number, array: T[]) => value is S, thisArg?: any): S[];

When a callback returns a type predicate, filter returns an array of the narrowed type S[].

Inline Type Guards

You can define the type guard directly inside the filter method call:

const mixedValues: (string | null | undefined)[] = ["alpha", null, "beta", undefined];

// Type is narrowed to string[]
const strings = mixedValues.filter((item): item is string => item !== null && item !== undefined);

Reusable Type Guard Functions

For cleaner code and reusability, define dedicated type guard functions:

// Reusable guard to filter out null and undefined
function isNonNullable<T>(value: T): value is NonNullable<T> {
  return value !== null && value !== undefined;
}

const numbersWithNulls: (number | null)[] = [1, 2, null, 4];

// Type is inferred as number[]
const numbersOnly = numbersWithNulls.filter(isNonNullable);

Filtering Discriminated Unions

Type guards are equally effective for narrowing arrays of complex objects or discriminated unions:

interface User {
  type: "user";
  name: string;
}

interface Admin {
  type: "admin";
  name: string;
  permissions: string[];
}

type Account = User | Admin;

const accounts: Account[] = [
  { type: "user", name: "Alice" },
  { type: "admin", name: "Bob", permissions: ["manage_users"] }
];

// Reusable guard for the Admin type
function isAdmin(account: Account): account is Admin {
  return account.type === "admin";
}

// Type is inferred as Admin[]
const admins = accounts.filter(isAdmin);

By ensuring your filter predicates explicitly declare value is TargetType, TypeScript can safely resolve the output array to the exact subtype you expect.
