How allowUnusedLabels Works in TypeScript

The allowUnusedLabels compiler option in TypeScript controls how the compiler reacts when it encounters labeled statements that are never referenced by a break or continue statement. This article explains what unused labels are, how modifying the allowUnusedLabels setting impacts your code diagnostics, and why configuring it is important for preventing syntax mistakes.

What Are Labels in JavaScript and TypeScript?

In JavaScript and TypeScript, you can prefix statements with an identifier followed by a colon (such as myLoop: for (...)). These are called labels. They allow nested loops or code blocks to be selectively targeted by break or continue statements.

An unused label occurs when a label is declared, but no subsequent break or continue uses it:

outerLoop: 
for (let i = 0; i < 5; i++) {
    console.log(i);
}

In the example above, outerLoop is never used to break or continue execution, making it redundant.

How the allowUnusedLabels Flag Operates

The allowUnusedLabels setting is defined in the compilerOptions section of your tsconfig.json file. It accepts three potential values: undefined, true, or false.

{
  "compilerOptions": {
    "allowUnusedLabels": false
  }
}
  • undefined (Default): TypeScript will provide an informational suggestion in editors (such as VS Code), often graying out the unused label to indicate dead code, but it will not emit a compiler error or fail a build.
  • false: TypeScript treats unused labels as errors (TS7028: Unused label.). If an unused label is present in the code, compilation fails.
  • true: TypeScript completely ignores unused labels. No warnings, suggestions, or compiler errors will be produced.

Why You Should Set allowUnusedLabels to false

Unused labels are rarely written intentionally. In modern JavaScript and TypeScript development, they are almost always the result of a typo.

The most common occurrence is mistakenly returning an object literal from an arrow function without wrapping the object in parentheses:

const getUser = () => {
  name: "Alice"
};

In this snippet, JavaScript parses { name: "Alice" } not as an object literal, but as a block body containing a label named name: followed by an expression statement "Alice".

Setting allowUnusedLabels: false flags name: as an unused label error, allowing you to catch this syntax error immediately during the build process instead of letting the function return undefined silently at runtime.
