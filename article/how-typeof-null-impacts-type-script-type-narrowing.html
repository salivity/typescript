How typeof null Impacts TypeScript Type Narrowing

In JavaScript, the expression typeof null evaluates to 'object', a legacy behavior dating back to the language's initial release. In TypeScript, this historical quirk directly impacts control flow analysis and type narrowing logic. Because TypeScript aligns its type system with runtime JavaScript semantics, checking whether a value has a typeof equal to 'object' does not exclude null. Understanding how this behavior shapes TypeScript's narrowing rules is crucial for preventing unexpected runtime errors and writing robust type guards.

The JavaScript Root Cause

When JavaScript was created, values were represented with a type tag in the lower bits of their memory representations. The tag for an object reference was 000. Since null was represented as a null pointer (a reference value of 0x00 in most platforms), its type tag also resolved to 000. Consequently, typeof null returned 'object'. Although proposals were made to fix this in ECMAScript, they were rejected to avoid breaking backwards compatibility with existing web applications.

How TypeScript Handles typeof === 'object'

TypeScript uses control flow analysis to narrow down union types based on conditionals. When an engineer writes a standard JavaScript type check, TypeScript interprets the check according to JavaScript runtime rules:

function processValue(value: string | { name: string } | null) {
  if (typeof value === 'object') {
    // TypeScript narrows 'value' to: { name: string } | null
    console.log(value.name); // Error: 'value' is possibly 'null'.
  }
}

Because typeof null is 'object', the guard typeof value === 'object' cannot eliminate null from the union. TypeScript narrows string | { name: string } | null down to { name: string } | null.

The Impact Under strictNullChecks

How this narrowing impacts code depends heavily on the compiler configuration:

  1. With strictNullChecks enabled (Default in modern setups): TypeScript prevents runtime failures by recognizing that null remains within the narrowed type. If a developer attempts to access a property immediately after a typeof x === 'object' check, the compiler emits an error (e.g., Object is possibly 'null'). This forces the developer to handle null explicitly.
  2. With strictNullChecks disabled: TypeScript treats null as a valid subtype of all domain types. In this scenario, checking typeof value === 'object' incorrectly leads the developer to believe the value is safely accessible, bypassing compile-time safety and resulting in runtime TypeError: Cannot read properties of null exceptions.

Effective Patterns for Narrowing Objects

To cleanly eliminate null alongside primitives, developers must combine checks or use alternative narrowing mechanisms.

1. Compound Truthiness Guard

Because null is falsy and non-null objects are truthy, combining a truthiness check with typeof is the most common pattern:

if (value && typeof value === 'object') {
  // 'value' is safely narrowed to the object type, excluding null
  console.log(value.name);
}

2. Explicit Non-Null Comparison

Explicitly checking against null is often preferred when working with objects that might legitimately be empty or falsy:

if (typeof value === 'object' && value !== null) {
  // 'value' is safely narrowed to the non-null object
  console.log(value.name);
}

3. The in Operator

The in operator checks for the presence of a property in an object. However, attempting 'prop' in null throws a runtime TypeError. Therefore, a non-null assertion or guard must precede it:

if (value && 'name' in value) {
  // 'value' is narrowed to an object containing the 'name' property
  console.log(value.name);
}

4. Custom User-Defined Type Guards

For reusable checks, particularly across unknown payloads, a custom type guard encapsulates the null-handling logic:

function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === 'object' && value !== null;
}

function handleInput(input: unknown) {
  if (isRecord(input)) {
    // 'input' is safely typed as Record<string, unknown>
    console.log(Object.keys(input));
  }
}

By factoring in the typeof null === 'object' quirk, TypeScript maintains type safety while adhering strictly to JavaScript runtime behavior, requiring explicit patterns to separate genuine objects from null values.
