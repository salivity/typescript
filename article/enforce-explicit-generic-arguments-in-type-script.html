Enforce Explicit Generic Arguments in TypeScript

TypeScript automatically infers generic type parameters from function arguments by default, which can sometimes bypass intended strict typing. This article covers how to prevent automatic type inference and force developers to pass generic arguments explicitly, using the native NoInfer<T> utility type for parameterized functions and conditional type guards for parameterless functions.

Preventing Inference from Arguments with NoInfer

When a generic parameter T appears in a function's argument list, TypeScript naturally infers T from the provided value. Starting in TypeScript 5.4, you can wrap the parameter type with the built-in NoInfer<T> utility to block inference and require the generic argument to be supplied at the call site.

function processValue<T>(value: NoInfer<T>): T {
  return value;
}

// Error: Argument of type 'string' is not assignable to parameter of type 'never'
// (or fails because T cannot be inferred)
processValue("hello"); 

// Correct: Generic argument is explicitly provided
processValue<string>("hello");

If you are using TypeScript versions prior to 5.4, you can create a custom NoInfer utility using a conditional tuple type:

type NoInfer<T> = [T][T extends any ? 0 : never];

function processValue<T>(value: NoInfer<T>): T {
  return value;
}

This constructs a deferred tuple lookup that tells the compiler not to use that position as an inference candidate for T.

Enforcing Generics on Parameterless Functions

When a function does not accept runtime parameters—such as an API fetcher or factory function—TypeScript defaults unsupplied generics to unknown instead of raising an error:

function fetchData<T>(): Promise<T> {
  return fetch("/api").then((res) => res.json());
}

// Silently compiles with T as unknown
const result = fetchData();

To force callers to supply a generic type, set the generic's default value to a sentinel type (like never or a custom brand) and use a conditional return type to invalidate calls that omit it.

function fetchData<T = never>(): [T] extends [never] 
  ? "Error: Generic argument is required" 
  : Promise<T> {
  return fetch("/api").then((res) => res.json()) as any;
}

// Error: Type '"Error: Generic argument is required"' is not assignable...
const badCall = fetchData();

// Correct: Evaluates to Promise<User>
const goodCall = fetchData<User>();

Wrapping [T] extends [never] in tuples avoids unintended distributive behavior across union types, ensuring the type check behaves predictably.

Requiring Generics via Dummy Function Constraints

Another pattern involves defaulting T to a forbidden state that fails an argument constraint if omitted:

type ValidateGeneric<T> = [T] extends [never] 
  ? "Explicit generic type required" 
  : unknown;

function parseJson<T = never>(
  raw: string, 
  ...guard: [T] extends [never] ? [never] : []
): T {
  return JSON.parse(raw);
}

// Error: Expected 2 arguments, but got 1.
parseJson('{"id": 1}');

// Correct: Compiles with no extra arguments required
parseJson<User>('{"id": 1}');

By leveraging NoInfer<T> for functions with inputs and conditional never defaults for functions without inputs, you can reliably eliminate implicit type inference across all generic functions in TypeScript.
