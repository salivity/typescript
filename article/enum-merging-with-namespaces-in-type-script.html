Enum Merging with Namespaces in TypeScript

In TypeScript, an enum can successfully merge with a namespace of the same name. This article explores how TypeScript's declaration merging rules allow enums to combine with namespaces, the syntax required to achieve this, practical use cases such as attaching static helper methods to an enum, and the limitations to keep in mind when implementing this pattern.

How Enum and Namespace Merging Works

TypeScript features declaration merging, which means the compiler combines two or more separate declarations declared with the same name into a single definition. When you declare an enum and a namespace with identical names within the same scope, TypeScript merges them. The enum provides the runtime object containing the keys and values, while the namespace allows you to attach static properties, functions, or sub-types to that same object.

Basic Syntax and Example

By default, TypeScript enums can only hold constant values (numeric or string) and cannot contain methods. Merging a namespace allows you to augment the enum with utility functions:

// 1. Declare the enum
enum OrderStatus {
  Pending = "PENDING",
  Shipped = "SHIPPED",
  Delivered = "DELIVERED",
  Cancelled = "CANCELLED"
}

// 2. Declare the namespace with the identical name
namespace OrderStatus {
  export function isFinal(status: OrderStatus): boolean {
    return status === OrderStatus.Delivered || status === OrderStatus.Cancelled;
  }

  export function parse(value: string): OrderStatus | undefined {
    return Object.values(OrderStatus).includes(value as OrderStatus)
      ? (value as OrderStatus)
      : undefined;
  }
}

// 3. Usage
const currentStatus = OrderStatus.Shipped;

console.log(OrderStatus.isFinal(currentStatus)); // false
console.log(OrderStatus.isFinal(OrderStatus.Delivered)); // true

In the compiled JavaScript, the OrderStatus namespace simply adds the isFinal and parse functions as properties on the already-existing OrderStatus object.

Common Use Cases

  1. Static Helper Functions: Encapsulating validation, serialization, or formatting logic directly on the enum object avoids polluting the global or module scope with freestanding functions like isFinalOrderStatus().
  2. Type Augmentation: You can export types or interfaces from within the namespace to group closely related types together (for example, OrderStatus.TransitionRule).
  3. Lookup Maps: You can place static lookup tables or display labels inside the namespace, keeping configuration data co-located with the enumeration.

Key Considerations and Limitations

  • Order of Declaration: While TypeScript often hoists declarations, standard practice requires declaring the enum before the namespace to ensure the runtime object is initialized before properties are assigned to it.
  • const enum Restriction: You cannot merge a namespace with a const enum. Because const enum members are completely inlined at compile time and generate no runtime JavaScript object, there is no object available for the namespace to extend.
  • Property Overwrites: Names declared inside the namespace must not collide with the keys of the enum itself; otherwise, a compile-time collision error will occur.
