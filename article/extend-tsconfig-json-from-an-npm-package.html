Extend tsconfig.json from an npm Package

TypeScript allows you to share and standardize compiler configurations across multiple projects by extending a tsconfig.json file directly from an installed npm package. This article explains how the "extends" property works with node module resolution, how to install and implement pre-configured base settings, and how to customize or override specific rules for your project.

How Extending from npm Packages Works

The tsconfig.json file contains a top-level "extends" property designed to inherit compiler options and file configurations from another file. TypeScript uses Node-style module resolution to locate configuration files inside the node_modules directory.

When you specify a package name in the "extends" field, TypeScript searches node_modules for the target package, reads its configuration, and applies those settings to your local setup.

Using Standard Configuration Bases

The TypeScript team maintains community-recommended configurations under the @tsconfig namespace on npm, tailored to various runtimes and frameworks.

To use one of these shared configurations, install the desired package as a development dependency:

npm install --save-dev @tsconfig/node20

Next, reference the installed package in your project's tsconfig.json:

{
  "extends": "@tsconfig/node20/tsconfig.json",
  "compilerOptions": {
    "outDir": "./dist"
  },
  "include": ["src/**/*"]
}

TypeScript also supports omitting the /tsconfig.json suffix if the package defines a "tsconfig.json" entry in its root directory or sets the "files" field in its package.json.

{
  "extends": "@tsconfig/node20"
}

Overriding Inherited Configurations

Configurations resolved through "extends" are merged with the host project's configuration. Any property explicitly declared in your local tsconfig.json takes precedence over the extended configuration.

For example, if the extended package specifies "strict": true, but you need to disable a single strict check, declare it under your local compilerOptions:

{
  "extends": "@tsconfig/recommended/tsconfig.json",
  "compilerOptions": {
    "noImplicitAny": false
  }
}

Top-level arrays such as include, exclude, and files do not merge; the local configuration completely overwrites the inherited arrays.

Creating a Shareable tsconfig Package

To create and publish an internal or public configuration package for your team:

  1. Initialize a new npm package.
  2. Create a tsconfig.json file containing your base settings.
  3. In package.json, include the file in the "files" array:
{
  "name": "@my-org/tsconfig",
  "version": "1.0.0",
  "files": ["tsconfig.json"]
}
  1. Publish the package to npm or a private registry.

Consumers can then install @my-org/tsconfig and extend it by referencing "extends": "@my-org/tsconfig".
