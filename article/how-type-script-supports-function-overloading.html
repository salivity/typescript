How TypeScript Supports Function Overloading

TypeScript supports function overloading by allowing developers to define multiple function signatures with different parameter types and return types, followed by a single implementation that accommodates all of them. Unlike traditional object-oriented languages like C# or Java, which allow multiple runtime implementations for the same function name, JavaScript only allows a single function implementation. TypeScript bridges this gap at compile-time by validating caller arguments against the declared overload signatures while maintaining a single, unified runtime function body.

1. Overload Signatures vs. Implementation Signature

To overload a function in TypeScript, you define two distinct elements:

  • Overload Signatures: Two or more function declarations that specify the allowed combinations of parameter types and return types. These signatures do not have a function body.
  • Implementation Signature: A single function declaration that includes the actual code body. The types in this signature must be broad enough to be compatible with every overload signature preceding it.
// Overload signatures
function combine(a: string, b: string): string;
function combine(a: number, b: number): number;

// Implementation signature
function combine(a: string | number, b: string | number): string | number {
    if (typeof a === "string" && typeof b === "string") {
        return a + b;
    }
    if (typeof a === "number" && typeof b === "number") {
        return a + b;
    }
    throw new Error("Invalid arguments: both must be strings or numbers.");
}

2. Visibility of the Implementation Signature

Callers of an overloaded function can only call it using one of the explicitly declared overload signatures. The implementation signature is hidden from the external API.

Using the previous example:

combine("hello", "world"); // Allowed (returns string)
combine(10, 20);           // Allowed (returns number)
combine("hello", 10);      // Error: No overload matches this call

Even though the implementation signature accepts (a: string | number, b: string | number), the compiler rejects combine("hello", 10) because no overload signature permits mixing strings and numbers.

3. Handling Different Parameter Counts

Overload signatures can have different numbers of parameters. In the implementation signature, any parameter not present in every overload must be marked as optional (?):

// Overload signatures
function calculateArea(radius: number): number;
function calculateArea(width: number, height: number): number;

// Implementation signature
function calculateArea(first: number, second?: number): number {
    if (second !== undefined) {
        return first * second; // Rectangle
    }
    return Math.PI * first * first; // Circle
}

4. Method Overloading in Classes

Function overloading rules apply identically to methods inside TypeScript classes:

class Messenger {
    sendMessage(content: string): void;
    sendMessage(content: string, urgent: boolean): void;
    sendMessage(content: string, urgent?: boolean): void {
        const priority = urgent ? "[URGENT] " : "";
        console.log(`${priority}${content}`);
    }
}

Overloading vs. Union Types

Function overloading is most useful when the return type depends directly on the argument types, or when specific combinations of arguments are strictly required. If the return type remains the same regardless of parameter types, using union types or optional parameters is generally simpler and preferred over overloading:

// Prefer this:
function logId(id: string | number): void {
    console.log(id);
}

// Over this:
function logId(id: string): void;
function logId(id: number): void;
function logId(id: string | number): void {
    console.log(id);
}
