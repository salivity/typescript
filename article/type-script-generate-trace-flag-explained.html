TypeScript generateTrace Flag Explained

The generateTrace flag in TypeScript is an essential diagnostic feature designed to profile compiler performance and resolve slow type-checking times. This article explains what the generateTrace flag is, how it captures compilation telemetry, how to configure it in your project, and how to interpret the resulting trace data to eliminate bottlenecks in your codebase.

What Is the generateTrace Flag?

Introduced in TypeScript 4.1, --generateTrace is a compiler option that outputs detailed performance and profiling data during a build. When projects scale, TypeScript compilation often slows down due to complex types, deep recursions, or oversized union types.

Running the compiler with generateTrace instructs TypeScript to track every phase of the compilation process—such as parsing files, resolving dependencies, and performing type checks—and write this information to a designated output directory.

How to Enable generateTrace

You can enable performance tracing directly via the TypeScript command line or inside your tsconfig.json file.

Via the Command Line

To run a one-off trace, pass the --generateTrace flag followed by the path to the directory where you want trace files stored:

npx tsc --generateTrace ./trace-output

Via tsconfig.json

To include it in your project configuration, add generateTrace to the compilerOptions block:

{
  "compilerOptions": {
    "generateTrace": "./trace-output"
  }
}

Understanding the Generated Output

When compilation finishes, the target directory typically contains two primary files:

  1. trace.json: Contains a structured timeline of events recorded in the Chromium Event Tracing format. It includes precise start times, durations, and phase names (e.g., program, checkSourceFile, findSourceFile) for every operation performed by tsc.
  2. types.json: Acts as a lookup table that maps numeric type IDs referenced in trace.json to their human-readable type representations. This allows you to identify the exact problematic types without bloating the main trace file.

How to View and Analyze the Trace

Because the output follows the Chromium Event Tracing standard, you can visualize the data using standard profiling tools:

  1. Chromium Visualizers: Open Google Chrome or Microsoft Edge and navigate to chrome://tracing, or visit the modern web viewer at ui.perfetto.dev. Drag and drop your trace.json file into the interface to see a visual timeline of compiler execution.
  2. Analyze-Trace Tool: The TypeScript team provides an official CLI tool called @typescript/analyze-trace to parse the files automatically and highlight performance hotspots:
npx @typescript/analyze-trace ./trace-output

This utility scans the trace files and directly reports the files, functions, and type-checking events that consume the most processing time.

Common Issues Identified by generateTrace

Using generateTrace helps identify specific code patterns that hinder compiler efficiency:

  • Massive Union or Intersection Types: Types that trigger combinatorial explosions during type-checking.
  • Deeply Recursive Types: Utility types that recurse too deeply, stalling the compiler's inference engine.
  • Overly Broad Contextual Typings: Code locations where lack of explicit type annotations forces TypeScript to re-evaluate complex expressions across multiple files.
  • Heavy Third-Party Definitions: External packages in node_modules that introduce complex type structures requiring disproportionate compute cycles.
