Incompatible Property Types in TypeScript Interfaces

When an interface extends a base interface in TypeScript, any redeclared properties must remain assignable to the parent interface's original definitions. Attempting to override a parent property with an incompatible type causes TypeScript to trigger a compile-time error (TS2430). This article examines why this restriction exists, how the compiler enforces it, and how to properly handle situations where a derived structure requires a different property type.

The Compilation Error

When you redeclare an inherited property with an incompatible type, TypeScript halts compilation and reports an error:

interface Animal {
  id: number;
}

interface Dog extends Animal {
  // Error: Interface 'Dog' incorrectly extends interface 'Animal'.
  // Types of property 'id' are incompatible.
  // Type 'string' is not assignable to type 'number'.
  id: string;
}

TypeScript requires an extending interface to maintain a valid subtype relationship with its base. Because an instance of Dog should be usable anywhere an Animal is expected, changing id from number to string breaks substitutability.

Subtype Narrowing vs. Incompatible Types

Redeclaring an inherited property is permitted only if the new type is a subtype of (assignable to) the parent's type. This is known as property narrowing.

Permitted: Type Narrowing

If the parent property is a broader type or union, a child interface can narrow it to a more specific member:

interface Response {
  status: string | number;
}

interface SuccessResponse extends Response {
  status: number; // Valid: 'number' is assignable to 'string | number'
}

Forbidden: Incompatible Overrides

If the types do not overlap in a subtype-supertype relationship, the declaration fails:

interface User {
  metadata: { [key: string]: string };
}

interface AdminUser extends User {
  // Error: Type 'string' is not assignable to type '{ [key: string]: string; }'
  metadata: string;
}

How to Resolve Incompatible Property Overrides

Because interfaces strictly enforce hierarchy compatibility via extends, you cannot use interface inheritance to replace a property with an arbitrary new type. To achieve this, use a type alias combined with the Omit utility type.

interface BaseUser {
  id: number;
  name: string;
}

type SpecializedUser = Omit<BaseUser, "id"> & {
  id: string;
};

By omitting the conflicting property from the base definition before applying the intersection (&), you remove the original definition, allowing the new property type to exist without triggering a collision or type incompatibility error.
