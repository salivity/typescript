TypeScript [key: string]: unknown Index Signatures

An index signature such as [key: string]: unknown enables TypeScript developers to define objects with dynamic property keys while maintaining strict type safety. This article covers what index signatures are, why [key: string]: unknown is preferred over [key: string]: any, how it interacts with known object properties, and how to safely access and narrow the types of dynamic values.

What Is an Index Signature?

In TypeScript, an index signature defines the types for keys and values when the exact property names of an object are not known ahead of time. The syntax [key: string] specifies that the keys must be strings, and the accompanying value type specifies what data type those keys map to.

Without an index signature, attempting to access an arbitrary key on an object literal produces a TypeScript compiler error. Adding an index signature explicitly tells the compiler that the object can hold arbitrary properties.

The Role of [key: string]: unknown

Using [key: string]: unknown serves two primary functions: it permits arbitrary string keys on an object, and it declares that the values of those keys could be of any type, but their exact types are not yet verified.

The unknown type acts as a type-safe counterpart to any. While both allow any value to be assigned, unknown prevents developers from performing operations on that value—such as calling methods, accessing nested properties, or passing it into typed functions—without first verifying its type via runtime type checks or type narrowing.

type DynamicData = {
  [key: string]: unknown;
};

const payload: DynamicData = {
  id: 101,
  status: "active",
  tags: ["typescript", "javascript"]
};

Why Use unknown Instead of any

When using [key: string]: any, TypeScript disables type checking on any property accessed from the object. This can lead to runtime exceptions if code assumes a property is a string or function when it is not.

With [key: string]: unknown, TypeScript forces you to narrow the type before executing operations:

const value = payload["status"];

// Error: Object is of type 'unknown'.
// console.log(value.toUpperCase());

// Correct: Narrow the type first
if (typeof value === "string") {
  console.log(value.toUpperCase()); // Safe
}

Compatibility with Explicit Properties

In TypeScript, all explicitly declared properties in an object type must match the return type of the index signature. Because unknown is a top type—meaning every type is assignable to unknown—you can safely combine explicit properties of any type with [key: string]: unknown:

interface UserProfile {
  id: number;
  name: string;
  [key: string]: unknown;
}

In this structure, id must be a number and name must be a string, but any additional properties can hold values of any type while remaining subject to type-narrowing rules upon access.

Common Use Cases

  • Handling External Data: Parsing unstructured JSON payloads, webhooks, or API responses where fields may vary or expand over time.
  • Dictionary Structures: Building lookup maps or cache layers where keys are dynamically generated, but values must be validated before consumption.
  • Extensible Configurations: Defining configuration interfaces that require core options while permitting arbitrary plugin or middleware settings.
