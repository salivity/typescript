TypeScript JSX: Preserve vs React vs React-JSX

TypeScript provides the jsx compiler option in tsconfig.json to control how JSX syntax is processed and emitted into JavaScript files. Choosing between preserve, react, and react-jsx determines whether TypeScript transforms JSX directly, which runtime functions it generates, and whether an explicit React import is required in your source files. This guide breaks down how each setting works, what output it produces, and when to use it.

1. preserve

The preserve mode instructs TypeScript to leave all JSX syntax untouched in the emitted JavaScript. Instead of compiling JSX into function calls, it outputs code containing raw JSX with a .jsx file extension.

  • Emitted Output: Native JSX tags remain intact (e.g., <div className="box">Hello</div>).
  • Runtime Requirement: None at the TypeScript compilation level.
  • Imports Needed: Depends on your downstream build tool.

When to use it: Use preserve when TypeScript is not the final step in your build pipeline. This is common when using bundlers and transpilers like Babel, Vite, SWC, or esbuild, which handle the final JSX transformation and optimization themselves.

2. react

The react mode represents the classic React transform introduced in early versions of React. TypeScript compiles JSX tags directly into React.createElement calls and emits standard .js files.

  • Emitted Output: React.createElement("div", { className: "box" }, "Hello")
  • Runtime Requirement: React must be globally available or imported in the file.
  • Imports Needed: You must explicitly include import React from 'react' at the top of every file containing JSX, even if React is not directly referenced elsewhere.

When to use it: Use react if you are working on older React applications (React 16 or earlier) or targeting environments that specifically require the classic React.createElement API without an intermediate build tool.

3. react-jsx

Introduced in TypeScript 4.1 to support the modern JSX transform released in React 17, react-jsx compiles JSX into internal runtime function calls rather than React.createElement.

  • Emitted Output: Calls to _jsx or _jsxs functions imported automatically from react/jsx-runtime (e.g., import { jsx as _jsx } from "react/jsx-runtime"; _jsx("div", { className: "box", children: "Hello" })).
  • Runtime Requirement: React 17 or higher (or a compatible runtime).
  • Imports Needed: No manual import React from 'react' is required purely for JSX syntax.

(Note: A related option, react-jsxdev, behaves the same way but emits debug information like file names and line numbers via react/jsx-dev-runtime for development builds.)

When to use it: Use react-jsx for modern React projects (version 17 and above) when you want TypeScript itself to compile JSX directly to standard JavaScript without needing an external transpiler like Babel.

Summary of Differences

Option Output Syntax File Extension Requires import React? Typical Use Case
preserve Raw JSX (<div />) .jsx No Secondary build step handles JSX (Babel, Vite, esbuild)
react React.createElement(...) .js Yes Legacy React (v16 and older)
react-jsx _jsx(...) via react/jsx-runtime .js No Modern React (v17+) using TS for direct emission
