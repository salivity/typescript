How to Type Object.entries in TypeScript

By default, TypeScript types Object.entries() as [string, any][] or [string, T[keyof T]][] to account for structural typing and excess properties at runtime. This article explains why this occurs and details how to construct a custom ObjectEntries<T> utility type that strictly preserves the exact key-value tuple pairs of an input object.

The Limitation of Native Object.entries

TypeScript’s standard library defines Object.entries as:

entries<T>(o: { [s: string]: T } | ArrayLike<T>): [string, T][];
entries(o: {}): [string, any][];

Because TypeScript uses a structural type system, objects may contain additional runtime properties not present in their compile-time types. To remain strictly sound, TypeScript refuses to assume that keyof T represents all keys that could ever exist on o at runtime, degrading the key type to string.

Building the ObjectEntries Utility Type

To represent key-value pairs accurately, a naive union like [keyof T, T[keyof T]][] fails because it pairs every key with a union of every possible value, breaking type correlations. Instead, you must use a distributive mapped type that creates individual tuples before indexing into them.

Step 1: Basic Mapped Tuple Lookup

type SimpleObjectEntries<T> = {
  [K in keyof T]: [K, T[K]];
}[keyof T][];

In this implementation:

  1. [K in keyof T]: [K, T[K]] maps over each key K in T, pairing it directly with its corresponding value type T[K].
  2. [keyof T] indexes into the resulting mapped type to extract a union of all individual tuples.
  3. [] creates an array of that union.

Step 2: Accounting for Runtime String Coercion and Symbols

Object.entries at runtime only returns an object's own enumerable string-keyed properties. Symbols are omitted, and numeric keys are coerced into strings. To mirror this behavior accurately:

type ObjectEntries<T> = {
  [K in Extract<keyof T, string | number>]: [
    `${K}`,
    T[K]
  ];
}[Extract<keyof T, string | number>][];
  • Extract<keyof T, string | number> removes any symbol keys, mirroring the runtime exclusion of symbols.
  • ${K} uses template literal types to serialize numeric keys to string literals (for example, 0 becomes "0").

Handling Optional Properties

If an object has optional properties, their values include undefined, but the key might still be undefined if indexed loosely. Using -? ensures that every possible key defined in the interface is accounted for in the tuple union:

type StrictObjectEntries<T> = {
  [K in keyof T]-?: [
    K extends string | number ? `${K}` : never,
    T[K]
  ];
}[keyof T][];

Creating a Strongly-Typed Function Wrapper

To use this type seamlessly in code without using type assertions (as) at every call site, wrap the native Object.entries method:

function getObjectEntries<T extends object>(obj: T): StrictObjectEntries<T> {
  return Object.entries(obj) as StrictObjectEntries<T>;
}

Usage Example

interface UserProfile {
  id: number;
  name: string;
  role?: "admin" | "user";
}

const user: UserProfile = {
  id: 1,
  name: "Alice"
};

// Type: (["id", number] | ["name", string] | ["role", "admin" | "user" | undefined])[]
const entries = getObjectEntries(user);

for (const [key, value] of entries) {
  if (key === "id") {
    // TypeScript knows `value` is `number`
    console.log(value.toFixed(0));
  } else if (key === "role") {
    // TypeScript knows `value` is `"admin" | "user" | undefined`
    console.log(value?.toUpperCase());
  }
}
