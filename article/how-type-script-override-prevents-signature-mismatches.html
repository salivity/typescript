How TypeScript Override Prevents Signature Mismatches

The override keyword in TypeScript ensures that a subclass method or property explicitly corresponds to an existing member in its parent class. By requiring intentionality when overriding inherited members, TypeScript produces a compile-time error if the parent class method is renamed, removed, or if the subclass introduces a typo. This mechanism prevents silent runtime bugs caused by accidental method shadowing or orphaned methods resulting from upstream refactoring.

The Problem with Implicit Overrides

Before the introduction of the override keyword in TypeScript 4.3, overriding methods was implicit. When you defined a method in a subclass with the same name as a method in the superclass, TypeScript assumed you intended to override it.

This implicit behavior creates two major points of failure:

  1. Typos in the Subclass: If a developer attempts to override calculateTotal() but accidentally types calculateTotals(), the subclass simply creates a new, separate method. The parent class's calculateTotal() remains active, and the subclass version never gets called by inherited code.
  2. Fragile Base Class Refactoring: If the base class changes calculateTotal() to computeTotal(), the subclass method silently becomes an unused, standalone method. The code still compiles, but the intended runtime polymorphism is broken.

How the override Keyword Fixes This

Marking a member with the override keyword instructs the TypeScript compiler to verify that the parent class contains a member with the exact same name and a compatible signature.

class BaseService {
  saveData(data: string): void {
    console.log("Saving base data:", data);
  }
}

class ExtendedService extends BaseService {
  override saveData(data: string): void {
    console.log("Saving extended data:", data);
  }
}

If the BaseService is refactored and saveData is renamed to persistData, the compiler immediately flags an error on ExtendedService:

This member cannot have an 'override' modifier because it is not declared in the base class 'BaseService'.

This alert guarantees that developers catch stale or mismatched signatures during compilation rather than diagnosing silent logic failures in production.

Enforcing Strict Safety with noImplicitOverride

While using the override keyword is optional by default, TypeScript provides the noImplicitOverride compiler flag in tsconfig.json. When this setting is set to true, TypeScript strictly prohibits any subclass from overriding an inherited member unless the override keyword is explicitly present.

{
  "compilerOptions": {
    "noImplicitOverride": true
  }
}

Enabling this setting ensures that:

  • Any intentional override must use the override keyword.
  • Any unintentional name collision between a subclass and a superclass generates an error, preventing developers from accidentally overriding parent methods without realizing it.

Signature Compatibility Verification

Beyond verifying name existence, the override keyword works in tandem with TypeScript’s structural type system to enforce strict signature compatibility:

  • Parameter Count and Types: The overriding method must accept parameter types that are compatible with the base class implementation (bivariant or contravariant, depending on compiler flags).
  • Return Types: The return type of the overriding method must be a subtype of the return type declared in the parent method (covariant).

If the base class expects saveData(data: string): void and the subclass attempts override saveData(data: number): void, TypeScript triggers a type mismatch error because the method signature violates inheritance contracts.
