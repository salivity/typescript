TypeScript typeRoots: How to Specify Type Paths

The typeRoots compiler option in TypeScript specifies the directories that the compiler checks when resolving global or ambient type declarations. By default, TypeScript looks for declaration files inside node_modules/@types of the current directory and its parent directories. By configuring typeRoots in your tsconfig.json, you gain precise control over where the compiler searches for type definitions, allowing you to include custom local declarations or restrict automatic type inclusion.

Default Behavior Without typeRoots

When typeRoots is not defined in tsconfig.json, TypeScript automatically scans for all packages located in:

  • ./node_modules/@types
  • ../node_modules/@types
  • ../../node_modules/@types
  • And so forth up the directory tree to the root of the file system.

Any package found within these directories is considered visible and its declarations are automatically included in the compilation scope.

How typeRoots Works

The typeRoots option accepts an array of directory paths. When specified, TypeScript completely disables the default traversal behavior and only scans the directories listed in the array for type packages.

A typical configuration looks like this:

{
  "compilerOptions": {
    "typeRoots": [
      "./node_modules/@types",
      "./custom-typings"
    ]
  }
}

In this setup, TypeScript searches for declaration packages in both the standard node_modules/@types directory and a local ./custom-typings folder.

Expected Directory Structure

Each directory specified in typeRoots is expected to contain subfolders for individual packages or modules. TypeScript does not look for single .d.ts files directly in the root of the specified path. Instead, each folder under a typeRoots directory must contain:

  1. An index.d.ts file, or
  2. A package.json file specifying a "types" or "typings" field.

For example, to provide types for an untyped library named legacy-library, structure your project as follows:

project-root/
├── custom-typings/
│   └── legacy-library/
│       └── index.d.ts
├── node_modules/
│   └── @types/
├── tsconfig.json
└── src/
    └── index.ts

Inside ./custom-typings/legacy-library/index.d.ts, you declare the module:

declare module "legacy-library" {
  export function doSomething(): void;
}

Important Considerations

  • Overriding Defaults: Specifying typeRoots overrides the default node_modules/@types behavior entirely. If you omit "./node_modules/@types" from the typeRoots array, none of your npm-installed @types packages will be automatically resolved.
  • typeRoots vs. types: While typeRoots specifies the folders to search within, the types option specifies the specific packages to include. If types is specified, only the named packages within the resolved typeRoots are included in global scope.
  • Direct File Inclusion: If you simply want to include a standalone declaration file (like globals.d.ts) without folder nesting, use the include array in tsconfig.json instead of typeRoots.
