as const vs Object.freeze() in TypeScript

While both as const and Object.freeze() are used to achieve immutability in TypeScript, they operate at completely different phases of the software lifecycle. as const is a compile-time assertion that instructs the TypeScript compiler to infer the narrowest literal types and mark all nested properties as readonly, disappearing entirely once transpiled to JavaScript. In contrast, Object.freeze() is a native JavaScript runtime method that physically locks an object to prevent runtime mutations, shallowly freezing its top-level properties.

Compile-Time vs. Runtime Execution

The primary distinction lies in when and where the immutability is enforced:

  • as const (Compile-time only): This is purely a TypeScript construct. The TypeScript compiler enforces immutability by producing compile-time type errors if you attempt to reassign a property. Once compiled into JavaScript, the as const assertion is stripped away completely, meaning there is zero runtime overhead and zero runtime protection against mutation.
  • Object.freeze() (Runtime and Compile-time): This is an ECMAScript standard method executed by the JavaScript engine. At runtime, attempting to modify a frozen object fails silently in non-strict mode or throws a TypeError in strict mode. TypeScript also automatically types the return value of Object.freeze() as Readonly<T>, providing compile-time feedback alongside runtime enforcement.

Type Narrowing and Literal Types

as const enables literal type inference, whereas Object.freeze() does not narrow types by default:

  • Using as const converts general types into strict literal values. For example, { role: "admin" } as const produces the type { readonly role: "admin" }. Arrays defined with as const become fixed-length readonly tuples.
  • Object.freeze({ role: "admin" }) yields the type Readonly<{ role: string }>. The property becomes readonly, but the string is not narrowed to the literal "admin".

Deep vs. Shallow Immutability

Another critical difference is the depth of the immutability applied:

  • as const is deep: It recursively applies readonly modifiers to nested objects, arrays, and primitive fields down the entire object tree.
  • Object.freeze() is shallow: It only locks the immediate, top-level properties of the target object. Any nested objects or arrays remain fully mutable at runtime unless manually frozen using a custom deep-freeze implementation.

Comparison Summary

Feature as const Object.freeze()
Enforcement Layer TypeScript compiler JavaScript runtime (and TypeScript)
Runtime Output None (erased) Standard JavaScript function call
Type Narrowing Narrows to literals & tuples Retains widened types (e.g., string)
Depth Deep (recursive) Shallow
Performance Impact Zero runtime cost Minor runtime cost for function execution

When to Use Which

Use as const when your primary goal is strong TypeScript typing, such as creating literal union types, configuring action constants, or defining read-only configuration tables where runtime overhead is undesirable.

Use Object.freeze() when you need guaranteed runtime safety, such as protecting shared state, preventing external consumer mutation in a public API, or safeguarding sensitive application settings.

For maximum safety, both can be combined: Object.freeze({ ... } as const) provides deep literal type inference during development along with top-level runtime immutability in production.
