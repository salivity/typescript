Default Generic Type Arguments in TypeScript

TypeScript allows generic parameters to have default type arguments. This feature enables developers to define fallback types for generics, making type parameters optional when invoking functions, interfaces, or classes. This guide explains how generic defaults work, the syntax required, how to combine them with constraints, and the rules governing their order.

Basic Syntax and Usage

Generic parameter defaults follow an assignment-like syntax using the equals sign (=). If a consumer does not provide an explicit type argument, TypeScript automatically falls back to the specified default.

type ApiResponse<T = Record<string, unknown>> = {
  status: number;
  data: T;
};

// Uses the default type: Record<string, unknown>
const genericResponse: ApiResponse = {
  status: 200,
  data: { key: "value" },
};

// Overrides the default type with string
const stringResponse: ApiResponse<string> = {
  status: 200,
  data: "Operation successful",
};

Combining Defaults with Constraints

Default types can be combined with type constraints using the extends keyword. When used together, the constraint is declared first, followed by the default type. The default type must satisfy the specified constraint.

interface Container<T extends HTMLElement = HTMLDivElement> {
  element: T;
}

// Valid: HTMLDivElement satisfies the HTMLElement constraint
const defaultContainer: Container = {
  element: document.createElement("div"),
};

// Valid: HTMLSpanElement satisfies HTMLElement
const spanContainer: Container<HTMLSpanElement> = {
  element: document.createElement("span"),
};

If the default type does not assign cleanly to the constraint, the TypeScript compiler will raise a type error.

Ordering Rules for Generic Defaults

TypeScript enforces ordering rules for generic parameters similar to default function parameters:

  1. A required generic parameter cannot follow an optional generic parameter.
  2. All generic parameters with defaults must be placed after any generic parameters without defaults.
// Valid: required parameter precedes optional parameter
type Result<T, E = Error> = {
  value: T;
  error?: E;
};

// Invalid: causes a compilation error
type Invalid<T = string, U> = {
  first: T;
  second: U;
};

Defaults in Generic Functions

Default generic parameters are especially useful in utility functions, providing fallback behavior when inference cannot determine the type:

function createList<T = string>(): T[] {
  return [];
}

const defaultList = createList(); // Type is string[]
const numberList = createList<number>(); // Type is number[]

By using generic parameter defaults, you make your TypeScript types and APIs more flexible without requiring consumers to provide repetitive boilerplate type arguments.
