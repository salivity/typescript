TypeScript Optional vs Default Parameters

In TypeScript, both optional parameters and default parameters allow functions to be called without providing every argument, but they handle missing values and types differently. An optional parameter explicitly allows a value to be omitted, resulting in a value of undefined within the function body. In contrast, a parameter with a default value automatically assigns a predefined fallback if no argument (or undefined) is supplied. Understanding these differences is essential for writing accurate function signatures, managing strict null checks, and controlling runtime behavior.

Syntax and Type Inferences

An optional parameter is declared using a question mark (?) after the parameter name. TypeScript automatically expands its type to include undefined.

function greetOptional(name?: string): void {
  // typeof name is string | undefined
  console.log(`Hello, ${name ? name.toUpperCase() : "stranger"}`);
}

A parameter with a default value is defined using the assignment operator (=). TypeScript infers the parameter's type from the default value if an explicit type annotation is omitted, and the parameter's type inside the function remains the concrete type rather than a union with undefined.

function greetDefault(name: string = "stranger"): void {
  // typeof name is string
  console.log(`Hello, ${name.toUpperCase()}`);
}

Runtime Evaluation

When an optional parameter is omitted during a function call, its value resolves directly to undefined at runtime. The developer must manually check for undefined before performing operations on that variable.

When a parameter with a default value is omitted, or when undefined is explicitly passed, the default expression is evaluated and assigned at runtime. Passing null, however, does not trigger the default value; null is treated as an intentional, provided argument.

greetDefault();          // Output: "Hello, STRANGER"
greetDefault(undefined); // Output: "Hello, STRANGER"
greetDefault("Alice");   // Output: "Hello, ALICE"

Parameter Positioning Rules

Optional parameters must be placed after all required parameters in the function signature. Placing an optional parameter before a required parameter causes a compiler error.

// Compiler Error: A required parameter cannot follow an optional parameter.
function invalid(a?: string, b: number) {}

Parameters with default values can be placed anywhere in the parameter list. However, if a defaulted parameter appears before a required parameter, callers must explicitly pass undefined to utilize the default value.

function calculate(rate: number = 0.05, amount: number): number {
  return amount * (1 + rate);
}

// Callers must provide undefined to use the default rate
calculate(undefined, 100); // rate defaults to 0.05

Usage in Function Types and Interfaces

Default parameter values are implementation details and cannot be defined in type signatures, interfaces, or abstract method declarations. Only optional modifiers (?) are permitted in these contexts.

// Valid: Interface with optional parameter
interface Formatter {
  format(input: string, uppercase?: boolean): string;
}

// Invalid: Default values are not permitted in function types
type FormatterType = (input: string, uppercase: boolean = false) => string;

Key Differences Summary

  • Fallback Value: Optional parameters evaluate to undefined; default parameters evaluate to the specified fallback.
  • Internal Type: Optional parameters have the type T | undefined; default parameters retain type T within the function scope.
  • Positioning: Optional parameters must follow required parameters; default parameters can appear in any position.
  • Type Signatures: Optional flags can appear in abstract types and interfaces; default values can only be declared inside concrete function implementations.
