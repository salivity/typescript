TypeScript Mapping Modifiers: -? and -readonly

In TypeScript, mapped types allow you to create new types by transforming existing ones. By prefixing the mapping modifiers with a minus sign (-? and -readonly), you explicitly remove optionality and immutability from properties. While TypeScript defaults to adding or preserving modifiers, the - prefix acts as a removal operator, turning optional properties into required ones and immutable readonly properties into mutable ones.

Understanding Mapping Modifiers

When constructing mapped types, you can apply property modifiers to adjust how properties behave:

  • readonly: Controls whether a property can be reassigned after initialization.
  • ?: Controls whether a property is optional.

By default, omitting a prefix or using a + prefix adds the modifier (e.g., +? or +readonly). Prefixing a modifier with - removes it from the resulting type definition.

The Effect of -?

The -? modifier removes the optional flag from all properties being mapped, making them strictly required.

If an interface contains properties marked with ?, mapping over it normally preserves that optionality. Using -? forces the resulting type to require every key, effectively stripping undefined from the property's potential values.

interface UserProfile {
  id: string;
  name?: string;
  email?: string;
}

// Without -?, optionality is preserved
type PartialCopy<T> = {
  [K in keyof T]: T[K];
};

// With -?, properties become required
type Concrete<T> = {
  [K in keyof T]-?: T[K];
};

type Result = Concrete<UserProfile>;
// Result is:
// {
//   id: string;
//   name: string;
//   email: string;
// }

This is the exact mechanism TypeScript uses internally to implement the built-in utility type Required<T>.

The Effect of -readonly

The -readonly modifier removes the readonly attribute from properties, making previously immutable fields writable.

When working with frozen objects, configuration types, or types wrapped in TypeScript's Readonly<T>, properties cannot be modified. Applying -readonly in a mapped type strips this constraint, producing a mutable version of the type.

interface ImmutableConfig {
  readonly endpoint: string;
  readonly port: number;
}

type Mutable<T> = {
  -readonly [K in keyof T]: T[K];
};

type EditableConfig = Mutable<ImmutableConfig>;
// EditableConfig is:
// {
//   endpoint: string;
//   port: number;
// }

In the resulting EditableConfig type, properties can now be reassigned without triggering compiler errors.

Combining Modifiers

Both removal modifiers can be used simultaneously within the same mapped type declaration. This allows you to construct a type that is both completely mutable and fully required in a single step.

interface StrictSettings {
  readonly theme?: string;
  readonly autoSave?: boolean;
}

type FullyUnlocked<T> = {
  -readonly [K in keyof T]-?: T[K];
};

type ActiveSettings = FullyUnlocked<StrictSettings>;
// ActiveSettings is:
// {
//   theme: string;
//   autoSave: boolean;
// }

Using -? and -readonly gives you precise, granular control over property contracts in TypeScript, allowing you to invert constraints imposed by third-party definitions or upstream types.
