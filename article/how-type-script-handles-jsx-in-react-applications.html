How TypeScript Handles JSX in React Applications

TypeScript natively integrates JSX parsing, type-checking, and code transformation into its compiler to support React applications. By pairing .tsx file extensions with custom compiler flags and React-specific type definitions, TypeScript validates component props, children, and HTML elements at compile time before emitting clean, standardized JavaScript.

The .tsx File Extension

To handle JSX syntax, TypeScript requires files to use the .tsx file extension rather than standard .ts. This distinguishes JSX tags from standard TypeScript type assertions that use angle brackets (e.g., <Type>value), avoiding ambiguity during syntax parsing.

The jsx Compiler Option

TypeScript’s behavior toward JSX is controlled via the "jsx" property in tsconfig.json. The primary options include:

  • react-jsx: Designed for React 17 and newer. It transforms JSX into calls to _jsx imported from react/jsx-runtime, omitting the need to explicitly import React into scope.
  • react-jsxdev: Similar to react-jsx, but emits code suited for development, providing extra debugging information.
  • react: The legacy approach for React 16 and older. It converts JSX tags into React.createElement calls, requiring React to be imported in the file.
  • preserve: Leaves the JSX intact in the output .jsx file, allowing an external bundler or compiler like Babel or SWC to handle the final transformation.

How TypeScript Type-Checks JSX

TypeScript divides JSX elements into two categories to perform type verification: intrinsic elements and value-based elements.

1. Intrinsic Elements

Intrinsic elements are built-in HTML or SVG tags, such as <div>, <span>, or <button>. TypeScript detects them because they begin with a lowercase letter.

To validate them, TypeScript looks for an interface named IntrinsicElements inside the global JSX namespace, provided by @types/react. If an attribute passed to a <div> does not exist on JSX.IntrinsicElements['div'], the compiler raises a type error.

2. Value-Based Elements

Value-based elements correspond to React custom components and begin with an uppercase letter. TypeScript evaluates these components as functions or classes:

  • Function Components: TypeScript validates the arguments passed to the function against the component's defined props interface.
  • Class Components: TypeScript checks the element against the component instance's props type.
interface ButtonProps {
  label: string;
  onClick: () => void;
  disabled?: boolean;
}

export const Button = ({ label, onClick, disabled = false }: ButtonProps) => {
  return (
    <button onClick={onClick} disabled={disabled}>
      {label}
    </button>
  );
};

When rendering <Button label="Submit" onClick={handleClick} />, TypeScript verifies that all required properties are present and that their types match ButtonProps.

Children and Return Type Verification

TypeScript checks JSX children by treating them as a special prop named children. In modern React types, components explicitly specify whether they accept children using types such as React.ReactNode.

TypeScript also verifies that the component returns a valid JSX expression, typically resolving to JSX.Element, React.ReactNode, or null. If a component returns an unsupported type (such as an unhandled object), the compiler flags the error immediately during development.
