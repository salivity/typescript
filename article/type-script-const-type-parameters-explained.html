TypeScript Const Type Parameters Explained

TypeScript 5.0 introduced const type parameters, a feature that enables functions to infer the most specific, literal types for generic arguments without requiring callers to write as const assertions manually. This article explains how generic inference traditionally widens types, how prefixing a type parameter with const alters this behavior, and the practical scenarios where this pattern simplifies code and prevents type-widening bugs.

The Limitation of Standard Generic Inference

By default, TypeScript prioritizes mutability when inferring types for generic arguments. When an object or array literal is passed to a generic function, the compiler widens primitive values to their general types (such as "hello" to string) and infers arrays as mutable arrays rather than fixed-length tuples.

function setConfig<T>(config: T): T {
  return config;
}

// Inferred type of config: { routes: string[]; timeout: number }
const standardConfig = setConfig({
  routes: ["/home", "/dashboard"],
  timeout: 5000,
});

Prior to TypeScript 5.0, the only way to preserve exact string literals and fixed-length tuples was to require the caller to append as const at the call site:

// Inferred type: { readonly routes: readonly ["/home", "/dashboard"]; readonly timeout: 5000 }
const strictConfig = setConfig({
  routes: ["/home", "/dashboard"],
  timeout: 5000,
} as const);

This approach shifts the burden of type safety to the caller. If the caller forgets as const, the strict literal inference is lost.

Enhancing Inference with const Modifiers

Placing the const modifier directly on a type parameter shifts the responsibility from the caller to the function definition. It instructs the compiler to automatically treat the passed argument as an as const expression.

function setConfig<const T>(config: T): T {
  return config;
}

// Inferred type: { readonly routes: readonly ["/home", "/dashboard"]; readonly timeout: 5000 }
const autoConfig = setConfig({
  routes: ["/home", "/dashboard"],
  timeout: 5000,
});

With const T, TypeScript performs the following adjustments during type argument inference:

  1. Primitive Literal Retention: String, numeric, and boolean literals are retained as their exact types rather than widened to string, number, or boolean.
  2. Tuple Conversion: Array literals are inferred as readonly tuples with exact indices rather than mutable, variable-length arrays.
  3. Readonly Modifiers: Object properties and array elements are marked readonly to reflect their immutable status.

Practical Example: Route and Key Matching

A common use case involves validating that a string is a member of an array defined in the same function call. Without const type parameters, arrays widen to string[], preventing compile-time checks.

type RouteConfig<T extends readonly string[]> = {
  routes: T;
  defaultRoute: T[number];
};

function createRouter<const T extends readonly string[]>(config: RouteConfig<T>) {
  return config;
}

// Valid: "home" is part of the routes tuple
const router = createRouter({
  routes: ["home", "about", "contact"],
  defaultRoute: "home",
});

// Compilation Error: Type '"login"' is not assignable to type '"home" | "about" | "contact"'
const invalidRouter = createRouter({
  routes: ["home", "about", "contact"],
  defaultRoute: "login",
});

Without the const parameter on createRouter, routes would widen to string[], making T[number] evaluate to string. This would cause the invalid route "login" to pass type checking silently.

Important Constraints to Consider

While const type parameters provide automatic literal inference, their behavior depends on how data is passed:

  • Inline Literals Only: The const modifier only applies to values written inline at the call site. If a pre-existing mutable variable is passed, its already-widened type is preserved.
  • Readonly Outputs: Inferred structures become deeply readonly. Functions that intend to mutate their inputs or return mutable structures should not use const type parameters, as doing so leads to type mismatches with standard mutable types.
