How to Create a DeepWritable Type in TypeScript

This article provides a complete guide to constructing a recursive DeepWritable (or DeepWriteable) utility type in TypeScript to remove readonly modifiers from deeply nested data structures. While TypeScript provides the -readonly mapping modifier to make properties mutable at the top level, it does not provide a native solution for nested objects, arrays, and tuples. Below, you will learn the limitations of shallow mutability, how to implement a recursive type definition, and how to handle edge cases like functions, arrays, and primitives.

The Problem with Shallow Mutability

TypeScript provides a way to remove the readonly modifier from an object's immediate properties using mapped types and the -readonly token:

type Writable<T> = {
  -readonly [K in keyof T]: T[K];
};

This works for top-level keys, but nested structures remain immutable:

type Config = {
  readonly endpoint: string;
  readonly preferences: {
    readonly timeout: number;
  };
};

type MutableConfig = Writable<Config>;
// MutableConfig.preferences is still { readonly timeout: number }

Building the DeepWritable Utility Type

To strip readonly modifiers at all levels, you must create a recursive type that checks the type of each property. If the property is an object or an array, the type recurses; if it is a primitive or a function, it leaves the value untouched.

Here is the complete implementation:

export type DeepWritable<T> = T extends (...args: any[]) => any
  ? T
  : T extends readonly (infer U)[]
  ? DeepWritable<U>[]
  : T extends object
  ? { -readonly [K in keyof T]: DeepWritable<T[K]> }
  : T;

How the Implementation Works

  1. Function Handling (T extends (...args: any[]) => any): Functions in JavaScript are objects, meaning mapped types can inadvertently iterate over their prototype properties and break function signatures. This check ensures functions are preserved without modification.
  2. Arrays and Tuples (T extends readonly (infer U)[]): This branch captures both standard readonly T[] arrays and tuple types defined with as const. Using infer U extracts the element type and wraps it in a standard, mutable array type recursively.
  3. Objects (T extends object): For standard objects, a mapped type applies the -readonly modifier to strip immutability from keys at the current level, while recursively applying DeepWritable<T[K]> to all values.
  4. Primitives (: T): Primitives such as string, number, boolean, null, and undefined are immutable by definition and are returned as-is.

Supporting Tuples Preserving Exact Lengths

If your application strictly relies on fixed-length tuples created with as const, mapping directly across the indices preserves tuple lengths better than generic array inference:

export type DeepWritable<T> = T extends (...args: any[]) => any
  ? T
  : T extends object
  ? { -readonly [K in keyof T]: DeepWritable<T[K]> }
  : T;

Because TypeScript's mapped types automatically map over arrays and tuples while preserving their structural constraints (like array methods and tuple lengths), iterating directly over T extends object handles both plain objects and tuples cleanly in modern TypeScript versions (3.1+).

Verification Example

You can test the implementation with a deeply nested, immutable structure:

const appConfig = {
  env: "production",
  ports: [8080, 8081],
  database: {
    host: "localhost",
    credentials: {
      user: "admin",
      roles: ["read", "write"] as const,
    },
  },
} as const;

type ImmutableConfig = typeof appConfig;
type MutableAppConfig = DeepWritable<ImmutableConfig>;

// Verification:
const writableConfig: MutableAppConfig = {
  env: "production",
  ports: [8080, 8081],
  database: {
    host: "localhost",
    credentials: {
      user: "admin",
      roles: ["read", "write"],
    },
  },
};

// All properties are now mutable:
writableConfig.env = "staging";
writableConfig.database.credentials.user = "root";
writableConfig.database.credentials.roles[0] = "admin";
writableConfig.ports.push(9000);

Applying DeepWritable eliminates compiler errors when mutating properties across any depth of your data structures.
