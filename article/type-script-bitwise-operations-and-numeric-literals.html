TypeScript Bitwise Operations and Numeric Literals

TypeScript provides robust static typing for JavaScript, yet its handling of numerical literals and bitwise operations comes with specific behaviors and limitations. This article explains how TypeScript defines numerical literal types, why it broadens those literals to primitive types during bitwise operations, and how it enforces type safety across 32-bit integers and bigint values.

Numerical Literal Types in TypeScript

TypeScript allows specific numbers to act as distinct types known as numeric literal types. When you declare a constant with a numeric value using const, TypeScript infers the exact literal value rather than the broad number primitive:

const exactFive = 5; // Type: 5
let genericNumber = 5; // Type: number

You can also use numeric literals in union types to enforce restricted sets of numbers, such as HTTP status codes or custom identifiers:

type Port = 80 | 443 | 8080;

Despite supporting literal types, the TypeScript type system does not include a built-in compile-time arithmetic engine. TypeScript does not calculate numeric values at the type level during operations.

How TypeScript Handles Bitwise Operations

JavaScript supports several bitwise operators: & (AND), | (OR), ^ (XOR), ~ (NOT), << (left shift), >> (sign-propagating right shift), and >>> (zero-fill right shift).

In runtime JavaScript, bitwise operators convert their operands into 32-bit integers (signed for most operators, unsigned for >>>), perform the operation, and return a standard number.

1. Type Widening to number

Because TypeScript does not compute mathematical expressions at compile time, applying a bitwise operator to numeric literals results in type widening. The resulting value is typed as the broad primitive number, not a narrowed literal type:

const a = 1; // Type: 1
const b = 2; // Type: 2

const result = a | b; // Type: number (runtime value is 3)

Even if the operands are strictly typed as literals, TypeScript cannot determine the literal output type of a | b without explicit type casting.

2. Operand Compatibility and Safety

TypeScript enforces that operands of bitwise operators belong to valid numeric categories: number, bigint, or any.

TypeScript strictly forbids mixing number and bigint in bitwise operations, mirroring runtime JavaScript restrictions:

const num = 1;
const big = 2n;

// Error: Cannot mix BigInt and other types, use explicit conversions.
const invalid = num & big;

When both operands are bigint, the resulting type is bigint:

const bigA = 1n;
const bigB = 2n;

const bigResult = bigA & bigB; // Type: bigint

Additionally, TypeScript disallows the zero-fill right shift operator (>>>) on bigint types, as JavaScript does not support unsigned 64-bit representations via this operator:

const big = 10n;
// Error: Operator '>>>' cannot be applied to type 'bigint'.
const shifted = big >>> 1n;

Bitwise Flags and Numeric Enums

A common use case for bitwise operations is managing bitmasks and flags using numeric enums:

enum FileAccess {
  None = 0,
  Read = 1 << 0,    // 1
  Write = 1 << 1,   // 2
  Execute = 1 << 2, // 4
}

While TypeScript computes constant enum member values at compile time during emit, expressions that combine enum members with bitwise operators at runtime lose their specific enum typing:

const permissions = FileAccess.Read | FileAccess.Write; // Type: number

Because permissions widens to number, it cannot be passed directly into functions expecting the specific FileAccess enum without a type assertion:

function checkAccess(access: FileAccess) {
  // ...
}

// Fails if strict type checks are required without casting
checkAccess(permissions as FileAccess);

Summary

  • Numeric Literals: TypeScript can represent exact numbers as types, but operations strip this specificity.
  • Type Widening: Bitwise operations performed on numeric literals always evaluate to the generic number or bigint type.
  • Strict Separation: TypeScript disallows mixing number and bigint in bitwise expressions and prevents >>> on bigint.
  • Bitmasks: Enums used in bitwise expressions widen to number, requiring explicit assertions if you need to retain the original enum type.
