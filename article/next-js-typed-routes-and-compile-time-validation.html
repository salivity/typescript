Next.js Typed Routes and Compile-Time Validation

Next.js leverages TypeScript to provide compile-time route validation through its experimental typed routes feature, transforming internal navigation from error-prone string literals into strictly typed paths. By automatically scanning your application's file structure and generating corresponding TypeScript definitions, Next.js catches broken links and typos during development and build time rather than at runtime. This guide explains how this mechanism functions, how to enable it, and how it enforces route safety across Next.js navigation primitives.

How Next.js Generates Route Types

Next.js relies on its file-system-based routing model to determine available endpoints. When route typing is active, the Next.js compiler parses the directory structure inside the app or pages folder and automatically generates a hidden declaration file located at .next/types/link.d.ts.

This file exports an internal type representing all valid static and dynamic paths in the project as a union of string literals:

type StaticRoutes = "/" | "/about" | "/dashboard" | "/settings";
type DynamicRoutes = `/posts/${string}` | `/products/${string}`;
type Route = StaticRoutes | DynamicRoutes;

This generated union updates automatically as you add, rename, or delete page files during local development.

Enabling Typed Routes

Compile-time route validation is an experimental feature that can be enabled within next.config.js:

/** @type {import('next').NextConfig} */
const nextConfig = {
  experimental: {
    typedRoutes: true,
  },
};

module.exports = nextConfig;

Once enabled, running next dev or next build generates the required types and configures TypeScript to reference them automatically via tsconfig.json.

Type Validation with Next.js Link

The primary touchpoint for typed routing is the next/link component. When typed routes are active, the href prop of Link transitions from accepting generic string values to accepting only valid Route types.

Valid Static Links

A correct link matches the generated route union and compiles without issue:

import Link from 'next/link';

export default function Navigation() {
  return (
    <nav>
      <Link href="/about">About Us</Link>
    </nav>
  );
}

Invalid Links and Typos

If a route contains a typo or points to a non-existent page, TypeScript intercepts the error immediately within the editor and halts the build process:

import Link from 'next/link';

export default function Navigation() {
  // TypeScript Error: Type '"/abot"' is not assignable to type 'RouteImpl<...>'
  return <Link href="/abot">About Us</Link>;
}

Handling Dynamic Routes

Dynamic routes, such as /blog/[slug], are typed using TypeScript template literal types. Next.js creates pattern templates where parameters are represented as wildcards or generic strings:

import Link from 'next/link';

export default function BlogPost({ slug }: { slug: string }) {
  // Valid dynamic route pattern
  return <Link href={`/blog/${slug}`}>Read More</Link>;
}

If the base structure of the dynamic route does not match the actual folder hierarchy, TypeScript flags it as an invalid path pattern.

Imperative Routing with useRouter

Compile-time validation also extends to programmatic navigation. When using the useRouter hook from next/navigation, methods such as router.push() and router.replace() enforce the same strict typing:

'use client';

import { useRouter } from 'next/navigation';

export default function RedirectButton() {
  const router = useRouter();

  function handleClick() {
    // Validated at compile time
    router.push('/dashboard');
  }

  return <button onClick={handleClick}>Go to Dashboard</button>;
}

Passing an unregistered route to router.push() triggers a TypeScript diagnostic error, preventing runtime 404 responses caused by invalid navigation calls.

Core Advantages

  • Early Error Detection: Broken links are caught during CI/CD checks and local development instead of being discovered by users.
  • IDE Autocomplete: Developers receive intelligent code completion for available paths as soon as they open the quotes in an href attribute.
  • Refactoring Safety: Renaming or removing a route directory automatically highlights every location in the codebase where that path is referenced.
