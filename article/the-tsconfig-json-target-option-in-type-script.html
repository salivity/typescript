The tsconfig.json Target Option in TypeScript

The target option in a tsconfig.json file dictates the ECMAScript version to which TypeScript compiles your source code. This article explains the primary role of the target setting, how it influences JavaScript output and polyfills, its relationship with the lib option, and how to select the optimal version for your runtime environment.

Primary Purpose: Code Downleveling

TypeScript allows developers to write modern JavaScript features—such as arrow functions, classes, optional chaining, and async/await—even if the target execution environment does not support them natively.

The target setting instructs the TypeScript compiler (tsc) on how to "downlevel" these modern syntax features:

  • Older Targets (e.g., ES5): Modern syntax is transpiled into equivalent older syntax. For example, arrow functions are rewritten as standard function declarations, and classes are converted into constructor functions and prototype assignments.
  • Modern Targets (e.g., ES2020, ESNext): The compiler retains the modern syntax as-is, resulting in cleaner, smaller, and often faster code because modern runtimes execute native features more efficiently.

Syntax vs. APIs

The target option only transforms JavaScript syntax; it does not inject runtime polyfills for missing built-in APIs.

For instance, if your target is set to ES5, using an async/await structure will be converted into helper functions (like __awaiter and __generator). However, using modern APIs like Promise, Map, or Array.prototype.includes still requires a polyfill (such as core-js) at runtime if running on an actual ES5 browser.

Automatic Configuration of lib

When you set the target option, TypeScript automatically adjusts the default value of the lib compiler option to match.

For example:

  • Setting "target": "ES5" automatically includes type definitions for standard ES5 APIs and DOM objects.
  • Setting "target": "ES2020" automatically includes type definitions for newer APIs introduced up to ES2020 (such as BigInt and Promise.allSettled).

If you manually define the lib array in your tsconfig.json, it overrides this automatic mapping.

Supported Values

Commonly used values for target include:

  • ES5: Maximum compatibility with legacy environments and obsolete browsers (like Internet Explorer 11).
  • ES6 / ES2015: Introduces classes, modules, and arrow functions natively.
  • Specific years (ES2017, ES2020, ES2022, etc.): Aligns output with features introduced in that ECMAScript version.
  • ESNext: Targets the latest supported ECMAScript standard that TypeScript knows about.

Choosing the Right Target

To choose the appropriate target value, evaluate where your code will execute:

  1. Node.js Backends: Match your target to the Node.js version you are running. For instance, Node.js 18+ natively supports ES2022 features, meaning you can safely target ES2022 to avoid unnecessary transpilation overhead.
  2. Modern Web Applications: If you only support modern evergreen browsers (Chrome, Edge, Firefox, Safari), ES2020 or ES2022 produces smaller bundle sizes and leverages native browser performance.
  3. Bundled Environments: If you use tools like Babel, SWC, or esbuild after TypeScript compilation, you can set target to ESNext and let the downstream bundler handle browser-specific transpilation.
