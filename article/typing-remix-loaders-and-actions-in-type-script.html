Typing Remix Loaders and Actions in TypeScript

Typing server-side loaders and actions in Remix is essential for building robust, end-to-end type-safe web applications without unnecessary boilerplate. This guide covers the best practices for typing your server functions using built-in Remix utilities, inferring data directly into client hooks, safely handling dynamic route parameters, and validating form payloads to ensure complete type consistency from database to UI.

1. Use Function Arguments Types Instead of Function Types

Avoid typing the entire function with LoaderFunction or ActionFunction. When you annotate the function itself, TypeScript cannot infer its specific return type, which breaks type inference on the client.

Instead, annotate the function arguments using LoaderFunctionArgs and ActionFunctionArgs:

import type { LoaderFunctionArgs, ActionFunctionArgs } from "@remix-run/node";
import { json } from "@remix-run/node";

export async function loader({ request, params }: LoaderFunctionArgs) {
  const user = await getUserById(params.id);
  return json({ user });
}

export async function action({ request }: ActionFunctionArgs) {
  const formData = await request.formData();
  return json({ success: true });
}

This pattern allows TypeScript to infer the exact shape of the returned JSON response.

2. Infer Client Data via typeof loader and typeof action

Never manually write duplicate interfaces for the client component to consume. Remix automatically serializes and types data across the network boundary using typeof.

Pass typeof loader to useLoaderData and typeof action to useActionData:

import { useLoaderData, useActionData } from "@remix-run/react";
import type { loader, action } from "./route";

export default function RouteComponent() {
  const { user } = useLoaderData<typeof loader>();
  const actionData = useActionData<typeof action>();

  return (
    <div>
      <h1>{user.name}</h1>
      {actionData?.success && <p>Updated successfully!</p>}
    </div>
  );
}

Remix uses SerializeFrom under the hood. This automatically accounts for JSON serialization quirks, such as converting Date instances to ISO string formats.

3. Handle Dynamic Route Parameters Safely

Parameters inside LoaderFunctionArgs are typed as Params<string>, which means any dynamic segment like params.id is typed as string | undefined.

Always validate or assert that required parameters exist before using them:

import type { LoaderFunctionArgs } from "@remix-run/node";
import { json } from "@remix-run/node";
import invariant from "tiny-invariant";

export async function loader({ params }: LoaderFunctionArgs) {
  invariant(params.userId, "userId is required");

  const user = await getUser(params.userId);
  if (!user) {
    throw new Response("Not Found", { status: 404 });
  }

  return json({ user });
}

Using invariant or throwing a 400 response narrows params.userId from string | undefined to string.

4. Structure Discriminated Unions for Action Responses

Actions frequently return different shapes of data, such as validation errors or successful outcomes. Use discriminated union returns so the client can narrow down the response cleanly.

import type { ActionFunctionArgs } from "@remix-run/node";
import { json } from "@remix-run/node";

export async function action({ request }: ActionFunctionArgs) {
  const formData = await request.formData();
  const email = formData.get("email");

  if (typeof email !== "string" || !email.includes("@")) {
    return json(
      { ok: false as const, error: "Invalid email address" },
      { status: 400 }
    );
  }

  await saveEmail(email);
  return json({ ok: true as const, error: null });
}

In the component:

const actionData = useActionData<typeof action>();

if (actionData?.ok === false) {
  console.error(actionData.error);
}

Using as const on status indicators preserves the literal types (true or false), enabling TypeScript to narrow the union within your JSX.

5. Validate Input Payloads with Schema Parsers

request.formData() returns untyped values (FormDataEntryValue). Pair your actions with a validation library like Zod to create verified, strongly typed data structures directly from user input.

import { z } from "zod";
import type { ActionFunctionArgs } from "@remix-run/node";
import { json } from "@remix-run/node";

const UserSchema = z.object({
  name: z.string().min(1),
  age: z.coerce.number().int().positive(),
});

export async function action({ request }: ActionFunctionArgs) {
  const formData = await request.formData();
  const result = UserSchema.safeParse(Object.fromEntries(formData));

  if (!result.success) {
    return json(
      { success: false as const, errors: result.error.flatten().fieldErrors },
      { status: 400 }
    );
  }

  // result.data is now strongly typed as { name: string; age: number }
  await createUser(result.data);
  return json({ success: true as const, errors: null });
}

Combining schema validation with Remix's inference hooks provides complete runtime safety and end-to-end compile-time typing.
