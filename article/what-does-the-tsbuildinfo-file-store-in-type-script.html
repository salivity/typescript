What Does the tsbuildinfo File Store in TypeScript?

The tsbuildinfo file is a build cache generated by the TypeScript compiler when incremental compilation or project references are enabled. Its primary function is to store internal metadata about your project's dependency graph, file states, and compiler configurations, allowing TypeScript to check and rebuild only the files that have changed since the last compilation rather than re-analyzing the entire codebase from scratch.

When the File Is Created

TypeScript generates this file when either "incremental": true or "composite": true is specified in your tsconfig.json. By default, the compiler writes it to your build output directory as tsconfig.tsbuildinfo, though its location and filename can be customized using the "tsBuildInfoFile" configuration option.

Key Data Stored in the tsbuildinfo File

Under the hood, the tsbuildinfo file is a JSON structure containing several critical pieces of compilation state:

1. Compiler Options and Version

The file records the exact version of the TypeScript compiler (tsc) and a representation of the compiler options used during the compilation. If you upgrade TypeScript or alter flags in tsconfig.json (such as strict, target, or moduleResolution), TypeScript compares the current settings against this stored record. If discrepancies exist, the cache is invalidated, and a full rebuild is triggered automatically.

2. File Signatures and Hashes

To avoid re-parsing and re-checking untouched code, the file stores cryptographic hashes or signature representations of each input source file (.ts, .tsx, .d.ts). When a build command runs, TypeScript computes new hashes for the current files on disk and compares them to the stored signatures to quickly detect which files were modified, added, or deleted.

3. The Dependency Graph

The file contains an internal mapping of all relationships between files in your project. It records which files import, export, or transitively reference one another. When a specific file changes, TypeScript consults this stored dependency graph to determine the minimal subset of downstream files that must be re-type-checked and re-emitted, preventing unnecessary work on unrelated modules.

4. Emit Signatures and Output Mappings

The compiler tracks the relationship between source files and their corresponding generated outputs (such as .js, .js.map, and .d.ts files). It stores the hash of emitted files to ensure they stay synchronized with source files and to determine whether a .d.ts file's public API actually changed. If an implementation changes without altering the external type surface, TypeScript can skip rechecking files that depend solely on the type definitions.

5. Bundle Information (for outFile)

When using the outFile setting to concatenate outputs into a single artifact, the tsbuildinfo file also keeps track of section boundaries, source map offsets, and bundle ordering to allow fast prepending or appending of newly compiled code sections.

Best Practices for tsbuildinfo

Because the tsbuildinfo file contains machine-specific path references and frequently changes on local builds, it is generally recommended to add *.tsbuildinfo to your .gitignore file. Committing it to version control often creates merge conflicts. If a build ever behaves unexpectedly or fails to register recent changes, deleting the tsbuildinfo file forces TypeScript to perform a clean, complete rebuild of the project.
