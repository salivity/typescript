How to Implement DeepReadonly in TypeScript

This article explains how to achieve compile-time deep immutability in TypeScript by building a recursive DeepReadonly<T> utility type. You will learn why the standard library's Readonly<T> is insufficient for complex data structures, how conditional and mapped types work together recursively, how to handle edge cases like arrays, functions, and primitives, and how to combine compile-time type safety with runtime immutability.

The Limitation of Shallow Readonly<T>

TypeScript includes a built-in utility type, Readonly<T>, implemented as a shallow mapped type:

type Readonly<T> = {
  readonly [P in keyof T]: T[P];
};

Because Readonly<T> iterates only over the immediate keys of T, it prevents modification of top-level properties but leaves nested objects mutable:

interface UserProfile {
  name: string;
  preferences: {
    theme: string;
  };
}

const user: Readonly<UserProfile> = {
  name: "Alice",
  preferences: { theme: "dark" }
};

// user.name = "Bob"; // Compile error: Cannot assign to 'name'
user.preferences.theme = "light"; // Allowed! Nested mutation still occurs.

To prevent nested mutations, TypeScript needs to traverse the type tree and enforce readonly modifiers at every level.

Constructing the Recursive DeepReadonly Type

A recursive type checks the structure of each nested property. If a property is a primitive or a function, it is returned without modification (or marked readonly). If it is an array or an object, the type invokes itself recursively.

Here is a robust implementation of DeepReadonly<T>:

export type DeepReadonly<T> = T extends (infer R)[]
  ? ReadonlyArray<DeepReadonly<R>>
  : T extends Function
  ? T
  : T extends object
  ? { readonly [K in keyof T]: DeepReadonly<T[K]> }
  : T;

Breaking Down the Type Logic

  1. Handling Arrays (T extends (infer R)[]): When TypeScript encounters an array, it extracts the inner element type R using the infer keyword. It returns a ReadonlyArray, recursively wrapping R in DeepReadonly<R>. This forbids methods like .push(), .pop(), or direct index assignments like arr[0] = value.

  2. Handling Functions (T extends Function): In JavaScript and TypeScript, functions are technically objects. Without explicitly checking for Function, TypeScript would treat a function signature as an object and attempt to map its internal properties, breaking callable signatures. Preserving T leaves the function callable.

  3. Handling Nested Objects (T extends object): If T is an object, a mapped type iterates over each key K in keyof T. It adds the readonly modifier to the key and recursively resolves the property value using DeepReadonly<T[K]>.

  4. Handling Primitives (Fallback T): If T is a primitive (string, number, boolean, symbol, null, undefined), it cannot have mutable nested properties. It is returned as-is.

Practical Usage

Applying DeepReadonly ensures complete immutability down the entire object tree:

interface Company {
  name: string;
  locations: string[];
  details: {
    founded: number;
    executives: {
      ceo: string;
    };
  };
}

const company: DeepReadonly<Company> = {
  name: "TechCorp",
  locations: ["Berlin", "San Francisco"],
  details: {
    founded: 2015,
    executives: {
      ceo: "Jane Doe"
    }
  }
};

// All of the following produce TypeScript compile-time errors:
company.name = "NewCorp";
company.locations.push("Tokyo");
company.details.founded = 2020;
company.details.executives.ceo = "John Doe";

Compile-Time vs. Runtime Immutability

DeepReadonly<T> operates strictly within the TypeScript type system. It does not alter the generated JavaScript code or prevent runtime mutations via dynamic code, untyped JavaScript, or reflection.

To achieve runtime immutability alongside compile-time guarantees, recursive utility functions like deepFreeze using Object.freeze() are often paired with DeepReadonly<T>:

function deepFreeze<T>(obj: T): DeepReadonly<T> {
  Object.keys(obj as object).forEach((prop) => {
    const value = (obj as Record<string, unknown>)[prop];
    if (value !== null && (typeof value === "object" || typeof value === "function")) {
      deepFreeze(value);
    }
  });
  return Object.freeze(obj) as DeepReadonly<T>;
}

This combination ensures that illegal mutations fail both during development via the compiler and during execution via JavaScript runtime exceptions.
