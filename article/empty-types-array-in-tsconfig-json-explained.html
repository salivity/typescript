Empty Types Array in tsconfig.json Explained

Setting the "types" array to an empty array ("types": []) in your tsconfig.json explicitly prevents TypeScript from automatically including any @types packages in the global scope. By default, TypeScript scans your node_modules/@types directory and includes all installed declaration files, such as Node.js, Jest, or Mocha globals. Passing an empty array disables this automatic discovery, ensuring that no third-party global declarations are injected into your project unless explicitly imported.

Default Behavior vs. "types": []

By default, if the types property is omitted from compilerOptions, the TypeScript compiler walks up the directory tree looking for node_modules/@types folders. Every package found within those folders—such as @types/node, @types/jest, or @types/lodash—is automatically treated as part of the global execution environment.

When you configure "types": []:

{
  "compilerOptions": {
    "types": []
  }
}

You instruct the compiler to register zero global declaration packages. As a result, ambient global definitions from your dependencies are completely ignored during compilation.

What Happens to Your Code

  1. Global Variables Disappear: If you have @types/node installed but set "types": [], references to global Node.js objects like process, Buffer, or __dirname will result in compiler errors (such as Cannot find name 'process') unless you provide your own ambient declarations or explicitly import them.
  2. Explicit Module Imports Still Work: Setting "types": [] only affects global ambient declarations. It does not affect modules imported using standard import syntax. For example, import fs from 'fs' will still resolve its types properly if the package is installed.
  3. Built-in Library Types Remain Unaffected: The core JavaScript and DOM types controlled by the "lib" compiler option (such as Array, Promise, document, or window) remain active. Only external packages under node_modules/@types are blocked.

Why Use an Empty Types Array?

  • Preventing Namespace Pollution: If your repository contains both client-side and server-side code, having @types/node installed can cause the compiler to allow Node-specific globals inside browser code without raising errors. Setting "types": [] in the client configuration ensures browser code cannot accidentally use server APIs.
  • Avoiding Testing Framework Conflicts: Testing libraries like Jest and Mocha define overlapping globals (such as describe, it, and expect). Disabling automatic type inclusion prevents typing collisions between competing test runners.
  • Library Authoring: Library authors frequently use "types": [] to guarantee their code does not unintentionally rely on ambient types present in their development environment, ensuring maximum compatibility for end-users.
