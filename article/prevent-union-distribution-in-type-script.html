Prevent Union Distribution in TypeScript

In TypeScript, conditional types automatically distribute over union types when the type being checked is a naked type parameter. While this distributive behavior is often helpful, it can produce unintended results when you want to treat the union as a single, indivisible entity. This article explains how conditional type distribution works and demonstrates the standard square-bracket technique used to disable it completely.

Understanding Default Distribution

When a generic parameter T is checked directly in a conditional type, TypeScript breaks unions into individual members and evaluates the condition for each one:

type DistributiveArray<T> = T extends any ? T[] : never;

// Result: string[] | number[]
type Result = DistributiveArray<string | number>;

Instead of returning (string | number)[], TypeScript evaluates DistributiveArray<string> and DistributiveArray<number> separately, then combines their results into a new union.

How to Prevent Distribution

To stop TypeScript from distributing over a union, wrap both the type parameter and the type being checked against in square brackets ([ and ]). This creates a tuple, signaling to the compiler that the type should be evaluated as a single unit rather than a naked type parameter.

type NonDistributiveArray<T> = [T] extends [any] ? T[] : never;

// Result: (string | number)[]
type Result = NonDistributiveArray<string | number>;

Checking for never

A common issue with distributive conditional types is checking if a generic argument is never. Because never is an empty union, a distributive conditional type automatically resolves to never without executing the branches:

// Distributive (broken for never)
type IsNeverDistributive<T> = T extends never ? true : false;
type Test1 = IsNeverDistributive<never>; // Resolves to never, not true

// Non-distributive (working)
type IsNever<T> = [T] extends [never] ? true : false;
type Test2 = IsNever<never>; // Resolves to true
type Test3 = IsNever<string>; // Resolves to false

By enclosing T and never in brackets, the type [never] behaves as a single-element tuple, allowing the condition to evaluate as expected.
