TypeScript Helpers Injected for Legacy JavaScript

When compiling modern ECMAScript features to older JavaScript standards like ES5 or ES3, the TypeScript compiler automatically injects runtime helper functions into the generated output to emulate native functionality. This downleveling process allows modern syntax—such as classes, async/await, and object spread—to run seamlessly on legacy engines. This article outlines the most common runtime helpers TypeScript injects, the modern features that trigger them, and how their footprint can be managed using the tslib library.

Class Inheritance: __extends

When compiling ES6 class syntax that uses the extends keyword down to ES5, TypeScript injects the __extends helper. This helper sets up the prototype chain and copies static properties from the base constructor to the derived constructor, faithfully reproducing ES6 inheritance behavior using legacy prototype manipulation.

Async/Await: __awaiter and __generator

Targeting ES5 while writing async and await triggers two primary helpers:

  • __awaiter: Wraps an execution context in a Promise, resolving or rejecting based on the step-by-step progress of an asynchronous operation.
  • __generator: Converts an async function body into a state-machine function capable of pausing and resuming execution, emulating generator and coroutine behavior without native ES6 generator support.

Object Spread and Rest: __assign and __rest

  • __assign: Emulates Object.assign when compiling object spread syntax (e.g., { ...a, ...b }). It shallow-copies own enumerable properties from source objects to a target object.
  • __rest: Handles object destructuring with rest properties (e.g., const { x, ...rest } = obj;). It copies remaining own enumerable properties from the source object to a new object while excluding the explicitly destructured keys.

Array Spread and Iteration: __spreadArray and __values

  • __spreadArray (formerly __spread): Transforms array spread elements (e.g., [...arr, 1, 2]) and spread function arguments into standard ES5 Array.prototype.concat calls while maintaining correct handling of sparse arrays and iterable protocol semantics.
  • __values: Enables the use of for...of loops over collections by emulating iteration protocols, safely retrieving an iterator object or falling back to array indexing.

Decorators: __decorate, __param, and __metadata

When using TypeScript's experimental decorators, several helpers manage metadata reflection and application:

  • __decorate: Evaluates and applies class, method, accessor, and property decorators in the required order.
  • __param: Attaches parameter decorators to target methods.
  • __metadata: Emits design-time type metadata via the Reflect.metadata API when emitDecoratorMetadata is enabled.

Module Re-exports: __exportStar

When modern re-export syntax is used (e.g., export * from "./module"), TypeScript generates __exportStar in CommonJS or AMD formats. This helper iterates over the exported members of the target module and re-binds them to the current module's exports object, omitting default exports.

Template Literals: __makeTemplateObject

Tagged template literals compiled to ES5 use __makeTemplateObject to construct the array of strings passed to the tagging function. It ensures the freeze state and the raw property of the template array adhere to the ECMAScript specification.

Managing Helper Duplication with tslib

By default, TypeScript injects these helper definitions inline at the top of every file where they are needed. In multi-file projects, this causes significant code duplication and increases bundle size. Enabling the importHelpers compiler option in tsconfig.json instructs the compiler to import these functions from the external tslib package instead, ensuring each helper is included only once in the final bundle.
