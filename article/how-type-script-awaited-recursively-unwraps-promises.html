How TypeScript Awaited Recursively Unwraps Promises

TypeScript’s Awaited<T> utility type models the runtime behavior of await and Promise.all by recursively unwrapping nested Promise and promise-like types until an underlying value is reached. This article explains how conditional types and the infer keyword work together within the compiler's built-in definition of Awaited<T> to peel away layers of promises, handle custom thenable objects, and safely terminate recursion.

The Definition of Awaited

Introduced in TypeScript 4.5, Awaited<T> is defined in the standard library (lib.es5.d.ts) roughly as follows:

type Awaited<T> =
    T extends null | undefined ? T :
    T extends object & { then(onfulfilled: infer F, ...args: infer _): any } ?
        F extends ((value: infer V, ...args: infer _) => any) ?
            Awaited<V> :
            never :
    T;

This definition relies on conditional types, type inference with infer, and direct recursion.

Step-by-Step Recursion Process

The unwrapping process follows a deterministic sequence of type evaluations:

1. Handling Null and Undefined

The type first checks whether T extends null or undefined:

T extends null | undefined ? T : ...

If T is null or undefined, the type evaluation immediately halts and returns T. This preserves strict null checks so that types like Promise<string | null> properly resolve to string | null instead of dropping the nullish variants.

2. Identifying "Thenable" Objects

TypeScript does not strictly check for the global Promise class. Instead, it checks for structural compatibility with any "thenable" object (an object that implements a then method):

T extends object & { then(onfulfilled: infer F, ...args: infer _): any }

By constraining T to object & { then(...) }, TypeScript ensures it only inspects valid objects or instances that can be chained. It uses infer F to capture the type of the onfulfilled callback argument passed to then.

3. Inferring the Resolved Value

Once the onfulfilled callback type F is captured, TypeScript inspects its signature:

F extends ((value: infer V, ...args: infer _) => any) ? Awaited<V> : never

If F is callable, TypeScript infers its first parameter as infer V. At runtime, onfulfilled receives the resolved value of the promise; at the type level, V represents that resolved type.

4. The Recursive Call

Instead of returning V directly, the type evaluates Awaited<V>. This is the recursive step:

  • If V is another Promise (for example, Promise<number>), Awaited<Promise<number>> runs the checks again, peels the next thenable layer, and extracts number.
  • If V is a primitive or standard non-thenable object (for example, number), the next iteration fails the T extends object & { then(...) } check.

5. Reaching the Base Case

When the argument passed into Awaited does not have a then method, it drops through all conditional branches to the final fallback:

: T;

At this point, recursion terminates, and the base non-promise type is returned.

Demonstration

Consider a triply-nested promise:

type Deep = Promise<Promise<Promise<string>>>;
type Flat = Awaited<Deep>; // string
  1. Iteration 1: T is Promise<Promise<Promise<string>>>. It matches the thenable pattern, infers V as Promise<Promise<string>>, and evaluates Awaited<Promise<Promise<string>>>.
  2. Iteration 2: T is Promise<Promise<string>>. It matches the thenable pattern, infers V as Promise<string>, and evaluates Awaited<Promise<string>>.
  3. Iteration 3: T is Promise<string>. It matches the thenable pattern, infers V as string, and evaluates Awaited<string>.
  4. Iteration 4: T is string. It fails the thenable check and falls through to the final branch, returning string.

Handling Circular and Ill-Formed Promises

TypeScript incorporates recursion limits and structural checks to prevent infinite compilation loops. If a promise resolves to itself or forms a circular reference (such as interface Cycle { then: (cb: (val: Cycle) => void) => void }), the compiler detects the cycle and falls back to unknown or raises a depth limit error, ensuring that type checking terminates safely.
