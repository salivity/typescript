TypeScript Route Parameters and Union Distribution

TypeScript template literal types provide powerful string manipulation at compile time, commonly used to parse dynamic route parameters in type-safe routing libraries. When these types encounter union types, TypeScript automatically applies distributive behavior, splitting the union across conditional type branches. This article examines how union distribution works within template literal types, how it affects route parameter extraction, and how to harness or suppress this behavior to construct precise parameter types.

Understanding Union Distribution in Template Literals

In TypeScript, template literal types naturally distribute over unions. When a union is embedded directly inside a template literal, TypeScript generates a cartesian product of all possible combinations:

type Entity = 'user' | 'post';
type Action = 'create' | 'delete';

type Endpoint = `/${Entity}/${Action}`;
// Result: "/user/create" | "/user/delete" | "/post/create" | "/post/delete"

When building route parsers, template literals are typically combined with conditional types and the infer keyword. When a generic conditional type encounters an unconstrained, naked type parameter that resolves to a union, it distributes evaluation over each member of that union independently.

Parsing Dynamic Route Parameters

A standard route parser searches for path segments prefixed with a colon (:) and recursively extracts the parameter names.

type ExtractRouteParams<Path extends string> =
  Path extends `${string}:${infer Param}/${infer Rest}`
    ? Param | ExtractRouteParams<`/${Rest}`>
    : Path extends `${string}:${infer Param}`
      ? Param
      : never;

When provided with a single path, this utility extracts all route variables:

type UserPost = ExtractRouteParams<'/users/:userId/posts/:postId'>;
// Result: "userId" | "postId"

How Unions Distribute During Parsing

When a union of different route strings is passed to ExtractRouteParams, the conditional type distributes across each route candidate individually:

type Routes = '/users/:userId' | '/teams/:teamId/projects/:projectId';

type AllParams = ExtractRouteParams<Routes>;
// Evaluates to:
//   ExtractRouteParams<'/users/:userId'> 
//   | ExtractRouteParams<'/teams/:teamId/projects/:projectId'>
// Result: "userId" | "teamId" | "projectId"

While returning a union of parameter names is often intended, creating strongly typed parameter dictionaries requires careful handling of this distribution.

Generating Route Parameter Objects

If you map extracted keys directly into an object type without distribution, parameter requirements from different routes can merge into a single invalid shape. Instead, leveraging distribution allows each route to produce its own distinct parameter object:

type RouteParams<Path extends string> = Path extends string
  ? [ExtractRouteParams<Path>] extends [never]
    ? {}
    : { [K in ExtractRouteParams<Path>]: string }
  : never;

type ParamsUnion = RouteParams<'/users/:userId' | '/files/:fileId'>;
// Result: { userId: string } | { fileId: string }

In this implementation, Path extends string forces distributive evaluation. For each route in the union, TypeScript resolves the specific parameters and constructs a dedicated object shape, yielding a discriminated or overloaded set of parameter dictionaries.

Preventing Union Distribution

In certain route-matching scenarios, you may need to evaluate routes as an aggregate rather than distributing over each member. You can disable distributive conditional types by wrapping the type parameter in a tuple:

type NonDistributiveRouteCheck<T> = [T] extends ['/admin' | '/dashboard']
  ? 'Strict route match'
  : 'Flexible route match';

Wrapping both the checked type and the comparison target prevents TypeScript from splitting the union, forcing the type checker to treat the union as a single cohesive type.

Summary

Union distribution in TypeScript template literal types ensures that route parsing operations scale across multiple endpoints simultaneously. By relying on conditional distribution, each route path in a union is parsed independently, allowing developers to generate isolated, accurately typed parameter maps for dynamic APIs and frameworks.
