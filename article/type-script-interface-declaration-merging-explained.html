TypeScript Interface Declaration Merging Explained

Declaration merging is a TypeScript feature where the compiler automatically combines two or more separate declarations sharing the same name into a single definition. When applied to interfaces, it allows developers to distribute an interface definition across multiple locations or files, unifying all declared properties and methods under a single type. This mechanism is essential for extending third-party types, augmenting global objects, and building modular type architectures.

The Mechanics of Merging

When TypeScript encounters multiple interfaces with the identical identifier in the same scope, it merges them sequentially. The resulting interface contains every property and method declared across all individual definitions.

interface User {
  id: string;
  name: string;
}

interface User {
  email: string;
}

const user: User = {
  id: "u-101",
  name: "Alex",
  email: "alex@example.com",
};

An object typed as User must satisfy the combined requirements of both blocks.

Rules for Non-Function Properties

Non-function members within merged interfaces must have compatible types. If you declare a property with the same name in multiple interface definitions, their types must be identical. If the types conflict, TypeScript emits a compilation error.

interface Settings {
  theme: string;
}

interface Settings {
  // Error: Subsequent property declarations must have the same type.
  theme: number;
}

Method Overloading Behavior

When interfaces declare methods with the same name, declaration merging treats them as function overloads. Each subsequent interface declaration is resolved in reverse order: the methods declared in later interfaces take precedence over earlier ones.

interface ElementHandler {
  handle(element: HTMLElement): void;
}

interface ElementHandler {
  handle(element: HTMLInputElement): void;
}

In this case, the resulting overload signature places the HTMLInputElement overload first and HTMLElement second:

interface ElementHandler {
  handle(element: HTMLInputElement): void;
  handle(element: HTMLElement): void;
}

An exception to this rule applies to signatures that use string literal types (e.g., 'click', 'input'). Signatures containing string literal parameters bubble to the top of the overload list, retaining their specific-to-general resolution order.

Merging Generic Interfaces

Interfaces that use generics can also be merged, provided that their type parameters match in name and order. If generic parameter lists differ, the compiler raises an error.

interface Container<T> {
  value: T;
}

interface Container<T> {
  metadata: string;
}

Module Augmentation

A primary practical application of interface declaration merging is module augmentation. When working with external libraries, you can inject custom properties into existing types without modifying the original source code.

// Extending the NodeJS ProcessEnv interface
declare global {
  namespace NodeJS {
    interface ProcessEnv {
      DATABASE_URL: string;
      PORT: string;
    }
  }
}

export {};

Because TypeScript's standard library and many external type packages define their contracts using interfaces rather than type aliases, declaration merging allows consumers to seamlessly extend these global definitions to fit custom application requirements.
