How TypeScript importHelpers Reduces Bundle Size

The importHelpers flag in TypeScript reduces JavaScript bundle sizes by replacing duplicated inline runtime helper functions with shared imports from the external tslib library. When TypeScript compiles modern ECMAScript features to older JavaScript targets, it generates boilerplate helper functions to replicate those behaviors. By enabling importHelpers, TypeScript imports these functions once from a single centralized module rather than injecting identical copies into every transpiled file, significantly cutting down code redundancy across your project.

The Problem: Inlined Helper Functions

When targeting older ECMAScript standards (such as ES5 or ES6), TypeScript downlevels modern syntax—such as async/await, object spread operations, class inheritance, and decorators—into equivalent, backward-compatible code. To make these features work in older environments, the compiler emits helper functions such as __awaiter, __generator, __assign, and __spreadArray.

By default, TypeScript injects the full implementation of these helpers directly into the top of every compiled file that requires them. If you have 100 files using async/await, TypeScript will copy the identical __awaiter and __generator definitions 100 times throughout your codebase. In large codebases, this duplication adds substantial dead weight to the final distribution bundle.

The Solution: The importHelpers Flag

Enabling "importHelpers": true alters this behavior. Instead of generating inline definitions, TypeScript changes the output to import helpers from a standard external runtime library called tslib.

For example, without importHelpers, a file using object spread generates this at the top:

var __assign = (this && this.__assign) || function () { ... };

With importHelpers: true, the generated code changes to:

var tslib_1 = require("tslib");
// or: import { __assign } from "tslib";

How This Optimizes Bundle Size

  1. Elimination of Duplication: Every file references the same canonical function definitions provided by tslib. The code for __awaiter, __assign, and other helpers exists only once in memory and in the final bundle.
  2. Bundler Deduplication: Modern bundlers like Webpack, Rollup, esbuild, and Vite naturally resolve module imports and bundle tslib as a single shared dependency, eliminating all redundant declarations.
  3. Tree-Shaking Support: The tslib package is organized to support tree-shaking, meaning bundlers only include the specific helpers your application actually uses, avoiding unnecessary overhead.

How to Implement importHelpers

To take advantage of this optimization, install tslib as a production dependency:

npm install tslib

Then, enable the flag inside the compilerOptions section of your tsconfig.json:

{
  "compilerOptions": {
    "target": "es5",
    "importHelpers": true
  }
}

By decoupling helper definitions from individual modules, importHelpers provides an immediate, low-effort reduction in bundle size, with the greatest impact seen in large, multi-file codebases transpiling modern syntax to older JavaScript targets.
