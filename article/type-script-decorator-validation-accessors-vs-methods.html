TypeScript Decorator Validation: Accessors vs Methods

TypeScript validates decorators applied to class accessors and class methods by enforcing distinct type signatures, execution contexts, and compilation constraints. While both target member definitions, TypeScript differentiates between them to ensure type safety over functions versus property accessors. This guide explains how TypeScript checks these decorators under modern ECMAScript standards (TypeScript 5.0+) as well as legacy experimental flags, contrasting how property descriptors, contextual metadata, and return types are validated for methods versus accessors.

Standard ECMAScript Decorators (TypeScript 5.0+)

Modern TypeScript enforces type constraints using built-in generic types defined in the standard library: ClassMethodDecoratorContext, ClassGetterDecoratorContext, ClassSetterDecoratorContext, and ClassAccessorDecoratorContext.

Method Decorator Validation

A method decorator is validated against a function value. Its signature generally corresponds to:

type ClassMethodDecorator = <This, Args extends any[], Return>(
  target: (this: This, ...args: Args) => Return,
  context: ClassMethodDecoratorContext<This, (this: This, ...args: Args) => Return>
) => ((this: This, ...args: Args) => Return) | void;

TypeScript checks:

  1. Target Compatibility: The decorated member must be a function.
  2. Context Kind: The context.kind property is statically typed as the literal "method".
  3. Replacement Value: If the decorator returns a value, TypeScript ensures the returned function matches the parameter types and return type of the original method.

Accessor Decorator Validation

TypeScript distinguishes between standard accessors (get/set) and auto-accessors (declared with the accessor keyword).

For getters and setters:

  • Getters: The target is a function taking zero arguments and returning a value (() => Value). The context is ClassGetterDecoratorContext, where context.kind is "getter".
  • Setters: The target is a function accepting a single argument and returning void ((value: Value) => void). The context is ClassSetterDecoratorContext, where context.kind is "setter".

For auto-accessors (accessor myProp: string):

  • The target is an object containing both accessors: { get(): Value; set(value: Value): void }.
  • The context is ClassAccessorDecoratorContext, with context.kind typed as "accessor".
  • TypeScript permits the decorator to return a wrapper object containing new get, set, or init functions, validating each against the underlying property type.

Legacy Decorators (--experimentalDecorators)

Under the legacy implementation, both method and accessor decorators share the runtime signature (target: any, propertyKey: string, descriptor: PropertyDescriptor), but TypeScript applies divergent compiler rules.

Single-Accessor Rule

TypeScript strictly forbids decorating both the get and set accessors for the same member name. Because decorators modify a combined PropertyDescriptor for the property, decorating both generates a compile-time error (TS1207: Decorators cannot be applied to multiple get/set accessors of the same name).

Instead, the decorator must be placed on the first accessor that appears in the source order. Methods have no such constraint, as each method has its own distinct declaration.

PropertyDescriptor Validation

  • Method Decorators: TypeScript expects the descriptor to contain a value field typed as a function. If the decorator returns a descriptor, TypeScript verifies that descriptor.value retains a compatible function signature.
  • Accessor Decorators: TypeScript expects the descriptor to define get and/or set functions instead of a value property. A returned descriptor is validated to ensure that get takes no parameters and returns the expected type, and set accepts exactly one parameter.

Summary of Differences

Feature Class Method Decorator Class Accessor Decorator
Context Kind (TS 5.0+) "method" "getter", "setter", or "accessor"
Target Representation The function definition directly. The specific getter/setter function, or a { get, set } pair for auto-accessors.
Paired Declarations N/A (single declaration). Under legacy mode, only the first accessor in the source code can be decorated.
Return Value Constraints A substitute function matching the original call signature. A substitute getter/setter function or an object updating get, set, and initializers.
