How to Type Dynamic Return Types in TypeScript

Typing functions that accept varying configurations and return different types is a common requirement in scalable TypeScript applications. This guide covers how to achieve dynamic return types using TypeScript's most effective patterns: function overloads, generics with conditional types, and mapped configurations. By mastering these patterns, you can provide precise autocompletion and strict type safety for consumers of your functions based entirely on the options they pass.

1. Function Overloads

Function overloads are best suited for functions with a finite, explicit set of configuration options (such as a boolean flag or a fixed set of string literals). You declare multiple function signatures followed by a single implementation signature that accommodates all variants.

interface User {
  id: string;
  name: string;
}

// Overload signatures
function fetchUser(id: string, detailed: true): User & { email: string; createdAt: Date };
function fetchUser(id: string, detailed?: false): User;

// Implementation signature
function fetchUser(id: string, detailed = false) {
  if (detailed) {
    return { id, name: "Alice", email: "alice@example.com", createdAt: new Date() };
  }
  return { id, name: "Alice" };
}

// Usage
const simple = fetchUser("1");         // Type: User
const detailed = fetchUser("1", true); // Type: User & { email: string; createdAt: Date }

2. Generics with Conditional Types

When configuration options map to distinct return shapes or depend on arbitrary input values, generics combined with conditional types provide a more scalable solution than writing dozens of overload signatures.

type Format = "json" | "text" | "blob";

type ApiResponse<T extends Format> = 
  T extends "json" ? Record<string, unknown> :
  T extends "text" ? string :
  Blob;

interface RequestConfig<T extends Format> {
  url: string;
  format: T;
}

function request<T extends Format = "json">(config: RequestConfig<T>): ApiResponse<T> {
  // Implementation logic here
  return {} as ApiResponse<T>;
}

// Usage
const jsonResponse = request({ url: "/api", format: "json" }); // Record<string, unknown>
const textResponse = request({ url: "/api", format: "text" }); // string

3. Object-Lookup Maps

For deep or extensive mappings, nested ternary operators in conditional types can become difficult to read. You can define an interface acting as a registry to map configuration keys directly to their return types.

interface ParserRegistry {
  number: number;
  string: string;
  boolean: boolean;
  date: Date;
}

interface ParseConfig<T extends keyof ParserRegistry> {
  target: T;
  strict?: boolean;
}

function parse<T extends keyof ParserRegistry>(
  value: string,
  config: ParseConfig<T>
): ParserRegistry[T] {
  switch (config.target) {
    case "number":
      return Number(value) as ParserRegistry[T];
    case "boolean":
      return (value === "true") as ParserRegistry[T];
    case "date":
      return new Date(value) as ParserRegistry[T];
    default:
      return value as ParserRegistry[T];
  }
}

// Usage
const parsedNum = parse("42", { target: "number" }); // Type: number
const parsedDate = parse("2024-01-01", { target: "date" }); // Type: Date

4. Discriminated Unions in Parameters

When different configurations require mutually exclusive arguments, pass a discriminated union as the parameter. This allows TypeScript to narrow both the configuration structure and the return type simultaneously.

type SyncConfig = {
  async: false;
};

type AsyncConfig = {
  async: true;
  timeout?: number;
};

function execute(config: SyncConfig): string;
function execute(config: AsyncConfig): Promise<string>;
function execute(config: SyncConfig | AsyncConfig): string | Promise<string> {
  if (config.async) {
    return Promise.resolve("Done async");
  }
  return "Done sync";
}

// Usage
const syncResult = execute({ async: false }); // Type: string
const asyncResult = execute({ async: true, timeout: 5000 }); // Type: Promise<string>

Choosing the Right Pattern

  • Use Function Overloads when dealing with two to three static configuration states, such as boolean toggle flags.
  • Use Generics with Registry Maps when the configuration keys represent a dynamic or extensible set of known types.
  • Use Conditional Generics when the return type depends on inspecting a type parameter directly (e.g., checking if T extends Array<any>).
