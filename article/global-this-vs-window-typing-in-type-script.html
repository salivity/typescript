globalThis vs window Typing in TypeScript

Understanding the difference between globalThis typing and window typing in TypeScript comes down to runtime environment portability, standard library dependencies, and how global interfaces are augmented. While both refer to the top-level execution context in a standard web browser, window is strictly tied to browser-specific DOM typings, whereas globalThis is an ECMAScript standard that provides a universal, platform-agnostic type definition for the global scope across Node.js, Web Workers, and browsers.

Environment Scope and Library Dependencies

In TypeScript, window is typed using the Window interface, which is defined in TypeScript's dom standard library (lib.dom.d.ts). This type encompasses browser-specific APIs such as document, localStorage, and DOM manipulation methods. If your TypeScript project targets a non-browser environment—such as a Node.js backend or a standalone Web Worker—referencing window causes a compile-time error (Cannot find name 'window') unless the DOM library is explicitly included in tsconfig.json.

Conversely, globalThis is typed as typeof globalThis and is defined within the core ECMAScript standard library (lib.es2020.globalthis.d.ts or higher). It represents the standardized global object introduced in ECMAScript 2020. Because it does not assume a browser environment, globalThis only includes standard JavaScript built-in objects (such as Object, Array, Promise, and JSON) unless combined with other platform-specific declarations.

Type Augmentation Differences

Modifying or extending the global scope requires different approaches depending on whether you are augmenting window or globalThis.

To add custom properties to window, you augment the Window interface using declaration merging:

declare global {
  interface Window {
    myCustomGlobal: string;
  }
}

// Accessible via:
window.myCustomGlobal = "value";

Because window is a named interface, it can be extended directly anywhere in your codebase.

To extend globalThis, TypeScript requires variable declarations within a declare global block rather than modifying an interface named globalThis:

declare global {
  var myUniversalGlobal: string;
}

// Accessible via:
globalThis.myUniversalGlobal = "value";

Top-level var declarations inside declare global automatically merge into the globalThis type definition across all environments.

Which Type Should You Use?

  • Use window typing when writing code that is exclusively intended for the browser and interacts directly with browser-specific features like DOM nodes, CSS, or window events.
  • Use globalThis typing when building universal libraries, isomorphic applications (such as Next.js or Remix), or server-side tools where the code must compile and run predictably across Node.js, Deno, Bun, and browser workers without throwing missing type errors.
