TypeScript: Extract Path Params with Template Literals

TypeScript template literal types enable compile-time parsing of string patterns, allowing developers to build strictly typed URL routing systems. This article demonstrates how to construct recursive conditional types that parse route strings containing parameters (such as "/users/:id/posts/:postId"), extracting them into a strongly typed object shape to guarantee type safety in route handler arguments.

The Mechanism: Recursive Conditional Types

To parse dynamic segments within a string literal, TypeScript uses template literal types combined with the infer keyword. By recursively splitting a path string at each delimiter (such as / and :), you can isolate dynamic parameter names and accumulate them into an object type.

Here is the utility type that implements this extraction logic:

type ExtractRouteParams<Path extends string> =
  Path extends `${infer _Prefix}:${infer Rest}`
    ? Rest extends `${infer Param}/${infer Suffix}`
      ? { [K in Param]: string } & ExtractRouteParams<`/${Suffix}`>
      : { [K in Rest]: string }
    : {};

To flatten the resulting intersection types (e.g., { id: string } & { postId: string }) into a single, clean object type, use a helper utility:

type Simplify<T> = { [K in keyof T]: T[K] } & {};

export type RouteParams<Path extends string> = Simplify<ExtractRouteParams<Path>>;

How the Type Works

  1. Parameter Detection: Path extends\({infer _Prefix}:\){infer Rest}`searches the string from left to right for the first colon (:). The substring before the colon is discarded via_Prefix, and the remainder is captured inRest`.
  2. Segment Delimitation: Rest extends\({infer Param}/\){infer Suffix}`checks if another forward slash exists after the parameter. If so, it extracts the current parameter name (Param) and creates a mapped type{ [K in Param]: string }`.
  3. Recursion: The type then calls itself recursively with the remaining path (/${Suffix}) to catch subsequent parameters.
  4. Base Case: If no further slash is present after the colon, the entire remaining Rest string is captured as the final parameter name. If no colon exists at all, it evaluates to {}.

Building the Type-Safe Router

Once the extraction utility is defined, it can be applied to route registration methods on a router class or interface:

type RouteHandler<Path extends string> = (
  params: RouteParams<Path>
) => void | Promise<void>;

class Router {
  get<Path extends string>(path: Path, handler: RouteHandler<Path>): void {
    // Runtime registration logic here
  }
}

Example Usage

When registering routes, TypeScript infers the exact string literal passed to the path argument and computes the params argument type automatically:

const router = new Router();

// Single parameter
router.get("/users/:id", (params) => {
  // params is typed as { id: string }
  console.log(params.id);
});

// Multiple parameters
router.get("/orgs/:orgId/teams/:teamId", (params) => {
  // params is typed as { orgId: string; teamId: string }
  console.log(params.orgId, params.teamId);
});

// Static route without parameters
router.get("/about", (params) => {
  // params is typed as {}
});

If a developer attempts to access a property that was not defined in the path literal—such as params.userId instead of params.id—the TypeScript compiler raises an error at compile time, eliminating runtime errors caused by mismatched URL segment names.
