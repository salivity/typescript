How to Type SSE Streams in TypeScript

Handling Server-Sent Events (SSE) in TypeScript requires strong typing to ensure runtime stability and developer confidence. This article explores how to model structured SSE event schemas, create type-safe wrappers around the native browser EventSource API, and handle modern fetch-based streaming with typed ReadableStream readers and discriminated unions.

Defining the SSE Schema with Discriminated Unions

The most robust way to type an SSE stream is by defining a discriminated union representing all possible events emitted by the server. This allows TypeScript to automatically narrow the payload type based on the event name.

export type SSEEvent =
  | { type: 'connected'; data: { userId: string; timestamp: number } }
  | { type: 'message'; data: { id: string; content: string; sender: string } }
  | { type: 'heartbeat'; data: null }
  | { type: 'error'; data: { code: number; message: string } };

export type SSEEventType = SSEEvent['type'];

Typing the Standard EventSource API

The native browser EventSource provides an onmessage handler and an addEventListener method. By default, incoming messages contain raw strings in event.data. You can create a typed wrapper around EventSource to enforce event names and payload parsing:

type ExtractEventData<T extends SSEEventType> = Extract<SSEEvent, { type: T }>['data'];

export class TypedEventSource {
  private source: EventSource;

  constructor(url: string, eventSourceInitDict?: EventSourceInit) {
    this.source = new EventSource(url, eventSourceInitDict);
  }

  public addEventListener<T extends SSEEventType>(
    type: T,
    listener: (data: ExtractEventData<T>) => void,
    options?: boolean | AddEventListenerOptions
  ): void {
    this.source.addEventListener(
      type,
      (event: Event) => {
        const messageEvent = event as MessageEvent<string>;
        const parsedData: ExtractEventData<T> = messageEvent.data 
          ? JSON.parse(messageEvent.data) 
          : null;
        listener(parsedData);
      },
      options
    );
  }

  public close(): void {
    this.source.close();
  }
}

Typing fetch-Based SSE Streams (ReadableStream)

Because the native EventSource API does not support custom headers or HTTP POST requests, modern applications frequently use fetch and consume the response body as a ReadableStream.

Using an async generator allows you to parse the incoming text chunks line-by-line and yield strictly typed event objects:

export async function* parseSSEStream(
  response: Response
): AsyncGenerator<SSEEvent, void, unknown> {
  if (!response.body) {
    throw new Error('Response contains no readable body.');
  }

  const reader = response.body.pipeThrough(new TextDecoderStream()).getReader();
  let buffer = '';

  while (true) {
    const { value, done } = await reader.read();
    if (done) break;

    buffer += value;
    const lines = buffer.split('\n');
    buffer = lines.pop() ?? '';

    let currentEvent: SSEEventType = 'message';

    for (const line of lines) {
      const trimmed = line.trim();
      if (!trimmed) continue;

      if (trimmed.startsWith('event:')) {
        currentEvent = trimmed.replace('event:', '').trim() as SSEEventType;
      } else if (trimmed.startsWith('data:')) {
        const rawData = trimmed.replace('data:', '').trim();
        const parsed = rawData ? JSON.parse(rawData) : null;

        yield {
          type: currentEvent,
          data: parsed,
        } as SSEEvent;

        // Reset to default SSE event type
        currentEvent = 'message';
      }
    }
  }
}

Consuming Typed SSE Streams Safely

Once typed via an async generator or typed wrapper, consuming the stream enables full autocomplete and exhaustive type checking:

async function listenToStream(url: string) {
  const response = await fetch(url, {
    headers: { Accept: 'text/event-stream' },
  });

  for await (const event of parseSSEStream(response)) {
    switch (event.type) {
      case 'connected':
        console.log(`Connected user: ${event.data.userId}`);
        break;
      case 'message':
        console.log(`New message: ${event.data.content}`);
        break;
      case 'heartbeat':
        console.log('Heartbeat received');
        break;
      case 'error':
        console.error(`Stream error [${event.data.code}]: ${event.data.message}`);
        break;
    }
  }
}

By decoupling protocol parsing from schema definition using discriminated unions, TypeScript ensures that stream consumers always receive verified, fully typed event data.
