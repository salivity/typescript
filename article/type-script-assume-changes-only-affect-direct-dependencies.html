TypeScript assumeChangesOnlyAffectDirectDependencies

The assumeChangesOnlyAffectDirectDependencies flag in TypeScript is an optimization setting designed to significantly speed up incremental rebuild times in large projects. By default, TypeScript's watch and build modes re-evaluate both direct and indirect (transitive) dependencies whenever a file changes to guarantee complete type safety across the entire dependency graph. Enabling this flag alters that behavior by instructing the compiler to only re-check files that directly import the modified file, reducing compilation overhead at the cost of potentially missing indirect type errors during active editing.

How the Default Dependency Graph Works

In standard incremental compilation or watch mode (--watch), TypeScript tracks relationships between files across your entire project. Consider a dependency chain where:

  • File C imports File B
  • File B imports File A

If you modify a type or export in File A, TypeScript checks File B to see if the change broke anything. Because File B might re-export a modified type or alter its own shape as a result, TypeScript also proceeds to re-check File C, continuing down the chain until every downstream dependent has been validated. In large codebases with deep dependency trees, this transitive checking can cause noticeable delays during daily development.

How the Flag Changes Compilation

When you enable assumeChangesOnlyAffectDirectDependencies: true, TypeScript restricts its rebuild scope. Using the same example:

  1. You edit File A.
  2. TypeScript re-evaluates File A and File B (the direct dependent).
  3. TypeScript stops there and does not automatically re-check File C or any other downstream files.

By preventing the compiler from traversing the entire downstream graph, rebuild times during iterative development remain fast and responsive, regardless of how deep or wide the project structure is.

Trade-offs and Best Practices

While this flag significantly improves developer experience by reducing feedback loops in large codebases, it introduces a trade-off in type accuracy during watch sessions:

  • Risk of False Negatives: If a change in File A causes an implicit change in File B's exported types, File C may now contain type errors that TypeScript will not report in watch mode.
  • Intended Environment: This option is best reserved for local development workflows and watch modes where speed is paramount.
  • CI/CD Requirements: Full, clean builds (without this flag, or running complete checks) should always be enforced in continuous integration pipelines to catch any indirect breakages before code is merged.

Configuration

You can enable this setting directly within your tsconfig.json under compilerOptions:

{
  "compilerOptions": {
    "incremental": true,
    "assumeChangesOnlyAffectDirectDependencies": true
  }
}

This flag is most effective when paired with --incremental or --watch in large projects, multi-package repositories, or monorepos where incremental build performance has become a bottleneck.
