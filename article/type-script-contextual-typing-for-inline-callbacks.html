TypeScript Contextual Typing for Inline Callbacks

In TypeScript, contextual typing is a form of type inference where the type of an expression is determined by its location or context within the code, rather than from the expression alone. When passing an inline callback to a higher-order function, TypeScript looks at the expected signature of the target parameter and automatically assigns those types to the callback's arguments. This article breaks down how this top-down inference mechanism works, how it pairs with generics, and why inline declarations behave differently from standalone function variables.

How Contextual Typing Operates

Standard type inference in TypeScript works from the inside out: the compiler inspects an expression, calculates its type, and assigns that type to the variable holding it.

Contextual typing inverts this process, working from the outside in. When the compiler evaluates an argument passed to a function call, it checks the declaration of the function being invoked. If the parameter expects a function type (such as (item: string, index: number) => void), that expected signature becomes the "contextual type."

When an inline callback is supplied, TypeScript compares the callback's parameter list to the contextual type position by position:

const names = ["Alice", "Bob", "Charlie"];

// 'name' is contextually typed as string
// 'index' is contextually typed as number
names.forEach((name, index) => {
  console.log(`${index}: ${name.toUpperCase()}`);
});

Because Array.prototype.forEach defines its callback parameter as (value: T, index: number, array: T[]) => void, and names is string[], TypeScript fixes T to string. The inline arrow function receives string for its first parameter and number for its second, without requiring explicit type annotations.

The Role of Position over Name

Contextual inference matches arguments strictly by their ordinal position, not by their identifier names.

If a callback signature expects (event: MouseEvent, target: HTMLElement) => void, an inline callback written as (e, el) => ... will map e to MouseEvent and el to HTMLElement.

TypeScript also permits the callback to declare fewer parameters than the contextual type provides. For example:

// Only the first parameter is used; TypeScript ignores the rest safely
names.map((item) => item.length);

The unused parameters defined by the host method (like index and array) are simply discarded during contextual matching, which matches standard JavaScript runtime behavior.

Interaction with Generic Functions

Contextual typing plays a critical role in inferring generic type arguments. When a function has type parameters, TypeScript often uses the context of the caller to resolve them:

function transform<T, U>(items: T[], fn: (item: T) => U): U[] {
  return items.map(fn);
}

const numbers = [1, 2, 3];
const result = transform(numbers, (n) => n.toString());

In this scenario:

  1. TypeScript inspects the first argument, numbers, and infers that T is number.
  2. With T established, the contextual type for fn becomes (item: number) => U.
  3. The compiler examines the inline callback (n) => n.toString(). Because n is contextually typed as number, calling n.toString() returns a string.
  4. The return value of the callback contextually satisfies U, inferring U as string.
  5. The return type of transform is finalized as string[].

Why Inlining Matters

Contextual typing requires an immediate structural context. If an identical function is extracted into a standalone variable without explicit annotations, contextual typing cannot occur at the point of declaration:

// ERROR: Parameter 'item' implicitly has an 'any' type.
const logItem = (item) => {
  console.log(item);
};

names.forEach(logItem);

When logItem is declared separately, TypeScript must evaluate it in isolation (inside-out). Because there is no contextual type to inform the parameter item, it falls back to any (triggering an error under noImplicitAny). Keeping the callback inline maintains the link between the host function's signature and the callback's parameters, allowing TypeScript's bidirectional type inference to resolve types seamlessly.
