TypeScript Indexed Access on Generic Objects

TypeScript types indexed access on generic objects by combining indexed access types (T[K]) with the keyof operator to guarantee type safety at compile time. This mechanism allows developers to capture property types dynamically without sacrificing strict typing, ensuring that accessed values always correspond directly to their specific keys on an object. This article explains how TypeScript represents and evaluates indexed access types across generic boundaries, how the type checker enforces valid property lookups, and how to safely read and write dynamic object properties.

The Foundation: keyof and T[K]

Indexed access types let you look up the type of a specific property on another type using syntax similar to standard JavaScript property access. When applied to generic types, indexed access requires establishing a relationship between the target object and the requested key.

The basic pattern relies on constraining a generic key parameter using keyof:

function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}

In this pattern:

  • T represents the generic object.
  • keyof T produces a union of all known public property names (keys) of T.
  • K extends keyof T ensures that K can only ever be a valid key of T.
  • T[K] evaluates to the specific value type associated with property K on type T.

Deferred Resolution of Generic Indexed Access

When TypeScript processes generic definitions containing T[K], it cannot immediately compute the final type because T and K are not yet known. Instead, it maintains T[K] as a deferred type.

During this deferred phase:

  1. Constraint Checking: The compiler validates that K satisfies keyof T. If K is not constrained to keyof T, TypeScript raises a compile-time error (Type 'K' cannot be used to index type 'T').
  2. Type Preservation: TypeScript retains the precise relationship between the key and the property type rather than widening the return value to a broad union or any.
  3. Instantiation: When the function or type is invoked with concrete types, TypeScript substitutes the concrete arguments for T and K, immediately resolving T[K] to its concrete member type.
interface User {
  id: number;
  name: string;
  isActive: boolean;
}

const user: User = { id: 1, name: "Alice", isActive: true };

// The return type is inferred specifically as string, not string | number | boolean
const userName = getProperty(user, "name");

// Compile-time error: Argument of type '"age"' is not assignable to parameter of type 'keyof User'
const userAge = getProperty(user, "age");

Handling Union Types in Keys

When the key parameter K evaluates to a union of keys, TypeScript distributes the indexed access across each constituent in the union.

function getProperties<T, K extends keyof T>(obj: T, keys: K[]): T[K][] {
  return keys.map((key) => obj[key]);
}

// Type of 'values' is (string | number)[]
const values = getProperties(user, ["id", "name"]);

Because K is instantiated as "id" | "name", T[K] resolves to User["id"] | User["name"], which evaluates to number | string.

Mutating Generic Properties Safely

Indexed access types are equally applicable when updating generic properties. By typing function parameters with T[K], TypeScript ensures that values assigned to an object strictly match the type defined for that exact key.

function setProperty<T, K extends keyof T>(obj: T, key: K, value: T[K]): void {
  obj[key] = value;
}

const settings = {
  timeout: 5000,
  debug: true,
};

// Valid
setProperty(settings, "timeout", 10000);

// Error: Argument of type 'string' is not assignable to parameter of type 'number'
setProperty(settings, "timeout", "fast");

Nested Indexed Access

Generic indexed access can be chained to traverse nested object structures. By nesting keyof constraints, you can achieve deep, type-safe path resolution:

function getNestedProperty<
  T,
  K1 extends keyof T,
  K2 extends keyof T[K1]
>(obj: T, key1: K1, key2: K2): T[K1][K2] {
  return obj[key1][key2];
}

const config = {
  server: {
    port: 8080,
    host: "localhost",
  },
};

// Inferred return type is number
const port = getNestedProperty(config, "server", "port");

In this implementation, K2 is constrained not to keyof T, but to keyof T[K1]. The return type resolves directly to the deeply indexed type T[K1][K2].
