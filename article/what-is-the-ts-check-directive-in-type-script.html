What Is the ts-check Directive in TypeScript?

The // @ts-check directive is a special comment used in JavaScript files to enable TypeScript-powered type checking without converting the file to TypeScript syntax. This article explains what the directive does, why it is useful for JavaScript development, and the exact rules for where it must be placed within a file.

What Is the ts-check Directive?

The // @ts-check directive instructs the TypeScript language server and compiler to perform static type analysis on a standard JavaScript (.js or .jsx) file. Normally, TypeScript ignores regular JavaScript files unless the checkJs option is enabled globally in a tsconfig.json or jsconfig.json configuration file.

By adding // @ts-check to a single file, developers can opt into type safety on a file-by-file basis. When enabled, the editor highlights common programming errors, such as:

  • Calling functions with the wrong number or type of arguments.
  • Accessing non-existent properties on objects.
  • Type mismatches during variable assignments.
  • Syntax errors and typos in variable names.

To define custom types or enforce specific signatures in a checked JavaScript file, developers can use JSDoc annotations such as @type, @param, @returns, and @typedef. TypeScript parses these annotations to infer and validate types in the same way it evaluates native TypeScript code.

Where Is the ts-check Directive Placed?

The // @ts-check directive must be placed at the very top of the JavaScript file, before any executable code or statements.

For the directive to be recognized by the compiler:

  1. Top of the File: It should ideally be the first line of the file.
  2. Preceding Code: It must appear before any executable JavaScript code (such as import, require, variable declarations, or function definitions).
  3. Exceptions: It can follow an operating system shebang line (e.g., #!/usr/bin/env node) or standard top-level license and copyright comments, provided no actual JavaScript execution logic precedes it.

Placement Example

Here is the correct way to place the directive in a JavaScript file:

// @ts-check

/**
 * Calculates the total price including tax.
 * @param {number} price 
 * @param {number} taxRate 
 * @returns {number}
 */
function calculateTotal(price, taxRate) {
  return price + (price * taxRate);
}

// TypeScript will flag an error here: Argument of type 'string' is not assignable to parameter of type 'number'.
calculateTotal("100", 0.05);

If the directive is placed after any executable statements, the TypeScript engine will simply ignore it, treating the file as unchecked standard JavaScript.

Disabling Type Checking

If a project has the checkJs flag enabled globally in its configuration file, every JavaScript file is checked by default. In this scenario, developers can use the opposite directive, // @ts-nocheck, placed at the very top of a file, to suppress type-checking for that specific file.
