Using tsconfig outDir for Multi-Target Outputs

When building TypeScript projects that need to support multiple environments—such as CommonJS (CJS) and ECMAScript Modules (ESM)—managing build outputs is critical. The outDir compiler option in tsconfig.json controls where the TypeScript compiler places generated JavaScript files, declaration maps, and type definitions. This article explains how outDir works, why it is fundamental for organizing multi-target outputs, and how to configure it across multiple build targets.

The Role of outDir in TypeScript Compilation

The outDir flag specifies the root directory for all emitted files (.js, .d.ts, and .map). By default, if outDir is not defined, the compiler emits JavaScript files alongside their corresponding TypeScript source files.

When outDir is enabled, the TypeScript compiler creates an identical folder hierarchy inside the specified folder, determined relative to the rootDir (or the common root of all input files). For example, setting "outDir": "./dist" will place the compiled output of src/index.ts at dist/index.js.

The Multi-Target Challenge

Modern libraries often require dual publishing:

  • CommonJS for legacy Node.js environments.
  • ES Modules for modern bundlers, browsers, and modern Node.js versions.
  • Type Declarations to provide static typing support.

Because a single tsconfig.json can only specify one target, one module system, and one outDir, a single configuration cannot generate multiple targets simultaneously. Attempting to output both formats into the same directory leads to file collisions and overwritten code.

Structuring Multi-Target Builds with outDir

The standard approach to organizing multi-target outputs involves creating a base configuration and extending it with target-specific configuration files, each defining its own outDir.

1. The Base Configuration (tsconfig.json)

Define shared compiler options, such as type-checking rules and source file inclusion:

{
  "compilerOptions": {
    "strict": true,
    "declaration": true,
    "declarationMap": true,
    "sourceMap": true,
    "rootDir": "./src"
  },
  "include": ["src/**/*"]
}

2. The CommonJS Configuration (tsconfig.cjs.json)

Inherit from the base configuration, specify CommonJS settings, and direct the output to a designated CJS directory:

{
  "extends": "./tsconfig.json",
  "compilerOptions": {
    "module": "CommonJS",
    "target": "ES2020",
    "outDir": "./dist/cjs"
  }
}

3. The ES Module Configuration (tsconfig.esm.json)

Inherit from the base configuration, specify ESM settings, and route the output to a dedicated ESM directory:

{
  "extends": "./tsconfig.json",
  "compilerOptions": {
    "module": "ESNext",
    "target": "ES2022",
    "outDir": "./dist/esm"
  }
}

The Importance of rootDir with outDir

When using outDir in multi-target setups, always explicitly define rootDir. If rootDir is omitted, TypeScript computes the root path based on the longest common path of all input files. If an unexpected file outside of src is included in one build target but not the other, the generated output structure will shift, breaking your export paths. Defining "rootDir": "./src" guarantees that both dist/cjs and dist/esm maintain identical internal directory structures.

Aligning outDir with package.json Exports

Once outDir isolates each build target into its own folder, map those directories directly in your package.json:

{
  "name": "example-package",
  "main": "./dist/cjs/index.js",
  "module": "./dist/esm/index.js",
  "types": "./dist/esm/index.d.ts",
  "exports": {
    ".": {
      "import": {
        "types": "./dist/esm/index.d.ts",
        "default": "./dist/esm/index.js"
      },
      "require": {
        "types": "./dist/cjs/index.d.ts",
        "default": "./dist/cjs/index.js"
      }
    }
  },
  "scripts": {
    "build:cjs": "tsc -p tsconfig.cjs.json",
    "build:esm": "tsc -p tsconfig.esm.json",
    "build": "npm run build:cjs && npm run build:esm"
  }
}

Using outDir systematically to separate build artifacts prevents namespace collisions, simplifies cleanup tasks, and ensures full compatibility across diverse JavaScript runtimes.
