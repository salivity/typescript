import type vs import { type } in TypeScript

In TypeScript, both import type { X } and import { type X } exist to import types that will be completely erased during compilation, preventing type-only imports from being emitted as runtime dependencies in the final JavaScript output. The primary difference lies in their scope and flexibility: declaration-level import type enforces that every single identifier imported in that statement is strictly a type, whereas inline import { type X } allows you to mix runtime values and compile-time types within a single import statement.

Declaration-Level: import type { X }

Introduced in TypeScript 3.8, declaration-level type-only imports apply the type keyword at the beginning of the import statement:

import type { User, Role } from './user';

When you use this syntax, the entire statement is locked to type space. You cannot import any runtime values (such as functions, classes as instances, or constants) using this statement. If you attempt to access an imported identifier as a value in your code, TypeScript will throw a compiler error (TS1361: 'X' cannot be used as a value because it was imported using 'import type').

If you needed both a runtime function and a type from the same module in earlier versions of TypeScript, you were forced to write two separate import statements:

import type { User } from './user';
import { getUser } from './user';

Inline-Level: import { type X }

Introduced in TypeScript 4.5, inline type imports (or type modifier imports) allow the type prefix to be placed on individual specifiers inside the import clause:

import { getUser, type User } from './user';

This syntax solves the need for duplicate import declarations. Here, getUser is imported as a runtime value, while User is imported strictly as a type.

You can also use this syntax with default imports or namespace imports:

import defaultFunction, { type CustomType } from './module';

Compiler Emit and Output Differences

At compile time, both forms result in the exact same output regarding type erasure. The TypeScript compiler (or transpilers like Babel, esbuild, and SWC) strips out all specifiers marked with type.

  • With import type { X }: The entire import statement is stripped from the compiled JavaScript file, ensuring that the imported module is never loaded at runtime.

  • With import { type X, Y }: The compiler strips only X. If Y remains, the resulting JavaScript output will be:

    import { Y } from './module';

  • With import { type X }: If all specifiers within an inline import are prefixed with type, the transpiler will strip the entire import statement completely, yielding the exact same compiled output as import type { X }.

Summary of Use Cases

  • Use import type { X } when you are importing only types, interfaces, or type aliases from a module and want to guarantee that no runtime code is ever inadvertently bundled from that file.
  • Use import { type X } when you are consuming both runtime values (functions, components, variables) and type declarations from the same source file and want cleaner, single-line imports.
