Importing and Typing WebAssembly in TypeScript

Integrating WebAssembly (Wasm) into TypeScript requires bridging the gap between binary execution and static type checking. While WebAssembly executes compiled code from languages like Rust, C++, or AssemblyScript at near-native speeds, TypeScript needs structural definitions to validate function signatures, memory imports, and returned values. This article covers how to import Wasm binaries into TypeScript projects, generate ambient type declarations, configure modern bundlers, and use automated tooling for seamless type safety.

Native Fetch and Manual Type Definitions

By default, the TypeScript compiler does not know the internal exports of a .wasm file. When using the standard WebAssembly JavaScript API, modules are loaded asynchronously, and their types must be explicitly defined using custom TypeScript interfaces.

// Define the exports provided by your WebAssembly module
interface MathWasmExports {
  add(a: number, b: number): number;
  memory: WebAssembly.Memory;
}

async function loadWasm(url: string): Promise<MathWasmExports> {
  const response = await fetch(url);
  const { instance } = await WebAssembly.instantiateStreaming(response);
  
  // Cast the exports to the typed interface
  return instance.exports as unknown as MathWasmExports;
}

// Usage
const wasm = await loadWasm('/math.wasm');
console.log(wasm.add(5, 10));

Direct Imports via Bundlers

Modern bundlers like Webpack 5 and Vite allow importing .wasm files directly as ES modules. To make TypeScript recognize these imports without throwing compilation errors (such as TS2307: Cannot find module), you must declare ambient modules using a declaration file (e.g., wasm.d.ts).

Generic Module Declaration

For basic setups where module exports are not identical across all files, you can declare a generic module pattern in your declarations directory:

// wasm.d.ts
declare module "*.wasm" {
  const init: (imports?: WebAssembly.Imports) => Promise<WebAssembly.Instance>;
  export default init;
}

Module-Specific Declarations

For precise type safety, declare the exact module path and export its specific function signatures:

// math-wasm.d.ts
declare module "*math.wasm" {
  export function add(a: number, b: number): number;
  export function subtract(a: number, b: number): number;
}

Once declared, you can import the Wasm module directly into your TypeScript code:

import { add, subtract } from "./math.wasm";

const result = add(10, 20);

Automated Typing with wasm-pack and wasm-bindgen

When compiling higher-level languages like Rust to WebAssembly, manual type declarations can become out of sync. Tools such as wasm-pack and wasm-bindgen automate this workflow by parsing the source code and automatically generating a JavaScript wrapper along with matching .d.ts definition files.

  1. Compilation: Running wasm-pack build --target web generates a pkg/ directory containing:
    • The compiled .wasm binary.
    • A .js JavaScript loader script.
    • A .d.ts TypeScript definitions file mapping Rust structs and functions to TypeScript types.
  2. Importing the Generated Package:
import init, { greet, calculate_hash } from './pkg/my_wasm_library';

async function run() {
  // Initialize the Wasm memory and instantiate the module
  await init();

  // Full IDE autocompletion and type checking are now active
  greet("TypeScript Developer");
  const hash: string = calculate_hash(new Uint8Array([1, 2, 3]));
}

run();

Configuring tsconfig.json

Ensure your tsconfig.json includes the declaration files by either placing them in the root source directory or explicitly referencing them in the include array:

{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true
  },
  "include": ["src/**/*", "types/**/*.d.ts"]
}

Setting moduleResolution to bundler or node16/nodenext ensures compatibility with modern module systems handling binary assets.
