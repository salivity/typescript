How to Write TypeScript Compiler API Transformers

This article provides a comprehensive guide to authoring custom Abstract Syntax Tree (AST) transformer plugins using the TypeScript Compiler API. It covers the foundational architecture of the TypeScript transformer pipeline, details how to traverse and modify AST nodes using the visitor pattern, demonstrates a complete code example that alters TypeScript code at compile time, and explains how to integrate your custom transformer into modern build workflows.

Understanding the Transformer Architecture

The TypeScript compiler operates in distinct phases: parsing source text into tokens, constructing an Abstract Syntax Tree (AST), binding symbols, type-checking, and emitting output (JavaScript and declaration files).

Custom transformers hook directly into the emitter phase. They take an AST as input, traverse its nodes, and return a modified AST before the final code generation occurs. This allows you to remove debugging code, inline compile-time constants, inject logging, or implement custom domain-specific syntax transformations.

The Transformer Factory Pattern

A custom transformer is implemented as a higher-order function known as a TransformerFactory. Its structure follows a three-tier hierarchy:

  1. Outer Factory: Accepts compiler options and plugin configurations.
  2. Context Factory: Receives the ts.TransformationContext, which contains compiler state and the AST node factory (context.factory).
  3. Node Transformer: Receives the root ts.SourceFile (or any ts.Node) and returns the transformed node.
import ts from "typescript";

export default function customTransformer(pluginOptions?: any): ts.TransformerFactory<ts.SourceFile> {
  return (context: ts.TransformationContext) => {
    return (sourceFile: ts.SourceFile) => {
      // Transformation logic executes here
      return sourceFile;
    };
  };
}

Implementing the Visitor Pattern

To inspect and alter nodes, TypeScript provides the ts.visitEachChild utility, which facilitates recursive tree traversal using the visitor pattern.

Within the visitor function:

  • Return the original node to leave it unchanged.
  • Return undefined to delete the node from the AST.
  • Return a new or modified node (created using context.factory) to replace it.

Step-by-Step Implementation: Removing console.log Calls

The following complete example demonstrates a transformer that finds all console.log(...) calls and replaces them with an empty statement or strips them out completely.

import ts from "typescript";

export default function removeConsoleTransformer(): ts.TransformerFactory<ts.SourceFile> {
  return (context: ts.TransformationContext) => {
    const { factory } = context;

    return (sourceFile: ts.SourceFile) => {
      const visitor = (node: ts.Node): ts.Node | undefined => {
        // Check if the node is an expression statement containing a call expression
        if (ts.isExpressionStatement(node) && ts.isCallExpression(node.expression)) {
          const call = node.expression;
          const expression = call.expression;

          // Check if the call target is `console.log`
          if (
            ts.isPropertyAccessExpression(expression) &&
            ts.isIdentifier(expression.expression) &&
            expression.expression.text === "console" &&
            expression.name.text === "log"
          ) {
            // Drop the node entirely
            return undefined;
          }
        }

        // Continue walking through child nodes
        return ts.visitEachChild(node, visitor, context);
      };

      return ts.visitNode(sourceFile, visitor) as ts.SourceFile;
    };
  };
}

Creating New Nodes with the Node Factory

When replacing nodes rather than removing them, always use context.factory methods rather than instantiating AST objects manually. This ensures internal node flags, parent pointers, and synthetic ranges are handled correctly.

For example, to replace an identifier named __VERSION__ with a literal string value:

if (ts.isIdentifier(node) && node.text === "__VERSION__") {
  return context.factory.createStringLiteral("1.0.0");
}

Running Custom Transformers

The standard TypeScript CLI (tsc) does not support pluggable compiler transformers natively via tsconfig.json. To execute custom transformers, use one of the following approaches:

1. Using ts-patch

ts-patch extends tsc to support the plugins field directly in tsconfig.json.

Install ts-patch:

npm install --save-dev ts-patch
npx ts-patch install

Configure tsconfig.json:

{
  "compilerOptions": {
    "plugins": [
      {
        "transform": "./path/to/transformer.js"
      }
    ]
  }
}

2. Using Webpack (ts-loader)

If using Webpack, pass the transformer into ts-loader options:

const removeConsoleTransformer = require("./transformer").default;

module.exports = {
  module: {
    rules: [
      {
        test: /\.tsx?$/,
        loader: "ts-loader",
        options: {
          getCustomTransformers: () => ({
            before: [removeConsoleTransformer()],
          }),
        },
      },
    ],
  },
};

3. Programmatic Invocation via ts.transpileModule

For testing transformers in isolation, use the compiler's programmatic API:

const source = `console.log("drop me"); const x = 42;`;

const result = ts.transpileModule(source, {
  compilerOptions: { module: ts.ModuleKind.CommonJS },
  transformers: {
    before: [removeConsoleTransformer()],
  },
});

console.log(result.outputText);
// Output: const x = 42;\n
