TypeScript Variadic Tuple Types and Spread Elements

Variadic tuple types in TypeScript allow developers to model function arguments and array structures with dynamic, generic lengths while maintaining strict type safety. Introduced in TypeScript 4.0, this feature transforms how the spread operator (...) behaves inside tuple types, permitting generic spreads anywhere within a tuple definition. This article explains what variadic tuple types are, how they resolve spread elements at compile time, and how to use them effectively for complex array manipulations and higher-order functions.

What Are Variadic Tuple Types?

Before TypeScript 4.0, tuple types were rigid. Spread elements within tuples could only represent fixed types or had to be the final element representing an open-ended array (such as [string, ...number[]]). Generic types could not be spread inside tuples, making it impossible to accurately type functions that concatenated or reshaped tuples of unknown lengths.

Variadic tuple types resolve this limitation by allowing generic type parameters to be spread inside tuple definitions. When a generic type parameter extends an array or tuple type (T extends unknown[]), TypeScript treats ...T as an actual variable sequence of types rather than flattening it into a generic union array type.

How Spread Elements Are Handled

TypeScript resolves spread elements in variadic tuples by matching fixed types around dynamic, generic segments. Spread elements can be placed at the beginning, middle, or end of a tuple.

1. Preserving Precise Types Across Concatenation

When two generic tuples are spread together, TypeScript retains the exact order and types of each element rather than collapsing them:

type Concat<T extends unknown[], U extends unknown[]> = [...T, ...U];

type Result = Concat<[number, string], [boolean]>;
// Equivalent to: [number, string, boolean]

Without variadic tuple types, spreading generic arrays would yield (number | string | boolean)[], losing element order and array length information.

2. Spreads in Any Position

Spread elements are not restricted to the end of a tuple. TypeScript allows leading and middle spreads, provided there is at most one unbounded spread element:

// Leading spread
type Prepend<T extends unknown[], Head> = [Head, ...T];
type WithString = Prepend<[number, boolean], string>;
// [string, number, boolean]

// Middle spread
type Sandwiched<T extends unknown[]> = [string, ...T, number];
type Core = Sandwiched<[boolean, boolean]>;
// [string, boolean, boolean, number]

TypeScript uses the fixed elements at the boundaries to infer types correctly, even when the middle spread is of dynamic length.

3. Constraints on Multiple Spreads

TypeScript permits multiple spread operations within a single tuple only if the types being spread are bounded (known fixed-length tuples). If an unbounded or rest array type (such as string[]) is included, no other rest or open-ended spread can follow it:

// Valid: multiple bounded spreads
type Merge<A extends unknown[], B extends unknown[]> = [...A, ...B];

// Invalid: TypeScript cannot determine where the first rest ends
type InvalidSpread<T extends unknown[]> = [...T, ...string[], ...T];
// Error: A rest element cannot follow another rest element.

Practical Application: Strongly Typed Function Signatures

Variadic tuple types are widely used in higher-order functions, function composition, and curry patterns. They allow functions to accept and pass through parameter lists while preserving exact parameter types and order:

function partialCall<T extends unknown[], U extends unknown[], R>(
  fn: (...args: [...T, ...U]) => R,
  ...headArgs: T
) {
  return (...tailArgs: U): R => fn(...headArgs, ...tailArgs);
}

const add = (a: number, b: string, c: boolean) => `${a} - ${b} - ${c}`;
const partial = partialCall(add, 42); 
// Inferred signature: (tailArgs_0: string, tailArgs_1: boolean) => string

In this pattern, TypeScript infers T from headArgs and computes the remaining required arguments U for the returned function, guaranteeing end-to-end type safety.
