How Parameter Decorators Work in TypeScript

Parameter decorators in experimental TypeScript allow developers to introspect and record metadata about specific function or method parameters within a class declaration. While they do not directly intercept or modify parameter values at runtime, they provide a hook to capture parameter indexes and associate them with metadata, commonly enabling features like dependency injection, parameter validation, and routing in modern application frameworks.

The Anatomy of a Parameter Decorator

A parameter decorator is declared as a function that accepts three specific arguments:

  1. target: The prototype of the class for an instance member, or the constructor function itself for a static member.
  2. propertyKey: The name of the member (method) where the parameter is defined, represented as a string or symbol. For constructor parameters, this value is undefined.
  3. parameterIndex: A zero-based number indicating the ordinal position of the parameter in the function’s parameter list.

The return value of a parameter decorator is ignored by the TypeScript runtime. Consequently, a parameter decorator cannot replace the parameter or wrap its execution directly.

function LogParameter(target: Object, propertyKey: string | symbol | undefined, parameterIndex: number) {
  console.log(`Method: ${String(propertyKey)}, Parameter Index: ${parameterIndex}`);
}

class UserService {
  getUser(@LogParameter id: string) {
    return `User: ${id}`;
  }
}

Compiler Configuration

To use experimental parameter decorators, you must explicitly enable the feature in your tsconfig.json:

{
  "compilerOptions": {
    "target": "ES6",
    "experimentalDecorators": true,
    "emitDecoratorMetadata": true
  }
}

The emitDecoratorMetadata flag works with reflection libraries like reflect-metadata to serialize design-time type information, allowing decorators to inspect parameter types at runtime.

Execution Timing and Metadata Storage

Parameter decorators run only once when the class is initially defined, not when the decorated method is executed. Because the return value is ignored, their primary mechanism is registering metadata using the Reflection API.

Typically, a parameter decorator marks an index with specific metadata, which is later read by a corresponding method or class decorator during execution.

import "reflect-metadata";

const REQUIRED_METADATA_KEY = Symbol("required");

function Required(target: Object, propertyKey: string | symbol | undefined, parameterIndex: number) {
  const existingRequiredParameters: number[] = 
    Reflect.getOwnMetadata(REQUIRED_METADATA_KEY, target, propertyKey!) || [];
  
  existingRequiredParameters.push(parameterIndex);
  
  Reflect.defineMetadata(REQUIRED_METADATA_KEY, existingRequiredParameters, target, propertyKey!);
}

function Validate(target: any, propertyKey: string, descriptor: PropertyDescriptor) {
  const originalMethod = descriptor.value;

  descriptor.value = function (...args: any[]) {
    const requiredParameters: number[] = 
      Reflect.getOwnMetadata(REQUIRED_METADATA_KEY, target, propertyKey);

    if (requiredParameters) {
      for (const parameterIndex of requiredParameters) {
        if (args[parameterIndex] === undefined || args[parameterIndex] === null) {
          throw new Error(`Missing required argument at position ${parameterIndex}`);
        }
      }
    }

    return originalMethod.apply(this, args);
  };
}

class OrderService {
  @Validate
  createOrder(@Required orderId: string, @Required amount: number) {
    return `Order ${orderId} created for $${amount}`;
  }
}

Decorator Evaluation Order

When a method contains multiple decorators across its definition, TypeScript evaluates parameter decorators before the method decorator itself:

  1. Parameter decorators are evaluated in right-to-left order based on their index.
  2. The enclosing method decorator is evaluated after all its parameter decorators have executed.

This sequence guarantees that all parameter-level metadata is fully attached to the class prototype before the method decorator inspects it.
