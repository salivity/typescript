Enforcing Integer vs Float in TypeScript

TypeScript does not natively distinguish between integers and floating-point numbers because it inherits JavaScript's single, IEEE 754 double-precision number primitive. However, you can enforce this distinction at compile time using a technique known as branded types (nominal typing). By attaching unique type-level tags to the standard number primitive and restricting value creation via smart constructors or type guards, TypeScript can prevent floats from being passed where integers are required, and vice versa.

The Native Limitation

In standard TypeScript, both whole numbers and decimals share the number type:

let count: number = 42;
let price: number = 19.99;

count = price; // Valid in TypeScript, even though price is a float

Because TypeScript's type system is structural, any value assignable to number satisfies any variable typed as number.

Solution: Branded Types

To distinguish between integers and floats at compile time, you can define branded types. A branded type intersects the primitive number with an uninstantiable object containing a unique tag:

declare const IntegerSymbol: unique symbol;
declare const FloatSymbol: unique symbol;

export type Integer = number & { readonly [IntegerSymbol]: true };
export type Float = number & { readonly [FloatSymbol]: true };

Because ordinary numbers lack these unique symbols, they cannot be assigned directly to variables typed as Integer or Float:

let id: Integer;

id = 10; // Compile error: Type 'number' is not assignable to type 'Integer'

Creating Safe Constructors and Guards

Since primitive numbers cannot be assigned directly to branded types, you enforce validation at runtime boundaries using type predicates or assertions:

export function isInteger(val: number): val is Integer {
  return Number.isInteger(val);
}

export function toInteger(val: number): Integer {
  if (!Number.isInteger(val)) {
    throw new TypeError(`Expected integer, received float: ${val}`);
  }
  return val as Integer;
}

export function toFloat(val: number): Float {
  if (Number.isInteger(val)) {
    throw new TypeError(`Expected float, received integer: ${val}`);
  }
  return val as Float;
}

Practical Compile-Time Enforcement

Once branded types are established, functions can mandate specific numerical variants. The TypeScript compiler will reject mismatched types before code execution:

function setPaginationLimit(limit: Integer): void {
  // Logic here
}

function applyTaxRate(rate: Float): void {
  // Logic here
}

const safeLimit = toInteger(25);
const safeRate = toFloat(0.08);

setPaginationLimit(safeLimit); // Compiles successfully
applyTaxRate(safeRate);         // Compiles successfully

setPaginationLimit(safeRate);  
// Compile error: Argument of type 'Float' is not assignable to parameter of type 'Integer'

setPaginationLimit(10);        
// Compile error: Argument of type 'number' is not assignable to parameter of type 'Integer'

Trade-offs and Limitations

While branded types enforce safety across function calls, basic arithmetic operations in TypeScript always widen back to the base number type:

const result = safeLimit + safeLimit; // Type is 'number', not 'Integer'

To maintain safety after arithmetic operations, results must be re-validated or cast through designated helper functions. Despite this limitation, branded types provide a reliable compile-time guarantee across domain models, database identifiers, and public API interfaces.
