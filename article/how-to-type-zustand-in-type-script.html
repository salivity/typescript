How to Type Zustand in TypeScript

This article provides a comprehensive guide on implementing TypeScript with Zustand, a lightweight and flexible global state management library for React. You will learn the recommended patterns for typing state values and action methods, applying middleware such as persist and devtools, structuring scalable applications using the slice pattern, and consuming state safely within your components.

Basic Store Typing

The standard approach to typing a Zustand store involves declaring a unified interface that defines both the state properties and the actions that modify them.

Zustand provides a curried version of the create function—invoked as create<T>()(...)—which allows TypeScript to properly infer types and avoid losing generic definitions:

import { create } from 'zustand';

interface UserState {
  username: string;
  isLoggedIn: boolean;
  login: (name: string) => void;
  logout: () => void;
}

export const useUserStore = create<UserState>()((set) => ({
  username: '',
  isLoggedIn: false,
  login: (name) => set({ username: name, isLoggedIn: true }),
  logout: () => set({ username: '', isLoggedIn: false }),
}));

Using the empty call create<UserState>()(...) ensures that your state interface is correctly bound to set, get, and the resulting hook without relying on loose parameter inference.

Typing Asynchronous Actions

Asynchronous functions fit naturally into Zustand store definitions. Define the return type of the async action as Promise<void> within the interface:

interface TodoState {
  todos: string[];
  loading: boolean;
  fetchTodos: () => Promise<void>;
}

export const useTodoStore = create<TodoState>()((set) => ({
  todos: [],
  loading: false,
  fetchTodos: async () => {
    set({ loading: true });
    try {
      const response = await fetch('/api/todos');
      const data = await response.json();
      set({ todos: data, loading: false });
    } catch {
      set({ loading: false });
    }
  },
}));

Adding Middleware with Types

When using middleware like devtools or persist, TypeScript requires specialized type definitions to properly compose the store's internal state. Zustand’s curried create syntax handles this composition seamlessly:

import { create } from 'zustand';
import { devtools, persist } from 'zustand/middleware';

interface SettingsState {
  theme: 'light' | 'dark';
  setTheme: (theme: 'light' | 'dark') => void;
}

export const useSettingsStore = create<SettingsState>()(
  devtools(
    persist(
      (set) => ({
        theme: 'light',
        setTheme: (theme) => set({ theme }),
      }),
      { name: 'settings-storage' }
    )
  )
);

By passing the generic SettingsState at the very start of the create<SettingsState>() call, both the devtools and persist middleware properly infer the inner action types and persistent configuration.

Typing the Slices Pattern

For larger applications, stores should be split into smaller slices using the StateCreator type. This utility takes the full store interface, optional middleware parameters, and the specific slice's shape.

import { create, StateCreator } from 'zustand';

interface AuthSlice {
  token: string | null;
  setToken: (token: string | null) => void;
}

interface ProfileSlice {
  name: string;
  setName: (name: string) => void;
}

// Combine all slice interfaces into one Root State
type AppStore = AuthSlice & ProfileSlice;

const createAuthSlice: StateCreator<AppStore, [], [], AuthSlice> = (set) => ({
  token: null,
  setToken: (token) => set({ token }),
});

const createProfileSlice: StateCreator<AppStore, [], [], ProfileSlice> = (set) => ({
  name: '',
  setName: (name) => set({ name }),
});

export const useAppStore = create<AppStore>()((...a) => ({
  ...createAuthSlice(...a),
  ...createProfileSlice(...a),
}));

The empty array arguments [], [] represent middleware mutators. If middleware is applied to the root store, these types are adjusted to reflect the active middlewares (such as [['zustand/devtools', never]]).

Consuming Typed Stores in Components

When consuming the store, TypeScript automatically infers the return type based on your selector function:

import React from 'react';
import { useUserStore } from './userStore';

export const UserProfile = () => {
  // TypeScript infers username as `string`
  const username = useUserStore((state) => state.username);
  
  // TypeScript infers logout as `() => void`
  const logout = useUserStore((state) => state.logout);

  return (
    <div>
      <p>Logged in as: {username}</p>
      <button onClick={logout}>Sign Out</button>
    </div>
  );
};

Selecting narrow slices of state via selectors prevents unnecessary component re-renders while preserving full type safety across your application.
