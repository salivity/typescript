Generator vs AsyncGenerator in TypeScript

In TypeScript, Generator and AsyncGenerator are built-in generic interfaces used to represent the return types of generator functions. While both interfaces allow execution to be paused and resumed using the yield keyword, Generator produces values synchronously using the standard iterator protocol, whereas AsyncGenerator handles asynchronous sequences by returning promises for each iterated value and supporting await expressions within its execution context.

Syntax and Function Declarations

The distinction between the two interfaces begins with how their corresponding functions are defined:

  • Generator is produced by a synchronous generator function declared with function*.
  • AsyncGenerator is produced by an asynchronous generator function declared with async function*.
// Synchronous Generator
function* syncNumberSequence(): Generator<number, void, unknown> {
  yield 1;
  yield 2;
}

// Asynchronous Generator
async function* asyncNumberSequence(): AsyncGenerator<number, void, unknown> {
  yield 1;
  await new Promise((resolve) => setTimeout(resolve, 100));
  yield 2;
}

The Interface Type Signatures

Both interfaces accept three generic parameters: Type<T, TReturn, TNext>.

  • T: The type of values returned by yield.
  • TReturn: The type of the final return value when the generator finishes execution.
  • TNext: The type accepted by the .next(value) method to pass data into the generator.

The fundamental structural difference lies in the return types of their iterator methods (next, return, and throw):

Generator<T, TReturn, TNext>

The standard Generator interface extends Iterator<T, TReturn, TNext> and Iterable<T>. Calling .next() returns a synchronous IteratorResult:

interface Generator<T = unknown, TReturn = any, TNext = unknown> {
  next(...args: [] | [TNext]): IteratorResult<T, TReturn>;
  return(value: TReturn): IteratorResult<T, TReturn>;
  throw(e: any): IteratorResult<T, TReturn>;
  [Symbol.iterator](): Generator<T, TReturn, TNext>;
}

The resulting object is { value: T, done: boolean } immediately accessible in memory.

AsyncGenerator<T, TReturn, TNext>

The AsyncGenerator interface extends AsyncIterator<T, TReturn, TNext> and AsyncIterable<T>. Calling .next() returns a Promise resolving to an IteratorResult:

interface AsyncGenerator<T = unknown, TReturn = any, TNext = unknown> {
  next(...args: [] | [TNext]): Promise<IteratorResult<T, TReturn>>;
  return(value: TReturn | PromiseLike<TReturn>): Promise<IteratorResult<T, TReturn>>;
  throw(e: any): Promise<IteratorResult<T, TReturn>>;
  [Symbol.asyncIterator](): AsyncGenerator<T, TReturn, TNext>;
}

Because every step returns a promise, handling values requires asynchronous resolution via .then() or await.

Execution and Capabilities

The internal and external execution models differ significantly:

1. Internal await Usage

An AsyncGenerator can pause execution waiting for asynchronous operations using await. Standard Generator functions cannot use the await keyword.

// Valid in AsyncGenerator
async function* fetchPaginatedData(urls: string[]): AsyncGenerator<string> {
  for (const url of urls) {
    const response = await fetch(url);
    const data = await response.text();
    yield data;
  }
}

2. Yielding Promises

When a synchronous Generator yields a promise, the yielded value type is simply Promise<T>, and the caller receives { value: Promise<T>, done: false }.

In an AsyncGenerator, yielding a promise unwraps it before handing the resolved value to the consumer, or resolves the promise created by .next().

Consumption: for...of vs for await...of

Because they implement different symbol protocols (Symbol.iterator versus Symbol.asyncIterator), they are consumed with different control structures:

  • Generator is consumed with a standard for...of loop:
for (const value of syncNumberSequence()) {
  console.log(value); // Synchronous logs
}
  • AsyncGenerator requires a for await...of loop within an asynchronous context:
for await (const value of asyncNumberSequence()) {
  console.log(value); // Logs after each promise resolves
}
