TypeScript Record vs Index Signature

In TypeScript, both the Record<Keys, Type> utility type and explicit index signatures ({ [key: KeyType]: ValueType }) allow developers to model dynamic, dictionary-like object structures. While both approaches often achieve identical runtime results, they differ fundamentally in how they handle key types, interfaces, code readability, and integration with union types. This guide examines the key differences, capabilities, and best use cases for each approach.

Syntax Comparison

An explicit index signature defines the type of keys and values using bracket syntax:

type UserScores = {
  [username: string]: number;
};

interface UserAges {
  [username: string]: number;
}

The Record utility type is a built-in generic mapped type that abstracts this pattern:

type UserScores = Record<string, number>;

Under the hood, TypeScript defines Record using a mapped type: type Record<K extends keyof any, T> = { [P in K]: T; }.

Handling Union Types

The most significant functional difference between the two is how they handle literal union types.

An explicit index signature cannot directly accept a union of string literals as its key type:

// This will throw a syntax error:
// "An index signature parameter type cannot be a literal type or a union type."
type PageNav = {
  [key: 'home' | 'about' | 'contact']: string;
};

To use a union with explicit syntax, you must convert it into a mapped type:

type PageNav = {
  [key in 'home' | 'about' | 'contact']: string;
};

In contrast, Record natively handles union types without modifying syntax:

type Pages = 'home' | 'about' | 'contact';
type PageNav = Record<Pages, string>;

When you use Record with a union of keys, TypeScript ensures that every key in the union is present in the object, providing compile-time exhaustiveness checks.

Interface Integration

Index signatures can be declared directly inside an interface:

interface CacheStorage {
  [key: string]: ArrayBuffer;
  clear(): void;
}

Record is a type alias. It cannot be used directly as an interface declaration, though an interface can extend a Record instance if the keys are broad types (string, number, or symbol):

interface CacheStorage extends Record<string, ArrayBuffer> {
  clear(): void;
}

However, an interface cannot extend a Record that uses a union of literals (e.g., Record<'a' | 'b', number>), because interfaces must describe fixed object shapes rather than mapped types.

Self-Documenting Key Names

Index signatures allow you to name the key parameter, which provides semantic context to developers reading the code:

type UserDirectory = {
  [userId: string]: UserProfile;
};

Here, userId clarifies what the string represents. The Record type does not support semantic naming for generic keys:

type UserDirectory = Record<string, UserProfile>;

In this case, the key is simply string, which does not provide descriptive context.

Permitted Key Types

Index signatures restrict key types to primitive primitives: string, number, symbol, or template literal types (${string}-${string}).

The Record type accepts any type that extends keyof any (i.e., string | number | symbol). Because it leverages mapped types, it easily accepts complex conditional types, key sets derived via keyof, and template literal unions.

Summary: When to Use Which

Use Record<Keys, Type> when:

  • Mapping specific string, number, or symbol unions to a value type.
  • Requiring compile-time exhaustiveness to ensure all union keys are defined.
  • Writing generic utility types or functions where concise, functional syntax is preferred.

Use an explicit index signature when:

  • Defining types inside an interface.
  • Mixing fixed properties with dynamic properties within the same structure.
  • Providing descriptive names for the key parameter (such as [productId: string]) to enhance code readability.
