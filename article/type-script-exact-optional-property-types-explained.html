TypeScript exactOptionalPropertyTypes Explained

TypeScript’s exactOptionalPropertyTypes compiler flag enforces a strict distinction between an optional property that is missing from an object and an optional property that is present with the value undefined. By default, TypeScript treats optional properties as implicitly accepting undefined, meaning you can explicitly assign undefined to an optional field. Enabling this flag prevents that behavior, requiring properties to be defined explicitly as union types with undefined if you want to assign undefined directly.

By default, when you declare an optional property on an interface or type:

interface UserProfile {
  bio?: string;
}

TypeScript allows three distinct states:

  1. The property is omitted: {}
  2. The property has a valid value: { bio: "Developer" }
  3. The property explicitly holds undefined: { bio: undefined }

Without exactOptionalPropertyTypes, TypeScript types bio internally as string | undefined. While this is convenient, it can lead to bugs because runtime checks such as 'bio' in user, user.hasOwnProperty('bio'), or Object.keys(user) yield different results depending on whether the key is missing or set to undefined.

When you enable "exactOptionalPropertyTypes": true in your tsconfig.json, TypeScript changes how it handles optional fields. An optional field prop?: T strictly means the property can either be present with the exact type T, or omitted entirely.

Under this flag, assigning undefined explicitly results in a compile-time error:

// With exactOptionalPropertyTypes: true
const profile: UserProfile = {
  bio: undefined // Error: Type 'undefined' is not assignable to type 'string'.
};

To explicitly allow a property to be passed with an undefined value when this flag is active, you must include undefined in the type definition explicitly:

interface UserProfile {
  bio?: string | undefined;
}

// Now this is valid:
const profile: UserProfile = {
  bio: undefined
};

This distinction allows TypeScript to accurately reflect runtime behavior. With exactOptionalPropertyTypes, prop?: string guarantees that if the property exists on the object, it is guaranteed to be a string, preventing accidental property creation with undefined values.
