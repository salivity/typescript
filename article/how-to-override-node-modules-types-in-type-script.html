How to Override node_modules Types in TypeScript

Third-party dependencies in node_modules frequently contain incomplete, incorrect, or missing type definitions. This guide covers how to override and extend these types locally within your project using TypeScript’s declaration merging, ambient module declarations, tsconfig.json path mapping, and package patching tools.

1. Extending Existing Types via Declaration Merging

When a library’s exported interface is simply missing a property, declaration merging is the cleanest solution. TypeScript merges multiple interface definitions with the same name in the same namespace or module.

  1. Ensure your tsconfig.json includes custom type definitions:
{
  "compilerOptions": {
    "typeRoots": ["./node_modules/@types", "./src/types"]
  },
  "include": ["src/**/*"]
}
  1. Create a declaration file (e.g., src/types/express.d.ts) to extend the module:
import 'express';

declare module 'express' {
  export interface Request {
    user?: {
      id: string;
      role: string;
    };
  }
}

The import 'express' statement is critical: it turns the file into a module rather than a global script, allowing declare module to augment the existing package rather than overwrite it completely.

2. Completely Replacing Module Declarations

If an entire module lacks types or has fundamentally incorrect declarations that cannot be merged, you can replace the module declaration locally.

Create an ambient declaration file (e.g., src/types/untyped-module.d.ts):

declare module 'untyped-module' {
  export interface CustomOptions {
    retries: number;
    timeout: number;
  }

  export function initialize(options: CustomOptions): boolean;
  export default function run(): void;
}

Do not use top-level import or export statements outside of declare module in this file, or TypeScript will treat it as a local module instead of an ambient declaration.

3. Redirecting Types Using tsconfig.json Paths

To override an entire @types package with a local file, redirect TypeScript's module resolution using the paths compiler option.

  1. Create a local type definition file, such as src/types/overrides/some-library.d.ts.
  2. Configure tsconfig.json:
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "some-library": ["src/types/overrides/some-library.d.ts"]
    }
  }
}

TypeScript will now resolve all imports of "some-library" to your local file instead of the package's bundled types or @types/some-library.

4. Patching Bundled Types with patch-package

When a package ships with internal .d.ts files that are tightly coupled to its implementation, declaration merging may fail to modify non-exported or nested types. In these scenarios, use patch-package to edit the files directly inside node_modules and persist changes across installations.

  1. Install patch-package:
npm install patch-package --save-dev

  1. Navigate into node_modules/<package-name>/ and modify the target .d.ts file directly to correct the types.

  2. Generate a patch:

npx patch-package <package-name>
  1. Add a postinstall script to your package.json to ensure the patch is automatically applied on every install:
{
  "scripts": {
    "postinstall": "patch-package"
  }
}
