How to Type Rest Parameters in TypeScript

Rest parameters in TypeScript allow functions to accept an indefinite number of arguments represented as a single array. To annotate rest parameters properly, you assign them an array type or a tuple type, depending on whether the arguments are uniform or follow a specific sequential pattern. This guide explains the syntax, type rules, and practical examples for annotating rest parameters effectively in TypeScript.

Basic Array Annotations

Because rest parameters collect remaining function arguments into an array, their type annotation must always be an array type. You can use standard bracket notation (Type[]) or generic array notation (Array<Type>).

function sumAll(...numbers: number[]): number {
  return numbers.reduce((total, num) => total + num, 0);
}

sumAll(1, 2, 3); // Valid
sumAll(10, 20); // Valid
// sumAll(1, "two"); // Error: Argument of type 'string' is not assignable to parameter of type 'number'.

In this example, ...numbers: number[] specifies that the function can take any number of numeric arguments, all of which are accessible inside the function as an array of numbers.

Tuple Type Annotations

When a function requires an exact number of arguments of specific types, or a set pattern of arguments, you can type the rest parameter as a tuple.

function setCoordinates(...coords: [number, number, number?]): void {
  const [x, y, z] = coords;
  console.log(`X: ${x}, Y: ${y}, Z: ${z ?? 0}`);
}

setCoordinates(10, 20);       // Valid: optional third parameter omitted
setCoordinates(10, 20, 30);   // Valid
// setCoordinates(10);        // Error: Expected at least 2 arguments, but got 1.

Tuples allow you to enforce argument length, assign different types to specific positions, and mark trailing elements as optional using the ? modifier.

Leading and Middle Rest Elements in Tuples

TypeScript allows rest elements to appear anywhere within a tuple type, provided they are followed by strongly typed elements or are fixed at the end. This allows for flexible API designs where variable arguments precede fixed arguments.

function sendMessage(
  ...args: [prefix: string, ...messages: string[], suffix: string]
): void {
  const [prefix, ...rest] = args;
  const suffix = rest.pop();
  console.log(prefix, rest.join(" "), suffix);
}

sendMessage("START:", "Hello", "World", "END");

Key Rules for Rest Parameters

  1. Must be the last parameter: A rest parameter must always be the final parameter in the function's parameter list (e.g., (first: string, ...rest: number[])).
  2. Must be an array-like type: Providing a non-array type, such as ...args: number, will result in a compiler error. It must be number[], Array<number>, or a tuple [number, ...].
  3. Implicit any[] without strict mode: If noImplicitAny is disabled and no annotation is provided, TypeScript defaults the rest parameter type to any[]. Under strict mode, the annotation is required.
