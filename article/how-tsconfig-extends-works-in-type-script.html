How tsconfig extends Works in TypeScript

Configuration inheritance in TypeScript allows developers to share common compiler settings across multiple projects or configurations using the extends property in tsconfig.json. This article explains how the extends field works, how TypeScript locates base configuration files, how properties and options are merged or overwritten, and how relative file paths are resolved across inherited files.

The extends Property Syntax

The extends field accepts a string containing a path to another configuration file from which you want to inherit settings. This path can be a relative file path, an absolute path, or a package resolved via Node.js module resolution.

{
  "extends": "./tsconfig.base.json",
  "compilerOptions": {
    "strict": true
  }
}

You can also reference configurations distributed as npm packages, such as the official TypeScript bases:

{
  "extends": "@tsconfig/node20/tsconfig.json"
}

Since TypeScript 5.0, extends can also accept an array of file paths. Configurations are loaded and merged from left to right, meaning files listed later in the array override properties set by earlier files.

{
  "extends": ["./tsconfig.base.json", "./tsconfig.strict.json"]
}

Merging and Overriding Rules

When one configuration inherits from another, TypeScript applies specific merging strategies depending on the property type:

1. compilerOptions Merging

Objects under compilerOptions are shallowly merged. The derived configuration inherits all options from the base file, but any compiler option explicitly defined in the child configuration will overwrite the option defined in the base configuration.

  • Base config: Defines "target": "ES6" and "noImplicitAny": true.
  • Child config: Defines "target": "ES2022".
  • Result: "target": "ES2022" and "noImplicitAny": true.

2. Top-Level Array Properties

Top-level array fields—such as include, exclude, and files—do not merge. Instead, the derived configuration completely replaces the array defined in the base configuration.

  • Base config: "exclude": ["node_modules", "dist"]
  • Child config: "exclude": ["src/legacy"]
  • Result: "exclude": ["src/legacy"] (node_modules and dist are not included).

If the child configuration omits these fields entirely, it retains the base configuration's values.

3. Circular Inheritance

TypeScript checks for circular dependencies in the inheritance chain. If file A extends file B, and file B directly or indirectly extends file A, the TypeScript compiler raises an error and halts execution.

Path Resolution in Inherited Configurations

Understanding how relative paths resolve is critical to preventing file resolution bugs:

  • File selection (include, exclude, files): Relative paths in these arrays are always resolved relative to the specific tsconfig.json file in which they are written, not the inheriting file.
  • Compiler options paths (outDir, rootDir, baseUrl): Relative paths defined inside compilerOptions are also resolved relative to the configuration file in which they are declared. If defined in the base file, they point to locations relative to that base file unless explicitly overridden by the child configuration.
