TypeScript No-Infer Pattern Explained

The no-infer pattern in TypeScript is a type manipulation technique used to prevent the compiler from inferring a generic type argument from specific function parameters. Before TypeScript 5.4 introduced the built-in NoInfer<T> utility type, developers relied on conditional type workarounds like [T][T extends any ? 0 : never] to strip inference candidates. This article explains why inference blocking is necessary, deconstructs how the tuple-indexing trick works under the hood, and examines how it controls generic type resolution.

The Problem: Unwanted Type Inference

By default, when a generic parameter T appears in multiple function arguments, TypeScript collects candidate types from all corresponding call sites and merges them into a union or a common supertype.

Consider an equality assertion function:

function assertEqual<T>(actual: T, expected: T): void {
  // ...
}

assertEqual("admin", "guest"); // T is inferred as "admin" | "guest"

In this scenario, rather than flagging an error because "guest" is not "admin", TypeScript infers T as "admin" | "guest". The function accepts the call because both arguments satisfy the unified type. To fix this, you need TypeScript to infer T exclusively from actual, treating expected purely as a consumer of T.

How [T][T extends any ? 0 : never] Works

The pattern is typically defined as a custom utility type:

type NoInfer<T> = [T][T extends any ? 0 : never];

Applying it to the function changes the inference behavior:

function assertEqual<T>(actual: T, expected: NoInfer<T>): void {
  // ...
}

assertEqual("admin", "guest"); 
// Error: Argument of type '"guest"' is not assignable to parameter of type '"admin"'.

This trick relies on three key mechanics of the TypeScript type checker:

  1. Tuple Wrapping ([T]): Wrapping T in a single-element tuple type creates an array-like structure where index 0 corresponds to T.
  2. Distributive Conditional Indexing (T extends any ? 0 : never): Because T is a "naked" type parameter in the conditional type, the check T extends any is distributive. Even though T always extends any and evaluates to 0, TypeScript delays evaluating conditional types that depend on unresolved generic parameters during the initial type inference phase.
  3. Inference Lowering: TypeScript only infers generic parameters from positions where the type structure is statically inspectable. Because accessing [T][...] involves a deferred conditional index type, the compiler considers this position non-inferrable. As a result, it skips expected when calculating candidates for T.

Once T is determined from other non-blocked parameters (like actual), the compiler resolves T extends any ? 0 : never to 0, accesses index 0 of [T], and evaluates the argument type back to T.

Built-in Support in Modern TypeScript

Starting in TypeScript 5.4, the compiler includes an intrinsic NoInfer<T> utility type. The native implementation accomplishes the exact same goal without relying on deferred conditional indexing hacks:

function assertEqual<T>(actual: T, expected: NoInfer<T>): void {
  // Native implementation, no custom type definition needed
}

While modern codebases should use the built-in NoInfer<T>, the [T][T extends any ? 0 : never] pattern remains an important idiom in TypeScript's history, showcasing how conditional types and deferred evaluation can manipulate compiler inference rules.
