Using JSDoc @typedef for Custom Objects in TypeScript

The @typedef tag in JSDoc allows developers to create reusable custom object types directly in source code comments, which TypeScript natively understands and checks. This approach bridges the gap between JavaScript and TypeScript by providing robust type safety, IntelliSense, and inline documentation without requiring dedicated TypeScript compilation steps or .ts files. This guide explains how to declare custom object definitions using @typedef, annotate their properties, and apply them across your project.

Basic Syntax of @typedef for Objects

To define a custom object type, pair the @typedef tag with the {Object} (or {object}) type annotation, followed by your chosen name for the new type. You then define the object's fields using subsequent @property (or @prop) tags.

/**
 * @typedef {Object} UserProfile
 * @property {number} id - The unique identifier for the user.
 * @property {string} username - The user's handle.
 * @property {string} email - The user's primary contact email.
 * @property {boolean} isActive - Whether the account is active.
 */

TypeScript registers UserProfile in its type system just as it would an interface or type alias declared in standard TypeScript syntax.

Handling Optional Properties and Default Values

Optional properties are represented by wrapping the property name in square brackets []. You can also specify default values within these brackets.

/**
 * @typedef {Object} DatabaseConfig
 * @property {string} host - Host address of the database.
 * @property {number} port - Connection port.
 * @property {string} [username] - Optional username.
 * @property {number} [timeout=5000] - Connection timeout in milliseconds.
 */

In the example above, TypeScript marks username as string | undefined and timeout as an optional number.

Defining Nested Custom Objects

You can define nested properties using dot notation on the @property name, or by chaining multiple @typedef declarations together.

Method 1: Dot Notation

/**
 * @typedef {Object} Order
 * @property {string} orderId
 * @property {Object} shippingAddress
 * @property {string} shippingAddress.street
 * @property {string} shippingAddress.city
 * @property {string} shippingAddress.postalCode
 */

Method 2: Composing Typedefs

/**
 * @typedef {Object} Address
 * @property {string} street
 * @property {string} city
 * @property {string} postalCode
 */

/**
 * @typedef {Object} Order
 * @property {string} orderId
 * @property {Address} shippingAddress
 */

Using composed definitions is generally preferred for clarity, reusability, and modularity.

Applying Custom Types in Code

Once declared, the custom type can be referenced anywhere types are accepted in JSDoc annotations, such as with @type, @param, or @returns.

/**
 * Processes an incoming order.
 * @param {Order} order - The order to process.
 * @returns {Promise<boolean>} True if the processing succeeded.
 */
async function processOrder(order) {
  // TypeScript will provide autocompletion for order.shippingAddress.city
  console.log(`Shipping to: ${order.shippingAddress.city}`);
  return true;
}

/** @type {Order} */
const newOrder = {
  orderId: "ord-12345",
  shippingAddress: {
    street: "123 Main St",
    city: "Springfield",
    postalCode: "12345"
  }
};

If any mandatory property is omitted from newOrder, or if an invalid type is assigned, TypeScript flags the issue with a type error.

Importing and Exporting JSDoc Types

Custom types defined with @typedef in one file can be used in other files. In ES modules, TypeScript can import JSDoc types via the standard import syntax inside the type expression:

// in handlers.js

/**
 * @param {import('./types.js').UserProfile} user
 */
function displayUser(user) {
  console.log(user.username);
}

Alternatively, you can re-alias an imported type locally:

/** @typedef {import('./types.js').UserProfile} UserProfile */

/** @type {UserProfile} */
const currentUser = { id: 1, username: "dev1", email: "dev@example.com", isActive: true };

This modular structure allows teams to maintain strict type systems within vanilla JavaScript while harnessing the full diagnostic power of the TypeScript compiler.
