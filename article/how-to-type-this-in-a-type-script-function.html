How to Type this in a TypeScript Function

In JavaScript and TypeScript, the value of the this keyword is dynamic and determined at runtime by how a function is called. When writing standalone functions that rely on a specific execution context, leaving this untyped can lead to runtime errors or unsafe code. This article explains how to explicitly type the this context in standalone TypeScript functions, how to enforce that a function never uses this, and how the TypeScript compiler validates these execution contexts.

The Fake this Parameter

TypeScript allows you to declare the type of this by providing a mock first parameter named this in the function's parameter list. This parameter is strictly a compile-time construct; TypeScript erases it entirely when emitting JavaScript, meaning it does not alter the function's runtime signature or argument order.

interface DatabaseConnection {
  host: string;
  query(sql: string): void;
}

function runQuery(this: DatabaseConnection, sql: string): void {
  console.log(`Executing on host: ${this.host}`);
  this.query(sql);
}

In the compiled JavaScript output, the signature becomes function runQuery(sql).

Enforcing Calling Conventions

Once the this parameter is defined, TypeScript verifies that the caller provides the correct context. Attempting to call the function directly without an appropriate context results in a compile-time error.

// Error: The 'this' context of type 'void' is not assignable to method's 'this' of type 'DatabaseConnection'.
runQuery("SELECT * FROM users");

To invoke the function correctly, you must explicitly bind the context using Function.prototype.call, Function.prototype.apply, or Function.prototype.bind:

const db: DatabaseConnection = {
  host: "localhost",
  query: (sql) => console.log(`Running: ${sql}`)
};

// Valid: Context is explicitly provided
runQuery.call(db, "SELECT * FROM users");
runQuery.apply(db, ["SELECT * FROM users"]);

const boundQuery = runQuery.bind(db);
boundQuery("SELECT * FROM users");

You can also assign the function as a method to an object conforming to the declared interface:

const service = {
  host: "db.internal",
  query: (sql: string) => {},
  execute: runQuery
};

// Valid: 'service' matches the 'DatabaseConnection' interface
service.execute("SELECT * FROM logs");

Disallowing this Context

You can also use explicit typing to ensure a standalone function does not accidentally access any surrounding context. By typing this: void, TypeScript generates an error if the function body tries to access properties on this, or if a caller attempts to bind a context.

function calculateTax(this: void, amount: number, rate: number): number {
  // Error: Property 'rate' does not exist on type 'void'.
  // console.log(this.rate);

  return amount * rate;
}

Typing this in Callback Signatures

When designing higher-order functions or event listeners, explicitly typing the callback's this context informs consumers what data will be available inside their functions:

interface Button {
  element: HTMLElement;
  onClick(callback: (this: Button, event: MouseEvent) => void): void;
}

const submitBtn: Button = {
  element: document.createElement("button"),
  onClick(callback) {
    this.element.addEventListener("click", (e) => callback.call(this, e));
  }
};

submitBtn.onClick(function (this: Button, event) {
  // 'this' is recognized as 'Button'
  this.element.disabled = true;
});

Note: Arrow functions cannot have an explicit this parameter because they capture this lexically from their enclosing scope.

Compiler Configuration

To ensure strict checking across your codebase, enable the noImplicitThis compiler option (or strict: true) in your tsconfig.json. This flags any function where the type of this cannot be inferred, requiring you to provide an explicit type annotation whenever this is used.
