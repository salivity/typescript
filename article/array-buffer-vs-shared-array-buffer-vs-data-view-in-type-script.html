ArrayBuffer vs SharedArrayBuffer vs DataView in TypeScript

This article explains the core differences between ArrayBuffer, SharedArrayBuffer, and DataView typings in TypeScript. While all three deal with raw binary data in memory, TypeScript assigns distinct interfaces to each to enforce safe memory access, differentiate single-threaded versus multi-threaded memory, and govern how raw bytes are interpreted through typed views.

ArrayBuffer Typings

In TypeScript, ArrayBuffer represents a fixed-length, contiguous block of raw binary data. It acts strictly as an allocation of memory and does not provide direct read or write methods.

  • Interface and Properties: The ArrayBuffer interface provides metadata such as byteLength and the slice() method to clone a segment of the buffer.
  • Type Constraints: TypeScript does not allow direct indexing (e.g., buffer[0]). To read or mutate the data, you must wrap it in a typed array (such as Uint8Array) or a DataView.
  • Transferability: In browser and Node.js environments, an ArrayBuffer can be transferred across execution threads (like Web Workers) via structured cloning, which detaches the buffer from the sender.

SharedArrayBuffer Typings

SharedArrayBuffer represents raw binary data that can be accessed concurrently across multiple agents, such as Web Workers or the main thread, without detaching the memory during transfer.

  • Type Incompatibility with ArrayBuffer: Despite having an identical API surface (byteLength, slice()), TypeScript defines SharedArrayBuffer as a separate nominal interface. An ArrayBuffer cannot be assigned to a SharedArrayBuffer variable and vice versa.

  • Concurrency Safety: Because multiple threads can mutate the underlying memory simultaneously, TypeScript typings prevent it from being used in APIs expecting standard thread-isolated ArrayBuffer instances unless explicitly allowed. Operations on shared memory typically require the Atomics object to prevent race conditions.

  • The ArrayBufferLike Union: To accommodate functions that can accept either standard or shared memory buffers, TypeScript provides the utility type:

    type ArrayBufferLike = ArrayBuffer | SharedArrayBuffer;

    Most generic binary structures, including typed arrays, reference ArrayBufferLike for their underlying buffer property.

DataView Typings

Unlike ArrayBuffer and SharedArrayBuffer, DataView is not memory allocation; it is an accessor interface. It provides a low-level, heterogeneous view for reading and writing structured data within an ArrayBuffer or SharedArrayBuffer.

  • Interface and Properties: The DataView typing provides explicit getter and setter methods for various numeric types, such as getInt8(), getUint32(), setFloat64(), and others.
  • Endianness Control: Every multi-byte read and write method in the DataView interface accepts an optional littleEndian?: boolean parameter. This allows explicit handling of byte order, preventing architecture-dependent memory reads.
  • Arbitrary Alignment: While typed arrays (like Int32Array) require byte offsets to be multiples of their element size, DataView methods can read or write at any arbitrary byte offset within the buffer limits.
  • Structural Typing: DataView implements the ArrayBufferView interface, maintaining reference properties: buffer (typed as ArrayBufferLike), byteOffset, and byteLength.
