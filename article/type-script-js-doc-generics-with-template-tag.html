TypeScript JSDoc Generics with @template Tag

This article explains how the @template tag introduces TypeScript generics into standard JavaScript files using JSDoc annotations. By defining generic type parameters, developers can write reusable, type-safe functions, classes, and interfaces without a TypeScript compilation step, enabling IDEs to provide accurate type inference, autocomplete, and error checking directly in plain JavaScript.

Understanding the @template Tag

In TypeScript, generics allow you to write code that works with a variety of types rather than a single one, using placeholder types like <T>. When writing JavaScript, the @template JSDoc tag serves the exact same purpose, declaring one or more generic type variables for the scope of the associated function, class, or type alias.

/**
 * @template T
 * @param {T} value
 * @returns {T}
 */
function identity(value) {
  return value;
}

// Inferred as number:
const num = identity(42);

// Inferred as string:
const str = identity("hello");

Declaring Multiple Type Parameters

You can declare multiple type parameters in two ways: by listing them as a comma-separated list in a single @template tag, or by specifying multiple @template tags sequentially.

/**
 * Merges two objects together.
 * @template T, U
 * @param {T} first
 * @param {U} second
 * @returns {T & U}
 */
function merge(first, second) {
  return { ...first, ...second };
}

Alternatively:

/**
 * @template T
 * @template U
 * @param {T} key
 * @param {U} value
 */
function setEntry(key, value) {
  // ...
}

Constraining Generic Types

Just as TypeScript supports constraints using the extends keyword (e.g., <T extends HasId>), the @template tag allows constraints by specifying the constraint type in curly braces before the parameter name.

/**
 * @template {{ id: string | number }} T
 * @param {T} item
 * @returns {string | number}
 */
function getId(item) {
  return item.id;
}

// Valid:
getId({ id: 101, name: "Widget" });

// TypeScript/IDE Error: Argument is missing 'id' property
getId({ name: "Widget" });

Setting Default Generic Types

You can assign a default type to a generic parameter using an equals sign (=) inside the curly braces. If the type cannot be inferred from arguments and is not explicitly specified, the default type is applied.

/**
 * @template {HTMLElement} [T=HTMLDivElement]
 * @param {string} id
 * @returns {T | null}
 */
function getElement(id) {
  return /** @type {T | null} */ (document.getElementById(id));
}

Using @template with ES6 Classes

The @template tag can be placed above ES6 classes to make the entire class generic. The declared type parameters are available across all instance methods and properties within that class.

/**
 * @template T
 */
class DataStore {
  /**
   * @param {T} initialData
   */
  constructor(initialData) {
    /** @type {T} */
    this.data = initialData;
  }

  /**
   * @returns {T}
   */
  getData() {
    return this.data;
  }

  /**
   * @param {T} updatedData
   */
  setData(updatedData) {
    this.data = updatedData;
  }
}

// Inferred as DataStore<number>
const store = new DataStore(100);

Creating Generic Type Definitions

The @template tag also works with @typedef and @callback tags, allowing you to define reusable generic object shapes and function signatures.

/**
 * @template T
 * @typedef {Object} ApiResponse
 * @property {boolean} success
 * @property {T} payload
 * @property {string|null} error
 */

/**
 * @template T
 * @callback FilterCallback
 * @param {T} item
 * @returns {boolean}
 */

By leveraging @template, JavaScript developers achieve the full flexibility of TypeScript's type system while maintaining pure JavaScript source code.
