Using instanceof with TypeScript Interfaces

In TypeScript, you cannot use the instanceof operator to narrow custom interface types because interfaces exist solely at compile time and are erased from the emitted JavaScript. The instanceof operator is a JavaScript runtime check that evaluates an object's prototype chain against a constructor function. Because an interface has no runtime presence, referencing it as the right-hand operand of instanceof causes a TypeScript compilation error: "'InterfaceName' only refers to a type, but is being used as a value here." To achieve reliable type narrowing with interfaces, you must use runtime-compatible alternatives such as classes, user-defined type guards, the in operator, or discriminated unions.

Why instanceof Fails with Interfaces

The instanceof operator checks whether a constructor's prototype property appears anywhere in the prototype chain of an object. Consider this invalid example:

interface User {
  id: string;
  name: string;
}

function processEntity(entity: unknown) {
  // Error: 'User' only refers to a type, but is being used as a value here.
  if (entity instanceof User) {
    console.log(entity.name);
  }
}

Since the TypeScript compiler removes the User interface entirely when generating JavaScript, there is no User constructor function to evaluate at runtime.

Alternative 1: Use Classes Instead of Interfaces

If your design allows it, replace the interface with a class. Classes generate both a type declaration for compile-time checking and a constructor function for runtime execution.

class User {
  constructor(public id: string, public name: string) {}
}

function processEntity(entity: unknown) {
  if (entity instanceof User) {
    // TypeScript correctly narrows 'entity' to the User type
    console.log(entity.name);
  }
}

Alternative 2: User-Defined Type Guards

When you must retain interfaces, user-defined type guards (functions returning a type predicate value is Type) are the most common solution. They perform runtime verification of the object's shape and inform TypeScript's type checker of the result.

interface User {
  id: string;
  name: string;
}

function isUser(value: unknown): value is User {
  return (
    typeof value === 'object' &&
    value !== null &&
    'id' in value &&
    typeof (value as Record<string, unknown>).id === 'string' &&
    'name' in value &&
    typeof (value as Record<string, unknown>).name === 'string'
  );
}

function processEntity(entity: unknown) {
  if (isUser(entity)) {
    console.log(entity.name); // 'entity' is safely narrowed to User
  }
}

Alternative 3: The in Operator

TypeScript's control flow analysis natively understands the JavaScript in operator. You can narrow an interface by verifying that a unique property exists on the object.

interface Admin {
  role: string;
  privileges: string[];
}

interface Customer {
  loyaltyPoints: number;
}

function handleAccount(account: Admin | Customer) {
  if ('privileges' in account) {
    console.log(account.privileges); // Narrowed to Admin
  } else {
    console.log(account.loyaltyPoints); // Narrowed to Customer
  }
}

Alternative 4: Discriminated Unions

For domain models with multiple variants, assign a common literal property (a discriminant) to each interface. This allows straightforward narrowing using if or switch statements without explicit helper functions.

interface Circle {
  kind: 'circle';
  radius: number;
}

interface Square {
  kind: 'square';
  size: number;
}

type Shape = Circle | Square;

function calculateArea(shape: Shape): number {
  switch (shape.kind) {
    case 'circle':
      return Math.PI * shape.radius ** 2; // Narrowed to Circle
    case 'square':
      return shape.size * shape.size; // Narrowed to Square
  }
}
