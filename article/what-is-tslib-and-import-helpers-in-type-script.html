What Is tslib and importHelpers in TypeScript

This article explains the role of the tslib library and the importHelpers compiler option in TypeScript projects. When compiling modern TypeScript to older ECMAScript targets, TypeScript generates internal helper functions to replicate modern language features. By default, these helpers are duplicated across every file that requires them, bloating bundle sizes. Enabling importHelpers instructs the compiler to import these functions from the external tslib package instead, resulting in deduplicated, cleaner, and significantly smaller production bundles.

How TypeScript Handles Helpers by Default

When targeting older JavaScript versions such as ES5 or ES6, TypeScript must downlevel newer syntax—such as the spread operator, async/await, destructuring, or class inheritance. To make this code run in environments that do not natively support these features, the TypeScript compiler injects boilerplate helper functions directly into the generated output.

Common generated helpers include:

  • __awaiter and __generator for async/await functions
  • __assign or __rest for object destructuring and spread syntax
  • __extends for class inheritance

By default, TypeScript inlines these helper implementations into the top of every single compiled file that uses the respective syntax. If an application contains hundreds of files that use async/await, the __awaiter helper function is repeated hundreds of times in the final compiled code.

The Problem: Bundle Bloat

Inlining helpers creates significant code duplication. While each individual helper function is small (typically a few lines of code), repeated definitions across a large project add unnecessary kilobytes to the final JavaScript bundle. This degrades network transfer speeds and parse times in browser environments without providing any functional benefit.

What Is tslib?

The tslib package is an official, lightweight runtime library maintained by the TypeScript team at Microsoft. It contains centralized implementations of all the internal helper functions that the TypeScript compiler might need during downlevel compilation.

Instead of generating local helper functions in every compiled output file, tslib provides these utilities as exportable modules.

How importHelpers Works

The importHelpers flag is a compiler option in your tsconfig.json file.

When importHelpers is set to true, the TypeScript compiler stops generating inline implementations of helper functions. Instead, it emits standard module import statements pointing to tslib:

// Generated output when importHelpers is enabled
import { __awaiter, __generator } from "tslib";

Because the helpers are imported as a module, modern bundlers (such as Webpack, Rollup, Vite, or esbuild) can bundle tslib once and share its functions across the entire application.

How to Use importHelpers and tslib

To utilize this optimization, follow two steps:

1. Install tslib as a Runtime Dependency

Because tslib contains code required at runtime by the compiled JavaScript, it must be installed as a production dependency, not a development dependency:

npm install tslib

2. Enable importHelpers in tsconfig.json

Add the "importHelpers": true flag under compilerOptions in your tsconfig.json:

{
  "compilerOptions": {
    "target": "es5",
    "module": "esnext",
    "importHelpers": true,
    "strict": true
  }
}

Once enabled, TypeScript will automatically replace inlined helpers with imports from tslib, ensuring optimal code reuse and minimal bundle sizes across your application.
