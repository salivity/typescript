How TypeScript Narrows Types with the ?? Operator

The nullish coalescing operator (??) in TypeScript provides a concise way to fall back to a default value when dealing with potentially absent data. TypeScript’s compiler uses control flow analysis to inspect the operands of the ?? operator, automatically narrowing the resulting expression's type by stripping out null and undefined from the left-hand operand and combining any remaining types with the type of the right-hand operand.

The Mechanics of Nullish Coalescing Narrowing

The ?? operator evaluates to its right-hand side only if the left-hand side is strictly null or undefined. Because of this runtime behavior, TypeScript models the resulting type as:

NonNullable<TypeLeft> | TypeRight

If the left operand is a union containing nullable and non-nullable types, TypeScript removes null and undefined from that union before joining it with the right operand's type.

For example:

function getPort(customPort: number | undefined): number {
  const port = customPort ?? 3000;
  return port;
}

In this case:

  1. customPort has the type number | undefined.
  2. The ?? operator filters out undefined.
  3. The remaining left-hand type is number.
  4. The right-hand operand 3000 is also of type number.
  5. The resulting type of port is narrowed strictly to number.

Preserving Falsy Values

A critical aspect of type narrowing with ?? is that it preserves other falsy values such as 0, "" (empty string), false, and NaN. This differs from the logical OR operator (||), which narrows out all falsy values.

type Config = {
  timeout: number | null;
  debug: boolean | undefined;
};

function applyConfig(config: Config) {
  // timeout is narrowed from (number | null) to number
  const timeout = config.timeout ?? 5000;

  // debug is narrowed from (boolean | undefined) to boolean
  // If config.debug is false, false is preserved rather than falling back to true
  const debug = config.debug ?? true;
}

Because false and 0 do not trigger the right-hand expression, TypeScript retains them as valid types in the narrowed outcome.

Combining Different Types

When the left operand and the right operand have completely different types, TypeScript forms a union of the non-nullable left-side types and the right-side type.

function processInput(input: string | null): string | number {
  const result = input ?? 0;
  return result; // Type is string | number
}

Here, input starts as string | null. Applying ?? 0 eliminates null, leaving string. It then unions string with the type of 0 (number), resulting in string | number.

Definite Assignment and Control Flow

TypeScript also applies narrowing across statements when short-circuiting or throwing an error on the right side:

function assertValue(value: string | null) {
  const resolved = value ?? throw new Error("Missing value");
  // resolved is narrowed to string
}

If the right-hand expression does not return (such as a function returning never or a throw statement), the compiler knows that execution cannot continue past that point if the left operand was null or undefined. Consequently, any subsequent usage treats the expression as strictly non-nullable.
