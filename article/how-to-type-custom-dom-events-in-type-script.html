How to Type Custom DOM Events in TypeScript

TypeScript provides robust type safety for standard DOM events, but dispatching and listening for custom events often causes developers to lose type inference or fall back on any. This guide demonstrates how to properly type custom DOM events using TypeScript's built-in CustomEvent<T> generic and how to augment global DOM interfaces (HTMLElementEventMap, DocumentEventMap, and WindowEventMap) so that addEventListener automatically recognizes your event names and their strongly typed payloads.

Defining the Custom Event Payload

When creating a custom event, the payload typically lives on the detail property. Start by defining the structure of that data using a TypeScript interface or type:

export interface UserLoginDetail {
  userId: string;
  timestamp: number;
}

Creating and Dispatching Typed Custom Events

TypeScript's standard library includes a generic CustomEvent<T> interface, where T represents the type of the detail property. You can use this generic directly when instantiating the event:

const event = new CustomEvent<UserLoginDetail>('user-login', {
  detail: {
    userId: 'usr_12345',
    timestamp: Date.now(),
  },
  bubbles: true,
  cancelable: true,
});

document.dispatchEvent(event);

If you construct the event with data that does not match UserLoginDetail, TypeScript will raise a compile-time error.

Extending Global Event Maps for Automatic Inference

By default, calling addEventListener('user-login', (e) => ...) will treat e as a generic Event, forcing manual type assertions (e.g., e as CustomEvent<UserLoginDetail>).

To enable automatic type inference without casting, merge your custom event definition into TypeScript's built-in event maps using interface declaration merging.

For HTMLElement or Generic DOM Elements

Augment the HTMLElementEventMap to enable typing on standard HTML elements:

declare global {
  interface HTMLElementEventMap {
    'user-login': CustomEvent<UserLoginDetail>;
  }
}

For document and window

If your events are dispatched at the document or window level, extend DocumentEventMap or WindowEventMap instead:

declare global {
  interface DocumentEventMap {
    'user-login': CustomEvent<UserLoginDetail>;
  }

  interface WindowEventMap {
    'user-login': CustomEvent<UserLoginDetail>;
  }
}

Note: If your code resides in an ES module (containing import or export statements), you must wrap the declarations inside declare global { ... }. In a non-module ambient declaration file (.d.ts), omit declare global.

Listening with Full Type Safety

Once the event maps are augmented, any call to addEventListener using your custom event name will infer the exact CustomEvent type for the event listener argument:

// 'e' is automatically inferred as CustomEvent<UserLoginDetail>
document.addEventListener('user-login', (e) => {
  console.log(e.detail.userId);
  console.log(e.detail.timestamp);
});

Attempting to access non-existent properties on e.detail will trigger a TypeScript type-checking error, ensuring complete type safety across your entire event pipeline.
