How Exclude Filters Union Members in TypeScript

TypeScript's built-in Exclude<T, U> utility type constructs a new type by removing all union members from T that are assignable to U. This article explains the underlying mechanism of Exclude, breaking down how distributive conditional types evaluate each member of a union individually and why the never type is used to eliminate unwanted variants.

The Definition of Exclude

In TypeScript's standard library, Exclude is defined using a conditional type:

type Exclude<T, U> = T extends U ? never : T;

This definition relies on two key TypeScript behaviors: distributive conditional types and the pruning behavior of the never type in unions.

Distributive Conditional Types

When a conditional type acts on a generic parameter T, and T is given a union type, the conditional type becomes distributive. Instead of evaluating the entire union at once, TypeScript splits the union into individual members, applies the condition to each member separately, and then combines the results back into a single union.

For example, consider filtering a union of string literals:

type Status = "pending" | "success" | "error";
type ActionableStatus = Exclude<Status, "pending">;

Because T (Status) is a naked type parameter receiving a union, TypeScript expands the operation into:

type ActionableStatus =
  | ("pending" extends "pending" ? never : "pending")
  | ("success" extends "pending" ? never : "success")
  | ("error" extends "pending" ? never : "error");

The Role of never in Unions

TypeScript evaluates each branch independently:

  1. "pending" extends "pending" is true, so it evaluates to never.
  2. "success" extends "pending" is false, so it evaluates to "success".
  3. "error" extends "pending" is false, so it evaluates to "error".

The intermediate result is:

type ActionableStatus = never | "success" | "error";

In TypeScript, never represents an empty set or a value that can never occur. When never appears inside a union type, TypeScript automatically removes it:

type ActionableStatus = "success" | "error";

Filtering by Assignability, Not Just Exact Matches

The condition T extends U checks whether a member is assignable to U. This means Exclude can filter out subtypes, not just exact literal matches.

type Events = 
  | { type: "click"; x: number; y: number }
  | { type: "hover"; element: string }
  | { type: "scroll"; offset: number };

// Remove any event that has a 'scroll' type
type UserInteractions = Exclude<Events, { type: "scroll" }>;

In this case:

  • { type: "click"; ... } extends { type: "scroll" } is false, returning the click event type.
  • { type: "hover"; ... } extends { type: "scroll" } is false, returning the hover event type.
  • { type: "scroll"; ... } extends { type: "scroll" } is true, returning never.

After removing never, UserInteractions consists only of the click and hover event object types.
