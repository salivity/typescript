Is Object.freeze() Deeply Immutable in TypeScript?

Object.freeze() does not provide deep immutability by default in either JavaScript or TypeScript. While it prevents modifications to an object's direct top-level properties, any nested objects or arrays remain mutable at runtime. Furthermore, TypeScript's type system mirrors this shallow behavior by only wrapping the top-level object in a shallow Readonly<T> type. This article breaks down how Object.freeze() operates, why nested properties remain vulnerable, and how to achieve true deep immutability.

The Shallow Nature of Object.freeze()

At runtime, JavaScript's built-in Object.freeze() function operates strictly on the immediate object passed to it. It prevents adding new properties, removing existing properties, and modifying the values of top-level properties. However, if a property holds a reference to another object, only the reference itself is frozen, not the target object.

const user = Object.freeze({
  name: "Alice",
  preferences: {
    theme: "dark"
  }
});

// Runtime Error: Cannot assign to read only property 'name' in strict mode
// user.name = "Bob"; 

// Allowed: Modifies the nested object
user.preferences.theme = "light"; 
console.log(user.preferences.theme); // "light"

How TypeScript Handles Object.freeze()

TypeScript's standard library defines Object.freeze() using the Readonly<T> utility type:

freeze<T>(o: T): Readonly<T>;

Because Readonly<T> is a shallow mapped type, it marks only the immediate keys of T as readonly. It does not recurse into nested objects. As a result, the TypeScript compiler will raise a type error if you try to mutate a top-level key, but it will allow mutations to nested keys without any compiler warnings:

const config = Object.freeze({
  endpoint: "https://api.example.com",
  headers: {
    authorization: "Bearer token"
  }
});

// Compile error: Cannot assign to 'endpoint' because it is a read-only property.
// config.endpoint = "https://new.example.com";

// Compiles and executes without error:
config.headers.authorization = "Bearer updated";

Achieving Deep Immutability

To ensure an object cannot be mutated at any level, you must enforce immutability at both compile time and runtime.

1. Compile-Time: DeepReadonly Type

You can define a recursive type that marks all properties, including nested ones, as readonly:

type DeepReadonly<T> = T extends Function | boolean | number | string | symbol | null | undefined
  ? T
  : { readonly [P in keyof T]: DeepReadonly<T[P]> };

2. Runtime: Recursive Deep Freeze Function

To protect the data at runtime, combine the DeepReadonly<T> type with a recursive freezing function:

function deepFreeze<T>(obj: T): DeepReadonly<T> {
  Object.keys(obj as object).forEach((prop) => {
    const value = (obj as Record<string, unknown>)[prop];
    if (value !== null && (typeof value === "object" || typeof value === "function")) {
      deepFreeze(value);
    }
  });

  return Object.freeze(obj) as DeepReadonly<T>;
}

Now, modifying a nested property will trigger both a TypeScript compiler error and a runtime error:

const immutableSettings = deepFreeze({
  display: {
    resolution: "1080p"
  }
});

// TypeScript Error: Cannot assign to 'resolution' because it is a read-only property.
// Runtime TypeError: Cannot assign to read only property 'resolution'
immutableSettings.display.resolution = "4k";

Alternatively, if you require full structural immutability across an application, consider using libraries like Immer or Immutable.js, which handle recursive immutability without the performance overhead of traversing and freezing deep object trees.
