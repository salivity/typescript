Nominal Typing in TypeScript with Unique Symbol

TypeScript's structural type system determines type compatibility based on shape rather than explicit declarations, meaning primitive types like string or number are interchangeable regardless of their semantic meaning. This article explains how TypeScript's unique symbol feature enables nominal typing—often referred to as type branding or flavoring—for primitive values, ensuring compile-time distinctness, preventing accidental substitutions, and maintaining zero runtime performance overhead.

The Limitation of Structural Typing for Primitives

In standard TypeScript, defining aliases for primitive types does not create distinct types:

type UserId = string;
type OrderId = string;

let user: UserId = "user_123";
let order: OrderId = "order_456";

user = order; // Compiles without error

Because both UserId and OrderId resolve to the primitive string, the compiler treats them as structurally identical. This makes it easy to accidentally pass an OrderId into a function expecting a UserId.

What Is unique symbol?

A unique symbol is a specialized subtype of symbol tied to a specific declaration. Unlike regular symbols, each unique symbol represents an entirely distinct identity within TypeScript’s static type system. It can only be instantiated using const or readonly static properties:

declare const BrandA: unique symbol;
declare const BrandB: unique symbol;

// BrandA and BrandB are not assignable to each other

Because the compiler guarantees that no two unique symbol types are equivalent, they serve as globally unique type-level identifiers.

Implementing Nominal Branding with unique symbol

To simulate nominal typing, you can intersect a primitive type with an object shape that contains a property keyed by a unique symbol.

declare const UserIdBrand: unique symbol;
export type UserId = string & { readonly [UserIdBrand]: void };

declare const OrderIdBrand: unique symbol;
export type OrderId = string & { readonly [OrderIdBrand]: void };

In this pattern:

  1. UserId remains assignable to string operations (such as .toLowerCase() or concatenation) because it is an intersection with string.
  2. A raw string cannot be assigned to UserId because it lacks the property keyed by UserIdBrand.
  3. An OrderId cannot be assigned to UserId because OrderIdBrand and UserIdBrand are distinct unique symbol types that cannot overlap.

Creating and Consuming Nominal Primitives

Because the branded properties do not exist at runtime, values are typically instantiated through explicit type assertions or validator functions:

function toUserId(id: string): UserId {
  // Optional runtime validation can be placed here
  return id as UserId;
}

function toOrderId(id: string): OrderId {
  return id as OrderId;
}

function fetchUserOrders(userId: UserId) {
  // Implementation
}

const userId = toUserId("usr_100");
const orderId = toOrderId("ord_200");

fetchUserOrders(userId);   // Valid
fetchUserOrders(orderId);  // Error: Type 'OrderId' is not assignable to type 'UserId'
fetchUserOrders("raw_id"); // Error: Type 'string' is not assignable to type 'UserId'

Advantages Over String-Based Branding

Developers frequently brand types using string literal tags, such as:

type UserId = string & { readonly __brand: "UserId" };

While functional, string-based brands introduce collision risks across different libraries or modules if they choose identical string keys or tag values. Using unique symbol ensures guaranteed uniqueness across distinct codebases. Even if two modules name their branded symbol declarations identically, the compiler isolates their identities, making unique symbol the most robust mechanism for nominal typing in TypeScript.
