What Is Emitted in a TypeScript .d.ts File?

TypeScript declaration files, designated by the .d.ts extension, act as type-only blueprints for JavaScript code. This article explains the exact information the TypeScript compiler emits into a .d.ts file, illustrating how executable logic is stripped away to leave only the shape, documentation, and metadata necessary for type checking, IntelliSense, and cross-project consumption.

Function and Method Signatures

The compiler emits the names, parameter lists, parameter types, and return types of all exported functions and methods. All implementation blocks ({ ... }) are stripped entirely, leaving only the signature ending in a semicolon. Overloaded functions retain all distinct overload signatures to provide accurate type inference to consumers.

Type Aliases and Interfaces

All exported type aliases, interface definitions, and generic type constraints are preserved directly in the .d.ts output. These elements are inherently type-level constructs, so they undergo minimal transformation beyond normalizing module imports and resolving internal aliases.

Class Declarations

Classes in declaration files are emitted as structural outlines. The output includes:

  • Constructors: Parameter names and types, without execution logic.
  • Public and Protected Members: Property names, their types, and method signatures.
  • Accessibility Modifiers: Keywords such as public, protected, and TypeScript-style private to inform access rules.
  • Readonly Modifiers: Flags indicating immutable properties.

Implementation details, including method bodies, default property initializers, and ECMAScript private fields (#field), are omitted.

Variable and Constant Declarations

Exported variables declared with var, let, or const are prefixed with the declare keyword. The file contains the variable name paired with its explicit or inferred type. Runtime values are stripped; however, for primitive const declarations, TypeScript may preserve literal types (e.g., declare const PORT = 3000; rather than number) to retain type precision.

Enums

Regular TypeScript enums are emitted either as ambient enum declarations or as declaration blocks detailing the enum members and their assigned numerical or string values. These values are retained because enums often exist at both the type and value levels in consuming code.

Export and Import Statements

The .d.ts file accurately mirrors the module structure of the original file. It includes:

  • Explicit import declarations for external types referenced by the signatures.
  • Named, default, and wildcard export declarations.
  • Ambient namespace or module declarations if the source uses internal modules.

Internal variables, unexported helper functions, and unused imports are excluded from the output.

JSDoc Comments

JSDoc comments (/** ... */) associated with exported declarations are preserved and copied into the declaration file. This ensures that parameter descriptions, deprecation notices (@deprecated), and usage notes remain visible via IDE tooltips for downstream users.
