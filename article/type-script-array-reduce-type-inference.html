TypeScript Array reduce Type Inference

This article explains how TypeScript handles type inference for Array.prototype.reduce. It details the underlying TypeScript declaration signatures, examines how inference behaves with and without an initial value, highlights frequent inference pitfalls—such as empty objects and widening—and demonstrates the best practices for providing explicit types to ensure compile-time type safety.

The Standard Reduce Overloads

TypeScript relies on the standard library definition (lib.es5.d.ts) to infer types for Array.prototype.reduce. It primarily defines two distinct overloads:

  1. Without an initial value:
reduce(
  callbackfn: (previousValue: T, currentValue: T, currentIndex: number, array: T[]) => T
): T;

When no initial value is passed, the accumulator takes the type of the array elements (T). The operation must produce a value of the same type T.

  1. With an initial value:
reduce<U>(
  callbackfn: (previousValue: U, currentValue: T, currentIndex: number, array: T[]) => U,
  initialValue: U
): U;

When an initial value is supplied, TypeScript introduces a new generic type parameter, U. The accumulator type is inferred directly from the initialValue passed as the second argument.

Case 1: Reducing Without an Initial Value

When aggregating an array where the accumulator matches the item type, TypeScript infers both the accumulator and return type from the source array.

const numbers = [1, 2, 3, 4];
const sum = numbers.reduce((acc, curr) => acc + curr);
// `acc` is inferred as number
// `curr` is inferred as number
// `sum` is inferred as number

If the callback attempts to return a different type than T, TypeScript emits a compiler error because the overload requires the accumulator and return type to remain strictly T.

Case 2: Reducing With an Initial Value

Providing an initial value allows the output to diverge from the element type. TypeScript checks the type of initialValue to instantiate the generic parameter U.

const words = ["apple", "banana", "cherry"];
const totalLength = words.reduce((acc, word) => acc + word.length, 0);
// `acc` is inferred as number (from initialValue `0`)
// `word` is inferred as string (from array element type)
// `totalLength` is inferred as number

Common Inference Pitfalls

1. The Empty Object Literal

A frequent mistake occurs when transforming an array into an object lookup using {} as the initial value:

const users = [
  { id: "u1", name: "Alice" },
  { id: "u2", name: "Bob" }
];

const userMap = users.reduce((acc, user) => {
  acc[user.id] = user; // Error: Element implicitly has an 'any' type because type '{}' has no index signature.
  return acc;
}, {});

TypeScript infers U as {} (an empty object with no known properties). Mutating acc fails because {} forbids arbitrary property additions.

2. The Empty Array Literal

Passing [] without context causes TypeScript to infer never[]:

const nested = [[1, 2], [3, 4]];
const flattened = nested.reduce((acc, curr) => acc.concat(curr), []);
// `acc` is inferred as never[]

Depending on the TypeScript version and strictness settings, attempting to invoke .concat() or .push() on a never[] accumulator will trigger type errors.

How to Correctly Guide Type Inference

When the initial value does not convey the full structure of the desired output, you must explicitly declare the type.

Method 1: Explicit Generic Argument (Recommended)

Pass the expected accumulator type explicitly to the reduce generic call:

interface User {
  id: string;
  name: string;
}

const userMap = users.reduce<Record<string, User>>((acc, user) => {
  acc[user.id] = user;
  return acc;
}, {});
// `acc` is correctly typed as Record<string, User>
// `userMap` is correctly typed as Record<string, User>

Method 2: Type Assertion on the Initial Value

Assert the type of the initial value directly:

const userMap = users.reduce((acc, user) => {
  acc[user.id] = user;
  return acc;
}, {} as Record<string, User>);

While functional, using the generic argument reduce<TargetType>(...) is generally safer because it avoids bypassing type checks via assertions.
