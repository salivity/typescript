Optional Properties Without Undefined in TypeScript

By default, marking a property as optional in TypeScript with the ? token allows callers to either omit the key entirely or explicitly pass undefined as its value. This article explains how to enforce that a property can be omitted from an object while strictly forbidding an explicit undefined value, using both TypeScript's native compiler settings and purely type-level constructs.

Method 1: Enable exactOptionalPropertyTypes (Recommended)

The most direct and idiomatic way to disallow explicit undefined on optional fields is by enabling the exactOptionalPropertyTypes flag in your tsconfig.json. Introduced in TypeScript 4.4, this flag changes how the ? modifier behaves.

1. Update tsconfig.json

{
  "compilerOptions": {
    "strict": true,
    "exactOptionalPropertyTypes": true
  }
}

2. Define the Interface

With this flag enabled, standard optional properties will only accept the specified type, not undefined.

interface UserProfile {
  username: string;
  bio?: string;
}

// Allowed: Key omitted
const user1: UserProfile = {
  username: "johndoe"
};

// Allowed: Key provided with the correct type
const user2: UserProfile = {
  username: "johndoe",
  bio: "Hello world"
};

// Error: Type 'undefined' is not assignable to type 'string'
const user3: UserProfile = {
  username: "johndoe",
  bio: undefined
};

If you ever need an optional property that does accept undefined, you must explicitly annotate it as bio?: string | undefined.

Method 2: Use Union Types (Without Modifying tsconfig.json)

If you cannot modify your project's tsconfig.json, you can model the behavior directly in the type system using a union. A property can be omitted if one member of the union lacks the property entirely, while the other requires the property as a non-undefined type.

1. Define Base and Extended Types

type BaseUser = {
  username: string;
};

type UserWithBio = BaseUser & {
  bio: string; // Required, not undefined
};

type UserProfile = BaseUser | UserWithBio;

2. Validate Behavior

Object literal excess property checking ensures that { bio: undefined } cannot be passed:

// Allowed: Key omitted
const user1: UserProfile = {
  username: "johndoe"
};

// Allowed: Key provided with valid type
const user2: UserProfile = {
  username: "johndoe",
  bio: "Hello world"
};

// Error: Type 'undefined' is not assignable to type 'string'
const user3: UserProfile = {
  username: "johndoe",
  bio: undefined
};

Method 3: Reusable Generic Helper

To apply this pattern across multiple interfaces without redefining unions manually, create a generic helper type:

type WithoutKey<T, K extends keyof T> = Omit<T, K>;

type OptionalStrict<T, K extends keyof T> = 
  | WithoutKey<T, K> 
  | (WithoutKey<T, K> & { [P in K]: Exclude<T[P], undefined> });

// Usage:
interface RawConfig {
  host: string;
  port: number;
}

type Config = OptionalStrict<RawConfig, "port">;

// Allowed: 'port' omitted
const server1: Config = { host: "localhost" };

// Allowed: 'port' is a number
const server2: Config = { host: "localhost", port: 8080 };

// Error: Type 'undefined' is not assignable to type 'number'
const server3: Config = { host: "localhost", port: undefined };

Summary

  • Use exactOptionalPropertyTypes if you control compiler settings. It applies globally and keeps standard ? syntax clean.
  • Use union types or generic utility types if you need this constraint scoped to specific types without changing project-wide TypeScript configurations.
