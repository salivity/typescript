TypeScript preserveConstEnums Explained

The preserveConstEnums compiler flag in TypeScript changes how const enum declarations are emitted into the resulting JavaScript. By default, TypeScript completely erases const enum definitions during compilation and inlines their raw scalar values directly into code where they are used. Enabling preserveConstEnums instructs the compiler to generate the actual runtime JavaScript object for the enum while still retaining the performance benefit of inlining member values at call sites.

Default Behavior Without the Flag

Under standard compiler settings (preserveConstEnums: false), a const enum exists solely as a compile-time construct. Consider the following code:

const enum Status {
  Active = "ACTIVE",
  Inactive = "INACTIVE",
}

const currentStatus = Status.Active;

When compiled, TypeScript strips away the Status definition entirely. The emitted JavaScript only contains the inlined literal value:

"use strict";
const currentStatus = "ACTIVE";

Because no Status object is emitted, you cannot access Status dynamically at runtime, inspect it in a debugger, or pass the enum collection to other functions.

Behavior With preserveConstEnums: true

When preserveConstEnums is set to true in tsconfig.json, TypeScript changes its output strategy. It continues to inline member accesses as literals, but it also generates the runtime object definition for the enum:

"use strict";
var Status;
(function (Status) {
    Status["Active"] = "ACTIVE";
    Status["Inactive"] = "INACTIVE";
})(Status || (Status = {}));

const currentStatus = "ACTIVE";

Notice that currentStatus still receives the inlined value "ACTIVE". However, the Status object now exists in memory.

Key Use Cases

  1. Debugging: Having the enum object present in the runtime environment allows developers to inspect available values in the browser console or Node.js REPL without having to look up source files.
  2. Runtime Lookups and Reflection: It allows external code or dynamic evaluation scripts to reference the enum object (e.g., Object.keys(Status)), while your local TypeScript code still enjoys the speed of inlined constants.
  3. Module Interoperability: When publishing libraries, non-TypeScript consumers or tools using isolated-file transpilers can still access the generated enum object directly.
